# figma-spec-08-экраны.md

> Проход 08 спецификации компонентов RutCampusTrack — завершающий.
> Блоки — проходы 07a–07d. Компоненты — проходы 01–06.
> Основания — `figma-spec-00-основания.md`.

**Что делает этот файл.** Отвечает, из каких блоков собирается каждый экран
и что меняется между тремя ширинами. **Экраны здесь не рисуются** — это
этап макетов.

**Чего в нём нет.** Состава блоков (проход 07), анатомии компонентов
(проходы 01–06), значений (брендбук).

## 4. Роль headman

### 111 · Главная старосты

| | |
|---|---|
| Блоки | `LessonCounters` · `ManualAttendance` · `LessonActivityLog` · `HomeworkToday` · `RequestsCounter` |

## 8. Порядок сборки библиотеки

Рекомендация под заведение через Figma MCP. Порядок вытекает из зависимостей:
каждый следующий уровень инстанцирует предыдущий.

| Шаг | Что заводится | Файл спеки |
|---|---|---|
| 1 | переменные: примитивы → семантика → размеры → эффекты | `tokens-v2.json` |
| 2 | текстовые стили по шкале | брендбук §3.3 |
| 3 | атомы: иконка, кольцо фокуса, символ статуса, чип | 01, 04 |
| 4 | контролы: кнопка, ссылка, поля, чекбокс, радио | 01 |
| 5 | наложения: поповер, подсказка, меню, модалка | 02 |
| 6 | навигация и листалки | 02 |
| 7 | примитивы таблиц | 03a |
| 8 | значения и статусы | 04 |
| 9 | сетки, журналы, реестры | 03b, 03c |
| 10 | карточки, панели, формы | 05a, 05b |
| 11 | состояния | 06 |
| 12 | блоки по ролям | 07a–07d |
| 13 | экраны | этот файл |

**Шаги 1 и 2 обязаны быть выполнены до всего остального.** Компонент,
собранный на литералах, придётся переделывать целиком: связать существующий
слой с переменной задним числом дороже, чем нарисовать заново.

## 9. Что осталось открытым

1. **Спеки 001, 001a, 001b не прикладывались** — блоки входа выведены
   из реестра (§2). Требуют сверки.
2. **`FloorRoomList`** — компонент без содержания; решение о выводе
   из обихода за владельцем (07a §11, подтверждено 07d §10.4).
3. **У роли admin нет экрана статистики** — JS-ADMIN-12 и JS-ADMIN-13 не
   ложатся ни на один экран. Дыра уровня роли, на сборку не влияет.
4. **Режим одной пары на 122** — вторая точка входа; если цепочка контекста
   при этом скрывается целиком, `SubjectJournalRead` придётся разделить
   на два блока.
5. **Правка данных студента на 116** — право не подтверждено, `PUT` помечен
   ADMIN.
6. **Полный перечень состояний `LessonManagementCell`** — шесть из
   одиннадцати названы, остальные в спеке 118, которая приложена: **добрать
   дельтой при склейке**.
7. **Состав `UserCreateForm` по трём ветвям** — спека 132 приложена, состав
   полей в ней есть (§4.2 прохода 07d), но поимённая сверка с проходом 05b
   не проводилась. Добрать дельтой.
