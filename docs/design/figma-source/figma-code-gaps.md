# Расхождения модели Figma и кода

Заведён на шаге 2 (переменные и стили), ведётся дальше по мере накопления.

Здесь записано то, что **не переносится из Figma в код один в один**. Ни один пункт не является ошибкой сборки: это места, где Figma физически не умеет выразить то, что выражает CSS. При переносе в код смотреть сюда, а не только на макеты.

---

## 1. Межстрочный и межбуквенный не привязаны к переменным

**В Figma:** заданы значениями в процентах, без binding.
**В коде:** останутся отношениями со ссылкой на токен (`font/leading/*`, `font/tracking/*`).

**Почему.** Переменные Figma хранят числа без единиц. При привязке к leading число трактуется как пиксели: `115` становится `115px`, а не `115%`. Возврат единицы в проценты снимает привязку. Проверено фактом на стиле `display`.

**Что отброшено.** Отдельные пиксельные переменные под каждый кегль: они превращают межстрочный из отношения в величину, привязанную к размеру, дают 21 переменную вместо трёх и расходятся с CSS.

**Следствие.** Правка `font/leading/*` не разойдётся по стилям Figma сама — пройти по девяти стилям руками. В коде правка токена работает как обычно.

## 2. Тень: составной токен против стиля с переменными

**В коде:** одна строка — `0 8px 24px rgba(...)`, один токен.
**В Figma:** Effect Style с литеральной геометрией + связанные цветовые переменные.

**Почему.** У Effect Style в Figma нет режимов, поэтому одна тень не может иметь разные значения в тёмной и светлой теме. Тема переключается только через цвет, а цвет — обычная семантическая переменная с двумя режимами.

**Следствие.** Смещение, размытие и разброс в Figma остаются литералами. Изменение геометрии тени правится в двух местах — в JSON и в Effect Style.

## 3. Прозрачные примитивы под тени добавлены задним числом

Тени вводились правкой §2.5 отдельным решением, и до слоя примитивов правка не дошла: шести прозрачных цветов и трёх семантических токенов в исходном брендбуке не было. Заведены на шаге 2, внесены в `tokens-v2.json` и `brandbook-v2.md` §6.2.

Чистый `#000000` в палитру **не заводился** намеренно: самая тёмная ступень — `neutral/1000` = `#0B0B0C`. Прозрачные `black/alpha-*` существуют только как цвет тени и поверхностью быть не могут.

## 4. Кубические кривые движения в Figma отсутствуют

`easing/out` и `easing/in-out` переменными Figma не выражаются: кривая — четыре числа, переменная хранит одно. Живут только в JSON и уедут прямо в CSS.

Длительности (`duration/*`) заведены числовыми в коллекции `Motion`, значения в миллисекундах. Области применения у них нет — в Figma нет свойства, к которому длительность привязывается.

## 5. Табличные цифры включаются только вручную

Plugin API читает OpenType-функции, но не включает их. Во всех девяти текстовых стилях пункт Numbers → Style → «Monospace uppercase/lining» переключён руками; агент прочитал `tnum: true, lnum: true` обратно и подтвердил.

**Следствие.** Любой новый текстовый стиль в Figma требует того же ручного шага. В коде функция включена глобально в базовом слое и на новые стили распространяется сама.

Переменная `font/feature/tabular` со строкой `"tnum" 1, "lnum" 1` в Figma ни к чему не привязывается — существует только для CSS.

## 6. Штриховая рамка загрузки — литералом

`FileUploadField`: пунктир 4/4. Figma не привязывает переменные к `dashPattern`, поэтому значение остаётся литералом в компоненте. В CSS — `border-style: dashed` со своими правилами; совпадения один в один не будет.

## 6a. Пунктир свободного слота — литералом

`ScheduleSlotCell`: пунктир `4/4` у свободного слота. Figma не связывает `dashPattern` с переменной — то же ограничение, что у `FileUploadField`. Это проверенное ограничение инструмента, а не пробел токенов.

## 6b. Арифметика в связях переменных не выражается

Ширины ячеек расписания связаны с `schedule/column-min-width`, но координаты колонок и ширины многоколоночных заглушек остаются вычисленными литералами: Plugin API не связывает выражения вида `112 + n × token`. То же ограничение раньше всплывало на хвостовой колонке метрик журнала (`journal/metric-column-width` заведён отдельным токеном вместо произведения).

В CSS этой проблемы нет — там ширины считаются из тех же токенов выражением.

✏️ **13.08: прокрутка и залипание в макете не моделируются — решение владельца.** В Figma нет ни `overflow-x`, ни `position: sticky`: залипшая колонка изображается выносом за прокручиваемый кадр, и это имитация, а не поведение. **Из макета берётся только факт:** на такой-то ширине содержимое шире вьюпорта, залипшая колонка — первая, шириной `name-column/width`. Механику пишет код. Не искать в Figma то, чего там нет, и не тратить сборку на её имитацию.

Что из таблиц и сеток **в макете всё-таки обязано быть верным**, потому что уезжает в код: состав и ширины колонок, полнота сетки (неделя целиком, а не фрагмент), вложенность ячеек в сетку (наложенные слои геометрию не дают) и адаптив — что меняется на 1440 и 1280.

✏️ **15.08: текстовое свойство родителя не связывается с подписью внутри вложенного компонента.** У `StepPager` заведено `current-reset-label`, но Plugin API не связывает его с `label` внутри вложенного `AppButton`. Текущее состояние синхронизировано вручную — свойство, видимая подпись и доступное имя совпадают, — однако **последующая смена только `current-reset-label` вложенную кнопку не обновит**: нужен один ручной шаг в редакторе. **Для кода расхождения нет:** там подпись — обычный проп, уходящий в кнопку. Следствие для макетов: правя подпись листалки, проверять кнопку глазами.

✏️ **13.08: переменная длина списка в Figma не выражается.** У `DefinitionList` число пар — данные, но мастер держит фиксированный набор слоёв, поэтому пары сверх первой включаются булевыми свойствами `has-pair-2..4`. **В код не эмитятся:** там `<dl>` произвольной длины. Тот же приём понадобится любому списку с фиксированной разметкой.

✏️ **13.08: `percent-display` у `MetricValue` — свойство только Figma.** Заведено, чтобы процент заполнялся из панели экземпляра, а не переопределением вложенного текста. **В код не эмитится:** процент вычисляется из `value` и `total`, пропа под него в компоненте нет.

✏️ **12.08: у текстовой области в Figma нет максимума — только высота.** `textarea/max-height` = 168 в макете задан **фиксированной высотой**: `max-height` Figma не выражает. В коде поле начинается с трёх строк и **растёт по содержимому до 168**, дальше внутренний скролл. Макет показывает предел, а не стартовое состояние — не переносить 168 как `height`.

✏️ **12.08: `LiveNotificationRegion` в библиотеке не существует.** Это область `aria-live`: визуального представления у неё нет, рисовать в Figma нечего. **Требование целиком на код:** одна вежливая область на приложение, объявления ставятся в очередь и не перебивают друг друга, текст объявления не дублирует то, что и так видно на экране. Из состава части 9 компонент исключён 12.08.

✏️ **11.08: зачёркивание отменённой пары разведено двумя текстовыми свойствами.** В `LessonCard` зачёркнутые предмет и время живут в отдельных слоях со своими свойствами `cancelled-subject` и `cancelled-time`: зачёркивание в Figma — атрибут слоя, а не значение текстового свойства, и общее свойство распространило бы линию на все 15 вариантов. **Следствие для макетов:** подставляя данные на экране, надо заполнять оба поля, иначе в отменённом варианте останется демонстрационный текст. **В CSS полей два не нужно** — одна строка и `text-decoration: line-through` у состояния `cancelled`.

✏️ **11.08: сюда же попали две ширины календаря части 8.** `MonthCalendar.width` = 320 — это `7 × calendar/cell-size + 2 × space/5`; ширина подсветки диапазона 80 — это `2 × calendar/cell-size`. Оба остаются литералами в Figma и **новых токенов не требуют**: в CSS обе величины выражаются теми же переменными арифметикой. Не эмитить как самостоятельные размеры.

✏️ **11.08: сюда же попал процент у `MetricValue`.** `format=percent` показывает вычисленную величину (`value` ÷ `total`), и в коде она именно вычисляется. В Figma числа процента — **текстовое переопределение в каждом экземпляре**: свойства процента не существует, и заводить его нельзя, иначе в коде появится второй источник истины рядом с `value` и `total`. При переносе следить, чтобы переопределения из макета не переехали в разметку литералами.

## 7. Движение занятости в Figma не выражается

Решение по `busy` (брендбук §6.3) описывает бегущую полосу с длительностью `duration/slow` и кривой `easing/in-out`. В Figma собираются только статичные кадры — покой, занятость, результат. Кривая и длительность живут в токенах и попадают прямо в CSS, минуя макеты.

## 8. `radius/full = 999` — сентинел, а не размер

Означает «скруглить полностью». При переносе в код **на 16 не делится**: целевое значение `9999px`, а не `62.4375rem`.

---

## Размерности при переносе

Переменные Figma хранят числа без единиц. Геометрические значения (`space/*`, `radius/*`, `border/*`, `focus/*`, `row-height/*`, `control/height`) при генерации CSS делятся на 16 и становятся rem. Исключения: `radius/full` (см. п. 6) и `border/hairline` = 1, который в rem даёт `0.0625rem` — оставить в пикселях, иначе на дробном масштабе граница исчезнет.

Значения, дающие некруглую дробь при делении на 16, зафиксированы в отчёте по партии `Sizes`. Все они — чистые доли (0.25, 0.375, 0.5, 0.625, 0.75, 1.25, 1.5, 2.5), правки шкалы не требуют.

## Геометрия части 7, привязанная «по числу, а не по смыслу» (11.08.2026)

Проверка 17 мастеров части 7 нашла 12 мест, где переменная держит не то, что называет. Решение владельца 11.08: **не перебирать, ловить на экранах.** Разбирается при переносе в код — здесь список, чтобы он не потерялся.

| Компонент | Что держит | Токен | Привязок | Что делать в CSS |
|---|---|---|---|---|
| `AttendanceTrendChart` | шаг и ширина ячеек оси | `journal/metric-column-width` | 1005 | **не эмитить**: шаг оси в коде вычисляется — ширина области деления на число точек |
| `AttendanceTrendChart` | вертикальный шаг сетки | `row-height/compact` | 525 | **не эмитить**: то же, вычисляется |
| `AttendanceTrendChart` | длина штриха пунктирной серии | `space/2` | 450 | `stroke-dasharray`, литерал или своя переменная линии |
| `AttendanceTrendChart` | диаметр точки данных | `space/1` | 300 | размер точки, не отступ |
| `AttendanceRankingList` | колонка позиции и слот «Это я» | `journal/metric-column-width` | 6 | доля ширины блока, не колонка журнала |
| `.internal/AttendanceReasonEntry` | ширина `ComponentSet` | `dialog/width` | 1 | редакторская оболочка, в экземпляр не попадает |

**Почему это неизбежно у графика.** Вся его сетка в коде — арифметика (§6b), а Plugin API арифметику не выражает. В Figma она демонстрационная и на части 11 пересчитается заново: график встанет в блок с `fill` по ширине.

**Принято правило по мелким размерам.** Диаметр круга `AttendanceStatusBadge` (`space/5` / `space/6`), высота пилюли `TicketStatusBadge` (`space/5`) и высота строки роли `UserRoleStatusList` (`space/6`) остаются на шкале отступов. Это **сознательное отступление** от принципа «размер элемента не держится шкалой отступов», принятого на высоте `progress/bar-height`: заводить `badge/size-*` владелец счёл преждевременным. Следствие для кода: у круга отметки будет `width: var(--space-5)`, и при сдвиге шкалы отступов круги поедут вместе с ней.

**Известный хвост.** `AttendanceStatusPicker`, `overwrite-note.width` = `dialog/width`, 8 привязок — остаток снятой фиксированной ширины `variant=row`. Подписи нужен `FILL` по родителю. Правится попутно, отдельной партии не требует.
