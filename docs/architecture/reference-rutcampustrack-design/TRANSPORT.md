## Решение

**REST. Тонкий слой композиции (BFF) перед существующими сервисами: вниз — gRPC, вверх — ресурсы формы экрана.**

GraphQL отклонён. Главный класс дефицита — отсутствующие агрегаты под форму экрана, 54 пункта — от транспорта не зависит вовсе: работа одинакова при любом решении. Около 80 % цены до первого работающего экрана транспортно-инвариантны, и это главный довод не платить за второй транспорт.

## Что такое слой композиции

Экран 111 показывает расписание на сегодня, отметки по паре и данные группы. Расписание в `schedule`, отметки в `attendance`, группа в `academic`. Кто-то должен сходить в три сервиса и собрать один ответ. Сейчас это делает фронт — три запроса на отрисовку одного экрана. BFF делает это на сервере.

**Живёт отдельной единицей выпуска**, не внутри `api-gateway`: у шлюза своя работа (маршрутизация, авторизация, лимиты), и правка формы экрана не должна требовать его передеплоя.

**Один BFF сейчас**, общий для веба, PWA и Telegram. Разделять — когда поверхность реально разойдётся по формам экранов. Разделить дешевле, чем слить: разделение добавляет, слияние требует сверки разошедшихся обработчиков и одновременного переключения всех клиентов.

## Правила

1. **В BFF живут только композиция и форма.** Ни одного доменного правила. Иначе через полгода это второй домен, рассинхронизированный с первым.
2. **Доменные сервисы не знают о формах экранов.** Обязательное правило: пока оно соблюдается, смена транспорта — переписать слой композиции, не трогая шесть сервисов и не трогая фронт. Статус решения — «REST, пока поверхность не докажет обратное»; обратимость сохраняется бесплатно только этим правилом.
3. **Права проверяются на границе**, а не в клиенте. Сохраняются RFC 9457 Problem Details, HATEOAS, contract-first, HTTP-кэш.
4. **Потребности в данных описываются транспортно-нейтрально** — как и раньше. Спеки и `COMPONENT_REGISTRY.md` этим решением не затрагиваются.

## Живой канал

**Один канал (SSE или WebSocket) на два случая:**

- **Готовность выгрузки.** Клик «скачать» → задание в очередь → сервис генерации → готово → событие → браузер получает файл. Синхронно файла в ответе нет: отчёт по группе за семестр собирается десятки секунд.
- **Актуальность расписания.** Изменение доезжает до всех, включая тех, кто смотрит экран прямо сейчас. Отмена, восстановление, разовая пара, перенос, смена аудитории.

Браузер не может слушать RabbitMQ напрямую — канал и есть мост между очередью и вкладкой. Умолчание: **терминируется в BFF** (он знает активную роль и права), события приходят из RabbitMQ; `notification-service` остаётся за ботом и почтой. Место терминации меняется без правок на фронте.

## Версия расписания (SC-11)

Версия на срез **«группа × семестр»**, меняется при любой правке расписания группы. Крупно и просто; правки редки, лишние сбросы кэша почти ничего не стоят. Без версии ключ кэша нечем инвалидировать, и студент видит неделю без только что добавленной пары.

**Каскад 117** (сохранение слота разворачивается в 16–32 пары на семестр): пары создаются фоном, **форма ждёт результат** — спиннер на форме, при ошибке красная плашка. Живого канала 117 не требует.

## Агрегаты

**Владеет `attendance`.** Отметка — исходный факт, все метрики из неё выводятся; недостающие измерения (назначения из `academic`, пары из `schedule`) приходят событиями через RabbitMQ, синхронные чтения — по gRPC. Новый сервис отчётности не заводится.

**Отметка применяется сразу, агрегаты догоняют.** Пересчёт группируется пачками (порядка минуты), чтобы массовая простановка не создавала нагрузку. Для интерфейса это значит: отметка на 111, 112 и 122 отображается немедленно из своей операции, а не из агрегата; экраны метрик (103, 113, 123, 131) мгновенности не обещают.

## Кэш и свежесть

- **Свежесть — по хешу** (HTTP ETag): сервер отдаёт хеш, клиент присылает его обратно, сервер отвечает «не менялось» без тела.
- **Redis остаётся** и кэширует данные, а не сессию.
- **При переключении роли клиентский кэш сбрасывается жёстко** — это изоляция контура, а не свежесть. Стоит примерно ноль: повторный запрос обслужит Redis, чаще всего ответом «не менялось».
- **Длина адреса:** мультисортировка без предела плюс многозначные фильтры могут упереться в лимит. Риск принимаем, идентификатор сохранённого вида не заводим.
