   import { House, Calendar, Fingerprint, Users, User, type Icon } from '@phosphor-icons/react'

           icon: Users,
           label: 'Группа',

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| JWT payload → client state | Untrusted JWT claims (including `is_headman`) flow into React state and gate UI rendering |
| Client UI → React Router | `/group` route is rendered only for headman; but routing is client-side — the route itself is reachable by anyone who knows the URL |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-56-01 | Spoofing | AuthProvider.tokenToUser — attacker forges a JWT with is_headman=true | accept | JWT signature is verified server-side on every API call; client-side UI reveal is not a security boundary. All backend endpoints re-check is_headman from the validated JWT (enforced in Phase 54 RoleCheckAspect + attendance-service filters). Client display of extra tabs does NOT grant actual permissions. |
| T-56-02 | Tampering | localStorage JWT mutation to flip is_headman | accept | Same as T-56-01 — backend enforces authorization. Worst case: attacker sees an additional tab that 403s on every call. |
| T-56-03 | Information Disclosure | Tabs leak app structure to non-headman users | accept | Tab labels are non-sensitive (Группа). The existence of a headman mode is public knowledge (documented in landing/presentation). |
| T-56-04 | Elevation of Privilege | Direct-navigate to /group as plain student | mitigate | `/group` route renders UI but every API call underneath will 403/404 via backend RoleCheckAspect (Phase 54 fix). No privileged operation is reachable. A future hardening could add a client-side route guard, but is out of scope for this plan. |
</threat_model>
