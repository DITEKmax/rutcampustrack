# v0.0.0 Debt Report — что не сделано, сдвинуто и упущено

**Дата:** 2026-04-24
**Статус:** v0.0.0 закрыт (M01-M12 ✅, 65 коммитов ahead origin/dev, push отложен до `go`)
**Источник:** Разбор 12 milestone'ов из `docs/milestones/M01..M12`.

Честный отчёт для владельца проекта. Включает:
- то, что явно отложено по решению владельца;
- то, что выглядит как scope-сокращение;
- баги, попавшие в код и найденные поздно;
- расхождения PLAN ↔ реальность.

## 1. Что НЕ было сделано и почему

### Инфраструктурные smoke/E2E проверки (сквозной паттерн)

**Ни один milestone не имеет реального end-to-end browser smoke** — всё валидируется Testcontainers IT. Физические проверки откладывались последовательно из milestone в milestone.

| Milestone | Что отложено | Причина |
|-----------|--------------|---------|
| M02 | Kill Rabbit mid-test + 2 инстанса schedule-app параллельно (ShedLock) | «Не воспроизводили физически... паттерн гарантирует это» |
| M03a | UAT Golden Path (30+ пунктов) | Checklist составлен в NOTES, но прогона не было |
| M03b | E2E Playwright golden path admin/teacher/student/headman | deferred to M08 → в M08 defer в M09 |
| M04 | End-to-end span-tree в Tempo, E2E bot trace, kill auth → alert | «требует docker-compose окружение» |
| M08 | Первый прогон k6 baseline | «Windows dev-стек не подходит для reproducible numbers» |
| M09 | Smoke на staging для лимитов | «staging env не поднят локально; smoke пройдёт при apply в prod» |
| M10 | Manual UAT headman + NotificationCenter UI, full E2E через Gateway | Отложено как smoke-driven validation |
| M11 | VPS smoke для nginx basic-auth | «выполняется при deploy go» |
| M12 | Runtime smoke login/logout в браузере | «откладывается на отдельную UAT сессию владельца» |

**Причина сквозная:** dev-окружение на Windows + отсутствие staging VPS. Решение: UAT будет в момент deploy.

### Конкретные незакрытые пункты

- **M01** — `AdminActionAspect` остался заглушкой, реальная реализация сдвинута в M04.
- **M02** — `shared-events/DomainEvent` envelope из M01 **не adopted сервисами**: schedule/academic через `ApplicationEvent`+`AFTER_COMMIT`, attendance через direct publisher'ы. Migration отложена («breaking change для 14+ schemas»).

- **M05** — Redis cache hit/miss metrics: `MetricsCacheManagerDecorator` сломал namespace-TTL, root-cause не найден за 30 мин. Заменено на integration-тест key-presence + TTL.
- **M06** — `/actuator/**` excluded from tracing sampling: comment в `application.yml:108` «Health-check исключены» **вводит в заблуждение** — sampling не выключен, «spam в Tempo продолжается». Defer M07 → по факту тоже не сделано.
- **M08** — `SecurityIdorIT` (NEW-31 M03a): считался сделанным, **по факту файла в codebase нет**. Обнаружено только в M08, defer в M09 → в M09 тоже не сделан.
- **M08** — JaCoCo 60% global gate (OWNER-ANSWERS QD2) **не выполнен**: attendance-app 16.5%, schedule-app 14.2%, academic-app 20.9%. Применён per-module ratchet «-2%» вместо абсолютного 60%.
- **M09** — Python contract-тест для `otp.requested`, integration `test_full_flow.py` для bot callbacks — пропущены по owner-decision «overhead не оправдан».
- **M10** — Optimistic mutations + infinite scroll в PWA: отложено, broadcast items показываются из sessionStorage.
- **M11** — POST creates с Location header (14 endpoints): «HATEOAS `_links.self` уже покрывает URL».
- **M12** — `@Schema` на DTO fields в `auth-api-contract`: «pass-2 через OpenApiSnapshotIT» — по факту pass-2 отдельно не выполнен.

## 2. Что сдвинуто в v0.1 (и почему)

### Security hardening — «OTP bundle» (M09 DECISIONS D7)

Большой связанный блок security-findings от auditor'ов, сдвинут одним куском в v0.1:

- **SA-H1 verifyOtpByCode attempts counter** (HIGH) — защита от перебора OTP: «нужен IP-resolve в сервисе или stricter Gateway RL; Gateway RL 5 req/min/IP держит single-IP атаки».
- **BH-H1 bot dispatcher event_id дедуп** (HIGH) — «50+ строк изменений в base infrastructure бота, задевает ВСЕ handler'ы. Регрессия риск».
- **8 MEDIUM findings** (SA-M1/M3/M4/M5, BH-M2/M5/M6) — bundled в тот же пакет.
- **NEW-54 CSP-Report endpoint** — владелец явно указал v0.1.
- **Magic-link для первого входа** — accepted tradeoff.

### Auth & security (кросс-milestone, откладывалось итеративно)

- **M03a KI-1/2** — X-Forwarded-For spoofing без trusted-proxies allowlist, dual-mode silent fallback без метрики → M06 → **v0.1**.

## 3. Что забыто / «поленились» / большой scope проглочен

### Архитектурные долги, которые вскрылись позже

- **M11 G0 scope удвоился.** Плановая «наполнить bean-заглушку» (оставленную M01) превратилась в «унифицировать ErrorResponse + создать shared-web starter + чистить customizer-per-service». Root cause: **M01 оставил архитектурный долг** — `shared-web` был подключён только в notification-app через scanBasePackages hack, остальные 3 сервиса имели свой GlobalExceptionHandler. «Без G0 customizer-per-service дубль drift'нул бы через месяц».

- **M04 G6 scope-blow 47 файлов.** Плановый retrofit (3-4 часа) превратился в полную migration на `shared-events/DomainEvent` — владелец выбрал (a) «полная migration» вместо (b). Event envelope drift из M02 прогремел в M04 как масштабный scope.

- **M08 обнаружил `SecurityIdorIT` (NEW-31 M03a) отсутствует в codebase.** Был в M03a PLAN, «считался реализованным», по факту файла нет. Классический «не заметили».

- **M09 `auth-api-contract`** — был в M09 PLAN как 01 P0-1, явно исключён и отложен. Реализован только в M12 — последний структурный долг.

### Баги, попавшие в код и найденные поздно

- **M04 Bug-hunter H1 RedZoneGauge self-invocation** — `@PostConstruct init()` обходил Spring proxy, `@SchedulerLock` не срабатывал. Обнаружен только финальным audit.
- **M08 G4 Clock-injection regression** — Clock добавлен в конструкторы 3 сервисов, unit-тесты не обновлены (`@InjectMocks → null → NPE`). Тесты падали с commit `f61537b`, но «до G10 никто не запускал».
- **M08 `LessonEventServiceParallelTest` flaky** — wall-time assertion 350ms был хрупок с M05, обнаружено только в M08.
- **M10 S4 HIGH** — Mongo `@PostConstruct + IndexOperations.ensureIndex` silently no-op'нул, TTL и compound-индексы НЕ создавались. «Pre-existing PushMongoConfig pattern (M05) уже имел fix — не применили при старте M10». Признак «поленились посмотреть на соседний код».
- **M10 H1 HIGH** — `excuse.decided`/`late_checkin.decided` **всегда маппились на APPROVED** даже при `status="rejected"`. «Юридически значимый bug» — простая ошибка switch/case без unit-теста на rejected-path.
- **M10 H2 HIGH** — Pageable без max-size cap → DoS через `?size=1M`.
- **M07 G9 Discovery** — admin sparklines **были псевдо-данными** (детерминированный random), «визуально неотличимо от реальных, юзер принимал их как факт». Жили до M07.
- **M07 G3b Discovery** — `ExcuseType` runtime bug (lowercase vs UPPERCASE); 3 frontend unit-теста фиксировали **неверное** lowercase поведение как «ожидаемое». Тесты подтверждали bug.
- **M03a** — 3 критических context-startup бага обнаружены поздно (`@Primary` на ipKeyResolver, `@Autowired` на primary конструктор, `setComplete()` vs `writeWith()`). Lesson learned: «первый IT написали сразу в Группе 4 сэкономил бы неделю».

### Scope-сокращения, обоснованные но спорные

- **M03b Группа 5 CSRF infrastructure полностью удалена.** Acceptance criterion «mutating request без X-CSRF-Token → 403» просто **удалён** (обоснование: same-origin + SameSite=Strict). Scope сокращён на ~1 день.
- **M03b `/auth/logout` без userId при cookie-only** — «пропускаем invalidation (ticket'ы истекут через 30s естественно). Не идеально, но OK для v0.0.0 — alpha». Явный shortcut.
- **M03a rate-limit семантика неверная** — `5 req/min` фактически реализовано как `burst=5 + 5/sec restore`. Документировано, **не исправлено**. «Для точного X/min нужно `replenishRate=1`+`requestedTokens=60/X` (следующий milestone/fix)» — сдвинуто устно.
- **M05 Группа 2 урезана до preventive-only (D5)** — N+1 fixes (`@EntityGraph`/projections) не делали. PLAN и OWNER-ANSWERS прямо требовали `@EntityGraph`. Честно: decline-scope, а не «нет риска». OWNER-ANSWERS QD2 формально не закрыт.
- **M05 race `pre-check vs upsert` в `markBatch`** + `unwrap()` interrupted handling — **accepted limitations** без fix.
- **M06 H4 `headmanBuckets.clear()` race + principal-based userId** — accepted as trade-off: «требует gRPC proto redesign (breaking change)».
- **M07 D3 types-only migration** — `openapi-fetch` установлен, runtime не подключен: «axios остаётся, generated types только как типы». Acceptance «ручные interface-копии удалены» выполнен формально через type-parameter, а не через полный swap.
- **M10 Hybrid strategy вместо full migration** — «Полный refactor на useInfiniteQuery как initial source... усложнение компонента». **Явное признание большого scope'а** — выбран minimum-invasive путь.
- **M08 `CsrfDoubleSubmitIT` → `SameSiteCookieContractIT` (D6)** — PLAN требовал тестировать double-submit, но M03b его отверг. **Рассогласование PLAN с реальностью v0.0.0**, обнаружено только в M08.
- **M08 `FlywayMigrationIT` в auth-service skip** — «auth-service не владеет Flyway-миграциями» → defer до M12 → в M12 тоже не сделан.

## Общие паттерны (итого по 12 milestones)

1. **Browser/staging UAT systematically deferred** во всех 12 milestones. v0.0.0 валидирован только Testcontainers IT + unit. Реальный smoke — только в момент VPS deploy.
2. **HIGH findings → v0.1**, не блокируют tag. В M09 два HIGH (SA-H1, BH-H1) ушли в v0.1 bundle; в M10 два HIGH (S4, H1) исправлены hot-patch'ем в той же сессии.
3. **`docs/future-ideas.md` превратился в parking lot.** Крупные bundle'ы: OTP hardening, notification N1-N11, Auth v0.1, a11y pass 2, bundle optimisation.
4. **Scope-решения «single event vs split» и «hybrid vs full migration»** повторяются систематически — выбирается minimum-invasive путь с документированным `[~]` статусом.
5. **Pre-existing flakiness** оставляют висеть вместо фиксации (`RateLimitIT`, `EventSchemaRefTest`, `ExcuseEventContractIT.createExcuse`).
6. **Архитектурные долги вскрываются поздно** — M01 `shared-web` → M11 G0 scope удвоился; M02 envelope drift → M04 G6 scope-blow; M03a NEW-31 → M08 обнаружил отсутствие; M09 auth-contract → M12.
7. **PLAN-vs-реальность расхождения** — копипаст устаревших пунктов (M12 OtpCodeResponse, M10 notification_user) проходят через planning без проверки.
