## Focal Points

Explicit primary focal point per feature area:

**`/student/excuses`**
Primary focal point: the "Подать тикет" button in `.page-header__actions`. The page is primarily a list (read path) — the single new-action entry point is the top-right CTA. Clicking it opens an in-page dialog / slide-over form. The ticket list below is the secondary visual weight (table rows with status chips).

**`/student/late-checkin`**
Primary focal point: each table row's "Запросить отметку" action button. There is no global CTA — every row is independently actionable. The page reads as a remediation list: absent lessons with one action per row. Sent rows immediately switch to a success state in-place.

**PWA Install Banner**
Primary focal point: the "Установить приложение" / "Открыть в Safari" / "Открыть приложение" button. The banner sits at the very top of the student layout area (below the Angular Material toolbar, above the page content). It must not push the page content off-screen. It is compact — a single row with icon, one-line text, one CTA, and a dismiss × at the far right.

### 1. `/student/excuses` — StudentExcusesComponent

Layout: `.page-stack` — standard page container.

**Ticket list states:**

| State | Behavior |
|---|---|
| Loading | 3× skeleton rows (`--bg-elevated` shimmer, same `dashboard-shimmer` keyframe, height 52px each, border-radius `--radius-md`) |
| Empty (no tickets ever submitted) | `.page-empty`: `ph-file-text` 32px duotone + heading "Нет тикетов о пропуске" + body "Подайте первый тикет, если пропустили занятие по уважительной причине" |
| Populated | `<table mat-table>` or div-based row list inside `.page-card--flush` |
| Load error | `.page-error` inline block with `ph-warning-circle` 20px + "Не удалось загрузить тикеты. Попробуйте обновить страницу." |

**Table columns (left to right):**
1. Дата создания — `--text-xs` / `--font-mono` / `--text-muted`
2. Предметы — comma-separated subject names, `--text-sm` / `--font-sans` / `--text-primary`
3. Статус — status chip (see color mapping above)
4. Действие — expand chevron (`ph-caret-down` 16px, `fill` when expanded) to reveal detail row

Detail row (expanded inline below ticket row):
- Shows affected lesson dates as chips
- Shows upload file names if available (read-only, files are NOT stored — display whatever the API returns)
- If no detail available: "Подробности недоступны" in `--text-muted`

**"Подать тикет" CTA button:**
Position: `.page-header__actions` — top right of page header.
Style: `.btn-brand` global class (pill, `--accent-primary` background, min-height 42px).
Icon: `ph-plus` 18px before label text.
Label: "Подать тикет"

**ExcuseFormDialog — in-page MatDialog:**

Trigger: clicking "Подать тикет".
Dialog width: 560px max on desktop; 100vw - 32px on mobile (< 600px breakpoint).
Dialog max-height: 80vh with internal scroll on the form body.

Form sections (top to bottom):
1. **Выберите занятия** — multi-select of the student's past lessons (filter to last 30 days). Rendered as a scrollable list of `MatCheckbox` rows. Each row: `[checkbox] [Subject name] [Date — mono --text-xs] [Time — mono --text-xs]`. Container: `--bg-surface` background, border-radius `--radius-md`, max-height 240px with `overflow-y: auto`.
2. **Прикрепите файлы (необязательно)** — drag-and-drop zone + click-to-browse. Visual: dashed border `2px dashed --border-default`, hover/active: `2px dashed --accent-primary`, background `--bg-elevated`, border-radius `--radius-md`, min-height 80px. Center icon: `ph-upload-simple` 28px `--text-muted`. Center text: "Перетащите файлы или нажмите для выбора" in `--text-secondary` / `--text-sm`. Accepted types: `image/*,application/pdf,.doc,.docx`. Max size per file: 10 MB (show inline error if exceeded: "Файл превышает 10 МБ"). Max files: 5. Uploaded file list below drop-zone: each file as a chip — `ph-file` 14px + filename (truncated 24ch) + size label + `ph-x` dismiss button.
3. **Комментарий (необязательно)** — `MatFormField` `<textarea>` rows=3, max-length 500. Placeholder: "Укажите причину пропуска".
4. **Кнопки** — row: `[Не подавать — mat-stroked-button] [Подать тикет — .btn-brand]`. Both right-aligned.

**Submit behavior:**
- Validate: at least one lesson must be selected.
- On submit: disable form + show spinner inside "Подать тикет" button.
- On success: close dialog + show MatSnackBar "Тикет подан. Документы переданы старосте через Telegram." (duration: 5000ms, panel class matches existing snackbars in the app).
- On API 404 / endpoint absent (deferred backend): close dialog + show MatSnackBar "Запрос отправлен. Подтверждение придёт в Telegram." — graceful degradation, no error state shown to the user.
- On API 4xx/5xx error: keep dialog open + show inline `.page-error` block below file upload zone: "Не удалось подать тикет. Попробуйте ещё раз."

### 2. `/student/late-checkin` — StudentLateCheckinComponent

Layout: `.page-stack` — standard page container.

Data: list of lessons where the authenticated student's attendance status is `absent`, limited to the current semester.

**States:**

| State | Behavior |
|---|---|
| Loading | 3× skeleton rows, height 52px, `dashboard-shimmer` keyframe |
| Empty (no absent lessons) | `.page-empty`: `ph-check-circle` 32px duotone + heading "Нет пропущенных занятий" + body "Все ваши занятия отмечены — запрашивать позднюю отметку не нужно." |
| Populated | Row list inside `.page-card--flush` |
| Load error | `.page-error` inline: "Не удалось загрузить список занятий. Попробуйте обновить страницу." |

**Row layout (left to right):**
1. Дата — `--text-xs` / `--font-mono` / `--text-muted`
2. Время — `--text-xs` / `--font-mono` / `--text-secondary` / tabular-nums
3. Предмет — `--text-base` / `--font-heading` / weight 600 / `--text-primary`
4. Статус (current) — `.status-chip--absent` ("н") chip — read-only indicator showing why the row appears
5. Действие — "Запросить отметку" button (see below) OR success state if already requested

**"Запросить отметку" button (per row):**
Style: `mat-stroked-button` variant with `--accent-primary` color. Min-height 36px. Label: "Запросить отметку". Icon prefix: `ph-clock-countdown` 16px.

**Row success state (after request sent):**
Replace "Запросить отметку" button inline with a read-only pill: `ph-check-circle` 16px fill (`--accent-primary` color) + "Запрос отправлен" label in `--text-sm` / `--accent-primary`. No revert. The row remains in the list (the absence status on the backend has not changed yet).

**Request submit behavior:**
- On click: show spinner inside button, disable button.
- On success: apply row success state in-place (no list reload).
- On API 404 / endpoint absent (deferred backend): apply row success state with copy "Запрос отправлен" — graceful degradation, same visual as success.
- On API error: re-enable button + show inline row error text below button: "Ошибка. Попробуйте ещё раз." in `--text-xs` / `--accent-danger`.

**No confirmation dialog** for late check-in requests — action is low-stakes; one click is sufficient. This is consistent with single-action row patterns used in the homework toggle.

### 3. PWA Install Banner — StudentPwaBannerComponent

**Trigger logic (TypeScript):**
- Check `localStorage.getItem('pwa-banner-dismissed')`. If `"true"`, never render the component.
- Check `localStorage.getItem('pwa-banner-shown')`. If `"true"`, banner has already been seen at least once — still show on subsequent logins (only permanent dismiss suppresses).
- On first STUDENT login (detected by `AuthService.currentUser()` signal emitting a STUDENT role for the first time after login): set `localStorage.setItem('pwa-banner-shown', 'true')`, render banner.
- On dismiss (× button): set `localStorage.setItem('pwa-banner-dismissed', 'true')`, animate banner out, destroy component.

**Placement:**
Rendered as a sibling above the `<router-outlet>` inside the student shell layout, below the Angular Material top toolbar. It is NOT a fixed/sticky overlay — it pushes page content down by its own height (~44px). The student shell wraps it with `ngIf` / `@if` on a signal from `StudentBannerService`.

**Desktop (Chrome/Edge — `beforeinstallprompt` supported):**
Show the banner. "Установить приложение" button calls `deferredPrompt.prompt()`. If the user accepts the browser dialog, dismiss the banner and set `pwa-banner-dismissed=true`. If the user cancels, keep banner visible until explicit × dismiss.

**iOS / Safari (no `beforeinstallprompt`):**
"Установить приложение" button links to `/app/` via `<a href="/app/">`. Banner body text changes to: "Установите RutTrack: откройте в Safari → Поделиться → На экран «Домой»". Install button label: "Открыть в Safari" (links to `/app/`).

**All other browsers (no `beforeinstallprompt`, not iOS):**
Show same copy as iOS / Safari variant. Button: "Открыть приложение" → href `/app/`.

**Banner layout:**

```
[ ph-device-mobile-camera 24px duotone --accent-primary ]
[ "Установите RutTrack на главный экран"  --text-sm/600 ]
[ "Быстрый доступ с иконки без браузера" --text-xs/--text-secondary ]  ← second line, optional
[ Установить приложение btn ]  [ × dismiss btn ]
```

Exact DOM structure (single row on desktop, wraps gracefully on mobile):

```
<div class="pwa-banner">
  <i class="ph-duotone ph-device-mobile-camera pwa-banner__icon"></i>
  <div class="pwa-banner__text">
    <span class="pwa-banner__title">Установите RutTrack на главный экран</span>
  </div>
  <button class="btn-brand pwa-banner__cta">Установить приложение</button>
  <button class="pwa-banner__dismiss" aria-label="Закрыть баннер">
    <i class="ph ph-x"></i>
  </button>
</div>
```

**Banner CSS tokens:**
- `.pwa-banner`: `background: var(--bg-secondary)`, `border-bottom: 1px solid var(--border-subtle)`, `border-left: 4px solid var(--accent-primary)`, `padding: var(--space-2) var(--space-5)`, `display: flex`, `align-items: center`, `gap: var(--space-4)`, `flex-wrap: wrap`.
- `.pwa-banner__icon`: `font-size: 24px`, `color: var(--accent-primary)`, `flex-shrink: 0`.
- `.pwa-banner__text`: `flex: 1`, `min-width: 0`.
- `.pwa-banner__title`: `--text-sm` / `--font-heading` / weight 600 / `--text-primary`.
- `.pwa-banner__cta`: `.btn-brand` class with reduced padding (`padding: 8px 16px`, min-height 36px) — use a modifier class `.btn-brand--sm`.
- `.pwa-banner__dismiss`: 32×32px, `border: 0`, `background: transparent`, `color: var(--text-muted)`, `border-radius: var(--radius-sm)`, hover `color: var(--text-secondary)`, cursor pointer. Icon: `ph-x` 16px.

**Animation (Angular `@angular/animations`):**
- Enter: `animate('200ms ease-out', style({ transform: 'translateY(-100%)' }))` → `style({ transform: 'translateY(0)' })`
- Leave: `animate('150ms ease-in', style({ opacity: 0, transform: 'translateY(-8px)' }))`

Use `@HostBinding('@bannerSlide')` or `[@bannerSlide]` on the host element. Respect `prefers-reduced-motion: reduce` by checking `matchMedia` and skipping animation if true.

## Accessibility

All patterns follow WCAG 2.1 AA minimum. No new audit concerns relative to Phases 51–52.

- Ticket status chips: include `aria-label` with full status text (not just the chip abbreviation).
- File upload zone: labelled with `aria-label="Загрузка файлов"` and `role="button"` for keyboard activation.
- PWA banner: `role="banner"` on the host element; dismiss button has `aria-label="Закрыть баннер"`.
- Late check-in table: `aria-live="polite"` region wrapping the row list so screen readers announce row state changes (Запросить отметку → Запрос отправлен).
- Form dialog: `MatDialog` provides `role="dialog"` and `aria-modal="true"` automatically; set `ariaLabel="Новый тикет о пропуске"` on the dialog config.
