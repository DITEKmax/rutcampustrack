## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-49-08 | Tampering | `<a href="/login">` could be manipulated if the landing were rebuilt from a compromised source | accept | Landing is pre-built HTML committed directly to the repo in `frontends/landing/dist/index.html`. There is no build pipeline that could inject malicious hrefs during CI. The edit is a straightforward string replacement verified by grep counts in the acceptance criteria — any unauthorized href modification would be caught by `git diff` in code review. |
| T-49-09 | Information Disclosure | Same-origin `rel="noopener"` on the three new /login anchors is technically redundant but harmless | accept | `rel="noopener"` on same-origin links causes no side effects — it only matters for cross-origin `target="_blank"` links (none of these anchors use `target`). Keeping `rel="noopener"` preserves line-level diff parity and matches the existing convention. |
| T-49-10 | Spoofing | `og:url` meta tag pointing to `/presentation/` could be cached by social media crawlers using the OLD `/landing/` URL until they re-crawl | accept | This is transient. Facebook/Twitter/LinkedIn crawlers will pick up the new canonical URL on next visit (typically within hours). The old `/landing/` URL returns 404 after Plan 01 ships, so any stale preview card that still shows `/landing/` in the URL bar will 404 instead of silently serving stale content — the user will click through and see the real new URL. No content spoofing possible. |
| T-49-11 | Denial of Service | The landing still links to `/login` which may 404 between Plan 01 ship and Phase 50 ship | accept | Acceptable per Phase 49 boundary. Phase 49 ONLY installs the routing scaffold; Phase 50 makes `/login` resolve via Angular web-panel baseHref migration. The transient 404 window is <= Phase 50 planning+execution time and impacts only the three landing buttons — direct visits to `/admin/`, `/api/`, `/app/`, and `/presentation/` all continue to work. |
| T-49-12 | Elevation of Privilege | Open redirect via the new `/app/` button on the landing | accept | `/app/` is a FIXED local path in Plan 01's nginx config (proxies to `rct-pwa-nginx`). It is not user-controlled and cannot redirect outside the site. No open redirect risk. |

**Overall assessment:** This plan is pure string replacement in a static HTML file. Zero new attack surface. All five edits are href attribute values to local paths (`/login`, `/app/`, `/presentation/` in meta). No CSP changes required — the existing CSP from Plan 01's nginx config (`default-src 'self'`) already permits all relative-URL same-origin navigation.
