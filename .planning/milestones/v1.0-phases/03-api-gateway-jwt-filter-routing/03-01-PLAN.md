<objective>
Implement JWT authentication filter and public key management in the API Gateway.

Purpose: The Gateway must validate JWT tokens on protected routes, inject user-context headers (X-User-Id, X-User-Role, X-Group-Id, X-Is-Headman) into downstream requests, and allow public auth endpoints through without authentication. This is the security perimeter for all downstream services.

Output: PublicKeyConfig (key fetch + cache), JwtAuthenticationFilter (GlobalFilter), updated application.yml and GatewayApplication, unit tests for filter and key parsing.
</objective>

    **`filter(ServerWebExchange exchange, GatewayFilterChain chain)`**:
    1. Get path: `exchange.getRequest().getURI().getPath()`
    2. If `isPublicRoute(path)` -> return `chain.filter(exchange)` immediately
    3. Get Authorization header: `exchange.getRequest().getHeaders().getFirst(HttpHeaders.AUTHORIZATION)`
    4. If null or not starting with `"Bearer "` -> return `unauthorized(exchange, "Missing or invalid Authorization header")`
    5. Extract token: `authHeader.substring(7)`
    6. Try-catch block (catch `JwtException | IllegalArgumentException`):
       - Parse: `Jwts.parser().verifyWith(publicKeyConfig.getPublicKey()).build().parseSignedClaims(token).getPayload()`
       - Build mutated request with headers using null-safe pattern (see below)
       - Return `chain.filter(exchange.mutate().request(mutatedRequest).build())`
    7. On catch -> log debug "JWT validation failed: {}" with exception message, return `unauthorized(exchange, "Invalid or expired JWT token")`

    **CRITICAL: Null-safe header injection.** Do NOT follow the RESEARCH.md Pattern 1 reference code (lines 174-179) — it uses `String.valueOf(claims.get("group_id"))` which produces the string "null" for TEACHER/ADMIN users. Instead, use the null-safe pattern from RESEARCH.md Code Examples section (lines 416-432):
    ```java
    Object groupId = claims.get("group_id");
    Object isHeadman = claims.get("is_headman");

    ServerHttpRequest.Builder requestBuilder = exchange.getRequest().mutate()
            .header("X-User-Id", claims.getSubject())
            .header("X-User-Role", claims.get("role", String.class));

    if (groupId != null) {
        requestBuilder.header("X-Group-Id", String.valueOf(groupId));
    }
    if (isHeadman != null) {
        requestBuilder.header("X-Is-Headman", String.valueOf(isHeadman));
    }

    ServerHttpRequest mutatedRequest = requestBuilder.build();
    ```

    **`isPublicRoute(String path)`**: return true if `PUBLIC_PATHS.contains(path)` OR any `PUBLIC_PREFIXES` prefix matches via `path::startsWith`.

    **`unauthorized(ServerWebExchange exchange, String detail)`** — RFC 7807 Problem Details response per CLAUDE.md mandate:
    ```java
    private Mono<Void> unauthorized(ServerWebExchange exchange, String detail) {
        ServerHttpResponse response = exchange.getResponse();
        response.setStatusCode(HttpStatus.UNAUTHORIZED);
        response.getHeaders().setContentType(MediaType.APPLICATION_PROBLEM_JSON);

        String body = """
                {"status":401,"title":"Unauthorized","detail":"%s"}
                """.formatted(detail).strip();
        DataBuffer buffer = response.bufferFactory().wrap(body.getBytes(StandardCharsets.UTF_8));
        return response.writeWith(Mono.just(buffer));
    }
    ```
    Use `MediaType.APPLICATION_PROBLEM_JSON` (content type `application/problem+json` per RFC 7807).

    **`getOrder()`**: return `-100` (run before routing filters).

    - Do NOT use `OncePerRequestFilter` or `HttpServletRequest` — this is reactive WebFlux
    - Do NOT use `parseClaimsJws()` — deprecated in JJWT 0.12, use `parseSignedClaims()`
