# Техническое SEO презентации RutCampusTrack

Публичная часть сайта начинается по адресу [ruttrack.site/presentation/](https://ruttrack.site/presentation/). Карта сайта описывает главную презентации и тематические страницы. Служебные экраны внутри демонстрации исключены из карты сайта. У них есть директива `noindex`, которую робот сможет прочитать при обходе.

При добавлении темы обновляй каталог тем и запускай `npm --prefix frontends run build:landing`. Проверяй, что основной адрес страницы и адрес в Sitemap совпадают, описание отражает содержание, а текст и ссылки доступны в исходном HTML. Сборка добавляет `lastmod` из истории Git для исходников содержимого каждой страницы. Повторная сборка той же версии сохраняет даты. Если проверенной даты нет, элемент опускается.

## Проверка после публикации

1. Проверь `https://ruttrack.site/robots.txt`, `https://ruttrack.site/sitemap.xml` и `https://ruttrack.site/llms.txt`. Все три должны отвечать HTTP 200. Первому и третьему нужен тип `text/plain`, карте сайта — XML. Проверь, что ответ содержит файл, а не HTML экрана входа.
2. Открой ссылки из Sitemap. Канонические URL должны отвечать HTTP 200, отдать содержимое в HTML и совпасть с `rel="canonical"`. Несуществующий маршрут презентации должен возвращать 404. Проверь, что прямые адреса служебных демо содержат `noindex`.
3. Подтверди владение `ruttrack.site` в [Google Search Console](https://search.google.com/search-console/about), [Яндекс Вебмастере](https://webmaster.yandex.ru/) и [Bing Webmaster Tools](https://www.bing.com/webmasters/). Если доступен DNS, можно подтвердить владение TXT-записью. Отправь одну и ту же ссылку на корневой `sitemap.xml` в каждой панели.
4. В проверке URL посмотри главную и несколько тем. Следи за статусом обхода и индексации, выбранным каноническим адресом, ошибками HTTP и показами. Браузеры Chrome, Firefox, Яндекс Браузер и Edge используют поисковую систему, выбранную пользователем. Собственной карты сайта для каждого браузера не требуется.

## Что обсудить

- **IndexNow.** Уведомлять участвующие системы только после успешной публикации и только об изменившихся публичных URL. Нужен файл подтверждения домена. Для 12 страниц на первом этапе достаточно Sitemap и ручной проверки важных URL. [Протокол IndexNow](https://www.indexnow.org/documentation)
- **Поиск и обучение ИИ.** `llms.txt` даёт агентам оглавление и ссылки на текст по темам. Это добровольный формат, а не требование поисковых систем. Если потребуется политика об обучении на материале, согласуй её отдельно от доступа поисковых и пользовательских ботов. [Спецификация llms.txt](https://llmstxt.org/) · [Боты OpenAI](https://developers.openai.com/api/docs/bots) · [Боты Anthropic](https://support.anthropic.com/en/articles/8896518-does-anthropic-crawl-data-from-the-web-and-how-can-site-owners-block-the-crawler)
- **Органический поиск.** После публикации полезно добавить ссылку на презентацию в публичное описание репозитория и, если это уместно, в каталог проектов вуза. По отчётам вебмастеров можно увидеть, по каким запросам уже появляются темы, и точнее описать их в поисковой выдаче.
