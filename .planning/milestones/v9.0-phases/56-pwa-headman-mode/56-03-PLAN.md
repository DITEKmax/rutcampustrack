<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Modal form input → API mutation | User-controlled input (subject name, permissions) sent to backend PUT/POST endpoints |
| API response → DOM | Group member names + subject names + teacher names rendered as text in lists |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-56-09 | Tampering | Subject name / assistant permission input — client-side bypass of min-length or enum constraints | mitigate | Backend ThresholdApi + SubjectApi validate input with Bean Validation (@Size, @NotBlank). Client-side validation is UX-only. |
| T-56-10 | Information Disclosure (XSS) | Subject name, teacher name, student name rendered in list rows and modals | mitigate | All text uses React children interpolation (`{subject.name}`) which auto-escapes. Forbid `dangerouslySetInnerHTML` — see Plan 56-05 verification enforcement. |
| T-56-11 | Elevation of Privilege | Plain student navigates to /group/students and attempts useCreateAssistant | mitigate | Backend RoleCheckAspect (Phase 54 fix) rejects with 403 when JWT is_headman=false. mapHeadmanApiError returns "У вас нет прав на эту операцию" — user sees inline error. |
| T-56-12 | Repudiation | Assistant permission changes not logged | accept | Backend service layer already logs assistant CRUD operations to audit table (Phase 54 scope); client does not need additional logging. |
</threat_model>
