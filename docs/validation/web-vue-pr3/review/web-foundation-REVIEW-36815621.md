## Findings

1. **P2 — obsolete refresh flight заменяет reconciliation новой операции.** `frontends/web-vue/src/auth/session.ts:39–41` (`selectRole` caller:125–132). `refreshFlight` возвращается без проверки operation, хотя сам flight отбрасывает результат при смене operation. Repro: ready STUDENT с двумя grants → начать медленный refresh из ответа homework401 → переключить роль → role PUT отвечает409/теряет ответ → catch вызывает refresh и присоединяется к старому flight → старый flight завершается, игнорируя результат из-за revision mismatch. Нового чтения authority не будет: phase=ready, snapshot=null, busy=false; App показывает бесконечную загрузку без recovery control. Аналогичная зависимость есть у logout reconciliation. Нужен authoritative refresh для текущей operation после устаревшего flight.

2. **P2 — старый GET отменяет в UI уже подтверждённую отметку выполнения.** `frontends/web-vue/src/features/student-homework/use-homework.ts:77–78`, mutation ACK:134–140. Счётчик request упорядочивает только GET; completion не инвалидирует уже начатое чтение. Repro: background GET читает completed=false, его ответ задержан → пользователь отмечает задание → PUT успешно возвращает completed=true, UI применяет ACK → приходит прежний GET и безусловно заменяет feed на completed=false. Ошибки нет, checkbox снова доступен; сохранённое состояние выглядит несохранённым и может оставаться таким, пока взаимодействие подавляет periodic refresh. Упорядочить reads относительно mutation/ACK или отбросить заведомо предшествующий снимок; PUT не повторять для восстановления UI.

3. **P2 — невозможно прочитать длинное условие задания.** `frontends/web-vue/src/shared/web.pcss:373–376`; потребитель `features/student-homework/HomeworkCard.vue:56–58`. Description всегда ограничен четырьмя строками с overflow hidden, у карточки нет раскрытия/полного просмотра. Любой текст длиннее четырёх строк теряет видимый хвост, включая инструкции и ссылки; открытие самого задания это не компенсирует, поскольку отдельного перехода нет. Предоставить полный текст непосредственно или доступное раскрытие.

4. **P2 — route роли не пересматривается при ready→ready смене роли.** `frontends/web-vue/src/App.vue:6–18`. Watcher зависит только от phase; selectRole очищает snapshot и затем принимает другой activeRole, сохраняя phase=ready. Router guard проверяет роль только при navigation. Backend сохраняет запрет доступа, но пользователь остаётся на неправильном экране с ошибками.
