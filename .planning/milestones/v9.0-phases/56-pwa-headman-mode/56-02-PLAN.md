<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Client → API Gateway | All headmanApi hook calls traverse API Gateway with Bearer token; gateway + backend services validate role/is_headman claim |
| React Router → rendered component | Client-side route renders regardless of role; trust boundary is enforced by backend 403/404, not by the route itself |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-56-05 | Information Disclosure | headmanApi hooks leak group-scoped data cross-tenant | accept | Backend scopes queries by JWT groupId claim (Phase 54 RoleCheckAspect). Client cannot request arbitrary groupId — the endpoints used (`/academic/groups/my/members`, threshold resolve with validated groupId) are server-scoped. |
| T-56-06 | Tampering | useMarkAttendance mutation with fabricated lessonId/userId | mitigate | Backend validates that the JWT subject has headman rights over the target group containing the lesson (attendance-service authorization). Client code uses only values returned by the journal GET for the same subject/date. |
| T-56-07 | Denial of Service | Unbounded TanStack Query retries on 404 (excuses/late-checkin endpoints may not exist) | mitigate | Configure `retry: false` on usePendingExcuses + usePendingLateCheckins per D-10 to prevent retry storms. |
| T-56-08 | Information Disclosure (XSS) | Hub card text rendered from API responses (subject names, student names) | mitigate | React auto-escapes text content by default; do NOT use `dangerouslySetInnerHTML` anywhere in headman feature code. Enforced by grep check in verification (see Plan 56-05). |
</threat_model>
