### Typed denial versus dependency failure
Do not copy the old onStatus(isError) blanket503 behavior. Parent design decision uses existing internal ErrorResponse.extras.code and maps it to the Java-first public MobileProblemDetails.code; no new shared error DTO is needed:
- 401 INVALID_SESSION / SESSION_REVOKED: producer-realizable admission denial; C preserves status/code. Wrong-purpose refresh/internal/bootstrap tokens at this access-only admission endpoint are INVALID_SESSION; this endpoint does not refresh and does not produce REFRESH_REJECTED. Bootstrap route-policy denial remains separate.
- 403 ROLE_NOT_GRANTED / ROLE_NOT_SELECTABLE at admission: the selected protected owner is no longer valid. For a confirmed denial of the current owner generation, purge that owner's protected state; do not promise whole-account logout where the valid session may return to neutral bootstrap. Preserve status/code and the current-generation guard. This is distinct from a downstream ROLE_READ_ONLY or resource-scope403: those do not inherently invalidate the owner, and permitted terminal own reads remain available. BOOTSTRAP_SCOPE_DENIED belongs to the bootstrap endpoint allowlist policy, not this access-only admission producer.
- 409 SESSION_STATE_STALE: preserve conflict, require explicit refresh/resolution; no hidden replay of the user's mutation.
- 503 AUTHORITY_UNAVAILABLE: SQL failure, timeout/network error, malformed/unknown response or internal-service credential failure; fail closed but do not purge a valid session merely for a dependency outage.
Auth service-secret failures are not user-token failures. Recognize only the frozen typed user-denial codes; an unrecognized/raw401/403 from the internal credential guard is service unavailability at C. Do not pass through arbitrary upstream response bodies or infer a user denial from status alone. All admission success/error responses and Gateway error responses are no-store.
