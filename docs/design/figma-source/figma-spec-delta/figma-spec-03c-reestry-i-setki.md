## Часть I. Таблицы реестров

Все шесть строятся на `DataTable` и собственных размеров не вводят: плотность,
высота строки, шапка и состояния наследуются от примитива. Спецификация каждой —
это состав колонок, тип ячейки и отклонения от правил примитива.

### 1. `academic/GroupMembersTable` — 116

Строки — студенты одной группы, **всегда по алфавиту**.

| Колонка | Ячейка | `align` |
|---|---|---|
| № | текст — порядковый номер строки, **не идентификатор** | end |
| ФИО | текст + `MemberRoleBadge` под подписью | start |
| логин | текст | start |
| пароль | `InitialPasswordCell` | start |
| Tr id | `TelegramIdCell` | start |
| доп. разрешения | `PermissionList` `readonly` | start |
| блокировка | `DisputeBlockCell` | start |
| действия | `RowActionsMenu` | end |

**Первое из трёх исключений Р-16: ни сортировки, ни фильтров, ни пагинации.**
В библиотеке — `sortable=false` и `filterable=false` у всех `HeaderCell`,
`has-footer=false`.

Раскрытие строки даёт `StatsDetailPanel` `variant=row`.

Сведение с `UsersTable` отклонено реестром: различаются сущность строки,
содержимое раскрытия и набор действий.

### 2. `academic/UsersTable` — 132

Строки — учётные записи всей системы. Серверные поиск, фильтры, сортировка,
пагинация — полный набор примитива.

| Колонка | Ячейка |
|---|---|
| логин | текст |
| ФИО | текст |
| роль | **многозначная** — список ролей |
| статус | **многозначная** — статус каждой роли |
| группа | текст |
| начальный пароль | `InitialPasswordCell` |
| табельный номер | текст |
| Tr id | `TelegramIdCell` `editable` |
| ⋮ | `RowActionsMenu` |

**Колонки «Роль» и «Статус» выровнены попарно.** Строка несёт несколько ролей
и несколько статусов; доступное имя статуса содержит роль, иначе связь видна
только глазами.

В Figma это две колонки с вертикальными стеками одинаковой высоты: `n`-я строка
стека статусов обязана совпасть по вертикали с `n`-й строкой стека ролей.
Auto Layout вертикальный с одинаковым gap в обеих ячейках, высота строки —
`hug`, а не фиксированная. **Единственная таблица продукта, где высота строки
не фиксирована**, и причина именно эта.

Раскрытие строки — inline-форма правки.

### 3. `academic/GroupsTable` — 133

| Колонка | Ячейка |
|---|---|
| буквенный код | текст |
| текущий курс | число, `align=end` |
| срок обучения | число, `align=end` |
| количество студентов | `MetricValue` |
| ФИО старосты | текст либо пометка «не назначен» |
| ⋮ | `RowActionsMenu` |

**Две колонки курса обязаны иметь разные подписи** — требование реестра:
одинаковые заголовки делают таблицу нечитаемой на слух.

Колонки «Статус» нет: разрез задают `Tabs`. В разрезе черновиков появляется
колонка **«Почему черновик»** — **третье исключение Р-16: фильтра не получает**,
внутри разреза причина одна. Причин две: «группа только создана» и «староста
выбыл» с основанием.

### 4. `academic/SemestersTable` — 134

Строки — семестры, обратно-хронологически.

| Колонка | Ячейка |
|---|---|
| название | текст |
| даты | текст фиксированной ширины |
| статус | `EntityStatusCell` |
| ⋮ | `RowActionsMenu` + `DestructiveActionPair` |

**Второе исключение Р-16: фильтр по колонке «Статус» есть, сортировки нет.**
Пагинации нет — набор конечен. Отбор при этом серверный.

Собственное состояние таблицы — `no-active`: активного семестра нет,
**предупреждение на весь экран**. Это единственный экран, где поломка,
которую видят три другие роли, видна и чинится.

### 5. `academic/SubjectLessonTypeTable` — 116.1

Переименован из `SubjectsTable`: прежнее имя врало про ось.
**Строка = тип занятия.** № и название предмета объединены `rowspan` по всем
его типам.

**Единственная таблица продукта с вертикальной склейкой строк.**

| Колонка | Ячейка |
|---|---|
| № | текст, склеен по предмету |
| предмет | текст, склеен по предмету |
| тип занятия | текст |
| пройдено / всего | `SubjectProgressCell` |
| преподаватели | `TeacherList` |
| ⋮ | `RowActionsMenu` |

**Сборка склейки в Figma.** `rowspan` в Auto Layout не выражается. Строится
двухколоночным горизонтальным контейнером: слева `SubjectGroupCell`
(вертикально центрированная, высота `fill`), справа вертикальный стек строк
типов занятий. Компонент `SubjectRowGroup` — минимальная повторяемая единица,
а не строка.

`rowspan` здесь допустим и не противоречит правилу «визуальный ритм
не превращается в семантику»: предмет действительно объединяет свои типы —
это факт данных.

### 6. `map/FloorPlansTable` — 135

Реестр «корпус × этаж». Без пагинации, порядок по корпусу и этажу.

| Колонка | Ячейка |
|---|---|
| корпус | текст |
| этаж | число, `align=end` |
| png | `UploadStatusCell` |
| svg | `UploadStatusCell` |
| спрос | `FloorDemandCell` |
| ⋮ | `RowActionsMenu` + `DestructiveActionPair` |

**Два независимых `UploadStatusCell` в строке**, каждый со своим доступным
именем. Слитный бейдж не даёт понять на слух, чего именно не хватает.

Состояние строки `partial` — загружен один файл из двух. Показывает
не голый статус, а **последствие**: «svg нет → этаж не открывается на карте».

## Часть II. Ячейки реестров

Атомы, живущие внутри `Cell`. Ни один не вводит собственных размеров:
высота — от строки, кегль — `dense`.

### 7. `admin/EntityStatusCell`

Состояние сущности реестра. **Перечень значений и подписи приходят с сервера
как данные** — фронт не зашивает.

| Часть | Обязательность |
|---|---|
| `label` | обязательна — **текст, а не только цвет** |
| `pill` | обязательна — форма `radius/full` |
| `hint` | опционально — пояснение вроде «редактирование запрещено» |

Оси: `state = default | disabled`. Цвет заливки приходит из `color/state/*/bg`
по значению, но **носитель — подпись**; пояснение входит в доступное имя ячейки.

Заменяет `GroupStatusCell` и `SemesterStatusCell`. Потребитель один — 134.

### 8. `academic/InitialPasswordCell`

Пароль с **обязательной подписью о происхождении**: `initial` /
`headman_reset` / `admin_reset`.

| Состояние | Что видно |
|---|---|
| `visible` | значение + подпись о происхождении |
| `changed` | текст «сменён пользователем» — **не пустое `disabled`-поле** |
| `hidden` | признак «не сменён» + действие «Показать» |

`hidden` — предложение фронта для 132: там пароли всего вуза в одном ответе,
значение раскрывается по явному действию строки. Помечено в реестре как тема
аудита безопасности; в библиотеке состояние заведено.

### 9. `academic/TelegramIdCell`

| Состояние | Что видно |
|---|---|
| `linked` | Tr id |
| `not-linked` | **пояснение и что делать**, не пустое поле |

Вариант `editable` — администратор привязывает и отвязывает: добавляется
`AppButton` `ghost` `compact`.

### 10. `attendance/DisputeBlockCell`

Израсходованные попытки из лимита семестра + признак блокировки + действие
«Сбросить». **Показывает число и статус, а не голый флаг.**

Число — `MetricValue` `format=ratio` (например «3/3»), статус — подпись,
действие — `AppButton` `ghost` `compact`, видимо только при блокировке.

### 11. `admin/UploadStatusCell`

Статус одного файла: `missing` · `uploading` · `processing` · `ready` ·
`failed`. Пять состояний, пять разных текстов.

`processing` и `ready` различаются обязательно — иначе администратор грузит
тот же файл повторно.

### 12. `admin/FloorDemandCell`

«Количество выбора этого» — спрос на этаж. **Число без периода бессмысленно:**
подпись, за какой период считано, обязательна и не отключается.

`MetricValue` + `caption` с периодом.

### 13. `academic/TeacherList` · `schedule/SubjectProgressCell`

`TeacherList` — преподаватели типа занятия, только чтение; при усечении списка
полный состав в `Tooltip`.

`SubjectProgressCell` — «пройдено / всего пар», значение отрисовывает
`MetricValue` `format=ratio`. Кандидат на консолидацию закрыт реестром:
та же форма, другая сущность и другой домен.

### 14. `headman/MemberRoleBadge`

Подпись под ФИО: «староста» / «помощник». **Текст обязателен, цвет вторичен.**
Стиль `micro`, `color/text/muted`. Не пилюля: это подпись, а не статус.

## Часть III. Сетки расписания

### 15. `schedule/TimetableGrid` — каркас

Реестр: настоящая `<table>`, `<th scope="col">` из колонок (допускается вторая
строка — дата), `<th scope="row">` из справочника слотов времени,
**фиксированный размер ячейки**, roving tabindex, скелетон на размер сетки,
проброс `loading` / `error` / `empty`, слоты `cell(row, column)`
и `rowExpansion(row)`. **О чётности, датах, статусах пар, режимах и формах
не знает.**

**Анатомия**

| Часть | Обязательность |
|---|---|
| `ColumnHeaderRow` | обязательна, один или два уровня |
| `TimeSlotColumn` | обязательна — номер пары и время, залипшая |
| `cell` | обязательна, instance swap |
| `rowExpansion` | опционально — отдельная строка во всю ширину |

Матрица 8 строк × 6 колонок, пн–сб. Auto Layout не применяется — сетка.

**Размеры**

| | значение |
|---|---|
| высота ячейки | `size/schedule-cell` |
| ширина колонки | `fill`, все колонки равны |
| ширина колонки времени | `size/name-column` ÷ 2 |
| padding ячейки | `space/2` |

**Размер ячейки фиксирован независимо от наличия пары** — требование реестра:
сетка не прыгает при правке.

**Оси**

```
header-level = one | two
state        = default | loading | empty | error
```
плюс boolean `has-row-expansion`.

Скелетон при `loading` рисуется **на размер сетки**, а не полосой: иначе
при загрузке страница меняет высоту.

**Кандидат в `shared` при третьем потребителе** — сейчас потребителей два,
владение `domain (schedule)`.

### 16. `schedule/ScheduleBuilderGrid` — 117

Обёртка над `TimetableGrid`: колонки без дат, ячейка `ScheduleSlotCell`,
`rowExpansion` **не используется** — форма живёт секцией ниже сетки.

Собственное состояние — `no-subjects`: предметы группы не заведены, работать
не с чем. Пояснение и переход на 116.1. Без него экран показывает сетку,
где каждый «+» ведёт в форму, которую невозможно заполнить.

### 17. `schedule/ScheduleSlotCell` — 117

**Оси**

```
variant = full | split
state   = default | hover | focused | disabled
```

`full` — один слот на обе недели. `split` — **верх неделя 1, низ неделя 2**,
деление передаётся текстом в доступном имени. Пустая половина показывает «+».

Половина при `split` — ровно половина высоты `size/schedule-cell`; общая высота
ячейки не меняется.

### 18. `schedule/ScheduleSlotCard` — 117

Содержимое половины ячейки: предмет (название сокращается, полное —
в `Tooltip` и в доступном имени), тип занятия, аудитория.

**Это шаблон, а не пара:** даты, статуса пары и отметки не существует.
С `LessonCard` не сводится — реестр решил.

Три строки, кегль `micro`, вертикальный Auto Layout, gap `space/1`.

### 19. `schedule/WeekParityPicker` — 117

«1» · «2» · «обе». Подписи цифрами. **Соответствие цифры и чётности приходит
с сервера**, фронт его не назначает.

Сегментированный переключатель из трёх `AppButton` `secondary` `compact`,
активный — `state=selected`. «обе» — `disabled` с причиной, если противоположная
половина занята.

### 20. `schedule/LessonManagementGrid` — 118

Обёртка над `TimetableGrid`: колонки несут день **и дату** (двухуровневая
шапка), ячейка `LessonManagementCell`, `rowExpansion` несёт `LessonActionsPanel`
или `OneOffLessonForm`. По чётности не делится — неделя уже выбрана.

Обёртка владеет **режимом выбора цели переноса** и его объявлением.

Состояние `transfer-picking`: выбран источник, идёт выбор цели. Свободные ячейки
объявляются целями, занятые недоступны **с текстовым пояснением**, Esc отменяет
режим и возвращает фокус на источник.

### 21. `schedule/LessonManagementCell` — 118

Ячейка конкретной даты. Может содержать **одновременно отменённую пару
и добавленную взамен** — порядок детерминированный, отменённая первой.

Названные реестром состояния: `transferred-in`, `transferred-out`, `cancelled`,
`past`, `transfer-target-available`, `transfer-target-unavailable`.
Реестр указывает 11 состояний; поимённо названы шесть.

**Полный перечень берётся из спеки 118** (`01-wireframes/headman`), она
к этому чату не приложена. Здесь описана анатомия и носители; таблица
состояний дополняется при склейке — см. §23.

**Носители, которые известны и заданы брендбуком:**

| Состояние | Носитель |
|---|---|
| `cancelled` | зачёркивание, `color/text/muted` — «этого больше нет» |
| `past` | приглушение до `color/text/secondary`, без цвета |
| `transfer-target-available` | пунктирная граница `color/border/accent` — «свободно, принимает» |
| `transfer-target-unavailable` | штриховка `component/hatch/step` — «занято, недоступно» |
| `transferred-in` / `transferred-out` | подпись текстом, направление словом |

**Стопка пар в ячейке.** Несколько пар на одной дате складываются вертикально
внутри фиксированной высоты; при переполнении — счётчик «ещё N», раскрытие
через `rowExpansion`, не через рост ячейки.

### 22. `schedule/LessonTransferControl` — 118

Перенос пары: включает режим выбора цели, показывает источник, позволяет листать
недели не выходя из режима, отменяется по Esc.

**Не drag&drop** — операция обязана быть клавиатурной. В библиотеке это значит:
компонент существует как видимая панель с кнопками, а не как невидимое
поведение перетаскивания.

| Часть | Обязательность |
|---|---|
| `source-readout` | обязательна — какая пара переносится |
| `hint` | обязательна — «выберите свободную ячейку» |
| `week-pager` | обязательна — `StepPager` |
| `cancel` | обязательна — `AppButton` `ghost` |

## 23. Нужен токен

| Токен | Значение | Почему |
|---|---|---|
| `size/schedule-cell` | 5rem | фиксированная высота ячейки сетки расписания. Требование реестра: размер не зависит от наличия пары. Из шкалы отступов не выводится, к высоте строки таблицы отношения не имеет — там одна строка текста, здесь карточка в три строки |

Накопительно: `icon/size/sm|md|lg`, `size/dialog-width`,
`size/popover-max-width`, `shadow/sticky-x`, `size/column-max-text`,
`size/journal-column`, `size/name-column`.

## 25. Что осталось открытым

1. **Высота строки `UsersTable` не фиксирована** — единственное отступление
   от правила «высота строки фиксируется всегда». Причина: попарное выравнивание
   ролей и статусов в двух колонках. Решение спеки; альтернатива — одна строка
   на роль, но тогда учётная запись перестаёт быть одной строкой.
2. **`SubjectRowGroup` как единица вместо строки.** Следствие `rowspan`,
   который в Auto Layout не выражается. На состав колонок не влияет,
   но меняет то, что инстанцируется в макете.
3. **`size/schedule-cell` = 5rem** подобрана под три строки `micro`
   плюс padding. Проверить на реальном названии предмета с типом занятия
   и аудиторией.
