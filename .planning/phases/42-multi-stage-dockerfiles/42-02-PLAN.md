Replace the existing single-stage Dockerfile with a 3-stage multi-stage build.

notification-app is special because:
1. It has a `notification-api-contract` submodule
2. It uses proto/ for gRPC client stubs
3. It uses `LoaderImplementation.CLASSIC` (BouncyCastle signed-JAR workaround)

**IMPORTANT — CLASSIC loader ENTRYPOINT resolution:**
Before writing the final Dockerfile, build the notification-app JAR locally and check the Main-Class in MANIFEST.MF:
```bash
./gradlew.bat :services:notification-service:notification-app:bootJar -x test
```
Then inspect:
```bash
jar -tf services/notification-service/notification-app/build/libs/notification-app-0.1.0.jar | grep MANIFEST
jar -xf services/notification-service/notification-app/build/libs/notification-app-0.1.0.jar META-INF/MANIFEST.MF
cat META-INF/MANIFEST.MF
```
Use the exact `Main-Class` value from MANIFEST.MF as the ENTRYPOINT class.

If the Main-Class is `org.springframework.boot.loader.JarLauncher` (CLASSIC), use that.
If the Main-Class is `org.springframework.boot.loader.launch.JarLauncher` (new), use that.

**Write `services/notification-service/notification-app/Dockerfile`:**
```dockerfile
# Stage 1: Build
FROM eclipse-temurin:21-jdk-alpine AS builder
WORKDIR /workspace

COPY gradlew .
COPY gradle gradle
COPY build.gradle.kts .
COPY settings.gradle.kts .

# Proto files for gRPC stub generation
COPY proto proto

# API contract module
COPY services/notification-service/notification-api-contract/build.gradle.kts \
     services/notification-service/notification-api-contract/
COPY services/notification-service/notification-api-contract/src \
     services/notification-service/notification-api-contract/src

# App module
COPY services/notification-service/notification-app/build.gradle.kts \
     services/notification-service/notification-app/
COPY services/notification-service/notification-app/src \
     services/notification-service/notification-app/src

RUN chmod +x gradlew && ./gradlew :services:notification-service:notification-app:bootJar --no-daemon -x test

# Stage 2: Extract layers
FROM eclipse-temurin:21-jre-alpine AS extractor
WORKDIR /app
COPY --from=builder /workspace/services/notification-service/notification-app/build/libs/*.jar app.jar
RUN java -Djarmode=layertools -jar app.jar extract

# Stage 3: Runtime
FROM eclipse-temurin:21-jre-alpine
RUN addgroup -S app && adduser -S app -G app
WORKDIR /app

COPY --from=extractor /app/dependencies/ ./
COPY --from=extractor /app/spring-boot-loader/ ./
COPY --from=extractor /app/snapshot-dependencies/ ./
COPY --from=extractor /app/application/ ./

USER app
EXPOSE 9094
ENTRYPOINT ["java", "{MAIN_CLASS_FROM_MANIFEST}"]
```

Replace `{MAIN_CLASS_FROM_MANIFEST}` with the actual Main-Class value from the MANIFEST.MF inspection above.

**If `jarmode=layertools` extraction fails** (unlikely but possible with CLASSIC loader), fall back to:
```dockerfile
# Simplified runtime (no layer extraction)
FROM eclipse-temurin:21-jre-alpine
RUN addgroup -S app && adduser -S app -G app
WORKDIR /app
COPY --from=builder /workspace/services/notification-service/notification-app/build/libs/*.jar app.jar
USER app
EXPOSE 9094
ENTRYPOINT ["java", "-jar", "app.jar"]
```

Verify build succeeds:
