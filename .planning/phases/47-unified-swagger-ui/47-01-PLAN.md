<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser -> Gateway JWT filter | Swagger UI paths bypass JWT — unauthenticated access to API documentation |
| Gateway -> upstream api-docs | Gateway proxies /openapi/* to internal service /api-docs endpoints |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-47-01 | Information Disclosure | /openapi/* proxy routes | accept | API docs expose endpoint schemas but no sensitive data (no credentials, no PII). Acceptable for a portfolio/educational project. In enterprise, restrict to internal network or require auth. |
| T-47-02 | Elevation of Privilege | JwtAuthenticationFilter PUBLIC_PATHS/PREFIXES | mitigate | Whitelist uses exact paths (`/swagger-ui.html`) and specific prefixes (`/swagger-ui/`, `/v3/api-docs`, `/openapi/`). No wildcard patterns. Does NOT whitelist `/api/**` or any business endpoint. Verified: all existing auth paths remain unchanged. |
| T-47-03 | Spoofing | Swagger UI "Try it out" | accept | "Try it out" requests still require valid JWT at the service level (JWT filter only skips swagger paths, not `/api/*` business routes). No mitigation needed. |
</threat_model>
