## 1. `schedule/LessonCard`

Реестр: пара в трёх вариантах. **Вариант задаёт компоновку, состав полей —
данные.** Обязательны предмет, тип занятия, аудитория; остальное необязательно
и при отсутствии не рендерится. Отметка и действия приходят снаружи —
карточка их не производит.

### 1.1. Анатомия

| Часть | Обязательность |
|---|---|
| `subject` | обязательна |
| `lesson-type` | обязательна |
| `room` | обязательна |
| `time` | опционально |
| `date` | опционально — вариант `row` на 107 |
| `origin` | опционально — происхождение пары |
| `lesson-status` | опционально — отменена, перенесена |
| `room-changed` | опционально — признак смены аудитории |
| `group` | опционально — вариант `row` на 121 |
| `my-status` | опционально, instance swap |
| `actions` | опционально, слот |
| `ProgressScale` `lesson` | видима при `is-current` |

**Отсутствующее не рендерится, соседи смыкаются.** Пустых мест на месте
необязательных полей не остаётся.

### 1.2. Оси

```
variant = featured | row | cell
state   = default | current | cancelled | past | future
```
плюс boolean по каждому необязательному полю, `has-actions`, `is-current`.

| `variant` | Где | Компоновка |
|---|---|---|
| `featured` | 101 — карточка отметки | вертикальная, крупная, единственная на экран |
| `row` | 102, 107, 118, 121 — строка расписания | горизонтальная |
| `cell` | ячейка таблицы | компактная, три строки `micro` |

### 1.3. Размеры

| | `featured` | `row` | `cell` |
|---|---|---|---|
| кегль предмета | `title-block` | `dense-strong` | `micro` |
| кегль остального | `body` | `dense` | `micro` |
| padding | `space/5` | `space/3` | `space/2` |
| радиус | `radius/lg` | `radius/md` | `radius/sm` |
| высота | `hug` | `hug` | `size/schedule-cell` |
| поверхность | `color/surface/raised` | прозрачная | прозрачная |
| тень | `shadow/raised` | нет | нет |

### 1.4. «Сейчас»

`state=current` — **единственный выделенный объект экрана**. Носители:
граница `border/emphasis` `color/border/accent`, поверхность
`color/accent/soft`, вес подписи на ступень выше.

**Акцент строится на весе, плотности и границе, не на светимости** — условие
§4.5 направления, при котором светлая тема не разворачивает композицию.

`state=cancelled` — зачёркивание предмета и времени, `color/text/muted`,
причина отмены через `CancellationReasonPopover`. **Статус «отменена»
передаётся текстом**: зачёркивание и серый цвет носителями смысла не являются.

`state=past` — приглушение до `color/text/secondary`.
`state=future` — приглушение, отметки нет.

Прошедшее полновесно, будущее приглушено, вес только у «сейчас» — §2.1
направления, выраженное яркостью и весом, а не цветом.

### 1.5. Переполнение

Название предмета в `cell` сокращается, полное — в `Tooltip` и в доступном
имени. В `featured` и `row` переносится на две строки. Аудитория и время
не обрезаются никогда — это то, зачем карточку читают.

### 1.6. Слоты

`my-status` принимает `AttendanceStatusBadge`. `actions` — `AppButton`,
`AttendanceButton`, `LateCheckInButton`. Внутрь `cell` слоты не подставляются.

## 2. `homework/HomeworkList` · `homework/HomeworkItem`

Реестр: одна пара компонентов на student и headman. **Переключатель выполнения
рендерится только при наличии личного состояния выполнения.** Вариант
`readonly` не вводится: отсутствие переключателя — следствие отсутствия данных,
а не режим компонента.

### 2.1. `HomeworkItem` — анатомия

| Часть | Обязательность |
|---|---|
| `subject` | обязательна |
| `lesson-type` | обязательна |
| `date` | обязательна |
| `description` | обязательна, через `LinkifiedText` |
| `main-link` | опционально — одна основная ссылка отдельным полем |
| `binding-mark` | опционально — привязка к паре |
| `author` | опционально |
| `published-at` | опционально — время публикации |
| `completion-toggle` | видим при наличии личного состояния |
| `actions` | слот — Удалить · Редактировать · История изменения |

**Массива ссылок нет.** Одна основная ссылка отдельным полем, прочие ссылки
кликабельны внутри текста через `LinkifiedText`.

### 2.2. Оси

```
variant = compact | full
state   = default | hover | completed | archived
```

| | `compact` | `full` |
|---|---|---|
| где | 101, виджет 111 | 104, 114 |
| описание | обрезано двумя строками | обрезано четырьмя строками |
| действия | нет | слот `actions` |

**Обрезка описания обязательна** — приём мудборда: иначе карточки перестают
быть сравнимыми.

`completed` — **выполненное остаётся видимым**, метка или галочка. Не
зачёркивание: зачёркивание закреплено за «этого больше нет».

`archived` — только действие «История изменения», остальные не рендерятся.

### 2.3. `HomeworkList` — оси

```
group-by = none | day
order    = completion-first | date-asc | lesson-order
scroll   = inner | page
```

`scroll=inner` — на 111 блок скроллится внутри себя.

**Несколько заданий на одну пару — норма**, список не схлопывается по паре;
порядок внутри пары детерминированный.

### 2.4. `homework/LinkifiedText`

Показ текста с автоматически кликабельными ссылками: внешние, **видимый домен**,
осмысленное доступное имя. Домена не знает.

Ссылка внутри текста рисуется как `AppLink`: подчёркивание, не цвет.

## 3. `homework/MonthCalendar`

Реестр: сетка месяца. Ячейка — кнопка выбора дня с `aria-pressed`, доступное имя
= дата + содержимое; сегодняшний день — `aria-current="date"` **+ текстовая
пометка**. Содержимое ячейки — слот. **Доступность дней задаётся снаружи**,
причина недоступности — текстом.

Сборка — по образцу приложенного PNG: сначала атом `DayNumber` во всех
состояниях, затем ячейка диапазона, затем календарь целиком.

### 3.1. Атом `DayNumber`

```
state = default | hover | selected | current | disabled
```
плюс boolean `focus-ring`, `in-range`.

| Состояние | Форма | Заливка | Текст |
|---|---|---|---|
| default | круг прозрачный | нет | `color/text/primary` |
| hover | круг | `color/surface/raised` | `color/text/primary` |
| selected | круг | `color/accent/now` | `color/accent/on-now` |
| current | круг, **обводка** `border/emphasis` `color/border/accent` | нет | `color/text/primary` |
| disabled | круг прозрачный | нет | `color/disabled/text` |

**`selected` и `current` различаются заливкой против обводки** — приём мудборда
«заливка против контура для двух состояний одного цвета». Оба могут совпасть
на одном дне: тогда заливка побеждает, обводка снимается, а «сегодня»
передаётся текстовой пометкой.

Размер круга `space/8`, кегль `dense`.

### 3.2. Ячейка диапазона

`in-range=true` — подложка `color/accent/soft` на всю ширину ячейки, без
скругления по бокам; у краёв диапазона скругление `radius/full` с внешней
стороны. Атом `DayNumber` лежит поверх подложки.

Подложка — отдельный слой под сеткой, а не заливка ячейки: иначе разрывы между
ячейками рвут полосу.

### 3.3. Календарь

| Часть | Обязательность |
|---|---|
| `header` | обязательна — `StepPager` по месяцам |
| `weekday-row` | обязательна — ПН…ВС |
| `day-grid` | обязательна, 7 × 6 |
| `day-content` | слот — количество заданий, краткие названия предметов |

Дни соседних месяцев показываются приглушёнными и недоступны.

Слот `day-content` пуст в форме публикации и заполнен на 104.

### 3.4. Переполнение

`day-content` — не больше двух строк `micro`; при большем количестве заданий
счётчик «ещё N». Ячейка не растёт: сетка месяца обязана оставаться сеткой.

## 5. `attendance/TicketCard`

Реестр: карточка тикета. Три варианта. **Пары внутри — простой список без
чекбоксов.** Состав пар грузится по раскрытию; в свёрнутом виде — период
покрытия и количество пар.

### 5.1. Анатомия

| Часть | Обязательность |
|---|---|
| `ticket-number` | обязательна |
| `submitted-at` | обязательна |
| `type` | обязательна |
| `reason` | видима только при типе «у» |
| `date-range` | обязательна |
| `lesson-count` | обязательна в свёрнутом виде |
| `lessons` | видима при раскрытии |
| `AttachmentList` | опционально |
| `TicketStatusBadge` | видим при `variant=archived` |
| `reject-reason` | видима при отклонении |
| `decided-at` | видима при `archived` |
| `author` | видим при `variant=incoming` |
| `overlap-warning` | видим при `incoming` — «N из M пар уже отмечены» |
| `actions` | слот |

### 5.2. Оси

```
variant = pending | archived | incoming
state   = collapsed | expanded | stale | busy
```

| `variant` | Действия |
|---|---|
| `pending` | «Отменить» — свои тикеты |
| `archived` | нет |
| `incoming` | «Подтвердить» / «Отклонить» — у старосты |

`stale` — заявку решил кто-то другой: карточка помечается решённой
**с пояснением, кем и когда**, действия блокируются. Без этого двое разбирают
одну очередь и получают ошибку сервера вместо объяснения.

### 5.3. Скелет карточки

Приём мудборда: метка → заголовок → описание → линия → метаданные.
Единственная разделительная линия `border/hairline` `color/border/subtle`
перед подвалом с метаданными.

Поверхность `color/surface/raised`, радиус `radius/lg`, padding `space/4`,
тень `shadow/raised`.

**`hover` карточке не положен** — §8.1. Раскрытие вызывается
`RowDetailTrigger`, а не кликом по всей карточке.

## 6. `attendance/AttachmentList`

Вложения **на чтение**: имя, размер, действие «Открыть».
Не путать с `FileUploadField` — у них разные состояния.

| Часть | Обязательность |
|---|---|
| `file-type-icon` | обязательна |
| `file-name` | обязательна |
| `file-size` | обязательна |
| `open-action` | обязательна, `AppLink` |

Вложение плашкой: тип, имя, вес — приём мудборда.

```
state = default | no-attachments | attachment-error | expired
```

**`no-attachments` и `attachment-error` различаются обязательно:** «файлов
не приложено» и «список не загрузился» — разные утверждения. Ошибка живёт
внутри списка, носитель остаётся жив.

`expired` — вложение удалено по сроку: зачёркивание имени, «этого больше нет».

Имя файла обрезается **в середине**: расширение обязано остаться видимым.

## 7. `attendance/ExcuseReasonPopover`

Краткая причина по «у»: тип + комментарий + дата постановки.
**Состав полей — данные**, правило «нет поля — блок не рендерится».

Строится на `Tooltip`, **не на `Popover`**: содержимое нефокусируемо
во всех применениях.

Открывается **по наведению и по фокусу**; содержимое дублируется в доступном
имени триггера. Где триггер уже несёт действие «открыть заявку» — подсказка
вешается на ту же кнопку, отдельного фокусируемого элемента не заводится.

Единственное место показа **краткой** причины во всём продукте.
Заявка целиком — `ExcuseTicketPanel`.

## 8. `attendance/ExcuseTicketPanel`

Заявка целиком. **Раскрывается на странице** — именованный регион, связанный
с триггером. Фокус переводится в панель и **не запирается**; Esc и повторное
нажатие закрывают с возвратом фокуса на триггер.

| Часть | Обязательность |
|---|---|
| `header` | обязательна — ФИО, дата подачи, дата подтверждения, тип, комментарий |
| `lessons` | обязательна — состав пар |
| `AttachmentList` | опционально |

Состав пар **урезан сервером по назначениям читателя** — свойство представления,
не проп и не роль. Тикет остаётся неделимым.

Собственное состояние **`no-ticket`**: «у» проставлен вручную, заявки
не существует — показываем это текстом, **без пустых полей и без списка файлов**.
Экран не должен обещать документ, которого нет.

Имя `ExcuseTicketDialog` выведено из обихода: два контракта фокуса на одном
имени недопустимы.

## 9. `attendance/StatsDetailPanel` · `RowDetailTrigger`

### 9.1. `StatsDetailPanel`

Детализация по выбранному студенту: четыре метрики и те же в количествах,
позиция в рейтинге группы, разбивка по предметам через `StatsBySubjectTable`.

**Встроенная область страницы, не модалка.** Фокус переводится в панель,
но **не запирается**.

```
variant = region | row
```

| `variant` | Где | Размещение |
|---|---|---|
| `region` | 113 | область под таблицей |
| `row` | 116 | раскрытая строка внутри таблицы |

**Контракт данных один** — различается только размещение, поэтому это вариант,
а не два компонента.

| Часть | Обязательность |
|---|---|
| `header` | обязательна — ФИО, кнопка закрытия |
| `DefinitionList` `stack` | обязательна — метрики |
| `rank` | обязательна — позиция в рейтинге |
| `StatsBySubjectTable` | обязательна — разбивка |

### 9.2. `RowDetailTrigger`

**Кнопка-стрелка в конце строки** — основной, клавиатурный путь.
Клик по строке целиком — дополнительный, для мыши.
`<tr>` кнопкой не делать.

На 119 применяется в карточке, а не в строке таблицы. Реестр помечает имя
как подлежащее обобщению — здесь используется как есть.

```
state = default | hover | pressed | expanded | disabled
```

`expanded` — стрелка повёрнута, `duration/fast`.

## 10. Хронологии

### 10.1. `attendance/LessonActivityLogPanel` · `LessonActivityLog`

Хронология событий по паре: кто, во сколько, каким способом отметился,
расстояние от центра гео-круга, тикеты по паре, действия старосты.
Свой пейджер и скролл.

| Часть элемента | Обязательность |
|---|---|
| `time` | обязательна, `tnum` |
| `actor` | обязательна |
| `event` | обязательна — **«было → стало» явно** |
| `method` | опционально — способ отметки |
| `distance` | опционально — расстояние от центра круга |

**Лента изменений «было → стало»** — приём мудборда: переход статуса показан
явно, без анимации. Формат: «н → у, староста, 12:57».

Относительное время рядом с абсолютным: «30 мин назад» отвечает на «свежо ли»,
точная дата — на «когда».

Вертикальный список, `scroll=inner`, `Pagination` `mode=show-more` внизу.

### 10.2. `homework/HomeworkHistoryPanel`

Кто и как менял задание: автор, время, что изменилось. Хронологически.
**Доступна всем, включая архив. Раскрывается на странице.**

Та же анатомия элемента, без `method` и `distance`.

История обязательна, потому что право править дз определяется правом
публиковать, а не авторством: автор остаётся информацией, и без истории
непонятно, кто менял.

## 11. `auth/PermissionList`

Набор делегированных прав. Подписи прав приходят с сервера как данные.
**У пользователя без прав блок не рендерится вовсе.**

```
variant = readonly | editable
```

| `variant` | Где | Что внутри |
|---|---|---|
| `readonly` | 108 — свои права; 116 — ячейка «Доп разрешения» | список подписей |
| `editable` | 116 — выдача и отзыв из меню строки | список с `Checkbox` |

Отзыв права требует `ConfirmDialog`.

## 12. Карта

### 12.1. `map/FloorPlanViewer`

Просмотр схемы этажа: **зум и панорамирование** — колесо с модификатором,
кнопки зума, сброс масштаба; с клавиатуры `+` / `−` и стрелки при фокусе
на области. Тач-таргеты ≥44×44.

| Часть | Обязательность |
|---|---|
| `canvas` | обязательна — SVG схемы |
| `zoom-controls` | обязательна — плюс, минус, сброс |
| `alt-text` | обязательна — осмысленная альтернатива |

```
state = default | loading | empty | error
```

**Органы управления картой поверх карты — узкое исключение** из правила
«наложений нет», принятое мудбордом.

**Палитра схемы нашей системе не подчиняется:** файлы приходят от
администратора. Токенами покрыты только органы управления и легенда.

### 12.2. `map/BuildingFloorPicker`

Связанная пара `SelectField`: этажи зависят от выбранного корпуса.
Смена корпуса объявляется, фокус остаётся на селекте.

### 12.3. `map/PlanLegend` · `map/FloorRoomList`

**Наполнение обоих отложено решением владельца.**

`PlanLegend` — легенда иконок текстом: иконка → значение. Справочник
общесистемный, не поле конкретной схемы. Анатомия описана, состав ждёт
отдельной сессии.

`FloorRoomList` — текстовый перечень аудиторий этажа: номер, назначение.
Поле остаётся пустым и неактивным, интерфейса наполнения нет.

**Известное ограничение доступности сохраняется:** пока перечень пуст, схема
остаётся изображением без полноценной текстовой альтернативы. Записано
в реестре, здесь только повторено.

## 14. Что осталось открытым

1. **Число строк обрезки описания** — два в `compact`, четыре в `full`.
   Требование «обрезка обязательна» из мудборда, конкретные числа —
   решение спеки.
2. **`RowDetailTrigger` → `DetailTrigger`.** Реестр помечает имя как
   подлежащее обобщению и отправляет в калибровочный чат. Здесь используется
   текущее имя; переименование не меняет анатомию.
3. **`PlanLegend` и `FloorRoomList`** — анатомия есть, наполнение отложено
   владельцем. Из библиотеки не выкидываются.
4. **Совпадение `selected` и `current` в календаре.** Решение спеки: заливка
   побеждает, обводка снимается, «сегодня» уходит в текстовую пометку.
   Проверить на макете месяца, где выбранный день и есть сегодня.
