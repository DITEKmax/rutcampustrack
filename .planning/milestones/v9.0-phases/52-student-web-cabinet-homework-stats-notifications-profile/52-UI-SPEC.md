## Design System

| Property | Value | Source |
|----------|-------|--------|
| Tool | none (custom) | `frontends/web-panel/src/styles/tokens.css` |

This phase adds four Angular component groups to the **existing web-panel Angular app**. All tokens, Material M3 bridge, global `.page-header` / `.page-card` / `.page-stack` / `.page-empty` / `.page-error` / `.page-filters` primitives, `.status-chip` classes, skeleton shimmer keyframe `dashboard-shimmer`, sidebar shell, student route tree, and `StudentApiService` are already in place from Phase 51. Do not redefine them — extend only.

The chart pattern (`ng2-charts` + `BaseChartDirective`) is already established in `teacher/stats/` — reuse it unchanged.

## Focal Points

Explicit primary focal point per page:

**`/student/homework`**
Primary focal point: the homework item list itself — specifically the completion checkbox on each item. The checkbox is the single interactive element per row. Items are ordered with incomplete items first (accent border) and completed items dimmed below. The page reads as a task list with a clear done/not-done visual split.

**`/student/stats`**
Primary focal point: the `<app-overall-stat-card>` summary bar at the top — shows total lessons and overall attendance percentage in `--text-2xl` / `--font-mono`. This number anchors the page. Per-subject charts below are supporting context. The overall percentage renders in `--accent-primary` when ≥ threshold, `--accent-warning` when < threshold.

**`/student/notifications`**
Primary focal point: the notification list. There is no primary CTA — this is a read-only log. The most recent notification is at the top. Unread items (first load, before user scroll) have a `2px solid --border-accent` left border strip as the sole visual differentiator.

**`/student/profile`**
Primary focal point: the password change form's submit button "Сохранить пароль". The identity card above it is purely informational. The page has a single writable action.

### 1. `/student/homework` — StudentHomeworkComponent

Layout: `.page-stack` — standard page container. No sidebar filter needed; all homework is for the student's own group and current semester (derived from JWT `group_id` claim).

**API call:** `GET /api/academic/homeworks?groupId={groupId}&semesterId={currentSemesterId}&size=50`

**Sub-components:**

| Sub-component | Selector | Pattern | Notes |
|---|---|---|---|
| Homework list container | `<div class="homework-list">` | flex column, gap `--space-3` | Parent for all `<app-homework-item>` rows |
| Homework item | `<app-homework-item>` | New standalone component | See detail spec below |
| Homework empty state | Inline in parent | `.page-empty` global class | `ph-notebook-text` 32px duotone + heading + body |
| Homework loading | Inline in parent | 4× skeleton rows | Same shimmer keyframe as dashboard |

**`HomeworkItemComponent` layout:**

Each homework item is a card row:
```
[ checkbox 20×20 ] [ title (heading 16px/600) ]   [ due badge ]
                    [ subject chip ]                [ link icon? ]
                    [ description (body 14px/400) — max 2 lines truncated ]
```

- Container: `background: --bg-secondary`, `border: 1px solid --border-subtle`, `border-radius: --radius-lg`, `padding: --space-4`.
- When `completed = true`: `opacity: 0.55` on the entire card; title gains `text-decoration: line-through`; border changes to `--border-subtle` (no accent).
- When `completed = false` and due date is today or past: `border-left: 3px solid --accent-warning` (overdue indicator).
- When `completed = false` and due date is in future: `border-left: 3px solid --border-default`.
- Checkbox: `MatCheckbox` re-styled — checked state uses `--accent-primary` color.
- Optimistic toggle: on checkbox click, `completed` flips immediately in local signal. Then `POST /api/academic/homeworks/{id}/complete` or `DELETE /api/academic/homeworks/{id}/complete`. On API error: revert local state + show inline error toast.
- If `link` field is non-null: render `<a [href]="item.link" target="_blank" rel="noopener">` icon button — `ph-arrow-square-out` 16px fill, color `--accent-secondary`. Positioned top-right of card.
- Subject chip: small pill with `ph-book-open` 12px fill + subject name. Background `color-mix(in oklab, --accent-secondary 10%, transparent)`. Border `1px solid color-mix(in oklab, --accent-secondary 20%, transparent)`. Font `--text-xs` / weight 400.

**Item ordering:**
1. Incomplete items first — sorted by `createdAt` descending (newest first).
2. Completed items last — sorted by `createdAt` descending.

Angular: use `computed(() => [...incomplete].sort() + [...complete].sort())` signal.

**`ChangeDetectionStrategy.OnPush`** on `HomeworkItemComponent`.

### 3. `/student/notifications` — StudentNotificationsComponent

Read-only scrollable log of past notification events received via STOMP on `/topic/group/{groupId}`. This is a **client-side in-memory log** — there is no backend API for notification history. The component stores STOMP events received during the session in a `signal<NotificationItem[]>` and persists them to `sessionStorage` so they survive Angular route navigation within the same browser tab.

**Data structure:**

```typescript
interface NotificationItem {
  id: string;           // crypto.randomUUID() at receive time
  type: string;         // STOMP envelope "type" field (e.g. "lesson.started")
  payload: Record<string, unknown>;
  receivedAt: Date;     // Date.now() at receive time
  read: boolean;        // false until user views the notifications page
}
```

**STOMP subscription:** The `StudentStompService` (already in `student/shared/`) already connects to `/topic/group/{groupId}`. Phase 52 extends it by adding an `onAnyEvent` observable that the `StudentNotificationsComponent` subscribes to. All non-`attendance.marked` events are stored in the notification log. `attendance.marked` events are NOT stored (they are handled by the checkin page). Events stored: `lesson.started`, `lesson.cancelled`, `homework.published`, `homework.updated`.

**Sub-components:**

| Sub-component | Pattern | Notes |
|---|---|---|
| Notification item row | `<app-notification-item>` (new standalone) | See detail spec below |
| Empty state | `.page-empty` global | `ph-bell-slash` 32px duotone + heading + body |
| "Новых уведомлений нет" badge | Shown when all items have `read: true` | Small pill at top of list — `ph-check-circle` 14px fill + "Все прочитано". Color `--text-muted`. Hidden when list is empty. |

**`NotificationItemComponent` layout:**

```
[ event icon 20px ] [ event heading (16px/600) ]    [ timestamp (xs mono muted) ]
                    [ body text (14px/400) — 1 line  ]
```

- Container: `background: --bg-secondary`, `border-radius: --radius-md`, `padding: --space-4 --space-5`.
- Unread: `border-left: 3px solid --border-accent`.
- Read: `border-left: 3px solid transparent`.
- No hover action, no click navigation — purely informational.

**Event type → icon + heading mapping:**

| event_type | Phosphor icon | Icon color | Heading copy |
|---|---|---|---|
| `lesson.started` | `ph-play-circle` 20px fill | `--accent-primary` | "Пара началась" |
| `lesson.cancelled` | `ph-x-circle` 20px fill | `--accent-info` (violet) | "Пара отменена" |
| `homework.published` | `ph-notebook` 20px fill | `--accent-secondary` | "Новое задание" |
| `homework.updated` | `ph-pencil-simple` 20px fill | `--accent-warning` | "Задание обновлено" |
| (unknown) | `ph-bell` 20px regular | `--text-muted` | "Уведомление" |

Body text: derived from payload. Format:
- `lesson.started` → "{subjectName} — отметьтесь!" (subject name from payload or `SubjectCacheService` lookup by `subject_id`)
- `lesson.cancelled` → "{subjectName} — пара отменена" (+ `cancelReason` if payload contains it)
- `homework.published` → "Новое ДЗ по {subjectName}: {title}"
- `homework.updated` → "ДЗ по {subjectName} обновлено: {title}"

**Mark-all-read:** All items marked `read: true` when `StudentNotificationsComponent.ngOnInit()` fires. Sidebar badge clears on navigation to `/student/notifications`.

**Session persistence:** `sessionStorage.setItem('rct-notifications', JSON.stringify(items))` on each update. Load on `ngOnInit`. Max 100 items stored — oldest dropped when exceeded.

Single-purpose page: password change form + identity display. Mirrors Angular web-panel pattern for forms (existing `MatFormFieldModule`, `ReactiveFormsModule`).

**Identity card:**
- Visually mirrors PWA `ProfilePage.tsx` identity section — same gradient halo, avatar initials, role chip.

- Role label: "Студент" — `--text-base` / `--font-heading` / weight 600.
- User ID: `--text-xs` / `--font-mono` / weight 400 / color `--text-muted`. Format: "ID {userId}".

**Password change form:**
- Card: `background: --bg-elevated`, `border: 1px solid --border-default`, `border-radius: --radius-xl`, `padding: --space-6`.
- Section heading: "Изменить пароль" — `--text-base` / `--font-heading` / weight 600.
- Two fields (vertical stack, gap `--space-4`):
  1. "Текущий пароль" — `MatFormField`, type `password`, `[formControlName]="currentPassword"`.

- New password validation inline hints (shown below field when focused or touched):
  - Min 8 characters
  - At least one uppercase letter
  - At least one digit

- Submitting state: button disabled, `MatProgressSpinner` 16px inside button, label changes to "Сохраняем…".
- Success state: button replaced by success banner for 3s: `ph-check-circle` 16px fill `--status-present` + "Пароль успешно изменён".
- Error state (401 — wrong current password): inline error below current-password field: "Неверный текущий пароль."
- Error state (other API): error banner below form: "Не удалось изменить пароль. Попробуйте позже."
- `ReactiveFormsModule` with `FormGroup`. No page navigation after success — form resets to empty.
- `ChangeDetectionStrategy.OnPush` on `StudentProfileComponent`.

## Interaction & Animation Contract

Reuses all animation triggers established in Phase 51. No new animation triggers needed.

| Interaction | Mechanism | Duration | Easing |
|---|---|---|---|
| Route enter (all 4 new pages) | `[@routeFade]`: opacity 0→1, translateY 8px→0 — **reuse existing trigger from Phase 51** | 200ms | `--ease-out` |
| Homework completion toggle | Optimistic: `opacity` and `text-decoration` change immediately via CSS class toggle | 150ms | `--ease-out` |
| Homework item reorder | Angular `@for` with `track item.id` — list re-renders on signal update; no layout animation (avoids jarring jump on toggle) | — | — |
| Notification badge count update | Signal update triggers `ChangeDetectionStrategy.OnPush` re-render; no animation | — | — |
| Password submit → success banner | `[@toastSlide]` reuse: opacity 0→1, translateY 8px→0 | 200ms | `--ease-out` |
| Password submit → error | Shake: `transform: translateX(-4px) → translateX(4px) → 0` on the affected form field | 200ms | ease-in-out |
| Chart bar render | chart.js built-in bar enter animation — `animation: { duration: 400 }` | 400ms | chart.js default easing |
| Skeleton shimmer | `@keyframes dashboard-shimmer` (already declared globally) | 1.5s | linear infinite |

All animations respect `@media (prefers-reduced-motion: reduce)` — disable transforms, keep functional state changes. Chart.js: set `animation: false` when `prefers-reduced-motion` matches.

## Accessibility Contract

All Phase 51 global rules apply unchanged. Phase 52 additions:

- Homework checkbox: `aria-label="Отметить задание '{{item.title}}' выполненным"` when unchecked; `aria-label="Снять отметку с задания '{{item.title}}'"` when checked. `aria-pressed` on the wrapping interactive element.
- Homework list: `role="list"` on container; each item `role="listitem"`.
- Homework optimistic pending: `aria-busy="true"` on item while API call is in-flight.
- External homework link: `aria-label="Открыть материалы к заданию (новая вкладка)"` on the icon-only `<a>` button.
- Stats page: `<canvas>` elements must have `role="img"` and `aria-label="{subjectName} — статистика посещаемости"`.
- Stats overall percentage: `aria-live="polite"` so screen readers announce when data loads.
- Notifications list: `role="list"` on container; each item `role="listitem"`. `aria-label="Уведомление: {heading}, {relativeTime}"`.
- Notification unread badge (sidebar): `aria-label="Уведомления, {N} непрочитанных"`.
- Password fields: standard `type="password"` + `autocomplete="current-password"` / `autocomplete="new-password"`.
- Password visibility toggle button: `aria-label="Показать пароль"` / `aria-label="Скрыть пароль"` (toggled).
- Password validation hints: rendered as `<ul role="list">` with `<li>` per rule. Each `<li>` has `aria-label="{rule}: {met/not met}"`.
- Password form: `aria-live="assertive"` region for error messages so screen readers announce immediately.
- Password submit button: `aria-disabled="true"` when form is invalid or submitting.
- Color alone never conveys status — percentage values always include numeric text; completion state always includes text badge alongside color change.
- Min touch target: 44×44px for all interactive elements.
