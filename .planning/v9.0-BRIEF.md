## 1. Why this milestone exists

После v8.0 production развёрнут, но реальное использование выявило **фундаментальные фронтенд-проблемы**, не закрытые предыдущими milestone-ами:

### 1.1 Observed production bugs (подтверждены вручную 2026-04-08)

1. **`https://ruttrack.site/` → PWA для всех.** Nginx корень проксирует на PWA (см. `nginx/conf.d/default.conf:125-128`). Админы, преподаватели и студенты попадают в один и тот же мобильный студенческий клиент независимо от роли.
2. **`https://ruttrack.site/admin/` — нельзя войти:**
   - `frontends/web-panel/src/app/core/auth/auth.service.ts:8` — тип роли жёстко `'TEACHER' | 'ADMIN'`. Студент ломает парсинг.
   - `frontends/web-panel/src/app/features/login/login.component.ts:50` — после логина редиректит на `/teacher/dashboard` для всех, кто не ADMIN. Студент попадает в цикл `/login` ↔ `/teacher/dashboard` через `roleGuard(['TEACHER'])` → визуально «перекидывает в никуда».
   - Web-panel **не имеет** ни роутов, ни компонентов для STUDENT.
3. **Ссылки на `https://t.me/` из лендинга.** `frontends/landing/dist/index.html:1029,1107,1306` — три кнопки «Открыть в Telegram» ведут на `https://t.me/` (пустой). Пользователь нажимает «Открыть» в шапке лендинга → попадает на telegram.org.
4. **Лендинг сейчас на `/landing/`**, но должен быть отдельной презентационной страницей по явному пути (пользователь хочет `/presentation`), НЕ показываться при первом заходе.

### 1.2 Gaps относительно зафиксированной архитектуры

**`docs/design-decisions.md §3` прямо фиксирует** (цитата):

> PWA — аудитория: **все роли** (студенты, старосты, преподаватели). Админы остаются на desktop веб-панели

Реальность:
- PWA реализована **только для студентов** (`frontends/pwa/src/`). Нет UI для старост, преподавателей.
- Web-panel реализован **только для teacher + admin**. Нет UI для студента и старосты.

**`docs/job-stories.md` фиксирует требования, частично не реализованные:**

| Story | Текст | Реализовано? |
|---|---|---|
| **JS-TEACHER-08** (L76) | Preпод открывает PWA на планшете/телефоне — мобильный журнал | ❌ Нет PWA-UI для TEACHER |
| **JS-HEADMAN-01** (L84) | Староста отмечает посещаемость **через веб-панель** (выбор пары → массовая простановка) | ❌ Нет UI старосты в web-panel |

### 1.3 Новое требование (не было в предыдущих milestone-ах)

Пользователь явно попросил: **«полноценная веб-версия для студентов»** — так, чтобы студент мог войти с компьютера в браузере и получить весь функционал (отметка, расписание, домашка, статистика, тикеты, уведомления), а не только мобильный PWA-клиент. Это расширяет архитектуру по сравнению с `design-decisions.md §3` и требует явного добавления в v9.0 requirements.

### 2.2 Где хостится единый `/login` — best practice

**Решение:** Единое Angular-приложение `web-panel` с **`baseHref: /`** (не `/admin/` как сейчас). Внутри — child-роуты `/login`, `/admin/*`, `/teacher/*`, `/student/*`, `/headman/*`. Обоснование:

- Одна кодовая база для auth: `AuthService`, `AuthApi`, `auth.interceptor.ts`, `auth.guard.ts`, `role.guard.ts`.
- Общие design-токены Material 3 и Tailwind theme.
- Один shell с sidebar/header, переключающийся по роли (как уже есть сейчас для ADMIN/TEACHER в `sidebar.component.ts:77-110`).
- Лёгкая поддержка: добавление новой роли/раздела = добавить lazy-route.
- Не будет дублирования `mat-form-field`, Material-темы, Phosphor icons между «отдельным login-бандлом» и «админкой».

**Trade-off:** `baseHref` смена с `/admin/` → `/` поломает прямые ссылки вида `https://ruttrack.site/admin/` (были в v7.0/v8.0 docs, в footer лендинга). Принимаем — исправим во всех местах в Фазе 0.

PWA (`frontends/pwa/`) остаётся **отдельным** React-проектом под `/app/` — это уже инвестиция в Service Worker, offline, manifest, Web Push, A2HS. Переделывать её в Angular **нельзя**: потеряем весь v6.0.

### 2.3 OTP login

- Backend готов (`POST /api/auth/otp/verify` уже возвращает `TokenResponse` — `AuthController.java:81-84`).
- В v9.0 **не реализуем** UI для OTP. Фиксируем как «future extension» — требование `AUTH-OTP-01`, «deferred».
- Текущая форма только username + password.

### 2.4 HEADMAN role

**Backend решение (не меняем):** HEADMAN — это не отдельная роль `UserRole`, а флажок `is_headman` на student-entity. Во всех 5 сервисах `UserRole = { ADMIN, TEACHER, STUDENT }` (см. `services/auth-service/src/main/java/ru/rutcampustrack/auth/entity/enums/UserRole.java:3`). Расширение enum было бы каскадным breaking change.

**Frontend решение:** `is_headman` **уже в JWT claims** (`services/auth-service/src/main/java/ru/rutcampustrack/auth/service/JwtService.java:96`). Фронт читает его прямо из токена, отдельного API-вызова не надо. Роль-гард `headmanGuard` проверяет `role === 'STUDENT' && is_headman === true`. Headman **всегда** имеет доступ к `/student/*` как расширение базовых прав — это правило в гарде.

**WPAN-13 remain blocked?** Нет. В v9.0 backend-гард `@RequireRole(STUDENT)` дополняется логикой «headman может выполнять actions от имени группы» через новый application-level check. Это отдельная фаза, возможно частично переиспользует `AssistantService` (уже есть в `services/academic-service/.../assistant/`).

## 3. Constraints (что НЕ трогаем)

- **Backend контракты.** `UserRole` enum не меняем. gRPC proto не меняем, кроме случаев, когда новая функция требует нового RPC (staroста-CRUD может потребовать).
- **PWA (`frontends/pwa/`).** Внешний функционал не меняем, только **дописываем** режимы для HEADMAN. Все существующие 63 vitest теста должны продолжать проходить.
- **Telegram Mini App.** Не трогаем в v9.0. TMA-ветка фронта остаётся как есть.
- **Telegram Bot.** Не трогаем.
- **CI/CD v8.0.** Все GitHub Actions workflow должны продолжать работать. Изменения в `docker-compose.prod.yml`, если потребуются, должны быть обратно-совместимы (те же имена контейнеров, те же env vars).
- **SSL / Let's Encrypt.** Не трогаем.
- **Всё инфраструктурное из v8.0** (Actuator healthchecks, nginx reverse proxy, unified Swagger UI) — сохраняем.

## 5. Requirements draft (для gsd-roadmapper при генерации REQUIREMENTS.md)

### INFRA (Nginx + deployment)
- **INFRA-v9-01**: Корневой URL `https://ruttrack.site/` редиректит на `/login` без отображения лендинга
- **INFRA-v9-02**: `https://ruttrack.site/presentation/` отдаёт лендинг-презентацию
- **INFRA-v9-03**: `https://ruttrack.site/app/` отдаёт PWA (React)
- **INFRA-v9-04**: Web-panel (Angular) обслуживает `/login`, `/admin/*`, `/teacher/*`, `/student/*`, `/headman/*` как единое SPA с `baseHref: /`
- **INFRA-v9-05**: Все внутренние ссылки в лендинге НЕ содержат `https://t.me/` (удалены или заменены на `/login`)
- **INFRA-v9-06**: CI pipeline v8.0 продолжает проходить без изменений

### AUTH (единый логин)
- **AUTH-v9-01**: Единая страница `/login` принимает username + password, вызывает `POST /api/auth/login`, хранит access token в Angular signal (memory-only, per D-06)
- **AUTH-v9-02**: После логина пользователь перенаправляется на dashboard роли: ADMIN → `/admin/dashboard`, TEACHER → `/teacher/dashboard`, STUDENT (не headman) → `/student/dashboard`, STUDENT+is_headman → `/headman/dashboard`
- **AUTH-v9-03**: `AuthService.currentUser` читает из JWT claims: `role`, `is_headman`, `group_id`
- **AUTH-v9-04**: `headmanGuard` разрешает доступ только пользователям с `role=STUDENT && is_headman=true`; автоматически разрешает доступ к `/student/*`
- **AUTH-v9-05**: `studentGuard` разрешает доступ пользователям с `role=STUDENT` (включая старост)
- **AUTH-v9-06**: Logout очищает токены и редиректит на `/login`
- **AUTH-OTP-01** (DEFERRED to v10.0): UI для логина через OTP — backend уже поддерживает `/api/auth/otp/verify`

### STUDENT (веб-кабинет студента)
- **STU-WEB-01**: `/student/dashboard` — обзор: сегодняшнее расписание, ближайшая пара, red-zone предупреждения

- **STU-WEB-03**: `/student/checkin` — активная пара, кнопка check-in, GPS capture, STOMP real-time status
- **STU-WEB-04**: `/student/homework` — список ДЗ, отметка выполнения (optimistic toggle)
- **STU-WEB-05**: `/student/stats` — статистика по предметам, red-zone, графики ng2-charts
- **STU-WEB-06**: `/student/notifications` — лог прошедших уведомлений (lesson.started, cancelled, homework.published)
- **STU-WEB-07**: `/student/excuses` — список своих тикетов, кнопка «Подать новый», файлы отправляются через Telegram-bot pipeline (не хранятся)

## 9. Known risks

1. **baseHref migration.** Смена `/admin/` → `/` может сломать любые внешние ссылки на админку. Нужен поиск `grep -r "ruttrack.site/admin" .` перед фазой 50.
2. **PWA code duplication.** Веб-кабинет студента в Angular частично повторяет PWA в React. Бизнес-логика одна — валидации check-in, формат статусов, API-контракты. Рекомендую выделить общие типы/константы в `frontends/shared/` (уже есть каталог).
3. **CI image size.** Web-panel с новыми student+headman routes вырастет в размере. v8.0 использует multi-stage Dockerfile — lazy-loaded routes должны отработать как надо.
4. **Tests.** 129 vitest тестов web-panel должны продолжать проходить после реструктуризации. Это критерий успеха Phase 50.
5. **HEADMAN backend authorization.** WPAN-13 был заблокирован v7.0. v9.0 должен либо закрыть этот долг (backend @RequireRole расширение), либо принять ограничение и отложить связанные STORY.
6. **User's "полноценная веб-версия для студента" — это большой скоуп.** Если фазы 51-53 окажутся слишком тяжёлыми, разумно разделить milestone на v9.0 (routing + login + student cabinet) и v9.1 (headman cabinet + PWA headman + landing).
