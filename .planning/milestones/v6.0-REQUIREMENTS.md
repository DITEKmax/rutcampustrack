# v6.0 PWA + Web Push — Requirements Archive

**Defined:** 2026-04-05
**Shipped:** 2026-04-06
**Core Value:** Student mobile client «RutTrack» (PWA) with native push notifications — independent from Telegram, installable, offline-capable

## Requirements (32/32 satisfied)

### PWA Foundation

- [x] **PWA-01**: User can log in with username and password (JWT stored in memory, refresh in httpOnly cookie)
- [x] **PWA-02**: Access token auto-refreshes silently before 15-min expiry
- [x] **PWA-03**: User can log out (clears tokens, invalidates refresh on server)
- [x] **PWA-04**: PWA has manifest.json with name "RutTrack", standalone display, 192/512 icons
- [x] **PWA-05**: Service Worker registers and caches app shell for offline loading
- [x] **PWA-06**: Android users see A2HS prompt after first successful check-in
- [x] **PWA-07**: iOS users see Safari install instructions when not in standalone mode

### Schedule

- [x] **SCHED-01**: User can view today's schedule (lessons with time, subject, room, status)
- [x] **SCHED-02**: User can navigate weekly schedule (swipe/tab between days)
- [x] **SCHED-03**: Schedule is cached offline (stale-while-revalidate, 1hr max stale)

### Check-in

- [x] **CHKIN-01**: User can tap check-in on active lesson card, GPS coords captured and submitted
- [x] **CHKIN-02**: User sees immediate success/failure feedback with reason (not in zone, already marked, no active lesson)
- [x] **CHKIN-03**: Check-in UI updates in real-time via STOMP WebSocket on attendance.marked event

### Web Push Backend

- [x] **PUSH-01**: notification-web generates VAPID key pair and stores persistently
- [x] **PUSH-02**: notification-web exposes POST /api/ws/push/subscribe to store PushSubscription
- [x] **PUSH-03**: notification-web exposes DELETE /api/ws/push/subscribe to unsubscribe
- [x] **PUSH-04**: notification-web sends Web Push for lesson.started events (async, non-blocking)
- [x] **PUSH-05**: notification-web sends Web Push for lesson.cancelled events
- [x] **PUSH-06**: notification-web sends Web Push for homework.published events
- [x] **PUSH-07**: notification-web handles expired/invalid subscriptions (HTTP 410 → delete)

### Web Push Frontend

- [x] **PUSHUI-01**: Service Worker handles push event and shows notification with action buttons
- [x] **PUSHUI-02**: notificationclick opens PWA on relevant screen (check-in for lesson.started, schedule for cancelled)
- [x] **PUSHUI-03**: Push permission requested via soft-ask pattern after demonstrated value (not on first load)
- [x] **PUSHUI-04**: Foreground push suppressed when PWA window is focused (dedup with WebSocket)

### Attendance

- [x] **ATT-01**: User can view attendance stats per subject (percentage, count)
- [x] **ATT-02**: User sees red zone warning when below threshold for a subject
- [x] **ATT-03**: User can view attendance records list with status indicators (with colors)

### Homework

- [x] **HW-01**: User can view homework list for their group
- [x] **HW-02**: User can mark homework as done/undone (personal completion tracker)

### Infrastructure

- [x] **INFRA-01**: API Gateway CORS configured for PWA origin
- [x] **INFRA-02**: API Gateway route for /api/push/** to notification-web
- [x] **INFRA-03**: PWA served via nginx container in docker-compose

## Deferred to v6.1+ (not in scope)

- HEAD-01: Headman can mark attendance for group from PWA
- HEAD-02: Headman can view group attendance summary
- EPUSH-01: User can configure push notification preferences
- EPUSH-02: Push notifications for headman alerts
