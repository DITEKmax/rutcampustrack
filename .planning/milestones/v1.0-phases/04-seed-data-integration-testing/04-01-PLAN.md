**CRITICAL — OTP resend cooldown isolation:** The `otp.resend-cooldown-seconds` is 60 seconds. Multiple OTP test methods calling POST `/auth/otp/request` with the same `telegram_id` will hit the 429 rate limit because cleanup scripts only reset the database, NOT Redis OTP keys. To prevent this:
- Inject `StringRedisTemplate` in a `@BeforeEach` method that cleans up ALL OTP-related Redis keys: `otp:*`, `otp_attempts:*`, `otp_sent:*`.
- Example:
  ```java
  @BeforeEach
  void cleanOtpRedisKeys() {
      Set<String> otpKeys = redisTemplate.keys("otp:*");
      if (otpKeys != null && !otpKeys.isEmpty()) redisTemplate.delete(otpKeys);
      Set<String> attemptKeys = redisTemplate.keys("otp_attempts:*");
      if (attemptKeys != null && !attemptKeys.isEmpty()) redisTemplate.delete(attemptKeys);
      Set<String> sentKeys = redisTemplate.keys("otp_sent:*");
      if (sentKeys != null && !sentKeys.isEmpty()) redisTemplate.delete(sentKeys);
  }
  ```
This ensures each OTP test starts with a clean Redis state — no stale cooldown or attempt counters.
