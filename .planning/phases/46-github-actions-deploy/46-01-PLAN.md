<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GitHub Actions runner -> GHCR | Runner authenticates with GITHUB_TOKEN to push images |
| GitHub Actions runner -> VPS | Runner authenticates via SSH key to execute remote commands |
| VPS -> GHCR | VPS pulls images (auth needed if private packages) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-46-01 | Information Disclosure | SSH private key in workflow logs | mitigate | GitHub Actions masks `secrets.*` in logs automatically; never echo secrets in `run:` steps; use `appleboy/ssh-action@v1` `key:` input (not manual file creation) |
| T-46-02 | Elevation of Privilege | Malicious PR triggering deploy | mitigate | Trigger is `push: branches: [main]` not `pull_request`; deploy only runs after code is merged to main |
| T-46-03 | Tampering | Image replaced between push and pull | accept | Using `:latest` tag is acceptable for single-VPS portfolio project; production would use digest pinning |
| T-46-04 | Information Disclosure | Secrets leaking via script echo | mitigate | SSH script contains only `cd`, `docker compose pull`, `docker compose up` — no echo/print of secrets; GITHUB_TOKEN is not passed to VPS |
| T-46-05 | Spoofing | Man-in-the-middle on SSH connection | accept | appleboy/ssh-action uses `-o StrictHostKeyChecking=no` by default; acceptable for portfolio VPS; production would pin host fingerprint |
| T-46-06 | Information Disclosure | GHCR packages expose source code | accept | Container images are public for portfolio visibility; no secrets are baked into images (secrets come from .env.prod on VPS) |
</threat_model>
