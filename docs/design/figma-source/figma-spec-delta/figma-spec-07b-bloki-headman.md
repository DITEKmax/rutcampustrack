## 1. `block/AppHeader` — вариант роли headman

Каркас тот же, что в 07a. Единственное отличие — **`MainNav` принимает два
независимых набора**: «разделы» (главная · посещаемость · статистика ·
домашнее задание · карта · заявки и тикеты) и «управление» (Группа · Предметы ·
Конструктор расписания · Управление парами).

```
nav-groups = one | two
```

Два набора — **не два уровня одного меню**: страницы рендерятся по-разному
и имеют разный функционал. Заголовок группы обязателен: без подписи «разделы»
и «управление» неразличимы.

### Варианты ширины

| | 1920 | 1440 | 1280 |
|---|---|---|---|
| два набора | в два ряда либо в ряд с разделителем | в два ряда | **оба набора в бургер, заголовки групп сохраняются** |

Заголовки групп в бургере не схлопываются — они и есть то, что различает
наборы.

## 2. ПК-111 — Главная старосты

Самый сложный экран роли. Ключевое свойство: **три независимые привязки к паре
на одном экране**.

| Блок | Привязка |
|---|---|
| `block/LessonCounters` | **текущая идущая** пара |
| `block/ManualAttendance` | пара, выбранная своим пейджером |
| `block/LessonActivityLog` | пара, выбранная **другим** пейджером |

**Каждый блок обязан нести подпись, к какой паре относится.** Без неё экран
врёт при любом листании — на скане счётчик стоит над панелью, из чего читается
«это цифры по паре из панели», что неверно.

### 2.1. `block/LessonCounters`

Два `LessonAttendanceCounter` — «+» и «у» — плюс подпись «Сейчас: <предмет>,
<время>».

Состояние `no-active-lesson` показывается пояснением: **«0 из 25» врёт**,
читается как «никто не отметился».

### 2.2. `block/ManualAttendance`

`ManualAttendancePanel`:

| Часть | Компонент |
|---|---|
| пейджер пар дня | `LessonPager` — только текущий день |
| контекст | `DefinitionList` `variant=inline` |
| блокировка | `LessonBlockToggle` |
| ростер | `LessonAttendanceRoster` `cellMode=edit` `scroll=inner` |

**Внутренний скролл обязателен** — панель не растягивает страницу.

### 2.3. `block/LessonActivityLog`

`LessonPager` (независимый экземпляр) + `DefinitionList` `inline` +
`LessonActivityLog` со своим пейджером и внутренним скроллом.

### 2.4. `block/HomeworkToday`

`HomeworkList` `variant=compact` `scroll=inner` + `AppButton` «Выдать задание»,
раскрывающая `HomeworkComposerForm` на странице.

**Переключателя выполнения здесь нет** — у старосты нет личного состояния
выполнения. Это следствие данных, а не режим компонента.

Отличается от `block/HomeworkDay` (101) отсутствием `DatePager`: контекст
всегда сегодня. Поэтому это **отдельный блок**, а не вариант.

### 2.5. `block/RequestsCounter`

`PendingRequestsCounter`. Блок кликабелен целиком — переход на 119
на нужную вкладку.

### 2.6. Раскладка 111

| | 1920 | 1440 | 1280 |
|---|---|---|---|
| счётчики | ряд из двух плиток | ряд из двух | ряд из двух |
| две панели | **рядом, ядро экрана** | рядом | **вертикально: отметка, затем журнал** |
| дз и заявки | ряд под панелями | ряд | одна колонка |

**Порядок вертикализации задан спекой:** счётчики → ручная отметка → журнал →
дз → заявки. Журнал уходит **под** панель отметки, а не наоборот: отметка —
основное действие.

**Схлопывается первым:** в ростере — колонка источника отметки (в раскрытие
строки или подсказку), в журнале — расстояние гео.

**Нельзя потерять:** независимость двух пейджеров, внутренний скролл обеих
панелей, подпись о привязке к паре.

## 3. ПК-112 — Журнал группы

### 3.1. `block/WeekJournalPanel`

| Часть | Компонент |
|---|---|
| пейджер | `DatePager` `unit=week` `showCurrentReset`, `max` = текущая |
| контекст | `DefinitionList` `inline` — даты недели, № недели, чётность |
| сетка | `AttendanceJournalGrid` `lessonScope=week` `columnLabel=subject-type` `cellMode=edit` |

Открыт по умолчанию.

### 3.2. `block/SubjectJournalPanel`

`SubjectFilter` + `LessonTypePicker` `multiple` `context=filter` (неактивны
до выбора предмета) + `AttendanceJournalGrid` `lessonScope=subject`
`columnLabel=date-type`.

**Появляется после выбора предмета** — до этого блока нет вовсе. Это состояние
`no-context`, а не `empty`.

### 3.3. `block/ExportRow`

`ExportButton` (docx · pdf · png) + `AppButton` «Скачать несколько недель»,
раскрывающая `WeeksExportPanel`. Два экземпляра блока — по одному под каждым
журналом.

### 3.4. Раскладка 112 — и главный конфликт экрана

Спека требует обойтись **без горизонтального скролла на большом экране**,
фиксируя первый столбец только если скролл всё же появился.

**Это требование невыполнимо, и спека сама это признаёт.** При 25–30 студентах
и до 20 пар недели ширина упирается уже в 1920; вторая таблица — семестр
по одному предмету, 30–40 колонок — делает скролл неизбежным.

**Решение спеки библиотеки:** фиксация столбца ФИО — **обязательный механизм
на всех трёх ширинах**, а не запасной вариант. `sticky-first-column=true`
всегда. Тень `shadow/sticky-x` появляется, когда контент под ней уезжает.

| | 1920 | 1440 | 1280 |
|---|---|---|---|
| столбец ФИО | залипший | залипший | залипший |
| колонки пар | сколько влезло, дальше скролл | то же | то же |
| название предмета в шапке | полное | **в подсказку** | в подсказку |
| тип занятия в шапке | есть | есть | **уходит** |
| деление каждые 5 студентов | есть | есть | **уходит** |

**Нельзя потерять:** фиксацию ФИО, двухуровневую шапку, различимость границ
дней, доступность кружков в один клик.

Порядок схлопывания задан спекой и в макете не переставляется.

## 4. ПК-113 — Статистика группы

### 4.1. `block/SemesterTotals`

Три `StatCard` («+», «н», «у») + `DefinitionList` `variant=stack` — разбивка
причин по убыванию частоты.

Вырожденный случай «семестр только начался, значения нулевые» — **валидный
результат**, показывается нулями, а не пустотой и не ошибкой.

Отличается от `block/SemesterSummary` (103) составом: там плитки + рейтинг,
здесь плитки + разбивка причин. **Разные блоки.**

### 4.2. `block/GroupStats` · `block/SubjectStats`

`StatsByStudentTable` (`scope=all` и `scope=subject`) + `ExportButton`.
Во втором — `SubjectFilter` и `LessonTypePicker` над таблицей.

Колонки: `%н` · `%+` · `%у` · `%(+ и у)` и те же в количествах, тикеты на «н»
и на «у», способ получения «+». `TableColumnFilter` — на всех колонках,
у которых бэкенд отдал дескриптор.

### 4.3. `block/TrendPanel` — тот же, что на 101 и 103

`scope=group-two-metric`: две линии — `%+` и `%(+ и у)`, шкала всегда 0–100.
Разрез «неделя по дням» даёт `DatePager`, разрез «по предмету» — `SubjectFilter`.

Третье применение блока подтверждает решение 07a: состав частей один,
различаются данные.

### 4.4. `block/StatsDetail`

`StatsDetailPanel` `variant=region` — встроенная область страницы под таблицей,
**не модалка**. Фокус переводится, но не запирается.

### 4.5. Раскладка 113

**Общий вертикальный скролл страницы** — таблицы не скроллятся внутри себя,
в отличие от панелей 111. Горизонтальный — только если не влезает, и тогда
ФИО и шапка фиксированы.

| | 1920 | 1440 | 1280 |
|---|---|---|---|
| плитки итогов | ряд из четырёх | ряд из четырёх | **2 × 2** |
| колонка «способ получения "+"» | четыре подзначения | **в подсказку или в `StatsDetailPanel`** | там же |
| блоки тикетов | три подзначения каждый | три | **схлопываются вторыми** |

**Нельзя потерять:** пару `%+` и `%(+ и у)` рядом — смысловое ядро экрана;
фиксацию ФИО и шапки; `ChartDataTable`.

## 5. ПК-114 — Домашнее задание старосты

### 5.1. `block/HomeworkModeSwitch`

`HomeworkModeSwitch` — «Добавить · Актуальное · архив».

**По умолчанию не показан ни один режим** — состояние `no-mode`: данных
не запрашивали, а не «пусто». Это прямое решение владельца: «непонятно, зачем
староста пришёл».

### 5.2. `block/HomeworkComposer`

`HomeworkComposerForm`: `SubjectFilter` → `LessonTypePicker` `multiple=false`
`context=form` → `LessonBindingToggle` → `MonthCalendar` → основная ссылка →
описание → «Опубликовать».

Порядок полей из спеки, не переставляется. В календаре подсвечен день
следующей подходящей пары; остальные дни недоступны **с причиной**.

### 5.3. `block/HomeworkScopeList`

`FilterBar` + `HomeworkList` с `HomeworkItem` `variant=full`.

```
scope = current | archive
```

В актуальном действия — Удалить · Редактировать · История изменения;
в архиве — только История изменения.

Отличается от `block/HomeworkScope` (104) осью: там режимы периода
(день/неделя/месяц), здесь режимы содержимого. **Разные блоки.**

### 5.4. Раскладка 114

Экран узкий по природе, до 1280 схлопывается почти без потерь.

| | 1920 | 1440 | 1280 |
|---|---|---|---|
| форма | одна колонка | одна колонка | одна колонка |
| панель фильтров | видима | видима | **в поповер** |
| действия карточки | видимы | видимы | **в `RowActionsMenu`** |

**Нельзя потерять:** видимость пометки привязки к паре (от неё зависит
поведение задания) и различие «актуальное / архив».

## 6. ПК-116 — Группа

### 6.1. `block/GroupMembers`

`GroupMembersTable` + `ExportButton` «скачать» под таблицей справа.

Раскрытие строки — `StatsDetailPanel` `variant=row`, внутри `StatCard` ×7
и `StatsBySubjectTable` с фильтрами в заголовках.

**Ни сортировки, ни фильтров, ни пагинации у самой таблицы** — первое
из трёх исключений Р-16. Порядок всегда алфавитный.

### 6.2. Раскладка 116

| | 1920 | 1440 | 1280 |
|---|---|---|---|
| колонки | семь плюс действия | **«Логин» и «Tr id» сокращаются** | они же |
| «Доп разрешения» и «Блокировка» | видимы | видимы | **видимы, схлопывать нельзя** |
| раскрытие по студенту | внутри таблицы | внутри таблицы | **перестаёт помещаться** |

Без «Доп разрешений» и «Блокировки» экран теряет обе управляющие функции
и превращается в справочник.

Точка, где раскрытие перестаёт помещаться, — та же, где в мобильной версии
детализация станет отдельным экраном. На десктопе она остаётся раскрытием.

## 7. ПК-116.1 — Предметы

### 7.1. `block/SubjectsList`

`AppButton` «Добавить предмет» + `SubjectLessonTypeTable`.

Единица инстанцирования — `SubjectRowGroup` (проход 03c): предмет объединяет
свои типы занятий вертикальной склейкой.

### 7.2. `block/SubjectEditor`

`SubjectForm`, свёрнута по умолчанию, раскрывается по «Добавить предмет»
или «Редактировать» из меню строки. **На странице, не модалкой.**

Внутри — `SubjectNameField` (комбобокс), `LessonTypePicker` `multiple`
`context=form`, и **`fieldset` с `TeacherPicker` на каждый выбранный тип**.

### 7.3. Раскладка 116.1

| | 1920 | 1440 | 1280 |
|---|---|---|---|
| колонки | пять плюс действия, запас есть | то же | **«Количество пар» уходит подписью под типом занятия** |
| «Тип» и «Преподаватель» | видимы | видимы | **видимы, схлопываются последними** |

## 8. ПК-117 — Конструктор расписания

### 8.1. `block/ScheduleBuilder`

`ScheduleBuilderGrid` — 8 строк × 6 дней, без дат. Ячейка `ScheduleSlotCell`
`full` либо `split`; в пустой ячейке или половине — «+».

### 8.2. `block/SlotEditor`

`ScheduleSlotForm` под сеткой, свёрнута по умолчанию. Порядок: чётность →
предмет → тип занятия → аудитория; `TeacherReadout` только на чтение.

**Обе кнопки — «Сохранить» и «Удалить пару» — видны постоянно.**

### 8.3. Раскладка 117 — конфликт фиксированной ячейки

Требование «размер ячейки не меняется» конфликтует с сужением.

**Решение спеки библиотеки:** ячейка сохраняет `size/schedule-cell`,
сетка получает горизонтальный скролл с залипшим первым столбцом. Уменьшать
ячейку нельзя — название предмета перестанет читаться, а сокращение в ней
уже заложено.

| | 1920 | 1440 | 1280 |
|---|---|---|---|
| сетка | помещается свободно | помещается | **горизонтальный скролл, столбец «№ / Время» залипший** |
| форма | одна колонка | одна колонка | одна колонка |

**Нельзя потерять:** деление ячейки по чётности (без него расписание врёт)
и тип занятия (без него слот неотличим от другого слота того же предмета).

## 9. ПК-118 — Управление парами

### 9.1. `block/WeekContextPager`

`DatePager` `unit=week` `showCurrentReset` + `DefinitionList` `inline` —
дата, чётность, № недели по порядку.

**Листается и в будущее:** границы — семестр, а не «сегодня». Этим отличается
от пейджера 112.

### 9.2. `block/LessonManagement`

`LessonManagementGrid` — датированная неделя. Ячейка `LessonManagementCell`.
Раскрытие — `LessonActionsPanel` либо `OneOffLessonForm` отдельной строкой,
**сдвигая сетку вниз**.

Два взаимоисключающих режима раскрытия: у существующей пары — панель действий,
у пустой ячейки — форма добавления.

### 9.3. Раскладка 118

| | 1920 | 1440 | 1280 |
|---|---|---|---|
| сетка | свободно | свободно | скролл, столбец времени залипший |
| аудитория в ячейке | видна | видна | **в `Tooltip`** |
| предмет и тип занятия | видны | видны | **видны, схлопываются последними** |
| дата в шапке | видна | видна | **видна, терять нельзя** |

**Дата в шапке столбцов обязательна** — неделя здесь конкретная, без даты
сетка врёт. Этим 118 отличается от 117, где дат нет по определению.

⚠️ Спека предупреждает: на узком экране раскрытая панель займёт почти всё поле
зрения, и контекст сетки — ради которого модалка и была отвергнута — потеряется.
На десктопных ширинах это ещё работает; записано как точка, где мобильная
версия потребует другого паттерна.

## 10. ПК-119 — Заявки и тикеты старосты

### 10.1. `block/TicketQueue`

`Tabs` «Активные · Архив» + `FilterBar` (**только в архиве**) +
список `TicketCard` `variant=incoming` + `Pagination` `mode=show-more`.

Карточка несёт: тип тикета текстом, ФИО, `ExcuseReasonPopover`, период покрытия,
количество пар, **предупреждение «N из M пар уже отмечены»**, раскрываемый
список пар, `AttachmentList`, две кнопки решения и `TicketRejectForm`
по «отклонить».

В архиве вместо кнопок — статус решения и дата решения.

**При исчезновении карточки из очереди фокус переводится на следующую**,
а не теряется в конец документа: разбор очереди с клавиатуры — основной
сценарий экрана.

### 10.2. Раскладка 119

| | 1920 | 1440 | 1280 |
|---|---|---|---|
| строка «ФИО · причина · период · количество» | одна строка | одна строка | **две строки** |
| действия | справа в строке | справа | **под содержимым** |
| список пар | вертикальный, не страдает | то же | то же |

**Нельзя потерять:** тип тикета текстом, ФИО, период покрытия, количество пар
и предупреждение об уже отмеченных парах — по ним староста принимает решение,
не раскрывая состав.

разная даже там, где название региона совпадает.

## 13. Что осталось открытым

1. **Требование «без горизонтального скролла» на 112 невыполнимо** — §3.4.
   Решение спеки: залипший столбец включён всегда. Это расхождение с заметкой 5
   макета 112, и оно названо.
2. **Фиксированная ячейка 117 против сужения** — §8.3. Выбран скролл,
   а не уменьшение ячейки.
3. **Раскрытие по студенту на 116 при 1280** — спека говорит «перестаёт
   помещаться», не говоря, что делать. Оставил раскрытием: альтернатива —
   отдельный экран, а это уже не адаптив, а другой сценарий.
4. **Порядок нескольких пар внутри ячейки 118** — нужен детерминированный,
   в спеке помечен как открытый. На раскладку не влияет, на анатомию ячейки
   влияет (проход 03c).
5. **Правка данных студента на 116** — право не подтверждено, `PUT` помечен
   ADMIN. Блок нарисуется, действие может быть отклонено сервером.
