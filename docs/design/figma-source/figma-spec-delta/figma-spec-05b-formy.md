# figma-spec-05b-формы.md

> Проход 05b спецификации компонентов RutCampusTrack.
> Основания — `figma-spec-00-основания.md`, контролы форм —
> `figma-spec-01-действия-и-формы.md`. Значения — `brandbook-v2.md`
> и `tokens-v2.json`. Состав — `COMPONENT_REGISTRY.md` v1.0.

**В этом проходе:** все формы продукта, доменные поля, панели настроек
и оставшиеся сквозные компоненты (`ExportButton`, `DestructiveActionPair`,
`FormError`, `LiveNotificationRegion`).

---

## 1. Общее для всех форм

### 1.1. Раскладка

**Формы раскрываются на самой странице, не поверх неё.** Единственная модалка
продукта — `ConfirmDialog`. У формы, вызываемой действием, обязательны:
`aria-expanded` на кнопке, перевод фокуса в первое поле при раскрытии,
возврат фокуса на кнопку при сворачивании.

| Правило | Источник |
|---|---|
| подпись над полем — для ввода со свободными значениями | мудборд |
| две колонки «подпись слева, значение справа» — для чтения | мудборд |
| ширина поля = ожидаемая длина значения | мудборд |
| рамка только у поля свободного текста | мудборд |
| обязательность символом, не цветом | мудборд |
| ограничение формата сказано **до** ошибки | мудборд |
| разный вес отмены и подтверждения | мудборд |

Auto Layout вертикальный, gap `space/4` между полями, `space/6` перед
блоком действий. Ширина `fill`, высота `hug`.

### 1.2. Оси, общие для форм

```
state = default | busy | error
```
плюс boolean `has-cancel`.

`hover`, `pressed`, `focused` формам не принадлежат — они у контролов внутри.

**`error` формы** — это `FormError` над блоком действий, а не подсветка полей.
Ошибка отдельного поля живёт в `FormField`.

### 1.3. Блок действий

Горизонтальный, выравнивание вправо, gap `space/3`.
Подтверждение — `AppButton` `primary` (или `danger`), отмена — `ghost`.

**Обе кнопки видны постоянно** там, где реестр требует прямо (`ScheduleSlotForm`).
Обратимое и необратимое действия показываются рядом, а не вместо друг друга.

## 2. Формы входа и восстановления

### 2.1. `auth/LoginPasswordForm` — 001

Логин + `PasswordField` + «Войти». Ошибка — `FormError`, фокус на сообщение.

### 2.2. `auth/OtpForm` — 001

Код из бота + `CountdownTimer` + «Войти». **Выдаёт сессию.**
Состояние `expired` — «Запросить новый код», не пустая форма.

### 2.3. `auth/RecoveryCodeForm` — 001a

**Не синоним `OtpForm`**: другой контракт — выдаёт право сменить пароль,
а не сессию. Внешне похожи, но контракт разный, поэтому компоненты разные.

### 2.4. `auth/RecoveryInstructions` — 001a

Не форма — текстовый блок: как получить код или ссылку в боте.
Fallback зависит от роли. **Администратору ничего не обещать:** сброс пароля
администратора — эксплуатационная процедура вне продукта.

### 2.5. `auth/QrLoginPanel` — 001

QR + статус подтверждения из мобильного клиента для **неавторизованного** гостя.
Рендер кода делегирован `QrCodeDisplay`.

```
state = waiting | confirmed | expired | error
```

### 2.6. `auth/NewPasswordForm` — 001b, 108

```
variant = reset | change
```

| | `reset` (001b) | `change` (108) |
|---|---|---|
| старый пароль | не спрашивается | **обязателен** |
| ссылка «Не помню пароль» | нет | есть, ведёт на 001a |

`PasswordPolicyHint` виден **до** ввода. Ошибка «старый пароль неверен»
ставится **на поле**, не общим `FormError`.

Смена пароля гасит все сессии — подтверждается через `ConfirmDialog`.

### 2.7. `shared/QrCodeDisplay`

Рендер QR + **обязательная текстовая альтернатива кодом**. Домена не знает.

## 3. Формы тикетов

### 3.1. `attendance/TicketForm` — 107

```
variant = excused | absent
```

| Поле | `excused` | `absent` |
|---|---|---|
| `DateRangePicker` | есть | есть |
| `LessonPicker` | есть | есть |
| причина (`SelectField`) | есть | нет |
| комментарий | есть, **обязателен при типе «прочее»** | нет |
| `FileUploadField` | есть | нет |

Раскрывается на странице: `aria-expanded` на кнопке подачи, фокус в первое поле.

Отправка «н» необратима → `ConfirmDialog` перед отправкой.

Состояние `blocked`: лимит попыток семестра исчерпан — кнопка подачи
недоступна **с пояснением**; снимает староста.

### 3.2. `attendance/TicketRejectForm` — 119

Обязательная причина отклонения, раскрывается **внутри карточки**, не модалкой.

Текст формы поясняет, что **отклонение не окончательно**: пары освободятся
для повторной подачи. Это не подсказка, а часть содержания — реестр требует
прямо.

## 4. Формы дз

### 4.1. `homework/HomeworkComposerForm` — 111, 114

Форма публикации **и редактирования**. **Одна и та же форма на обоих экранах** —
на 111 раскрывается снизу страницы, не модалкой.

| Поле | Контрол |
|---|---|
| предмет | `SubjectFilter` `context=form` |
| тип занятия | `LessonTypePicker` |
| привязка к паре | `LessonBindingToggle` |
| дата | `MonthCalendar` в `Popover` |
| основная ссылка | `TextInput` |
| описание | текстовая область |

Порядок полей — из реестра, не переставляется.

**«Перенести» объединено с «Редактировать»:** дата и привязка меняются внутри
этой формы. Отдельной кнопки переноса нет.

### 4.2. `homework/LessonBindingToggle`

`role="switch"`: «привязано к паре» / «любой день». Определяет, поедет ли
задание при переносе пары и по какому правилу уйдёт в архив.

**Переключение обязательно объявляется** — оно молча меняет содержимое
календаря. В библиотеке это значит: рядом с тумблером есть область под
объявление, а не только сам тумблер.

Режим привязки оставляет доступным только день следующей подходящей пары;
остальные дни календаря `disabled` **с причиной**.

## 5. Формы расписания

### 5.1. `schedule/ScheduleSlotForm` — 117

Порядок шагов: **чётность → предмет → тип занятия → аудитория.**

| Поле | Контрол |
|---|---|
| чётность | `WeekParityPicker` |
| предмет | `SubjectFilter` `context=form` |
| тип занятия | `LessonTypePicker` |
| преподаватель | `TeacherReadout` — **только чтение** |
| аудитория | `TextInput` |

**Обе кнопки — «Сохранить» и «Удалить пару» — видны постоянно.**

Состояние `no-subjects`: предметы группы не заведены — пояснение и переход
на 116.1, а не пустой список.

### 5.2. `academic/TeacherReadout`

Преподаватель, следующий из пары «предмет × тип занятия».
**Только чтение, текстом**, не `disabled`-полем: заблокированный инпут обещает
редактирование, которого нет.

Состояние `not-assigned`: «преподаватель не назначен» с переходом на 116.1.

### 5.3. `headman/LessonActionsPanel` — 118

Контейнер действий над выбранной парой. Раскрывается **под строкой** отдельной
строкой сетки, сдвигая её вниз: модалка скрыла бы картину.

**Состав зависит от статуса пары.** В библиотеке — слот `actions` и boolean
на каждое действие; перечень сочетаний принадлежит спеке 118.

### 5.4. `headman/LessonCancelForm` · `LessonPatchForm` · `OneOffLessonForm` — 118

| Форма | Поля | Особенность |
|---|---|---|
| `LessonCancelForm` | контекст пары + **обязательная причина** | отмена стирает данные → `ConfirmDialog` с числами |
| `LessonPatchForm` | прежде всего аудитория | точечная правка на конкретную дату |
| `OneOffLessonForm` | предмет, тип занятия, аудитория, необязательная причина | **выбора недели нет** — дата задана ячейкой |

`LessonCancelForm` — кандидат в `domain`: понадобится admin.

## 6. Формы предметов — 116.1

### 6.1. `academic/SubjectForm`

Одна форма на создание и редактирование. **Правится весь предмет**, режима
«править один тип занятия» не существует.

Порядок: **название → типы занятий → преподаватели по каждому типу.**

```
variant = create | edit
```

Внутри — повторяющийся блок «тип занятия + `TeacherPicker`». Блок добавляется
и удаляется; `TeacherPicker` — **отдельный экземпляр на каждый тип занятия**.

Удаление предмета требует `DangerousActionChallenge` `level=password-otp`.

### 6.2. `academic/SubjectNameField`

**Комбобокс со свободным вводом и подсказкой** по уже заведённым названиям.
Подсказка защищает от разнописи, но **ключом не является** — все связи по id.

Не путать с `SubjectFilter`: там выбор из перечня, здесь свободный ввод.

### 6.3. `academic/TeacherPicker`

Поиск по **ФИО или табельному номеру** с подсказкой по вводу, множественный
выбор, удаление выбранного.

Выбранные — чипы с крестиком, приём мудборда. Чип: `radius/full`, `micro`,
`color/surface/float`, кнопка удаления `icon/size/sm`.

## 7. Формы администратора

### 7.1. `academic/UserCreateForm` — 132

```
variant = create | add-role
```

**Состав полей определяется выбранной ролью** — три ветки: админ, преподаватель,
студент. В варианте `add-role` показываются **только незаполненные поля**.

**Логина и пароля в форме нет** — логин генерируется из данных человека.

Состояние `role-not-chosen`: роль не выбрана — **полей нет, их состав
неизвестен**. Это не `empty`, а «ещё не спросили».

Состояние `no-groups`: создание студента при пустом реестре групп — пояснение
и переход на 133, **а не пустой выпадающий список**.

Поимённый состав полей каждой ветки — спека 132, см. §12.

### 7.2. `academic/StudentTransferForm` — 132

Целевая группа + **обязательная причина** + **предпросмотр последствий
числами**. Раскрывается inline.

Предпросмотр обязателен: действие, уничтожающее или переносящее данные,
называет объём последствий до подтверждения.

### 7.3. `academic/GroupCreateForm` — 133

```
variant = create | edit
```

Буквенный код, цифровой код, срок обучения в годах, староста.

**В момент создания староста не задаётся** — студентов в новой группе ещё нет,
группа уходит в черновики. В варианте `create` поле старосты не рендерится
вовсе, а не стоит пустым.

### 7.4. `academic/HeadmanAssignPanel` — 133

Состав группы с выбором **одного** старосты.

**`radiogroup`, а не чекбоксы**: староста один, чекбокс обещает множественный
выбор, которого нет. Это осознанное расхождение со сканом, зафиксированное
реестром.

Показывает текущего старосту. Состояние `no-students`: «назначать некого» +
переход на 132 — штатный случай для только что созданной группы.

### 7.5. `academic/GroupPromotionPanel` — 133

Массовый перевод на следующий курс: **dry-run → предпросмотр с числами →
подтверждение.** Раскрывается на странице; модалкой служит только финальный
`ConfirmDialog`.

Состояния: `already-promoted` — группа уже переведена в текущем цикле,
пояснение вместо второго перевода; `partial-success` — операция не атомарна,
показываем **поимённо**, что прошло и что нет.

Без `already-promoted` курс уедет на два — порча данных всего вуза.

### 7.6. `academic/SemesterForm` · `SemesterNameField` — 134

```
variant = create | edit
```

Тип и год + даты начала и конца. **Архивный семестр не редактируется** —
пункт меню `disabled` с причиной.

`SemesterNameField` — составное значение: **тип из ровно двух значений**
(`radiogroup`) + год. Год подставляется автоматически, но **обязан быть виден
и редактируем**: осенний семестр, заводимый в январе, иначе получит неверный год.

### 7.7. `map/FloorPlanUploadForm` — 135

```
variant = create | replace
```

Корпус (число), этаж (число), **два независимых `FileUploadField`** (png и svg)
с разными `accept`, «Сохранить».

**Загрузка файлов может продолжаться после сохранения записи** — это нормальный
путь, а не ошибка. В библиотеке это значит: форма имеет состояние, где запись
сохранена, а один или оба загрузчика ещё в `uploading` или `processing`.

### 7.8. `headman/StudentProfileEditForm` — 116

Правка данных студента, раскрывается inline.

**Состав полей и само право не подтверждены реестром** — см. §12.

## 8. Панели настроек — 108

### 8.1. `settings/DeviceLinkQr`

QR привязки мобильного клиента из **авторизованной** сессии: `QrCodeDisplay` +
`CountdownTimer` + обновление + статус «устройство привязано».

**Не синоним `QrLoginPanel`**: тот выпускает сессию неавторизованному гостю,
этот передаёт доступ на второе устройство.

### 8.2. `settings/AccountHistoryList`

Лог событий аккаунта: тип, дата, человекочитаемое описание. Листание, фильтр
по типу. **Строки не кликабельны** → `hover` не положен.

### 8.3. `settings/ActiveSessionsList`

Текущие входы: устройство, место, время последней активности, пометка
«это устройство» **текстом**. Только чтение.

### 8.4. `auth/RecoveryLinkPanel`

Результат действия «сгенерировать ссылку для сброса»: ссылка, срок жизни,
копирование. Раскрывается на странице.

**Не синоним `RecoveryInstructions`**: там инструкция пользователю о себе,
здесь результат действия над другим человеком.

## 9. Сквозные, оставшиеся с прошлых проходов

### 9.1. `shared/ExportButton`

Выгрузка текущего разреза **со всеми активными фильтрами**. Перечень форматов
приходит пропом как данные — фронт его не зашивает.

**Выгрузка асинхронная.** Состояния: `idle` · `queued` · `preparing` ·
`ready` · `error`.

```
state = idle | queued | preparing | ready | error
```

`ready` — файл отдаётся ссылкой. **Скачивание готового ассета — это `AppLink`
`download`, не кнопка**; `ExportButton` для этого не используется.

Перечень форматов зависит от разреза: таблицы — все пять, **график только
png и html**. В библиотеке — boolean `chart-scope`, сужающий список.

Отрисовка набором кнопок или одной кнопкой с выбором — решается в макете;
компонент допускает оба.

### 9.2. `shared/DestructiveActionPair`

«Архивировать» + «Удалить», показываемые **рядом всегда**: обратимое действие
не подменяется финальным.

Два `AppButton` в горизонтальном Auto Layout, gap `space/3`.
Первая — `secondary`, вторая — `danger`.

**Доступные имена различаются настолько, чтобы их нельзя было спутать на слух.**
`delete-disabled-hint` — причина, по которой удаление недоступно, показывается
до нажатия.

### 9.3. `shared/FormError`

Ошибка отправки формы: `title` + `detail`, фокус на сообщение.

Поверхность `color/state/danger/bg`, граница `color/state/danger/border`,
текст `color/state/danger/text`, радиус `radius/md`, padding `space/3`.

**Ошибка — состояние объекта, а не сообщение об инциденте, и единственное,
что не исчезает само.** В интерфейсе, где всё обновляется, самоисчезающая
ошибка неотличима от очередного обновления.

### 9.4. `shared/LiveNotificationRegion`

**В реестре помечен как неразобранный кандидат.** Правила накопления, TTL
и группировки не определены.

Место в `AppShell` зарезервировано. Анатомия не описывается — см. §12.

## 10. Переполнение — общее по проходу

| Случай | Поведение |
|---|---|
| длинное название предмета в комбобоксе | обрезка в закрытом виде, полное в списке |
| много выбранных преподавателей | чипы переносятся на вторую строку, поле растёт вниз |
| длинная причина отклонения | текстовая область растёт до 6 строк, дальше внутренний скролл |
| длинное имя файла | обрезка **в середине**, расширение видимо |
| предпросмотр последствий с числами | не обрезается никогда |

2. **Состав `StudentProfileEditForm`** — реестр помечает прямо: состав полей

   спека 118 (уже отмечено в проходе 03c).
4. **`LiveNotificationRegion`** — неразобранный кандидат реестра.

## 13. Что осталось открытым

1. **Максимальная высота текстовых областей** (6 строк до внутреннего скролла) —
   решение спеки, не реестра.
2. **`ExportButton` одной кнопкой или набором** — реестр оставляет решение
   дизайну. Компонент допускает оба; выбор делается при сборке блоков,
   проход 07.
3. **`LessonCancelForm` как кандидат в `domain`** — повышение произойдёт, когда
   отмена пары появится у admin. На анатомию не влияет, влияет на имя
   в библиотеке.
