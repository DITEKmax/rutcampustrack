**Step 2: Create `services/api-gateway/Dockerfile`** — Pattern A (simple, no proto, no api-contract):
```dockerfile
# Stage 1: Build
FROM eclipse-temurin:21-jdk-alpine AS builder
WORKDIR /workspace

COPY gradlew .
COPY gradle gradle
COPY build.gradle.kts .
COPY settings.gradle.kts .

COPY services/api-gateway/build.gradle.kts services/api-gateway/
COPY services/api-gateway/src services/api-gateway/src

RUN chmod +x gradlew && ./gradlew :services:api-gateway:bootJar --no-daemon -x test

# Stage 2: Extract layers
FROM eclipse-temurin:21-jre-alpine AS extractor
WORKDIR /app
COPY --from=builder /workspace/services/api-gateway/build/libs/*.jar app.jar
RUN java -Djarmode=layertools -jar app.jar extract

# Stage 3: Runtime
FROM eclipse-temurin:21-jre-alpine
RUN addgroup -S app && adduser -S app -G app
WORKDIR /app

COPY --from=extractor /app/dependencies/ ./
COPY --from=extractor /app/spring-boot-loader/ ./
COPY --from=extractor /app/snapshot-dependencies/ ./
COPY --from=extractor /app/application/ ./

USER app
EXPOSE 8080
ENTRYPOINT ["java", "org.springframework.boot.loader.launch.JarLauncher"]
```

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Build stage → Runtime stage | JDK, Gradle, source code must NOT leak into runtime image |
| Host → Container | Container must not run as root |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-42-01 | Elevation of Privilege | Java runtime containers | mitigate | `RUN addgroup -S app && adduser -S app -G app` + `USER app` in every Dockerfile runtime stage |
| T-42-02 | Information Disclosure | Docker build context | mitigate | Root `.dockerignore` excludes `.env`, `*.key`, `*.pem`, `.git/`, `.planning/` |
| T-42-03 | Tampering | Runtime image attack surface | mitigate | Multi-stage build: JDK, Gradle, source code only in builder stage — runtime has JRE only |
</threat_model>
