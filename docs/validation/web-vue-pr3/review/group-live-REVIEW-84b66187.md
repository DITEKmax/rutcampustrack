## F1 — P2: transient projection error теряет pending/unknown export owner

**Путь:** `frontends/mobile-core/src/features/teacher/TeacherStatsScreen.vue:338–418,737–749`; unchanged dependency `shared/components/ExportButton.vue:45–58,104–139`; `shared/report-download-client.ts:434–478`.

Новый `useProjectionRefresh(refreshProjection)` запускает catalog/stats reads на realtime hint. При temporary503/network failure `refreshProjection` или `loadStatsForRevision` устанавливает общий `error`. При этом `ExportButton` получает `:disabled="loading || !!error"`. Его существующий синхронный watcher на disabled вызывает `invalidate()`: увеличивает revision, закрывает controls, обнуляет busy/state/status. Callback уже отправленного download становится не-current, хотя Auth identity, selected query и его group не менялись.

**Конкретный причинный сценарий:** Teacher с двумя группами смотрит statistics сохранённой группы и уже отправил report job; удаляется другая его группа, приходит hidden hint. Background catalog либо stats read временно503. Общий error переключает disabled и отменяет owner первого export. Его поздний accepted/ready ответ теперь отвергается как stale. `TEACHER_STATS` не относится к recoverable weekly/admin reports в `ReportDownloadClient`: первоначальный requestId не сохраняется для следующего вызова. После восстановления read повторный пользовательский download может создать новый job вместо продолжения уже принятого/неизвестного. Это новый unprompted invalidation от live hint, не разрешённая смена business context или authority.

Journal path отдельно блокирует projection refresh на exportLoading; Stats такого guard или отделения presentation error от active export ownership не имеет. Сохранение `statsQuery` на successful refresh защищает лишь success path, не этот failure path.

**Минимальное исправление:** сохранить callback/identity/status текущего statistics export при background read failure и unchanged scope; отдельно показывать read error и блокировать новые действия при необходимости. Authoritative удаление выбранного scope и реальная authority replacement должны по-прежнему retire недопустимое представление. Не добавлять новый export protocol/credential retry и не сохранять старый private scope ради pending export. Достаточная regression qualification — адресный mounted existing Stats/ExportButton flow с удержанным download, одним live invalidation и неудачным read; реальных security writes или новой общей кампании для этого не нужно.
