# Figma, шаг 3 — компоненты

Начинается после того, как шаг 2 принят и библиотека опубликована.

Работать в файле библиотеки `ui-kit-rct`. Файл экранов `rct-design` не трогать.

## Откуда берётся состав

| Источник | Что там | Как читать |
|---|---|---|
| `design/figma-spec.md`, части 1–9 | анатомия компонентов: слои, размеры, отступы, поведение | по одной части за партию, по оглавлению |
| `design/figma-spec.md`, часть 10 | состояния: загрузка, пусто, пусто после фильтра, ошибка, нет доступа | один раз перед первой партией |
| `design/COMPONENT_REGISTRY.md` | имена, владение, состав пропов, что отменено | точечно по имени компонента |
| `design/brandbook-v2.md` | §8 состояния, §5 кольцо фокуса, §9 носители смысла | при сборке состояний |
| `design/BRAND_DIRECTION.md` | запреты: наложения, движение, носители смысла | при сомнении |
| `design/A11Y_REQUIREMENTS.md` | фокус, клавиатура, контраст | при сборке интерактивных компонентов |

**`figma-spec-shadcn-overlay.md` на этом шаге не применяется.** Он описывает, какие контролы не пишутся руками в коде, а берутся из библиотеки. Кода сейчас нет, макеты собираются целиком — значит в Figma собираются **все** компоненты, включая те, что позже уйдут shadcn-vue или Reka UI. Не пропускать ничего на основании накладки.

## Порядок партий

Строго по частям `figma-spec.md`, одна часть — одна партия:

1. Основания
2. Действия и формы
3. Каркас и навигация
4. Таблицы — примитивы
5. Журналы и статистика
6. Реестры и сетки расписания
7. Значения и статусы
8. Карточки и панели
9. Формы

Порядок не переставлять: поздние части ссылаются на ранние. Часть 10 (состояния) читается перед первой партией и применяется во всех.

Если часть велика — дробить внутри неё, но не забегать в следующую.

## Правила сборки

**Имена — из реестра посимвольно.** `DetailTrigger`, не `RowDetailTrigger`. Если имя в `figma-spec` и в реестре расходится — прав реестр, расхождение назвать.

**Варианты, а не копии.** Состояния, размеры и режимы компонента — свойства варианта. Девять отдельных компонентов вместо одного с девятью вариантами считаются несделанной работой.

**Ни одного литерала.** Цвет, отступ, радиус, толщина границы, кегль — только через переменные и стили из шага 2. Если нужного токена нет — остановиться и сказать, не подставлять близкий.

**Автолейаут везде, где есть поток.** Компонент, собранный абсолютным позиционированием, развалится при смене длины русского текста. Проверять на длинной строке: фамилия из трёх частей, название дисциплины на 60 знаков.

**Состояния из §8 брендбука полностью.** У каждого интерактивного компонента: default, hover, focus, pressed, disabled, busy — те, что ему положены. Где состояние не положено (например hover на неинтерактивном) — так и записать в описание компонента, не оставлять пустым молча.

**Кольцо фокуса — контур 2px**, акцент «сейчас» — заливка. Перепутать эти два нельзя: это отдельное решение брендбука §5.

**Описание у каждого компонента.** Одна-две строки: что это, где применяется, какие состояния не положены и почему. Описание видно при вставке и экономит потом часы.

## Работа партиями

После каждой партии остановиться и показать:

- список собранных компонентов с именами;
- какие свойства вариантов заведены у каждого;
- что проверено по чек-листу;
- расхождения `figma-spec` ↔ реестр, если были;
- каких токенов не хватило.

Дождаться подтверждения. Следующую часть не начинать.

## Проверка после каждой партии

- [ ] Имена совпадают с реестром посимвольно
- [ ] Состояния собраны вариантами, а не отдельными компонентами
- [ ] Ни одного литерального значения: всё через переменные и стили
- [ ] Автолейаут там, где есть поток; проверено на длинной русской строке
- [ ] Обе темы: переключение режима не ломает композицию
- [ ] У каждого компонента заполнено описание
- [ ] Ни одного отсоединённого экземпляра
- [ ] Новых компонентов сверх реестра не заведено

## Чем закончить весь шаг

- полный список собранных компонентов против реестра: что собрано, что осталось;
- список расхождений `figma-spec` ↔ реестр;
- дополнения в реестр расхождений Figma ↔ код, если появились новые;
- список токенов, которых не хватило.

## Правила работы

Не ссылаться на пункт брендбука, которого нет в файле. Если правила для ситуации нет ни в `figma-spec`, ни в реестре, ни в брендбуке — остановить партию и сказать. Не подставлять умолчание и не выводить его из соседнего компонента.

Refero использовать точечно: когда непонятно, как решают конкретный паттерн. Не тянуть по два десятка экранов за раз. Референс никогда не перебивает брендбук — он показывает, как бывает, а не что делать.
