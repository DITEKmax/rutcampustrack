## Unsatisfied Requirements Detail

### NOTIF-02, NOTIF-03: Reminder Timer TZ Bug (High Severity)

**Root Cause:** `TZ=Europe/Moscow` is missing from the `notification-bot` docker-compose environment block. `ReminderScheduler` uses `datetime.now()` (naive) — in a UTC container, midpoint and near-end delay calculations will be 3 hours off from Moscow lesson times.

**Fix:** Add `TZ: Europe/Moscow` to `docker-compose.yml` notification-bot environment block.

**Code is correct** — all 8 unit tests pass, and the scheduling logic is sound. This is a deployment configuration gap only.

### WS-05, WS-06, NOTIF-08, NOTIF-09: No Event Publisher (Medium Severity)

**Root Cause:** `excuse.requested` and `late_checkin.requested` events are handled by both notification consumers (WebSocket routing and Telegram alerts), but no service in the codebase publishes these events. The excuse ticket and late check-in request workflows are future features (likely Phase 7/8 frontends).

**All receiving-side wiring is correct.** Handlers will work the moment a publisher is added. This is a planned scope boundary, not a defect.

### WS-07: Group Isolation Unverified (Low Severity)

**Root Cause:** Topic naming (`/topic/group/{groupId}`) provides isolation in theory. Unit tests confirm correct destination string construction. Actual broker-level isolation needs live testing with two connected WebSocket clients from different groups. Spring's SimpleBroker should provide correct topic isolation by design.
