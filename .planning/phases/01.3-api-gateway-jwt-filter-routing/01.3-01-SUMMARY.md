# Phase 01.3 Plan 01: API Gateway JWT Filter + Routing Summary

**One-liner:** JWT GlobalFilter with RSA public key caching (3-retry startup + hourly refresh), null-safe header injection, and RFC 7807 401 responses using reactive WebFlux patterns.

## What Was Built

### PublicKeyConfig (new)
- `@Component` that fetches RSA public key from Auth Service on `@PostConstruct`
- WebClient GET to `${gateway.auth-service-url}/auth/public-key` with 3-retry + 5s delay
- `AtomicReference<PublicKey>` for thread-safe caching across scheduled refresh
- `@Scheduled(fixedRate=3_600_000)` for hourly key refresh
- `parsePemPublicKey(String pem)` strips PEM headers and decodes X509EncodedKeySpec
- Graceful failure: logs error, keeps existing cached key (does not crash gateway)

### JwtAuthenticationFilter (new)
- Implements `GlobalFilter, Ordered` at order `-100` (before routing filters)
- Public routes whitelist: `/api/auth/login`, `/api/auth/refresh`, `/api/auth/public-key`, `/api/auth/otp/**`
- Bearer token extraction and validation via JJWT `parseSignedClaims` (not deprecated `parseClaimsJws`)
- Null-safe header injection: `X-Group-Id` and `X-Is-Headman` only injected when JWT claims are non-null
- RFC 7807 Problem Details JSON body on 401: `{"status":401,"title":"Unauthorized","detail":"..."}` with `application/problem+json` content type
- No `jakarta.servlet` imports — pure reactive WebFlux/Reactor implementation

### GatewayApplication (modified)
- Added `@EnableScheduling` to activate `@Scheduled` processing

### application.yml (modified)
- Added `gateway.auth-service-url: ${AUTH_SERVICE_URL:http://auth-service:9090}` property
- Added `ru.rutcampustrack: DEBUG` under `logging.level`
- Route configuration unchanged (FR-8 was already satisfied)
