# Request draft publication correction

- **Scope:** `StudentFeatureOwner.vue` request-draft publication and its existing lifecycle test only. Base: `f72e8d2d8f249673dfbde6272a5669dced14ea6e`.
- **Observed failure:** PWA flow `Ещё → Заявки → Подать → Уважительная причина`, then choose `icon-192.png`. The owner displayed «Добавлено файлов: 1», while selected-file rows/previews were absent. Runtime failed with the attachment-preview sentinel; cleanup passed (14/14, zero containers/errors). Screenshot: [preview-runtime-missing-file-f72e8d2d.png](preview-runtime-missing-file-f72e8d2d.png).
- **Root cause:** `requestDraft` was computed from `getOrCreateRequestsDraft`, which reads a plain `Map`. `updateRequestDraft` mutated that map but did not publish its returned clone, so Vue kept rendering the cached empty draft.
- **Acceptance criteria:** selected file, lesson ids and reason appear immediately; edits remain current after leaving and reopening the form; deletion remains empty after reopening; reselecting publishes the new file; scope purge and owner unmount clear the local published reference.
- **Correction:** keep the current cloned draft in an owner-local `shallowRef`; publish `updateRequestsDraft` results; reload it after scope changes/purges and clear it on unmount. Added one existing-renderer owner regression covering file/pairs/reason, navigation, delete, and reselect.
