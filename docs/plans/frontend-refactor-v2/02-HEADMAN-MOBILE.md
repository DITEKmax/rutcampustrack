## Первый пакет

Эталон открыт во внутреннем браузере. H01 подтверждает карточку и быстрый состав после выбора даты. H02 отменяет подтверждение и открывает его повторно, в эталоне одно действие. H03 снимает «+» и ставит «н» без меню. H04 показывает ошибку без причины, затем принимает «Болезнь» и обновляет отметку.

Используются существующие API чтения состава, постановки и снятия отметки с ожидаемым статусом и ревизией, блокировки и снятия блокировки геоотметок. ACK постановки содержит статус, ID пары и студента и время. Ревизия для следующей записи приходит при чтении состава. Удержание подтверждённого состояния после ошибки чтения и безопасный GET-only повтор проверяются отдельно.

Начальные состояния всех 30 сцен открылись в обоих фреймах. Пояснения сохранены в `.agent/evidence/headman-mobile-v2/reference-scenes.json`.

В исходной версии подтверждённый `PUT` с последующим `GET 503` показывал старую отметку. Теперь строка сохраняет подтверждённый статус, а кнопка обновления повторяет чтение. В PWA при ширине 390 CSS px проверены даты 4 → 5 → 4 ноября, соответствие состава выбранной паре и `PUT → GET 503 → GET`. После повтора осталась одна запись, статус строки сохранился.

В TMA при 390 CSS px проверены отмена геоблокировки без запроса, восстановление фокуса, одна команда при подтверждении и снятие блокировки. Форма «у» связала ошибку с полем и отправила ноль команд без причины. После выбора «Болезнь» отправлена одна запись. Переход в «Учёт» сохранил выбранную пару. Повторный выбор выставленной «у» снял отметку одним запросом.

Ревью нашло конфликт двух сессий. После `409 → 503` форма предлагает только GET. После успешного чтения отдельно показаны актуальный статус, причина и комментарий. Черновик сохраняется, следующая запись требует подтвердить просмотр и снова нажать «Сохранить». Проверено в PWA, счётчики `записи/чтения` прошли `1/2 → 1/3 → 1/3 → 2/4`. Адреса сценариев `http://127.0.0.1:14272/viewport?width=390&headman=marks&afterMark=fail-read` и `http://127.0.0.1:14272/viewport?width=390&headman=marks&afterMark=conflict-fail-read`. Для TMA порт 14273.

42 адресных теста, 4 повторных проверки после финальной правки текста, строгие проверки типов PWA и TMA и независимое повторное ревью прошли. Тест на одновременную геоблокировку проверяет, что обновление карточки той же пары сохраняет ожидающую ручную запись. Сборки PWA и TMA прошли. JSON, снимки и логи находятся в `.agent/evidence/headman-mobile-v2`. Браузер использовал настоящие Vue-оболочки и локальный транспорт, проверка Telegram на телефоне остаётся для стенда.

## Заявки H06–H08 и H22

Для следующего пакета по заявкам подтверждён эталон H08. Кнопка исключения называет дату и время, последнюю оставшуюся пару исключить нельзя, при частичном одобрении исходный период остаётся видимым. После подтверждения показаны уведомление и отдельные исключённые пары. Количество пар в демо отличается от формулировки QA, поэтому в этой сцене проверялось исключение одной из двух доступных пар.

В H06 из группы с несколькими заявками открыт «Медосмотр», видны исходный период и текущие пары. В H22 после закрытия уведомления остались блоки «До» и «После» с двумя исключёнными парами. Фильтр по типу в сцене H07 возвращает HTML из архива в открытую очередь. Требование H07 явно оставляет фильтрацию внутри архива, его и используем для поведения продукта. Снимки состояний в `.agent/evidence/headman-mobile-v2/headman-requests-reference.json`.

В исходной PWA заявка на четыре пары отображается четырьмя карточками. До первого открытия списка деталей загружаются шесть заявок, верхний фильтр переводит из архива в очередь. Состояние сохранено в `.agent/evidence/headman-mobile-v2/headman-requests-vue-baseline.json`.

API возвращает исходные сведения о парах и сохранённые отметки после решения. Отметки в исходных строках читаются из текущего журнала и могут отличаться от состояния перед решением. В транзакционную квитанцию добавляется `beforeLessons` по проверенным ID занятий. Архивные решения без снимка сохраняют исходные сведения и доступный результат. Локальные адреса заявок `http://127.0.0.1:14272/viewport?width=390&headman=requests` и `http://127.0.0.1:14273/viewport?width=390&headman=requests&decision=lost-ack`.

В PWA проверены одна карточка на заявку, ноль GET деталей до открытия, дата и время в действиях исключения, запрет исключить все пары, подтверждение одним POST, закрытие уведомления и повторное открытие сохранённого сравнения из архива. Фильтры обоих типов остаются в архиве, статусы «Одобрена» и «Отклонена» видны. В TMA ответ 503 после записи вызвал предупреждение. Повтор прочитал сохранённую квитанцию, число POST осталось 1. Возврат в очередь прошёл через локальный Telegram Back.

Клиент прошёл 39 адресных тестов, строгие проверки типов PWA/TMA, ESLint и обе сборки. Серверные тесты событий, сокращения покрытия и чтения архива прошли. Первый Mongo IT пропущен Testcontainers, поскольку Docker Desktop не поднял Linux-движок. В Ubuntu WSL тест выполнен на MongoDB 7. Он проверил, что потеря ответа не дублирует решение, снимок сохраняется, выбранные пары получают подтверждённый результат, исключённые отметки остаются прежними. Итоговый лог `root-h22-attendance-wsl.log` содержит один выполненный целевой IT без пропуска.

Ревью выявило отказ архивного GET после удаления предмета последней включённой пары. Теперь одобренная заявка с оставшимися исключёнными парами открывает свою квитанцию даже при пустой текущей проекции. Для открытых заявок, неподходящей квитанции и чужой группы проверки остаются строгими. Независимое повторное ревью прошло. Добавлен тест с реальным сокращением исходного покрытия.
