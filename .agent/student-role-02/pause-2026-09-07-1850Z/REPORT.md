# Отчёт на паузе 07.09.2026

PWA и TMA пока не готовы к сдаче. Ориентировочная готовность реализации согласованной роли: PWA frontend20–25%, TMA frontend15–20%, общий backend35–45%. Это оценка по функциональным блокам, не по строкам и не точный учёт трудозатрат. Все39 состояний ещё требуют полной приёмки через обе оболочки; общий компонент и проходящий build не равны готовому приложению. Процент backend относится к роли студента и необходимым ей изменениям, а не ко всем ролям RutCampusTrack.

Сделано: прочитаны и сведены39 Figma состояний; приняты shell и Homework API в локальном integration commit42files; принято Requests domain32 после трёх раундов review; реализованы общие задания, темы, фокус и повторы с28 тестами и актуальными визуальными проверками, но UIreview ещё не завершено. Подняты зависимости и закрыт HIGH/CRITICAL gate покрытого8JAR сканирования. Начат и существенно расширен Requests transport. Исправлены отдельные проблемы совместимости, snapshots, тестовых портов и покрытия renderer; окончательные dependency checks ещё не приняты.

Осталось: закончить review/repair заданий, реально подключить их к PWA/TMA, завершить transport/bot/uploads/старые маршруты заявок и UIформы, реализовать посещаемость/статистику на согласованной модели предметов и переносов, профиль/роли/сеансы/отзыв токенов, карту, объединённый runtime и end-to-end. Genuine Telegram host остаётся отдельной непроверенной границей.

Главная трудность: старый backend не полностью выражает новую продуктовую модель. Это не косметический frontend порт; нужны дисциплины/типы/назначения/история переносов, настоящие сеансы и права, каталог карт. Обновление библиотек проявило несовместимость Springdoc, schema changes и ошибки качества checks. Windows sandbox, занятые тестовые порты и CRLF/LF создают дополнительную диагностическую работу. Найдены реальные открытые ошибки token purpose, фильтра Gateway и асинхронной смены клиентской сессии. Отдельный случай случайной записи двух строк Gateway в main был полностью откатан,47 owner hashes повторно совпали.

Модели: Luna max производит существенные изменения, но первый вариант нельзя принимать без runtime и независимой проверки. Homework API прошёл3 review: сначала4MEDIUM, затемHIGH потери completedAt в OpenAPI/types, затемPASS. Requests domain тоже потребовал3 независимых раунда. Shared UI прошёл первоначальную реализацию и несколько точечных runtime исправлений, текущее независимое review ещё требует как минимум одной правки. Sol полезен, но тоже ошибается: range finding был снят после проверки точного composable. Astra root сверяет исходники, контракты, реальные артефакты и границы воспроизведения. Нет достаточной статистики для денежной оценки окупаемости или сравнения моделей по стоимости.

Review окупается снижением риска: пойманы неверная coercion boolean, потеря completedAt в контракте, гонки решений/повторов, ложный зелёный пустой Trivy report, проблемы тем и фокуса. Цена — дополнительные раунды и задержка интеграции. Для критичных backend/auth/data границ это оправдано; для UI часть дефектов стоило ловить раньше точными fixture данными и сравнением с оригиналом. Дальше следует сохранять bounded проверки, не повторять весь suite без нового изменения и не считать любое замечание reviewer доказанным.
