## 2. Layout-регионы

```
AppShell
├─ AppHeader                     [зелёный: RoleSwitcher, аватар] [жёлтый: поповер профиля]
```

Порядок табуляции: корпус → этаж → кнопки зума → область схемы → скачать. Совпадает с визуальным порядком.

## 3. Компоненты

**Из реестра, без изменений:** `AppShell`, `AppHeader`, `MainNav`, `RoleSwitcher`, `ProfileMenu`, `SelectField`, `Tooltip`, `LoadingState`, `EmptyState`, `ErrorState`, `OfflineState`.

**Из реестра, с расширением:**

| Компонент | Что добавляется |
|---|---|
| `AppLink` | download-семантика: скачивание готового ассета — ссылка, не кнопка. Доступное имя «Скачать схему: корпус 5, этаж 3, PNG». **`ExportButton` не используется** — он про выгрузку разреза данных с фильтрами |

**Новые:**

| Компонент | Назначение | Владение | Почему нет подходящего |
|---|---|---|---|
| `FloorPlanViewer` | Область показа схемы (svg): изображение, зум, панорамирование, свои `loading` / `empty` / `error`, осмысленный `alt` | `local` (map), кандидат в `domain` при появлении карты у других ролей | Не график и не таблица, ничего похожего в реестре нет |
| `BuildingFloorPicker` | Связанная пара `SelectField`: этажи зависят от выбранного корпуса | `local` (map) | Связка «родитель → зависимый список» в реестре не описана |
| `PlanLegend` | Легенда иконок схемы текстом: иконка → значение | `local` (map) | Новая сущность |

### Требования к зуму (решение владельца)

- Колесо мыши с модификатором (как в Google Maps) **и** кнопки зума — модификатор не может быть единственным способом.
- Действие «Сбросить масштаб» — отдельно, иначе из увеличенного состояния не выбраться предсказуемо.
- С клавиатуры при фокусе на области: `+` / `−` — масштаб, стрелки — панорамирование.
- Тач-таргеты кнопок ≥ 44×44 CSS-px (A11Y_REQUIREMENTS).
- Текущий масштаб озвучивается через `role="status"`, а не только рисуется.

## 4. Потребности в данных

### 4.1 Что нужно (транспортно-нейтрально)

| # | Сущность | Поля | Фильтры / пагинация |
|---|---|---|---|
| 1 | `Building` | `id`, `code` / `name`, порядок сортировки; вложенно `floors[]`: `number`, `label`, `hasPlan` | не нужны (десятки записей). Меняется редко → кэшируемо, нужна версия/ETag |
| 2 | `FloorPlan` | `buildingId`, `floor`, ссылка на **svg** (показ), ссылка на **png** (скачивание), размеры, `version` / хеш содержимого, `updatedAt` | по паре (корпус, этаж) |
| 3 | `PlanIcon` | `code`, изображение, человекочитаемое значение | общесистемный справочник, один на все схемы |

### 4.2 Что доступно сейчас

`[нет API]` — в `api-digest.md` нет ни корпусов, ни этажей, ни аудиторий как сущности, ни файлового хранилища. Аудитория в расписании приходит строкой.

### 4.3 Пробелы

`[предложение по бэкенду]`

- Справочник «корпуса + этажи + признак наличия схемы» одним кэшируемым ответом.
- Отдача схемы по паре (корпус, этаж) **в двух форматах**: svg для показа, png для скачивания. Решение владельца: храним оба. Определить поведение, если один из двух не загружен.
- Хранение по хешу содержимого (прим. 2 владельца) даёт иммутабельный URL → долгий кэш и бесплатная инвалидация при перезаливке.
- **Справочник иконок легенды** — отдельная сущность, а не поле конкретной схемы, иначе легенда разъедется между этажами.
- Публичный доступ к справочнику и схемам без авторизации — иначе лендинг (прим. 1) не сможет их показать. ❓ Форма решения — вопрос к бэкенду.
- Задел на будущее (прим. 1 и 5, **не проектируем**): аудитория как объект с координатами на схеме, отзывы / рейтинг / фото аудиторий. Если задел реален, структура `FloorPlan` должна допускать слой объектов поверх изображения — это решение о формате хранения, а не о фронте.

### 4.4 Фактура по транспорту

Экран лёгкий: **1–2 запроса**, over-fetching нет. Схема — **бинарный ассет**, доставляется вне GraphQL в любом случае → для решения о транспорте экран нейтрален.

## 5. Состояния

На бумаге присутствует только success. Всё остальное добавлено.

| Блок | Состояние | Что показываем |
|---|---|---|
| Справочник | `loading` | селекты `disabled` + `aria-busy` |
| | `empty` — ни одной схемы в системе | «Схемы пока не загружены». Реальный случай: у владельца схемы **некоторых** корпусов |
| | `error` | `ErrorState` + повтор; просмотрщик не рендерится |
| Просмотрщик | `loading` | скелетон области, `aria-busy` |
| | `empty` — у выбранного этажа схемы нет | «Для этого этажа схема не загружена» + подсказка выбрать другой. Текст **отличается** от «схем нет вообще» (§6.2) |
| | `error` — файл не отдался / битый | `ErrorState` + повтор, скачивание недоступно |
| Экран | `offline` | `OfflineState`: уже загруженная схема остаётся с пометкой, что данные могут быть устаревшими |
| | `forbidden` | неприменимо — доступ у всех ролей, страница ещё и кандидат в публичные |
| | `no-active-semester` | **неприменимо** — единственный разобранный экран без учебных данных |

Корпус без схем: решение владельца — «просто пусто и нет данных», в списке корпус остаётся, пометок не добавляем.

Ролевых различий нет.

## 6. Навигация и действия

| Элемент | Цвет на скане | Поведение |
|---|---|---|
| Корпус | зелёный | Перезагружает список этажей. Если в новом корпусе есть этаж с тем же номером — выбор сохраняется, иначе первый доступный. Смена объявляется `role="status"`, фокус остаётся на селекте |
| Этаж | зелёный | Перезагружает схему |
| Кнопки зума / сброс | добавлено | Масштабирование, объявление через `role="status"` |
| Скачать | зелёный | Скачивание png. Недоступно, пока схема не загружена успешно. Подтверждения не требует |
| Профиль | зелёный аватар / жёлтый поповер | `ProfileMenu`: «Настройки» → ПК-108, «Выход» |
| `MainNav` | серый | Переходы по разделам, «карта» с `aria-current="page"` |

Деструктивных действий на экране нет — подтверждения не нужны нигде.

**Предложение фронта (на скане нет):** держать выбранные корпус и этаж в адресе страницы, чтобы ссылку на схему можно было переслать однокурснику. Дёшево сейчас, дорого потом.

## 7. Адаптив (заметки)

- 1920: селекты в строку, схема — крупная область под ними, легенда сбоку или под схемой.
- При сужении: селекты в колонку, схема вписывается по ширине, легенда уходит под схему.
- Зум обязателен на всех ширинах — без него детали плана нечитаемы.
- PWA — отдельная поверхность, здесь не проектируется. Там почти наверняка потребуется жестовое управление.

## Известное ограничение A11Y

Легенда закрывает иконки, но **сама схема остаётся изображением**. Минимум для WCAG AA — осмысленный `alt` («Схема этажа 3, корпус 5») плюс легенда текстом рядом. Полноценная альтернатива (перечень аудиторий этажа текстом) появится только вместе с задумкой из прим. 5 — аудитория как объект на схеме. Зафиксировано как известное ограничение, не как задача текущего этапа.
