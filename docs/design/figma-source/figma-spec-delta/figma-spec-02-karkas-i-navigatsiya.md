> Проход 02 спецификации компонентов RutCampusTrack.
> Основания — `figma-spec-00-основания.md`. Значения — `brandbook-v2.md`
> и `tokens-v2.json`. Состав — `COMPONENT_REGISTRY.md` v1.0.

**В этом проходе:** `AppShell`, `AuthLayout`, `AppHeader`, `MainNav`,

## 1. Каркасы — не компоненты

`AppShell` и `AuthLayout` в реестре помечены как layout-обёртки: владеют только
размещением. **В Figma они заводятся шаблонами страницы, а не компонентами.**

Причина: компонент с двумя слотами во всю ширину экрана не переиспользуется —
он инстанцируется по одному разу на макет, и правка родителя ломает все экраны
сразу. Шаблон копируется, компонент наследуется; здесь нужно первое.

### 1.1. `AppShell` — шаблон

```
skip-link (видим только по фокусу)
AppHeader                      fill, hug
main                           fill, fill
```

`skip-link` — атом: кнопка `AppButton` `secondary` `compact`, спрятана над
верхней границей, всплывает по фокусу. Единственный элемент макета,
существующий только в состоянии `focused`.

Сетка `main` — из §10 оснований, вариант ширины задаётся на уровне блока.

### 1.2. `AuthLayout` — шаблон

```
brand-зона     fill  (заглушка, структура — этап логотипа)
panel          fixed по содержимому, по центру
```

Brand-зона на этапе 1 пустая. Иллюстрация здесь допустима — единственное место
в продукте, где она разрешена (§2.4 направления).

## 2. `shared/AppHeader`

Контейнер шапки. Реестр: переключатель ролей, навигация, профиль.

### 2.1. Анатомия

| Часть | Обязательность | Размещение |
|---|---|---|
| `role-slot` | обязательна | слева, `RoleSwitcher` |
| `nav-slot` | обязательна | центр, `MainNav` |
| `actions-slot` | обязательна | справа, `ProfileMenu` и уведомления |

Auto Layout горизонтальный, ширина `fill`, высота `hug`, padding по горизонтали
из полей сетки своей ширины, по вертикали `space/3`, gap `space/6`.
Поверхность `color/surface/raised`, нижняя граница `border/hairline`
`color/border/subtle`.

Правый верх под аккаунт, уведомления и настройки — приём мудборда.
Роль отдельным селектором, словом, вне ряда разделов — тоже.

### 2.2. Оси

Шапка — блок, а не компонент с состояниями. Единственная ось — `width`
(1920 / 1440 / 1280), и она принадлежит блоку `block/AppHeader` в проходе 07.
Здесь описан состав.

### 2.3. Залипание

При прокрутке шапка получает `shadow/overlay` и поверхность `color/surface/float`.
Это единственное изменение; высота и состав не меняются. Тень здесь работает
по назначению — «лежит поверх» — и дублируется сменой поверхности, как требует
§6.2 брендбука.

## 3. `shared/MainNav`

Реестр: `<nav>` с разделами активной роли, активный пункт `aria-current="page"`.
**Принимает несколько независимых наборов** (`groups[]`), а не плоский список:
у headman это «разделы» и «управление». У admin — один набор. Набор меняется
вместе с активной ролью.

### 3.1. Анатомия

Три уровня: `MainNav` → `NavGroup` → `NavItem`.

**`NavItem`** (атом)

| Часть | Обязательность |
|---|---|
| `icon` | опционально, `icon/size/sm`, instance swap |
| `label` | обязательна, `dense-strong` |
| `counter` | опционально, `micro`, приглушено |
| `marker` | видим при `current` — вертикальная засечка `border/emphasis` слева |

**Безымянных иконок в навигации не бывает** — раздел без названия не читается.
Поэтому `label` обязательна, а `icon` нет, а не наоборот.

**`NavGroup`**

| Часть | Обязательность |
|---|---|
| `group-label` | обязательна при двух и более наборах, `micro`, `color/text/muted` |
| `items` | обязательна, список `NavItem` |

Заголовок группы обязателен именно тогда, когда наборов больше одного: у headman
без подписи «разделы» и «управление» неразличимы. У admin с одним набором
подпись не рендерится.

### 3.2. Оси

**`NavItem`**
```
state = default | hover | pressed | current | disabled
```
плюс boolean `focus-ring`, `has-icon`, `has-counter`.

**`NavGroup`** — boolean `has-label`. Состояний нет: группа не интерактивна.

**`MainNav`** — контейнер, `groups` как instance swap ×2, второй опционален.

### 3.3. Состояния `NavItem`

| Состояние | Заливка | Текст | Засечка |
|---|---|---|---|
| default | прозрачная | `color/text/secondary` | нет |
| hover | `color/surface/raised` | `color/text/primary` | нет |
| pressed | `color/surface/float` | `color/text/primary` | нет |
| current | `color/surface/raised` | `color/text/primary` | `color/border/strong` |
| disabled | прозрачная | `color/disabled/text` + причина | нет |

**Акцент в навигацию не заходит** — 14 подтверждений мудборда. Активный пункт
выделяется нейтральной заливкой и засечкой.

### 3.4. Переполнение

Длинное название раздела обрезается многоточием, пункт не переносится
на две строки — иначе ряд навигации меняет высоту. Счётчик не сжимается
и не обрезается никогда.

При нехватке ширины (1280) набор сворачивается — правило в проходе 07.

## 4. `shared/RoleSwitcher`

Реестр: **рендерится всегда, включая случай одной роли.** Роль — массив,
у каждой свой статус. Активная роль живёт на сервере. Роли в терминальных
статусах остаются переключаемыми и показывают данные только для чтения.

### 4.1. Анатомия

| Часть | Обязательность |
|---|---|
| `current-role` | обязательна, `dense-strong` — **роль читается словом** |
| `icon-trailing` | видима при `has-alternatives` |
| `readonly-mark` | видима при `readOnly`, `micro`, `color/text/muted` |
| список | `Popover` с пунктами роли |

Пункт списка: `label` роли + `status` (`micro`, `color/text/muted`) + `check`
у активной.

### 4.2. Оси

```
state = default | hover | pressed | open | disabled
```
плюс boolean `has-alternatives`, `readOnly`, `focus-ring`.

**`has-alternatives=false`** — компонент виден, но не открывается: показывает
роль текстом без шеврона. Это прямое требование реестра — прежнее условие
«рендерить только при двух и более ролях» снято.

### 4.3. Что запрещено

Роль не оформляется вкладкой, чипом или веткой аккордеона — отклонено мудбордом:
смена роли изолирует контур, это не переключение раздела. Поэтому `RoleSwitcher`
не собирается из `Tabs` и внешне на них не похож.

### 4.4. Переполнение

Название роли короткое и конечное (четыре значения) — переполнения не бывает.
Статус роли в пункте обрезается многоточием.

## 6. `shared/Tabs`

Реестр: базовый ARIA tablist. **Обёрток над `Tabs` не существует** — состав
вкладок всегда данные, счётчик — поле элемента. Память разреза принадлежит
панели-потребителю.

### 6.1. Анатомия

**`Tab`** (атом)

| Часть | Обязательность |
|---|---|
| `label` | обязательна, `dense-strong` |
| `counter` | опционально, `micro` |
| `underline` | видима при `selected`, `border/emphasis` |

**`Tabs`** — горизонтальный Auto Layout, gap `space/5`, нижняя граница
`border/hairline` `color/border/subtle` во всю ширину, `hug` по высоте.

### 6.2. Оси `Tab`

```
state = default | hover | pressed | selected | disabled
```
плюс `focus-ring`, `has-counter`.

### 6.3. Состояния

| Состояние | Текст | Подчёркивание |
|---|---|---|
| default | `color/text/muted` | нет |
| hover | `color/text/secondary` | нет |
| pressed | `color/text/primary` | нет |
| selected | `color/text/primary` | `color/border/strong` |
| disabled | `color/disabled/text` + причина рядом | нет |

Акцент во вкладки не заходит. Активная вкладка выделяется весом, яркостью
и подчёркиванием.

`disabledReason` из реестра — text property `disabled-reason`, показывается
рядом с вкладкой, а не в подсказке: подсказка недоступна с клавиатуры
на неактивном элементе.

### 6.4. Переполнение

Вкладки не переносятся и не скроллятся: состав вкладок в продукте конечен
и короток (2–4). Длинная подпись обрезается многоточием со `space/16` минимума.

## 7. `shared/Popover`

Реестр: всплывающий слой с ловушкой фокуса, возвратом фокуса, закрытием
по Esc и клику вне.

### 7.1. Анатомия

| Часть | Обязательность |
|---|---|
| контейнер | обязательна |
| `content` | обязательна, instance swap |

Поверхность `color/surface/float`, граница `border/hairline`
`color/border/subtle`, радиус `radius/lg`, тень `shadow/overlay`,
padding `space/2`.

**Тень здесь дублирует, а не заменяет:** поверхность и граница уже отличают
поповер от подложки, тень добавляет третьим носителем (§6.2 брендбука).

Хвостика-стрелки нет. Стрелка требует позиционирования по краю и ломается
на границах экрана; связь с триггером даёт положение и `aria`.

### 7.2. Оси

Размерных вариантов нет: ширина `hug` по содержимому, минимум — ширина триггера,
максимум `space/16` × 20 (20rem) для текстового содержимого.

Состояний нет: поповер либо есть, либо его нет. Состояния принадлежат содержимому.

### 7.3. Слоты и вложенность

`content` принимает: список пунктов меню, `TableColumnFilter`, форму фильтра,
`MonthCalendar`, список `SelectField`, карточку профиля.

**Поповер в поповере запрещён.** Второй уровень наложения в продукте
не существует: единственная модалка — `ConfirmDialog`, всё остальное
раскрывается на странице.

## 8. `shared/Tooltip`

Реестр: подсказка, **открывается по hover И по фокусу с клавиатуры**.
Доменных подсказок не несёт.

### 8.1. Анатомия

Один слой: текст `caption`, `color/text/primary`, поверхность
`color/surface/float`, граница `border/hairline`, радиус `radius/sm`,
padding `space/2`, тень `shadow/overlay`, максимальная ширина 20rem.

### 8.2. Отличие от `Popover`

`Tooltip` **не фокусируем и не содержит интерактива**. Это разные контракты
фокуса, поэтому вариантом одного компонента они быть не могут — правило §3.2
оснований.

`ExcuseReasonPopover` из реестра строится на `Tooltip`, а не на `Popover`,
несмотря на имя: его содержимое нефокусируемо во всех применениях.

### 8.3. Состояния

Одно. Появление `duration/fast`, `easing/out`; при `prefers-reduced-motion`
появляется мгновенно.

## 9. `shared/RowActionsMenu`

Реестр: меню действий строки или карточки (⋮). Домена не знает. **Основной
носитель действий всей роли admin.** Недоступные пункты — `disabled`
с текстовой причиной, не скрыты.

### 9.1. Анатомия

| Часть | Обязательность |
|---|---|
| `trigger` | обязательна, `AppButton` `ghost` `compact` `has-label=false` |
| меню | `Popover` |
| `MenuItem` | атом |

**`MenuItem`**

| Часть | Обязательность |
|---|---|
| `icon` | опционально |
| `label` | обязательна, `dense` |
| `reason` | видима при `disabled`, `caption`, `color/text/muted`, второй строкой |
| `separator` | опционально перед пунктом, `border/hairline` |

### 9.2. Оси `MenuItem`

```
type  = default | destructive
state = default | hover | pressed | disabled
```
плюс `focus-ring`, `has-icon`.

`destructive` отличается цветом текста `color/state/danger/text`, а не заливкой:
цветные иконки действий построчно отклонены мудбордом.

### 9.3. Правило рядом стоящих действий

`DestructiveActionPair` из реестра — «Архивировать» и «Удалить» **всегда рядом**.
В меню это два соседних пункта без разделителя между ними: разделитель прочитается
как «это разные группы», а смысл в том, что выбор делает пользователь.

### 9.4. Переполнение

Пункт не переносится, обрезается многоточием. Причина недоступности переносится
на две строки и дальше обрезается — при этом пункт растёт по высоте, это
допустимо: меню не сетка.

## 10. `shared/ConfirmDialog`

Реестр: **единственная модалка продукта.** `role="dialog"`, ловушка и возврат
фокуса, Esc, `busy` на подтверждающей кнопке.

### 10.1. Анатомия

| Часть | Обязательность |
|---|---|
| `scrim` | обязательна, `color/surface/scrim`, прозрачность 60% |
| контейнер | обязательна |
| `title` | обязательна, `title-block` |
| `detail` | обязательна, `body` — **называет объект, дату и последствие конкретно** |
| `impact` | опционально — количества: сколько пар, отметок, заданий |
| `challenge` | опционально, `DangerousActionChallenge` |
| `actions` | обязательна — отмена и подтверждение |

Контейнер: `color/surface/float`, радиус `radius/xl`, padding `space/6`,
gap `space/4`, тень `shadow/overlay`, ширина фиксированная 28rem,
максимальная высота 80% экрана с внутренней прокруткой содержимого.

### 10.2. Разный вес отмены и подтверждения

Приём мудборда. Подтверждение — `AppButton` `danger` при `destructive=true`,
иначе `primary`. Отмена — всегда `ghost`. Порядок: отмена слева, подтверждение
справа.

### 10.3. Оси

```
type  = default | destructive
state = default | busy
```
плюс boolean `has-impact`, `has-challenge`.

`hover`, `pressed`, `focused` принадлежат кнопкам внутри, у диалога их нет.

### 10.4. Правило содержания

**Действие, уничтожающее данные, называет объём последствий до подтверждения.**
«Удалится всё» — не предупреждение. Слот `impact` существует именно под числа
и при `destructive=true` обязателен.

## 11. `auth/DangerousActionChallenge`

Реестр: доказательство намерения. **Рендерится внутри `ConfirmDialog`** — новой
модалки не заводим. Проп `level`: `password` и `password + otp`.
Термин «кодовая фраза» выведен из обихода.

### 11.1. Анатомия

| Часть | `level=password` | `level=password-otp` |
|---|---|---|
| `password` | `PasswordField` в `FormField` | то же |
| `otp` | — | `TextInput` в `FormField` |
| `countdown` | — | `CountdownTimer` рядом с полем кода |
| `resend` | — | `AppLink` «Запросить новый» |

### 11.2. Оси

```
level = password | password-otp
state = default | error | expired | busy
```

`expired` — состояние реестра: истёкший код заменяется действием «Запросить
новый», а не пустой формой. Это отдельное состояние, а не разновидность `error`.

## 12. Листалки

### 12.1. `shared/StepPager` — примитив

Реестр: шаговое листание ◀ ▶ по одной единице оси. Оси не знает. `ariaLabel`
обязателен: несколько независимых экземпляров на экране допустимы.

**Анатомия**

| Часть | Обязательность |
|---|---|
| `prev` | обязательна, `AppButton` `ghost` `compact` `has-label=false` |
| `label` | обязательна, `dense-strong` — текущее значение оси |
| `next` | обязательна, то же |
| `current-reset` | видима при `showCurrentReset` и `isAtCurrent=false` |
| `boundary-reason` | видима при недоступной стрелке |

Auto Layout горизонтальный, gap `space/2`, `hug`.

**`label` фиксированной ширины.** Иначе при листании «понедельник» → «среда»
стрелки прыгают, и по ним невозможно попасть дважды подряд. Это единственное
место, где фиксированная ширина ставится текстовому слою, и причина именно эта.

**Оси**

```
state = default | busy
```
плюс boolean `has-prev`, `has-next`, `show-current-reset`, `at-current`.

Состояния стрелок принадлежат `AppButton` внутри. Недоступная стрелка —
`disabled` **с пояснением**: `boundary-reason` показывается текстом рядом,
а не в подсказке.

`current-reset` — `AppButton` `ghost` `compact` с подписью из property
`current-reset-label`: «Сегодня», «Текущая неделя», «Текущий месяц».
Контрол виден только вне текущего значения.

### 12.2. `DatePager` и `LessonPager` — не отдельные компоненты Figma

Реестр называет их отдельно, и в коде это верно: разный тип значения, разное
происхождение границ, `LessonPager` берёт границы из набора пар дня,
`DatePager` — из календарной оси и границ семестра.

**Визуально они не различаются ничем.** Разница целиком в данных: подпись,
границы, что считать «текущим».

Поэтому в Figma заводится **один компонент `shared/StepPager`**, а `DatePager`
и `LessonPager` существуют как именованные пресеты — сохранённые экземпляры
с заполненными text properties. Заводить два компонента с одинаковой анатомией
и разными подписями — это синоним, а не вариант.

Расхождение с реестром названо здесь намеренно: реестр описывает код, этот файл —
библиотеку. Если при сборке окажется, что пресеты в Figma неудобны, решение
откатывается заведением двух обёрток-компонентов вокруг одного `StepPager`.

### 12.3. `shared/Pagination`

Реестр: постраничный проход **либо** «показать ещё». Состояния `loading-more`,
`end-of-list`. **Не путать со `StepPager`**: там одно значение оси, здесь
растущий список и страницы.

**Анатомия, `mode=pages`**

| Часть | Обязательность |
|---|---|
| `prev` / `next` | обязательны, кнопки-иконки |
| `page-item` | атом — номер страницы |
| `ellipsis` | видим при разрыве ряда |
| `total` | опционально, «Показано 01–10 из 256», `caption` |

**Анатомия, `mode=show-more`**

| Часть | Обязательность |
|---|---|
| `more-button` | обязательна, `AppButton` `secondary` |
| `total` | обязательна — дробь «текущее из общего» |
| `end-label` | видима при `end-of-list` |

**Оси `page-item`**

```
state = default | hover | pressed | current | disabled
```
плюс `focus-ring`.

**Состояния `page-item`** — по образцу приложенного PNG с пагинацией:

| Состояние | Заливка | Текст |
|---|---|---|
| default | `color/surface/raised` | `color/text/secondary` |
| hover | `color/surface/float` | `color/text/primary` |
| pressed | инверсия: `color/text/primary` | `color/surface/base` |
| current | инверсия постоянная | `color/surface/base` |
| disabled | `color/disabled/surface` | `color/disabled/text` |

`current` и `pressed` совпадают по значениям намеренно: нажатие на номер
и означает «стать текущим». Различает их постоянство, а не вид.

**Оси `Pagination`**

```
mode  = pages | show-more
state = default | loading-more | end-of-list
```

`end-of-list` при `mode=pages` не существует — матрица неполная.
