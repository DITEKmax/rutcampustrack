## Required behavior
Proposed compatible wire, confirmed in root coordination: GroupMembersRequest keeps group_id=1 and adds optional as_of_date=2 plus optional semester_id=3. Both absent retain the existing undated behavior. Exactly one present, invalid positive IDs, blank/noncanonical ISO date, or date outside the specified semester must fail before roster query. GroupMembersResponse keeps students=1 and adds matching optional date/semester echoes at tags2/3. Attendance verifies presence and exact equality; an old server that ignores new request fields and returns a current roster therefore fails closed.

Attendance first resolves the authoritative physical lesson, then sends its group/date/semester. Do not use the event's group as sole authority or the active-semester cache. Membership is calendar-date precision: V1__baseline.sql:47–54 defines joined_at DATE and left_at DATE; JdbcStudentProjectionQueryAdapter.findGroupHistory maps LocalDate. There is no authoritative intraday membership instant in this schema.

For a history interval with established authority, membership at D is joined_at <= D AND (left_at IS NULL OR D < left_at). UserService.transferStudent:304–320 closes the old open row and opens the new row using the same LocalDate.now() date. Thus the old group excludes that transfer date and the new group includes it; a same-day zero-length row contributes no membership. Do not reinterpret this as day-overlap or split the day by lesson time. Existing server-default LocalDate.now() must not be misreported as already explicitly Moscow-zoned.

Historical query must not filter by users.current group, current archived/active status, current headman flag or current role-grant group. If StudentInfo display fields are reused, distinguish present-day display data from historical eligibility; automatic marking consumes stable user IDs. A historical query must bypass the groupId-only current-roster cache; start uncached unless a separate date+semester key and invalidation contract is defined. Validate malformed/inverted or ambiguous overlapping history explicitly; never silently substitute a current roster.

Important readiness gap: existing history does not yet prove completeness. UserService.createUser:81–141 saves users.group_id but creates no student_group_history. transferStudent closes an old row only if present, then creates a destination row; an absent origin history is silently allowed. archiveUser:284–295 changes current status without closing history. A valid empty roster and missing historical records cannot be distinguished just by an empty SELECT. No coverage marker is present in the inspected history schema. Further canonical role-grant/trigger checks are recorded in the source-map addendum, not assumed.

Additional gap check completed: V24__auth_session_authority.sql:38–78 defines only current user_role_grants role/status/group with created_at/updated_at and a one-time copy from legacy users. Its :80–120 trigger bumps roles_version; it does not maintain membership intervals or role/status validity history. Targeted source discovery found no other product history writer or history trigger in the inspected Academic Java/migrations. This is bounded negative evidence, not a proof about external/manual data producers. StudentProjectionQueryAdapterIT deliberately inserts history/grants as test fixtures; those tests do not prove a production enrollment path creates complete history.

Therefore freeze transport/query mechanics separately from historical readiness: unknown/incomplete coverage or unavailable historical eligibility must yield an explicit typed failure (proposed FAILED_PRECONDITION), never an empty success. Unknown group/semester uses NOT_FOUND; malformed input INVALID_ARGUMENT; operational failure UNAVAILABLE. A nonempty result alone also does not prove completeness. A success with an empty student list requires independently established complete history for that scope.

New enrollment/transfer corrections must write authoritative membership history atomically with the actual enrollment change and define coverage from that supported effective date. Existing missing intervals cannot be backfilled to semester start, account creation date, or current group by inference. Root clarification: the authoritative membership interval itself defines student membership; do not require reconstruction of all historical role grants. Current role-grant snapshots cannot replace membership history, and the separate grant-creation gap is not a reason to expand this task into grant CRUD.

Bounded completeness recommendation: store group-scoped provenance {group_id, coverage_from DATE, writer_version=managed_v1}, created only atomically with a genuinely NEW group through the managed writer. Never infer this marker from an existing group being empty now. The lower bound comes from the accepted onboarding date policy or an explicit supported date, not a guessed legacy date. Every managed enrollment writes the membership interval atomically with assignment to that group under its lock; transfer/membership-affecting legacy mutations must use the same writer or fail before mutation. A dated query succeeds only within a marked complete range and consistent history; it can then return a meaningful empty list. Unmarked legacy groups or dates before coverage fail explicitly. No global backfill, no reconstruction of unrelated role history, no false completeness marker for a partial migration. Root owns final schema/writer scope and the pending owner's initial-membership-date answer.
