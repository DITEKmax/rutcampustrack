# RUT-UIT v2 — Job Stories по ролям

## Соглашения

- **Роли**: ADMIN, TEACHER, STUDENT (с флагом `is_headman` для старост)
- **Помощник старосты**: студент с делегированными правами из набора: `mark_attendance`, `manage_excuses`, `manage_homework`, `cancel_lessons`, `view_stats`
- **Статусы посещаемости**: `present`, `absent`, `excused`, `free_attendance`
- **Источники отметки**: `student_geo`, `headman`, `auto_scheduler`, `teacher_override`, `late_checkin`
- **Уважительные причины (excuse.type)**: `illness`, `summons`, `university_order`, `exemption`, `other`
- **Типы предметов**: `lecture`, `practice`, `lab`

## 1. Администратор (ADMIN)

### 1.1 Управление пользователями

**JS-ADMIN-01**: Когда в вуз приходят новые студенты и преподаватели, я (администратор) хочу массово добавить их в систему, указав ФИО, email, роль и группу (для студентов) / табельный номер (для преподавателей), чтобы им автоматически сгенерировались логин (`studentXXXXX` / `teacherXXXXX`) и пароль, которые будут отправлены при первом запуске Telegram-бота.

**JS-ADMIN-02**: Когда студент отчислен или ушёл в академический отпуск, я хочу изменить его статус (`active` → `expelled` / `suspended`), чтобы он потерял доступ к системе, но его исторические данные сохранились.

**JS-ADMIN-03**: Когда нужно перевести студента из одной группы в другую, я хочу выполнить перевод с указанием причины, чтобы в истории группы зафиксировались даты и причина перевода.

**JS-ADMIN-04**: Когда студент полностью покинул вуз, я хочу удалить его из системы, чтобы он не отображался в списках (soft delete — статус `archived`).

### 1.2 Управление группами

**JS-ADMIN-05**: Когда формируется новый учебный год, я хочу создать группы с кодом (например, `ИВТ-21-1`), чтобы староста мог начать настраивать расписание и предметы.

**JS-ADMIN-06**: Когда я назначаю старосту группе, я хочу выбрать студента из состава группы и установить ему флаг `is_headman`, чтобы он получил расширенные права.

**JS-ADMIN-07**: Когда старосту нужно сменить, я хочу снять флаг `is_headman` с текущего старосты и назначить нового, чтобы права передались корректно. При смене старосты все помощники предыдущего старосты автоматически деактивируются.

### 1.3 Управление семестрами

**JS-ADMIN-08**: Когда начинается новый семестр, я хочу создать семестр с названием и датами (начало/конец), чтобы привязать к нему расписание и посещаемость.

**JS-ADMIN-09**: Когда семестр начинается, я хочу активировать его (одновременно может быть активен только один семестр), чтобы система знала текущий контекст.

**JS-ADMIN-10**: Когда нужно удалить ошибочно созданный семестр, я хочу подтвердить действие вводом кодовой фразы (как в GitHub при удалении репозитория), чтобы исключить случайное удаление.

### 1.4 Статистика и аналитика

**JS-ADMIN-11**: Когда я захожу в панель администратора, я хочу видеть dashboard со сводной информацией: общее количество студентов в системе, количество групп, количество активных преподавателей.

**JS-ADMIN-12**: Когда деканат запрашивает данные, я хочу видеть среднюю посещаемость по каждой группе за семестр и список студентов в «красной зоне» (посещаемость ниже заданного порога).

**JS-ADMIN-13**: Когда нужен официальный отчёт, я хочу экспортировать данные посещаемости в PDF или Excel с фильтрацией по группе, предмету и периоду.

## 2. Преподаватель (TEACHER)

### 2.1 Просмотр посещаемости

**JS-TEACHER-01**: Когда я захожу в веб-панель, я хочу видеть выпадающий список только своих групп, а внутри каждой группы — выпадающий список только своих предметов, чтобы быстро найти нужный журнал.

**JS-TEACHER-02**: Когда я веду лекцию на потоке из нескольких групп, я хочу видеть посещаемость каждой группы отдельно по одному предмету, чтобы не путать данные разных групп.

**JS-TEACHER-03**: Когда я открываю журнал, я хочу видеть таблицу: строки — студенты, столбцы — даты пар, ячейки — статусы (б/н/у/сп), чтобы оценить картину посещаемости за семестр.

### 2.2 Ограничения

**JS-TEACHER-04**: Преподаватель НЕ может редактировать посещаемость. Журнал доступен только для чтения.

**JS-TEACHER-05**: Преподаватель НЕ имеет Telegram-бота и не взаимодействует через Telegram. Только веб-панель.

### 2.3 Статистика

**JS-TEACHER-06**: Когда я хочу понять тренд, я хочу видеть процент посещаемости по каждому предмету и группе, чтобы сравнить между группами и заметить проблемные.

**JS-TEACHER-07**: Когда нужен отчёт для кафедры, я хочу экспортировать журнал посещаемости в Excel/PDF.

### 2.3 PWA Mobile Client

**JS-TEACHER-08**: Когда преподаватель открывает PWA на планшете/телефоне между парами, он видит журнал посещаемости текущей группы в мобильно-адаптированном виде.

## 3. Староста (STUDENT + is_headman = true)

### 3.1 Отметка посещаемости

**JS-HEADMAN-01**: Когда пара идёт, я хочу отметить посещаемость студентов вручную через Telegram-бота или веб-панель, выбрав пару из расписания и проставив статусы всем студентам разом (массовая отметка).

**JS-HEADMAN-02**: Когда я хочу запретить студентам отмечаться по геолокации на конкретной паре (например, при подозрении на подмену), я хочу заблокировать пару для геоотметок, чтобы все отметки шли только через меня.

**JS-HEADMAN-03**: Когда пара прошла и часть студентов не отметилась, система автоматически проставляет им `absent`, чтобы журнал всегда был заполнен без моего ручного действия.

### 3.2 Управление уважительными причинами

**JS-HEADMAN-04**: Когда студент проставил себе уважительную причину, мне приходит уведомление в Telegram и веб-панель, чтобы я мог проверить и подтвердить или отклонить.

**JS-HEADMAN-05**: Когда студент запросил «забыл отметиться, но был» (`late_checkin`), мне приходит уведомление с просьбой подтвердить. Если я подтверждаю — статус меняется на `present`, если отклоняю — остаётся `absent`.

**JS-HEADMAN-06**: Когда я вижу некорректную уважительную причину, я хочу изменить статус студента с `excused` на `absent`, чтобы журнал отражал реальность.

**JS-HEADMAN-07**: Когда студент собирает справки для уважительной причины (болезнь, повестка), я хочу видеть список pending-запросов и одобрять/отклонять их.

### 3.3 Управление расписанием

**JS-HEADMAN-08**: Когда начинается семестр, я хочу создать расписание группы: выбрать предмет, день недели, номер пары и чётность недели (каждую / нечётную / чётную), чтобы система автоматически сгенерировала все конкретные даты пар на весь семестр.

**JS-HEADMAN-09**: Когда пара отменяется из-за праздника или болезни преподавателя, я хочу отменить одну конкретную пару или все пары на день, чтобы студенты получили push-уведомление в Telegram, а пара не считалась в статистике.

**JS-HEADMAN-10**: Когда нужно отменить серию пар (преподаватель в отпуске), я хочу отменить все пары по конкретному предмету на период, чтобы не отменять каждую вручную.

### 3.4 Управление предметами и преподавателями

**JS-HEADMAN-11**: Когда формируется семестр, я хочу создать предметы с указанием типа (лекция, практика, лабораторная), чтобы в расписании и отчётах тип отображался отдельно от названия.

**JS-HEADMAN-12**: Когда нужно назначить преподавателя, я хочу найти его по табельному номеру из общего пула преподавателей и привязать к предмету своей группы. У одного предмета может быть несколько преподавателей (лекции ведёт один, практики — другой). У преподавателя может быть несколько предметов.

**JS-HEADMAN-13**: Предметы привязаны к конкретной группе и семестру. Предмет с одинаковым названием у разных групп — это разные записи в `teacher_subject_groups`, и они не пересекаются.

### 3.5 Помощники старосты

**JS-HEADMAN-14**: Когда я не могу вести журнал (болею, уехал), я хочу назначить помощника из студентов своей группы и выбрать конкретные права из списка: `mark_attendance`, `manage_excuses`, `manage_homework`, `cancel_lessons`, `view_stats`.

**JS-HEADMAN-15**: Когда помощник больше не нужен, я хочу отозвать его права полностью или частично.

### 3.6 Домашнее задание

**JS-HEADMAN-16**: Когда преподаватель задал домашнее задание, я хочу опубликовать его для группы: текст задания + ссылка (на облако, Git-репозиторий или чат), чтобы все студенты получили уведомление.

**JS-HEADMAN-17**: Когда задание обновилось, я хочу отредактировать запись и опубликовать обновление, чтобы группа получила повторное уведомление об изменении.

### 3.7 Статистика

**JS-HEADMAN-18**: Когда я захожу в панель, я хочу видеть статистику группы: количество студентов, общий процент посещаемости, процент посещаемости по каждому студенту.

**JS-HEADMAN-19**: Когда мне нужен отчёт для куратора, я хочу экспортировать журнал посещаемости в PDF/Excel.

### 3.8 PWA Mobile Client

**JS-HEADMAN-20**: Когда староста использует PWA на мобилке, он может отметить посещаемость, подтвердить excuse и late_checkin, просмотреть журнал — полный функционал без десктопа.

## 4. Студент (STUDENT)

### 4.1 Отметка по геолокации

**JS-STUDENT-01**: Когда пара началась, я хочу отметиться по геолокации в Telegram Mini App, отправив свои координаты, чтобы система проверила, нахожусь ли я в радиусе кампуса.

**JS-STUDENT-02**: Когда отметка по геолокации не прошла (далеко от кампуса, GPS сбой, но я на паре), я хочу нажать кнопку «Отправить запрос старосте», чтобы староста подтвердил моё присутствие. Кнопка появляется только после неудачной попытки геоотметки — без попытки она недоступна.

### 4.2 Уважительные причины

**JS-STUDENT-03**: Когда я пропустил пару по уважительной причине, я хочу выбрать причину из списка (болезнь, повестка, приказ вуза, освобождение, свободное посещение, другое) и добавить комментарий, чтобы староста получил уведомление и мог подтвердить.

**JS-STUDENT-04**: Когда у меня причина `free_attendance` (свободное посещение — на паре нечего делать), я хочу отметить это, и статус автоматически становится `excused` с типом `free_attendance`.

**JS-STUDENT-05**: Когда я могу отметить уважительную причину как на прошедшие пары, так и на будущие (заранее знаю, что не приду).

### 4.3 Забыл отметиться

**JS-STUDENT-06**: Когда пара прошла и у меня стоит `absent`, но я был на паре, я хочу нажать кнопку «Был, но забыл отметиться» (доступна для всех пар с `absent`), чтобы старосте пришёл запрос на подтверждение. При подтверждении мой статус меняется на `present` с источником `late_checkin`.

### 4.4 Статистика

**JS-STUDENT-07**: Когда я хочу понять свою посещаемость, я хочу видеть: процент посещаемости по каждому предмету, график тренда по неделям (растёт или падает), рейтинг предметов — где пропускаю больше всего и меньше всего.

**JS-STUDENT-08**: Когда мне приходит уведомление о начале пары в Telegram, я хочу одним нажатием перейти в Mini App и отметиться.

### 4.5 PWA Mobile Client

**JS-STUDENT-09**: Когда студент открывает RutTrack в мобильном браузере, ему предлагается «Установить приложение». После установки на рабочем столе появляется иконка RutTrack, приложение открывается в standalone mode без адресной строки.

**JS-STUDENT-10**: Когда студент офлайн, он видит кэшированное расписание и свою статистику. При попытке check-in видит сообщение «Нет подключения к сети».

**JS-STUDENT-11**: Когда PWA свёрнута или закрыта, студент получает Web Push уведомление о начале пары с кнопкой «Отметиться» (открывает PWA на экране check-in).

## 5. Системные / автоматические

### 5.1 Авторизация и учётные записи

**JS-SYSTEM-01**: Когда администратор создаёт пользователя, система генерирует логин по паттерну (`student00001`, `teacher00001`) и случайный пароль. При первом `/start` бота пользователю отправляются логин и пароль. Эти данные зафиксированы в диалоге бота. Если пароль сменён — старые данные удаляются, и в открытом виде пароль больше недоступен.

**JS-SYSTEM-02**: Когда студент заходит в Telegram-бота, бот автоматически авторизует его по `telegram_id`, связанному с учётной записью в системе (привязка делается при первом `/start`).

**JS-SYSTEM-03**: Когда пользователь забыл пароль, он запрашивает OTP-код сброса через Telegram-бота. OTP действует 120 секунд, одноразовый, максимум 3 попытки за 5 минут.

**JS-SYSTEM-04**: Когда пользователь хочет сменить пароль (помнит старый), он вводит текущий и новый пароль через веб-панель. Старый пароль проверяется обязательно.

### 5.2 Автоматические процессы

**JS-SYSTEM-05**: Когда староста добавляет слот в расписание (предмет + день + номер пары + чётность), система автоматически генерирует все конкретные даты `lessons` на весь семестр на основе дат семестра и чётности недель.

**JS-SYSTEM-06**: Когда пара переходит в статус `active` (по времени начала), система публикует событие `lesson.started` → студенты группы получают push в Telegram: «Пара началась, отметьтесь».

**JS-SYSTEM-07**: Когда пара переходит в статус `closed` (по времени окончания), система автоматически проставляет `absent` всем студентам группы, у которых нет отметки за эту пару. Староста получает уведомление: «Сессия отметки завершена».

**JS-SYSTEM-08**: Когда староста отменяет пару, система публикует событие → все студенты группы получают push в Telegram: «Пара [предмет] [дата] отменена». Пара не считается в статистике посещаемости.

### 5.3 Уведомления

**JS-SYSTEM-09**: Уведомления доставляются по двум каналам одновременно: Telegram (через notification-bot) и WebSocket push (через notification-web) в веб-панель. Каждый канал работает независимо.

**JS-SYSTEM-10**: Типы событий, генерирующих уведомления: `lesson.started` (студентам), `lesson.closed` (старосте), `lesson.cancelled` (студентам), `attendance.marked` (подтверждение студенту), `excuse.requested` (старосте), `late_checkin.requested` (старосте), `homework.published` (студентам группы), `homework.updated` (студентам группы).

### 5.4 Web Push и PWA

**JS-SYSTEM-11**: Web Push уведомления доставляются параллельно с Telegram. Оба канала работают независимо. В будущем пользователь сможет выбрать предпочтительный канал в настройках профиля.

**JS-SYSTEM-12**: Для iOS пользователей при первом визите показывается инструкция «Откройте в Safari → Поделиться → На экран Домой» для корректной установки PWA и работы Web Push.

## 4. Web-кабинет студента (STUDENT, v9.0)

**JS-STUDENT-WEB-03**: Когда идёт активная пара и я открываю `/student/checkin`, я хочу нажать «Отметиться», чтобы геопозиция была отправлена и без перезагрузки появилось подтверждение через STOMP-сокет. (STU-WEB-03)

**JS-STUDENT-WEB-04**: Когда я открываю `/student/homework`, я хочу видеть все задания группы и одним кликом отмечать их как выполненные с оптимистичным UI и откатом при ошибке сервера. (STU-WEB-04)

**JS-STUDENT-WEB-09**: Когда я хочу сменить пароль, я хочу на `/student/profile` ввести старый и новый пароль, чтобы система проверила старый и сохранила новый без перезагрузки страницы. (STU-WEB-09)

**JS-STUDENT-WEB-10**: Когда я первый раз залогинился в web-панели как STUDENT, я хочу увидеть ненавязчивый баннер «Установите RutTrack на главный экран» с кнопкой на `/app/`, который можно закрыть один раз навсегда — без принудительного редиректа в PWA. (STU-WEB-10)

## 5. Web-кабинет старосты (STUDENT + is_headman=true, v9.0)
