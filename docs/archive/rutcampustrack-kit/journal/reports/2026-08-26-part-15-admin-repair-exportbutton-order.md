# Отчёт — ремонт порядка ExportButton в UsersRegistry и GroupsRegistry

Дата выполнения: 26.08.2026. Статус: партия выполнена. Публикации не было.

## Ответы на вопросы

1. `UsersRegistry`: существующий `ExportButton` переставлен после
   `UsersTable` во всех трёх размерных ветках.
2. `GroupsRegistry`: существующий `ExportButton` переставлен после
   `GroupsTable` во всех девяти ветках (`3 width × 3 scope`).
3. Прямые физические потребители до/после: `UsersRegistry` — **11 / 11**,
   `GroupsRegistry` — **19 / 19**.
4. Геометрическая дельта продуктовых кадров 132 и 133 равна **0 px** по
   ширине и высоте. Данные и переопределения сохранены.
5. Замыкания страниц 16–19 после ремонта: auth **30 кадров / 270 A**,
   student **48 / 408 A**, headman **66 / 456 A**, teacher **24 / 198 A**;
   дельта 0.
6. Других admin-мастеров с `ExportButton` выше таблицы не найдено.

## Разбор и стоп-ворота

Числовых расхождений с живым файлом не найдено. Потребители и замыкания
сняты до правки и повторно отдельным обходом после неё.

Простая отдельная вертикальная строка под таблицей увеличила бы каждый корень
на 56 px: высота кнопки 32 px плюс вертикальный gap 24 px. Образец teacher
122/123 использует строку `actions`, где пагинация и экспорт стоят в одном
ряду. Этот приём сохраняет высоту, потому что живая пагинация уже имеет
63 px. Он применён к двум целевым мастерам.

Старая формулировка `figma-spec` включала экспорт в верхний toolbar. Более
позднее решение владельца отменяет её только для `UsersRegistry` и
`GroupsRegistry`; рядом добавлена датированная пометка.

## Что изменено в Figma

Во всех ветках после таблицы создан HUG по высоте / FIXED по ширине контейнер
`actions`. В него без пересоздания перенесены существующие `Pagination` и
`ExportButton`: пагинация слева, экспорт справа.

| Мастер | Ветки | Порядок до | Порядок после | Высота корня до / после |
|---|---:|---|---|---:|
| `block/UsersRegistry` | 3 | toolbar с export → table → pagination | toolbar → table → actions[pagination, export] | 1639 / 1639 px |
| `block/GroupsRegistry` | 9 | tabs → toolbar с export → table → pagination | tabs → toolbar → table → actions[pagination, export] | 1703 / 1703 px |

Геометрия внутри мастеров изменилась только по задаче:

- toolbar `UsersRegistry`: **721→557 px** по ширине;
- toolbar `GroupsRegistry`: **732→564 px** по ширине;
- новые `actions`: высота **63 px**, ширины **1824 / 1376 / 1216 px**;
- `UsersTable`: y=64, h=1488, нижняя граница 1552; `actions` y=1576,
  зазор 24 px;
- `GroupsTable`: y=128, h=1488, нижняя граница 1616; `actions` y=1640,
  зазор 24 px.

Добавлено 12 физических FRAME-узлов A в мастерах: 3 у `UsersRegistry` и 9 у
`GroupsRegistry`. Вес продуктового экземпляра остаётся 1 A, поэтому вес
экранов и страниц не меняется. Новые компоненты, варианты, токены и
переменные не создавались.

## ExportButton и семантика

Общий компонент `ExportButton` не изменён. Во всех 12 ветках его живая
геометрия осталась 152×32 px, `strokeWeight=1`, `cornerRadius=10`; снимки
`fill` и `stroke` экземпляра совпали до/после. `border/interactive` не
применялся, существующие привязки не менялись и новых привязок «не по смыслу»
партия не создала.

Проверены пары мастер / QA: физические экземпляры на странице 14 получили
только новый порядок из мастера. Радиусы, толщины границ, заливки и эффекты
не правились ни в мастере, ни в QA.

## Закрывающая проверка

Закрытие выполнено другим проходом, чем правка.

| Страница | Кадры до / после | A до / после | Дельта |
|---|---:|---:|---:|
| auth | 30 / 30 | 270 / 270 A | 0 |
| student | 48 / 48 | 408 / 408 A | 0 |
| headman | 66 / 66 | 456 / 456 A | 0 |
| teacher | 24 / 24 | 198 / 198 A | 0 |

До правки дополнительно сняты геометрические снимки страниц 16–19. После
правки повторный обход подтвердил те же размеры кадров и A. Граф прямых
потребителей двух мастеров замкнут на страницах 14 и 20, поэтому содержимое
страниц 16–19 не могло получить компонентное обновление.

На 132 и 133 `clipsContent=false`, overflow не добавлялся, фактического выхода
содержимого за границы кадров и блоков нет. Перестановка не создала пустого
хвоста и не изменила высоту `main`.
