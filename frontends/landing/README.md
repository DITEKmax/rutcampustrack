# Презентация RutCampusTrack

Vue-версия страницы `/presentation/` для локального просмотра. Команды выполняются из корня репозитория с Node.js 24.14+ и npm 11.9+:

```sh
npm ci --prefix frontends
npm --prefix frontends run dev:landing
```

Открой [http://127.0.0.1:14312/presentation/](http://127.0.0.1:14312/presentation/). Если зависимости workspace уже установлены, первый шаг можно пропустить.

После схемы сервисов открывается [выбор темы](http://127.0.0.1:14312/presentation/#topics). На каждую тему есть свой статический адрес. Состав страниц и исходные якоря перечислены в [карте контента](LANDING-CONTENT-MAP.md).

У карточек и вступлений тем общие иллюстрации. Набор в стиле PWA хранится в `src/art/topics-pwa/` и подключается в `src/art/TopicFlatIllustration.vue`. Прежние варианты сохранены в `src/art/topics-layered/`, `src/art/topics-flat/` и `src/art/TopicIllustration.vue`. Чтобы вернуть предыдущий набор, замени путь `./topics-pwa/` на `./topics-layered/` в импортах десяти исходных тем. Иллюстрация страницы дизайна есть в `topics-pwa/`.

```sh
npm --prefix frontends run typecheck:landing
npm --prefix frontends run build:landing
npm --prefix frontends run preview:landing
```

`preview:landing` занимает тот же порт, что и dev-сервер. Для параллельного предпросмотра укажи другой порт через `-- --port 14314`. Сборка записывается в игнорируемый `dist-vue/`. Docker собирает этот же артефакт из workspace `frontends`, а Nginx обслуживает презентацию под `/presentation/`. Основное демо открывает `demo-pwa.html`.

Сборка также создаёт статический HTML, Markdown, `robots.txt`, `sitemap.xml` и `llms.txt`. Адреса проверки и порядок отправки карты сайта в поисковые системы описаны в [SEO.md](SEO.md).

## Кэш и выпуск

При первом открытии загружается сам лендинг. PWA внутри страницы начинает загрузку при приближении к демо, по прямой ссылке с `#demo` или при открытии полноэкранного режима.

Внешний Nginx передаёт заголовки кэша от контейнера лендинга. HTML, Markdown и файлы для поисковых роботов проверяются при повторном запросе. Если версия совпадает, сервер отвечает `304` без тела. Файлы с хешем в имени кэшируются на год, ресурсы с постоянным адресом, например favicon и Open Graph, на пять минут. Текстовые ресурсы сжимаются при сборке образа. Nginx выбирает gzip или оригинал по `Accept-Encoding`.

В CI проверяются типы и production-сборка лендинга. Для проверки того же контейнера локально выполни из корня:

```sh
docker build --build-arg "LANDING_SITEMAP_LASTMOD=$(node frontends/landing/scripts/sitemap-lastmod.ts --build-arg)" -f frontends/landing/Dockerfile -t rct-landing:local frontends
docker run --rm -p 127.0.0.1:14321:80 rct-landing:local
```

Локальные HTTP-проверки запускаются командой `python -B frontends/landing/scripts/smoke-http.py http://127.0.0.1:14321`. Для проверки публичного прокси передай `https://ruttrack.site --edge`.

В контейнере без внешнего прокси используй адрес `http://127.0.0.1:14321/`. В production внешний Nginx добавляет префикс `/presentation/` для маршрутов и ресурсов лендинга.

После успешных проверок нужного SHA запусти workflow [Deploy](../../.github/workflows/deploy.yml) с этим SHA. Режим `prepare_only` публикует образы без установки на VPS. Для выпуска на сервер используется штатный ручной Deploy. После него проверь главную, хотя бы одну тему, `/presentation/#demo` и файлы из [SEO.md](SEO.md) через публичный адрес. Повторный запрос к HTML с его `ETag` в `If-None-Match` должен дать `304`. При проверке gzip передавай одинаковый `Accept-Encoding` в обоих запросах.

## Сценарий

В [основном демо](http://127.0.0.1:14312/presentation/#demo) нажми «Отметиться». Слева появятся запрос PWA и ответ локального обработчика. В профиле можно переключить роль на старосту, преподавателя или администратора и пройти их сценарии. У каждой роли свой набор учебных данных. «Начать заново» перезапускает телефон и возвращает исходные данные всех ролей.

Телефон монтирует `pwa-vue/src/App.vue` и передаёт запросы к синтетическим обработчикам внутри iframe. Изменения живут в памяти демо. Отметка использует тестовые координаты. Схемы корпуса 1, этажей 0 и 1, встроены в сборку и загружаются через обычный API карты. В форме публикации можно указать отрицательный, нулевой или положительный номер этажа. Выгрузки загружают синтетические документы. Неподдержанные операции получают локальный диагностический ответ, и запросы не уходят во внешний API.
