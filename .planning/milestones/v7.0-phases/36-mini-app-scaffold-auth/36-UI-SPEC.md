### Telegram Theme Override

Telegram injects its own color palette via `window.Telegram.WebApp.themeParams`. On mount, map these to Tailwind CSS variables so all shadcn components pick up Telegram's light/dark theme automatically.

| Tailwind CSS var | Telegram themeParam key |
|-----------------|------------------------|
| `--background` | `bg_color` |
| `--foreground` | `text_color` |
| `--card` | `secondary_bg_color` |
| `--card-foreground` | `text_color` |
| `--primary` | `button_color` |
| `--primary-foreground` | `button_text_color` |
| `--muted` | `secondary_bg_color` |
| `--muted-foreground` | `hint_color` |
| `--accent` | `link_color` |

Apply by injecting CSS custom properties on `<html>` element in a `useThemeParams` hook during app initialization. Fall back to PWA defaults when running in dev mock mode (`VITE_TMA_DEV=true`).

## Screens and States

This phase produces three UI states. All live in `features/auth/` folder.

### State 1: Auth Loading (initial mount)

Displayed while `AuthProvider` calls `POST /api/auth/tma` with initData.

- Full-screen centered layout: `min-h-screen flex items-center justify-center`
- Loading spinner: 32px × 32px, `animate-spin rounded-full border-4 border-muted border-t-primary`
- Label below spinner: "Вход через Telegram..." — 14px, regular, `text-muted-foreground`
- No page chrome (no header, no bottom nav)
- Motion: spinner appears with `initial={{ opacity: 0 }} animate={{ opacity: 1 }}` at 150ms ease-out

### State 2: Auth Success (authenticated shell)

Displayed after JWT received. Phase 36 placeholder — Phase 37 fills feature pages.

- Full-screen background `bg-background`
- Centered placeholder: display text "Добро пожаловать в RutTrack" — 20px semibold
- Sub-text: "Функции появятся в следующей версии" — 16px regular, `text-muted-foreground`
- No bottom nav in scaffold (Phase 37 adds navigation)
- Motion: content fades in with `initial={{ opacity: 0, y: 8 }} animate={{ opacity: 1, y: 0 }}` at 150ms ease-out

### State 3: Auth Error

Displayed when `POST /api/auth/tma` fails or returns non-2xx.

- Full-screen centered layout: `min-h-screen flex items-center justify-center p-4`
- Error card: `bg-card border border-border rounded-xl p-6 max-w-sm w-full`
- Icon: `WarningCircle` from Phosphor, 32px, `weight="bold"`, `text-destructive`
- Heading: "Не удалось войти" — 20px semibold
- Body: "Произошла ошибка при авторизации. Попробуйте перезапустить приложение." — 14px regular, `text-muted-foreground`
- Retry button: full-width, `bg-primary text-primary-foreground`, label "Попробовать снова" — triggers re-auth
- No secondary actions (no back, no cancel — Mini App has no other entry point)

### State 4: Dev Mock Banner (VITE_TMA_DEV=true only)

Displayed in all states when running in dev mock mode.

- Fixed top banner: `bg-yellow-400 text-yellow-900`, height 28px
- Text: "DEV MODE — mock user: {VITE_TMA_MOCK_USER}" — 12px regular
- Does not appear in production build

## Interaction Contract

### Auth Flow Interaction Sequence

1. App mounts → `TelegramThemeProvider` reads `themeParams`, writes CSS vars → renders `LoadingScreen`
2. `AuthProvider` extracts `initData` from `window.Telegram.WebApp.initData` (or mock in dev)
3. `POST /api/auth/tma` with `{ initData }` → on success: store access token in React state → transition to authenticated shell
4. On 401 or network error → transition to `ErrorScreen`
5. Retry button → repeat from step 2 with cached `initData`

No loading delay feedback below 300ms (spinner appears immediately on mount; if auth resolves in <300ms, loading flicker is acceptable — no artificial minimum delay).

### Dev Mock Interaction

When `VITE_TMA_DEV=true`:
- `MockWebApp` injected before React renders: `window.Telegram.WebApp = mockWebApp`
- `mockWebApp.initData` contains a pre-built valid-format initData string (bypassed in test JWT path)
- Auth call `POST /api/auth/tma` made with mock initData against real API Gateway (or intercepted in unit tests)
- `DevModeBanner` appears at top of every screen

### Touch Target Contract

All interactive elements:
- Minimum hit area: 44px × 44px (`min-h-[44px] min-w-[44px]`)
- Retry button: full-width, height 48px minimum
- No hover-only states (touch-first)

### Transition Contract

- Screen transitions (loading → success, loading → error): `opacity: 0 → 1`, `y: 8px → 0`, 150ms ease-out, using Motion `AnimatePresence mode="wait"`
- No layout shifts during auth: fixed viewport height, no reflow
- Spinner does not pulse or bounce — only rotate
