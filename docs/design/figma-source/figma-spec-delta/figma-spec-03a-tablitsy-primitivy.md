# figma-spec-03a-таблицы-примитивы.md

> Проход 03a спецификации компонентов RutCampusTrack.
> Основания — `figma-spec-00-основания.md`. Значения — `brandbook-v2.md`
> и `tokens-v2.json`. Состав — `COMPONENT_REGISTRY.md` v1.0 и `table-filters.md`.

**В этом проходе:** `DataTable` и его атомы, `TableColumnFilter`, `FilterBar`.
Журналы, ростер и статистические таблицы — проход 03b: они собираются поверх
этих примитивов.

**Сквозное правило прохода.** Отбор, порядок и пагинация — **только серверные**
(Р-17). Клиентского режима в продукте нет, пропов `filterMode` и `sortMode`
не существует. В библиотеке это значит: контролы отбора рисуются, состояние
«применено» отображается, но никакой логики за ними не подразумевается.

---

## 1. `shared/DataTable`

Реестр: табличный примитив, домена не знает. Владеет описанием колонок,
сортировкой, фильтрацией, раскрытием строки, фиксацией первого столбца и шапки,
горизонтальным скроллом, клавиатурным режимом крупной сетки и слотами состояний
`loading` / `empty` / `filtered-empty` / `error` **раздельно**.

### 1.1. Иерархия сборки

```
атом:      SortControl · FilterTrigger · SortPriorityBadge · ExpandTrigger
атом:      HeaderCell · Cell
компонент: HeaderRow · Row · ExpansionRow
компонент: DataTable
```

### 1.2. Анатомия `DataTable`

| Часть | Обязательность | Что это |
|---|---|---|
| `toolbar` | опционально (`has-toolbar`) | слот: `SearchField`, `ExportButton`, кнопка «Сбросить» |
| `scroll-container` | обязательна | горизонтальный скролл |
| `HeaderRow` | обязательна | один или два уровня |
| `body` | обязательна | список `Row` |
| `state-slot` | видим вместо `body` | `loading` / `empty` / `filtered-empty` / `error` |
| `footer` | опционально | слот под `Pagination` |

Auto Layout вертикальный, ширина `fill`, высота `hug`.

**Кнопка «Сбросить»** появляется в `toolbar`, как только активен хотя бы один
фильтр **или** хотя бы одна сортировка, и снимает всё сразу. Это одна кнопка,
а не две.

### 1.3. Оси

```
density = compact | regular | roomy
state   = default | loading | empty | filtered-empty | error
```
плюс boolean `has-toolbar`, `has-footer`, `sticky-first-column`,
`two-level-header`.

**`density` — ось варианта, а не три компонента.** Решение владельца.

**Четыре состояния пустоты различаются обязательно.** `empty` — запрос успешен,
данных нет. `filtered-empty` — фильтры не оставили строк. Их слияние —
дефект: пользователь решит, что данные сломались.

### 1.4. Размеры по плотности

| | `compact` | `regular` | `roomy` |
|---|---|---|---|
| высота строки | `row-height/compact` | `row-height/regular` | `row-height/roomy` |
| высота шапки | `row-height/compact` | `row-height/compact` | `row-height/regular` |
| padding ячейки по горизонтали | `space/2` | `space/3` | `space/3` |
| кегль ячейки | `dense` | `dense` | `body` |
| кегль шапки | `micro` | `micro` | `micro` |
| разделитель строк | `border/hairline` | `border/hairline` | `border/hairline` |

**Шапка не растёт вместе с плотностью до `roomy`.** Заголовок колонки набран
`micro` и в высокой строке начинает висеть в пустоте; при этом высота шапки
съедает те самые строки, ради которых плотность и настраивается.

**Только горизонтальные разделители.** Вертикальных линий в сетках данных нет —
приём мудборда. Разделитель `color/border/subtle`.

### 1.5. `HeaderCell`

**Анатомия**

| Часть | Обязательность |
|---|---|
| `label` | обязательна, `micro`, `color/text/muted` |
| `SortControl` | видим при `sortable` — сама подпись является кнопкой сортировки |
| `sort-icon` | видим при активной сортировке |
| `SortPriorityBadge` | видим при мультисортировке, `micro` |
| `FilterTrigger` | видим при наличии дескриптора `filter` — **отдельная кнопка** |
| `group-label` | видим при двухуровневой шапке |

**Два контрола в одном `<th>` — требование реестра.** Подпись-кнопка сортирует,
кнопка рядом открывает фильтр. У них разные доступные имена. В Figma это два
разных слоя с двумя разными `accessible-name`, а не один кликабельный заголовок.

**Оси**

```
sort  = none | asc | desc
state = default | hover | pressed | disabled
```
плюс boolean `sortable`, `filterable`, `filtered`, `has-priority`, `focus-ring`.

**Состояния**

| Состояние | Заливка | Подпись | Граница снизу |
|---|---|---|---|
| default | прозрачная | `color/text/muted` | `color/border/default` |
| hover | `color/surface/raised` | `color/text/secondary` | `color/border/strong` |
| pressed | `color/surface/float` | `color/text/primary` | `color/border/strong` |
| sorted (`asc`/`desc`) | прозрачная | `color/text/primary` | `color/border/strong` |
| filtered | прозрачная | `color/text/primary` + точка-признак | `color/border/strong` |
| disabled | прозрачная | `color/disabled/text` + причина | `color/border/subtle` |

**Сортировка помечена только у активной колонки** — приём мудборда. У остальных
иконка появляется на `hover`, а в покое её нет: двенадцать серых стрелок в шапке
это шум.

**Приоритет ключа виден в заголовке** — требование реестра. `SortPriorityBadge`
показывает номер, а не только направление: без номера мультисортировка
нечитаема.

### 1.6. `Cell`

**Анатомия**

| Часть | Обязательность |
|---|---|
| `content` | обязательна, instance swap |
| `ExpandTrigger` | видим при `expandable`, **внутри ячейки** |

**Оси**

```
align = start | end
state = default | disabled
```
плюс boolean `sticky`, `has-expand`.

`align=end` — для всех числовых колонок: выключка вправо, разряд под разрядом.
Это не оформление, а требование §2.1 направления.

Собственного `hover` у ячейки нет — подсветка принадлежит строке.

**Слоты `content`:** текст, `MetricValue`, `AttendanceStatusBadge`,
`TicketStatusBadge`, `EntityStatusCell`, шкала заполнения, `AppButton`,
`AppLink`, `RowActionsMenu`, `Checkbox`, `AttachmentList`. Полный список
по колонкам — в проходе 03b и далее.

### 1.7. `Row`

**Оси**

```
state = default | hover | selected | expanded | stale | disabled
```
плюс `focus-ring`.

| Состояние | Заливка | Засечка слева |
|---|---|---|
| default | прозрачная | нет |
| hover | `color/surface/raised` | нет |
| selected | `color/selected/fill` | `color/selected/border`, `border/emphasis` |
| expanded | `color/surface/raised` | нет |
| stale | `color/surface/raised` | нет, **пометка текстом: кем и когда решено** |
| disabled | прозрачная | нет, текст `color/disabled/text` |

**`stale` — состояние реестра**, не оформление: элемент решил другой оператор.
Действия в строке блокируются, причина показывается текстом. Без него двое
разбирают одну очередь и получают ошибку сервера вместо объяснения.

`selected` и `hover` сочетаются: наведение на отмеченную строку даёт
`color/selected/fill` без изменения — заливка выбора сильнее подсветки.

### 1.8. `ExpansionRow`

**Раскрытие — сдвиг в DOM, а не наложение.** Панель рендерится отдельной строкой
сразу после своей, во всю ширину таблицы.

| Часть | Обязательность |
|---|---|
| контейнер | обязательна, `color/surface/raised` |
| `content` | обязательна, instance swap |

Padding `space/4`, верхняя граница отсутствует — строка-родитель и панель
читаются как одно целое. Нижняя граница `border/hairline`.

Слоты: `StatsDetailPanel`, `ExcuseTicketPanel`, `StatsBySubjectTable`.

### 1.9. Фиксация

**Первый столбец.** При `sticky-first-column` первая ячейка каждой строки
не уезжает при горизонтальной прокрутке. Признак того, что контент под ней
скроллится, — вертикальная тень по правому краю столбца.

**Шапка.** Залипает при вертикальной прокрутке, получает `color/surface/float`
и горизонтальную тень снизу.

Обе тени — по правилу §6.2 брендбука: тень дублирует смену поверхности,
а не заменяет её. Нужен токен, см. §4.

**Фиксация не выводит из порядка табуляции** — требование реестра. В Figma
это отражается только тем, что залипший столбец остаётся обычной ячейкой,
а не отдельным компонентом-накладкой.

### 1.10. Переполнение

| Случай | Поведение |
|---|---|
| длинное ФИО, название предмета, имя группы | обрезка многоточием, полное значение в `Tooltip` и в доступном имени |
| число в четыре знака и больше | колонка растёт, обрезки нет |
| дробь `18/24` | не переносится и не обрезается |
| колонок больше, чем помещается | горизонтальный скролл, **колонки не скрываются** |
| пустое значение | прочерк `—` |
| строк больше страницы | `Pagination` в `footer`, не бесконечная лента |

**Ширина колонки.** Минимум — по самому длинному заголовку плюс два контрола
шапки. Максимум — 24rem для текстовых колонок; числовые растут свободно.

**Данные не исчезают при сужении.** Колонка уходит в скролл, но со страницы
не пропадает.

### 1.11. Клавиатура

Сетка с десятками интерактивных ячеек — **одна остановка Tab, навигация
стрелками внутри** (roving tabindex). В библиотеке это не отображается,
но влияет на анатомию: у `Cell` не может быть трёх независимых кнопок,
иначе матрица набирает тысячи остановок.

## 2. `shared/TableColumnFilter`

Реестр: фильтр в заголовке колонки поверх `Popover`. Тип фильтра, мультивыбор
и перечень значений приходят дескриптором колонки. Перечень **не собирается
из загруженной страницы**.

### 2.1. Анатомия

| Часть | Обязательность |
|---|---|
| `FilterTrigger` | обязательна — кнопка-иконка в `HeaderCell` |
| `Popover` | обязательна |
| `search` | видим при `searchable`, `SearchField` |
| `body` | обязательна — контрол по типу |
| `match-mode` | видим при `multiple` — «любое из» / «все» |
| `actions` | обязательна — «Применить» и «Сбросить» |

### 2.2. Оси

```
type  = enum | text | number | number-range | date | date-range | boolean
state = default | applied | disabled
```

Семь типов — ровно те, что перечислены в дескрипторе колонки. Больше
не заводится: тип приходит с сервера, и восьмого не существует.

### 2.3. Тела по типам

| `type` | Что внутри |
|---|---|
| `enum` | **`fieldset` с `Checkbox`**, не список с галочками. При `multiple=false` — `Radio` |
| `text` | `TextInput` |
| `number` | `TextInput` с числовой раскладкой |
| `number-range` | два `TextInput`, «от» и «до» |
| `date` | `DateRangePicker` `mode=single` |
| `date-range` | `DateRangePicker` `mode=range` |
| `boolean` | два `Radio`: да / нет |

### 2.4. Состояния

| Состояние | `FilterTrigger` |
|---|---|
| default | иконка `color/text/muted` |
| applied | иконка `color/text/primary` + точка-признак, **признак в доступном имени** |
| disabled | `color/disabled/text` + причина текстом, **не скрыт** |

`disabled` по `enabledWhen` — штатный случай, а не ошибка: фильтр статуса
неактивен, пока не выбрана роль. Причина обязательна.

**Возврат фокуса — на `FilterTrigger`**, а не на подпись колонки.

### 2.5. Три исключения реестра

Фильтр и сортировка есть у каждой колонки, кроме:

| Где | Что отсутствует |
|---|---|
| состав группы, 116 | ни фильтра, ни сортировки |
| список семестров, 134 | фильтр есть, сортировки нет |
| колонка «Почему черновик», 133 | фильтра нет |

В библиотеке это не варианты, а значения boolean `sortable` и `filterable`
у `HeaderCell`.

### 2.6. Переполнение

Длинный перечень значений — внутренняя прокрутка поповера, максимум 20rem
по высоте. Длинное значение переносится на две строки, дальше обрезается.

## 3. `shared/FilterBar`

Реестр: панель фильтров **над нетабличным списком**. Рисует контролы
по описанию с бэкенда, перечень полей не зашивает. Применяется на 114 и 119.

**На 132, 133 и 134 панель исчезла целиком, а не выродилась** — все её поля
оказались колонками. Каскадный выбор контекста на 122 и 123 экземпляром
`FilterBar` не является: это параметры запроса, без которых данных нет.

### 3.1. Анатомия

| Часть | Обязательность |
|---|---|
| `fields` | обязательна — горизонтальный список контролов |
| `sort-field` | опционально — поле типа `sort` там, где список не табличный |
| `reset` | видим при активном отборе |
| `result-count` | обязательна, `caption` — объявляется через `role="status"` |

Auto Layout горизонтальный с переносом, gap `space/3`, ширина `fill`,
высота `hug`. Поверхность `color/surface/raised`, радиус `radius/lg`,
padding `space/4`.

### 3.2. Оси

```
state = default | busy | disabled
```
плюс boolean `has-sort`, `has-reset`.

Размерных вариантов нет: панель одна на экран и всегда во всю ширину своего
региона.

### 3.3. Слоты

`fields` принимает: `SelectField`, `SubjectFilter`, `LessonTypePicker`,
`GroupFilter`, `DateRangePicker`, группу `Checkbox` в `fieldset`.

**Доменные контролы подставляются картой `controls`.** Примитив домена не знает —
в Figma это instance swap с дефолтом `SelectField`.

## 4. Нужен токен

| Токен | Значение | Почему |
|---|---|---|
| `shadow/sticky-x` | тёмная `4px 0 8px rgba(0,0,0,0.50)`, светлая `4px 0 8px rgba(41,37,49,0.08)` | тень залипшего первого столбца направлена вбок. `shadow/raised` и `shadow/overlay` имеют вертикальное смещение и вбок не работают |
| `size/column-max-text` | 24rem | потолок ширины текстовой колонки. Без него одно длинное название предмета растягивает колонку и выдавливает остальные в скролл |

Накопительно с прошлых проходов: `icon/size/sm|md|lg`, `size/dialog-width`,
`size/popover-max-width`.

## 5. Что осталось открытым

1. **`RowDetailTrigger`.** В реестре помечен как имя под вопросом и числится
   в открытых вопросах этапа 1.5. Здесь заведён атомом `ExpandTrigger` внутри
   `Cell` — по описанию `DataTable` («кнопка-триггер внутри ячейки»). Если реестр
   решит оставить отдельное имя, компонент переименовывается, анатомия
   не меняется.
2. **Высота шапки при `density=roomy`.** Выбрана `row-height/regular`, а не
   `roomy` — обосновано в §1.4. Решение спеки, не реестра; откатывается одним
   значением.
3. **Ширина первого залипшего столбца.** Зависит от самого длинного ФИО
   в реальных данных. Задаётся при сборке блока журнала, проход 03b.
4. **`useRovingGrid`.** Открытый вопрос реестра. На анатомию влияет только
   ограничением «не больше одного интерактивного элемента на ячейку» — оно
   здесь записано и соблюдается.
