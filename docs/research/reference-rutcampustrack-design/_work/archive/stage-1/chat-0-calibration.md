общий словарь компонентов, на который обопрутся следующие чаты.

СКОУП

ЭКРАНЫ В ЭТОМ ЧАТЕ (сканы прикреплены)
- ПК-001 — Вход (все роли)
- ПК-101 — Студент, Главная
- ПК-102 — Студент, Посещаемость

ЦВЕТОВАЯ КОДИРОВКА НА СКАНАХ — читай так:
- ЗЕЛЁНЫЙ = интерактивные управляющие элементы: кнопки, выпадающие списки.
- ЖЁЛТЫЙ = условное/наложенное содержимое: модальные и выпадающие окна, формы,
  объекты, появляющиеся после взаимодействия. Часть из них может присутствовать
  на странице по умолчанию — уточняй у меня, если неочевидно.
- КРАСНЫЙ = фиксированное отображение, пользователь не взаимодействует
  (взаимодействие возможно лишь изредка, если это логически следует или описано).

Важно: красный означает «нет взаимодействия», но НЕ означает «нет состояний».
Если красный блок показывает данные — у него всё равно есть loading, empty и error.
Учитывай это.

СНАЧАЛА изучи из знаний проекта:
- PROJECT_CONTEXT.md — что переписываем и текущий скоуп
- job-stories.md — какие сценарии по ролям уже описаны
- api-digest.md — какие данные сейчас доступны (112 операций)
- A11Y_REQUIREMENTS.md — что учитывать в структуре
- COMPONENT_REGISTRY.md — пока пустой, будешь его заполнять

ЗАТЕМ

3. Для каждого элемента указывай, какой цветовой группе он соответствует
   на скане, чтобы я мог сверить, что ты прочитал рисунок правильно.
4. После всех трёх — выдай стартовый COMPONENT_REGISTRY.md.

ПРО API
Бэкенд можно и будем менять под фронт. Не подгоняй экраны под текущие эндпоинты —
описывай, что реально нужно экрану, и помечай [предложение по бэкенду].
