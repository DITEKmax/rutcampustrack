## 4. Потребности в данных

### 4.1. Цепочка контекста

Идентична 4.1 экрана 122: мои группы → мои предметы выбранной группы → реально заведённые у предмета типы занятий. Источник тот же — `GET /academic/assignments/my`. Тот же **блокирующий** пробел с измерением «тип занятия» в назначении (123 — пятый потребитель).

### 4.2. Разрез «по студентам группы»

**Нужно:** строки — студенты группы (`userId`, ФИО). Фильтры: `groupId` + `subjectId` + `lessonType[]` + семестр. Значения: `%+`, `%(+ и у)`, `%у`, `%н` **и те же в количествах** (числитель и знаменатель): процент без абсолютных чисел не читается — «50 %» при двух парах и при тридцати значит разное. Знаменатель — только **прошедшие и не отменённые** пары выбранных типов. Пагинации нет — группа целиком. Сортировка по любому столбцу, включая ФИО.

**Сейчас:** **нет.** `GET /attendance/reports/student/stats` — статистика студента про себя; `headman-weekly/*` — недельный отчёт старосты по своей группе. Ни один не подходит ни по субъекту, ни по разрезу.

**Пробел `[предложение по бэкенду]` — высокий.** Нужен агрегат по группе в разрезе одного предмета и набора типов, доступный преподавателю в границах его назначений.

**Один агрегат на два экрана.** Эти же четыре числа стоят в хвосте строки журнала на 122. Если их посчитают в двух местах, цифры разойдутся — и разойдутся именно в отчёте для кафедры. **Предложение: один серверный агрегат; 122 отдаёт его вместе с сеткой, 123 запрашивает самостоятельно.** Клиентский расчёт исключён на обоих экранах.

**Сортировка и фильтрация — серверные.** ✏️ **Пересмотрено задачей 4 (Р-17): всё на сервере, везде** — включая наборы, приходящие целиком. Прежняя редакция закладывала клиентский режим, потому что здесь ≈25 строк и пагинации нет; отличие от 113 снято, режим один на весь продукт. Причина решения: два режима у одного контрола дают два разных поведения при одинаковом виде, а перенос «когда вырастет» на практике не делается никогда.

### 4.3. Разрез «по моим группам» (подтверждено владельцем, вариант «б») — и блокер, который он вскрыл

**Нужно:** строки — мои группы. Значения: те же четыре метрики + **«пар учтено»**. Фильтр — типы занятий и период.

**Пробел `[предложение по бэкенду]` — новый, высокий.** Нужен агрегат «мои группы × метрики» за семестр в границах моих назначений.

**⚠️ Блокирующая проблема идентичности предмета.** Предмет в системе принадлежит **группе**: `GET /academic/subjects` помечен «HEADMAN — только своя группа», а `SubjectNameField` (116.1) — свободный ввод с подсказкой, где **«подсказка защищает от разнописи, но ключом не является — все связи по id»** (§0 чат 5). Значит «Предмет 1» в УИТ-211 и «Предмет 1» в УИТ-311 — **два разных предмета с разными id**, и кросс-групповой идентичности предмета в модели **не существует**. Сравнить группы «по одному предмету» не по чему: сопоставление по названию прямо запрещено правилом чата 5.

**Как экран работает сегодня (проектируем так):**

| Ситуация | Путь | Итог |
|---|---|---|
| Разрез «по моим группам», предмет не выбран | агрегат по **всем моим парам** в каждой группе, с фильтром типов | Работает на существующей модели. Отвечает на вопрос «какая из моих групп проблемная» — а это и есть цель JS-TEACHER-06 |
| Разрез «по моим группам», выбран предмет | `SubjectFilter` в этом разрезе **`disabled` с текстовым пояснением**: «сравнение по одному предмету между группами станет доступно после доработки» | Честное `disabled` с причиной вместо молчаливого вранья по названиям |
| Появилась кросс-групповая идентичность предмета | фильтр включается, сравнение сужается до одного предмета | Требует бэкенд-решения: общий каталог предметов либо явная связка «эквивалентные предметы разных групп» |

**Почему нельзя сопоставить по названию на клиенте:** правило чата 5 запрещает это прямо, и не формально — «Матанализ» и «Мат. анализ» в двух группах дадут либо две строки вместо одной, либо ложное слияние разных дисциплин. В отчёте для кафедры это ошибка, которую никто не заметит.

**Строки-группы кликабельны:** нажатие переключает разрез на «по студентам» с этой группой. Иначе сравнение приводит к «эта группа плохая» без пути «а кто именно».

**Колонка «пар учтено» обязательна.** Группы имеют разное число прошедших пар: 60 % при четырёх парах и 60 % при тридцати — разные утверждения. Без этой колонки разрез сравнивает несравнимое.

### 4.4. Поведение при пустом выборе типов

**Требует подтверждения (предложение фронта).** Прим. 2 говорит только про «выбрать несколько». Предлагаю: **пустой выбор = все типы**, с явной подписью в `DefinitionList` («все типы занятий»). Альтернатива — держать таблицу в «выберите тип» — делает частый сценарий «итог по предмету целиком» лишним кликом без пользы.

### 4.5. Выгрузка

**Нужно:** отчёт по текущему разрезу в docx · pdf · png · html · xlsx, **с шапкой контекста внутри файла** (группа/группы, предмет, типы, период, учтено пар).

**Сейчас:** нет.

**Пробел `[предложение по бэкенду]`.** Это **второй шаблон**, отличный от журнального (122): у журнала — матрица пар, здесь — сводка. С разрезом «по моим группам» шаблонов фактически **три**. Все — в пяти форматах.

### 4.6. Границы данных

ФИО студентов выбранной группы и их посещаемость **только по моим парам**; в разрезе групп — только мои группы и только мои пары в них. Не видит: общую посещаемость студента по всем предметам, рейтинг, тикеты, учётные данные, чужие группы и чужие предметы. **Персональных документов на экране нет вовсе** — в отличие от 122 с вложениями.

### ⚠️ Фактура к решению о транспорте

| Сценарий | Запросов |
|---|---|
| Вход через меню | 1 (назначения) + 1 (агрегат после выбора предмета) |
| Вход из 121 по группе | 1 + 1 |
| Переключение типа занятия | +1 полный агрегат |
| Переключение разреза | +1 (другой агрегат, не тот же с параметром) |
| Выгрузка | +1 генерация |

Самый лёгкий по трафику экран роли (~25 строк × 8 значений), но **самый необеспеченный**: оба агрегата не существуют. Сводно по роли: 121 требует новых данных почти целиком, 122 работает на существующих эндпоинтах с непроверенными фильтрами, **123 не работает вовсе ни в одном разрезе**.

| `empty-group` | в группе нет студентов | «в группе нет студентов» |
| `error` / `forbidden` / `offline` | — | `ErrorState` + повтор / `ForbiddenState` / `OfflineState` |

### `StatsByGroupTable` (разрез «по моим группам») — автомат состояний

| Состояние | Условие | Что показываем |
|---|---|---|
| `loading` | агрегат грузится | скелетон |
| `success` | ≥2 моих групп с прошедшими парами | строки-группы, четыре метрики + «пар учтено» |
| **`single-group`** | **у преподавателя ровно одна группа** | **пояснение «сравнивать не с чем» + переход в разрез по студентам. Таблица из одной строки — не сравнение, а вводящий в заблуждение отчёт** |
| `future` | ни в одной группе пары ещё не прошли | «пар ещё не было», не нули |
| `partial` | в части групп пары прошли, в части нет | группы без прошедших пар показываются **с «нет данных»**, а не с 0 % — иначе они возглавят рейтинг проблемных |
| `filtered-empty` | выбранные типы не дают пар ни в одной группе | пояснение с указанием фильтра |
| `subject-filter-unavailable` | пользователь пытается сузить до предмета | `SubjectFilter` `disabled` **с текстовой причиной** (§4.3), а не молча погашен |
| `no-assignments` | назначений нет вовсе | как на 121: объяснение, к кому обратиться |
| `no-active-semester` | активного семестра нет | агрегат не запрашиваем |
| `error` / `forbidden` / `offline` | — | стандартные |

**Отменённые пары в знаменатель не входят** (термин §7 реестра) — иначе отменённая лекция ухудшает статистику всей группы.

### Сортировка (подтверждено владельцем)

Сортировка **по всем столбцам**, включая ФИО и название группы. Дефолт — **по `%+` по возрастанию**: проблемные сверху, это прямая цель JS-TEACHER-06. Сортировка одиночная (не накопление приоритетов, как у `StatsBySubjectTable`) — четыре числовые колонки накопления не требуют. Каждый разрез помнит свою сортировку.

**Фильтрация в заголовках колонок.** По всем колонкам, отбор серверный (§4.2). Числовые колонки метрик фильтруются диапазоном (`type: 'numberRange'` — «`%+` ниже 50»), ФИО и название группы — подстрокой. **Каждый разрез помнит свои фильтры**, как и сортировку; память принадлежит `TeacherStatsPage` (K1), не таблице. Мультисортировка **без предела ключей**, приоритет виден в заголовке колонки; кнопка «Сбросить» снимает фильтры **и** сортировки разом (Р-17). Смена разреза фильтры другого разреза не сбрасывает. Состояние `filtered-empty` отличается текстом от `empty` — правило §6.2.

### Остальные блоки

Фильтры, `DefinitionList` и таблица независимы: падение агрегата не гасит фильтры. `ExportButton` недоступна, пока таблица не построена, — **с пояснением**; во время генерации — `busy`.

### По ролям

Экран одноролевой. Совмещённый teacher + admin видит `RoleSwitcher`; при активной роли admin маршрут отдаёт `forbidden`. Содержимое от совмещения не меняется.

## 6. Навигация и действия

| Элемент | Действие |
|---|---|
| `Tabs` | переключение разреза, то есть подмена компонента таблицы. Фильтры разрезов **независимы**, друг друга не сбрасывают; память разреза принадлежит странице (K1); смена объявляется |
| `GroupFilter` | выбор группы. **Сбрасывает предмет и типы.** Сброс объявляется, а не происходит молча |
| `SubjectFilter` | выбор предмета. Сбрасывает типы, размораживает переключатель типов. В разрезе групп — `disabled` с причиной |
| `LessonTypePicker` | мульти-выбор, пересчёт. Тип без пар у предмета — `disabled` с пояснением |
| Заголовок колонки — подпись-кнопка | сортировка по этому столбцу, `aria-sort`, фокус остаётся на заголовке. **Отдельный контрол**, фильтр не открывает |
| Фильтр в заголовке колонки — кнопка рядом с подписью | открывает `Popover` с отбором по колонке; активный фильтр помечен видимо **и текстом**, признак — в доступном имени кнопки. Клиентский, значение живёт в памяти разреза |
| Строка студента | **не кликабельна** (детализации нет) |
| **Строка группы** | переключает разрез на «по студентам» с этой группой — путь от «какая группа плохая» к «кто именно» |
| `ExportButton` «Скачать» | генерация сводки по текущему разрезу. Подтверждения нет, `busy` обязателен |
| `MainNav` | 121 / 122 / 123 / 105 |

Оптимистичного UI нет: экран ничего не меняет на сервере.

**Контекст в URL:** разрез, `groupId`, `subjectId`, `lessonType[]`, сортировка — по идентификаторам (правило чата 5). Приход с 121 задаёт только `groupId` и разрез «по студентам». F5 и пересылка ссылки сохраняют картину; между сессиями не сохраняем.

**Нехватка прав**

| Ситуация | Итог |
|---|---|
| Неавторизованный | редирект на 001 с сохранением адреса возврата |
| Нет роли teacher | `ForbiddenState` |
| Нет назначений | `no-assignments` |
| Прямая ссылка на чужую группу или чужой предмет | серверный 403 → `ForbiddenState`; клиентская проверка — только UX, не защита |

**A11y (структурно)**

- `<h1>` «Статистика», `<h2>` у фильтров и таблицы. `Tabs` — ARIA tablist с переводом фокуса в панель.
- `DefinitionList variant="inline"` — **список определений**, не таблица; читается до таблицы, чтобы сводка была самодостаточной вслух.
- Настоящая `<table>`: `<th scope="row">` = ФИО или название группы, `<th scope="col">` = метрика.
- **Подписи колонок словами** — «Процент присутствия», «Процент присутствия и уважительных», а не «% +» и «% + и у»: символ `+` вслух не читается.
- Абсолютные числа — в той же ячейке, одной фразой в доступном имени: «72 %, 18 из 25 пар».
- Сортировка: `aria-sort` на активном заголовке, результат объявляется через `role="status"` («отсортировано по проценту присутствия, по возрастанию»), **фокус остаётся на заголовке**.
- В `<th>` фильтруемой колонки **два контрола с разными доступными именами**: подпись-кнопка сортирует, кнопка рядом открывает фильтр. Возврат фокуса после закрытия поповера — на кнопку-триггер фильтра.
- Пересчёт после смены фильтра или разреза объявляется `role="status"`: разрез, предмет, типы, число строк и учтённых пар.
- Таблица небольшая (≈25 строк × 4–5 колонок) — правило крупных сеток и roving tabindex не применяются.
- Строка-группа кликабельна: **ссылка/кнопка внутри ячейки названия**, `<tr>` кнопкой не делаем (правило `RowDetailTrigger`).
- `ExportButton`: доступное имя включает разрез и формат («Скачать статистику: УИТ-211, Предмет 1, лекция, xlsx»).

## 7. Заметки на будущее

**Адаптив.** Экран узкий: пять колонок и подпись строки помещаются даже на 1280 без скролла. **Критично не потерять:** абсолютные числа рядом с процентами (их схлопывают первыми), соседство `%+` и `%(+ и у)`, колонку «пар учтено» в разрезе групп, шапку контекста. Кандидат на отдельный мобильный экран — карточка студента с четырьмя метриками; PWA отдельная поверхность и отдельный цикл.

### Дублирует ли 123 журнал со 122

**В разрезе «по студентам» — частично да, и это надо признать прямо.** При одинаковых фильтрах четыре числа равны хвостовым колонкам строки на 122. Разграничение (для §8 реестра):

| Экран | Зона ответственности |
|---|---|
| **122 Посещаемость** | **события**: что было на каждой конкретной паре, включая причины «у» и документы. Ответ на «что произошло 12 марта» |
| **123, разрез по студентам** | **итог по одной группе**: сводка за семестр без разреза по парам. Ответ на «кто провален по предмету». Читается и выгружается как самостоятельный документ |
| **123, разрез по группам** | **сравнение моих групп между собой.** Аналога в 122 нет вовсе — этот разрез 123 не дублирует ничего |

Аналогия с уже разобранным: 102 против 103 у студента, 112 против 113 у старосты — та же пара «факты против агрегатов». Разрез по группам — то, чего нет ни у одной другой роли: student и headman привязаны к одной группе по определению.

**Открытые вопросы и риски**

1. **Кросс-групповая идентичность предмета отсутствует** — новый блокер, вскрытый разрезом по группам (§4.3). До решения фильтр предмета в этом разрезе недоступен с пояснением.
2. **Единый агрегат для 122 и 123** — иначе расхождение цифр в отчётах для кафедры.
3. **Три шаблона отчёта** (журнал, сводка по студентам, сводка по группам) × пять форматов.
4. **Пустой выбор типов** — предложение «все типы», требует подтверждения.
5. **Порядок метрик на 122** приведён к каноническому — файл 122 выпущен раньше решения, требует правки (§11).
6. **Закрыто (K1).** Обёртки над `Tabs` сведены: на 123 используется сам `Tabs`, память разреза принадлежит странице.
7. **Графики нет ни на одном экране роли.** У student и headman динамика есть; преподаватель не видит тренда вообще. Наблюдение, не пробел рисунка.
8. ✏️ **Пункт снят задачей 4:** сортировка и фильтрация серверные с самого начала (Р-17), переносить нечего.

## Решения задачи 4 — внесено 01.08.2026

Источник — `02-backend/backend-conflicts.md`. Правила ниже имеют приоритет над более ранними формулировками этой спеки.

**Границы данных (Р-15).** «Предмет 1» в разных группах — **разные записи**: общего каталога дисциплин не будет, староста заводит предметы своей группы вручную.
