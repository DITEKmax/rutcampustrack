# Сборка библиотеки в Figma — план, проверки, промпты

> Вход: `tokens-v2.json`, `brandbook-v2.md`, `figma-spec.md`, `COMPONENT_REGISTRY.md`.
> Выход: файл дизайн-системы с переменными, текстовыми стилями и библиотекой компонентов.
> Экраны собираются после, из этой библиотеки.

---

## 0. Что решить до первой команды агенту

Три вещи, каждая может остановить работу на середине.

### 0.1. Тариф и место в Figma

Лимиты MCP-сервера Figma привязаны к месту, а не к аккаунту:

| Место | Лимит вызовов |
|---|---|
| Starter, либо View / Collab на платном тарифе | **до 6 вызовов инструментов в месяц** |
| Dev или Full на Professional и выше | поминутные лимиты уровня Tier 1 REST API |

Шести вызовов не хватит даже на одну коллекцию переменных. **Для этой работы нужен Dev или Full seat на Professional.** Это отдельная причина платить, помимо ограничения бесплатного тарифа в три файла по три страницы.

### 0.2. Как заводятся переменные

**REST API для переменных закрыт всем, кроме Enterprise.** Ни чтение, ни запись на Professional не работают — это давнее и не изменившееся ограничение Figma. Пайплайн «скрипт читает `tokens-v2.json` и постит в REST» на нашем тарифе не соберётся.

Работают два пути:

1. **Plugin API** — создание переменных доступно на любом тарифе. Пишущие Skills MCP-сервера — обёртка над ним.
2. **Ручной импорт** плагином вроде импортёра токенов.

Проверить это надо **до** того, как агент начнёт: пусть первым делом заведёт одну тестовую переменную и покажет результат. Если не может — дальше идти бессмысленно, меняем путь.

### 0.3. Каким клиентом

MCP-сервер Figma открыт не любому агенту: он ограничен списком одобренных клиентов, произвольное приложение через OAuth к нему не подключится. Запись в канву (Code to Canvas) запускалась в связке с Claude Code — это заведомо рабочий путь. Для любого другого агента **сначала проверь, поднимается ли соединение**, и только потом планируй на него работу.

Отдельно: писать в канву агент умеет «кодом во фреймы». Это хорошо ложится на блоки и экраны и хуже — на матрицу вариантов компонента. Заложи, что часть вариантов придётся досоздавать плагином или руками.

## 1. Принципы, из которых следует весь порядок

**Одно место правки.** Смена гарнитуры, оттенка, радиуса или шага отступов должна быть правкой одного значения. Отсюда: ни одного литерала в слое. Цвет, размер, отступ, радиус, толщина границы — только связанные переменные.

**Снизу вверх.** Сначала самое мелкое, потом то, что из него собрано. Атом → компонент → блок → экран. Компонент, собранный из литералов, потом дешевле перерисовать, чем связать с переменной задним числом.

**Максимум переиспользования, но не любой ценой.** Инстанс вместо копии всегда. Вариант вместо второго компонента — только когда анатомия та же. Разный контракт фокуса, разный источник данных, разный набор частей — это разные компоненты, а не варианты.

**Логика в одном месте.** Если правило («у отключённой кнопки курсор обычный») повторено в пяти компонентах — оно должно жить в одном и наследоваться.

## 2. Порядок шагов

Каждый шаг заканчивается проверкой. Не переходить дальше, пока проверка не прошла.

### Шаг 1. Файл и структура страниц

Один файл дизайн-системы. Страницы: `01 Основания`, `02 Атомы`, `03 Компоненты`, `04 Блоки`, `05 Песочница`.

*Проверка:* страницы созданы, файл назван, доступ есть.

### Шаг 2. Коллекции переменных

Из `tokens-v2.json`. Коллекции и режимы:

- `primitives` — один режим. Сырые ступени всех шкал.
- `semantic` — два режима: `dark` и `light`. Каждая переменная ссылается на примитив, а не на значение.
- `size` — один режим. Отступы, радиусы, границы, высоты, плотность.
- `component` — один режим. Ровно три токена из §10 брендбука.

*Проверка, обязательная:*
- ни одна семантическая переменная не содержит прямого значения — только ссылку на примитив;
- переключение режима `semantic` меняет обе темы целиком;
- количество совпадает с `tokens-v2.json`: 77 + 61 + 48 + 3;
- имена совпадают с JSON посимвольно, включая слэши.

### Шаг 3. Текстовые стили

Из типографической шкалы брендбука §3.3. Гарнитура Onest. Каждый стиль: размер, вес, межстрочный, межбуквенный.

*Обязательно:* включить функцию табличных цифр там, где стиль обслуживает числа. У Onest они не стоят по умолчанию.

*Проверка:* стилей столько же, сколько ступеней в шкале; ни одного текстового слоя без стиля дальше по работе; числа в тестовой таблице выстроены по разряду.

### Шаг 4. Эффекты и сетка

Две ступени тени из §6.2. Сетка трёх ширин: 12 колонок, желоба и поля из файла 00 спеки.

*Проверка:* тень нигде не единственное отличие уровня поверхности — убери её, иерархия должна сохраниться.

### Шаг 5. Атомы

Самое мелкое, что не собрано ни из чего: `TextInput`, `DayNumber`, ячейка, чип, иконка-обёртка, `ProgressScale`, бейджи статусов.

Для каждого — все состояния из `figma-spec`, все размерные варианты.

*Проверка после каждого атома:*
- ни одного литерала — выдели слой, каждое значение показывает имя переменной;
- Auto Layout стоит везде, где спека его требует;
- оси вариантов в порядке `type → size → state`;
- состояния покрыты полностью, пустых клеток матрицы нет.

### Шаг 6. Компоненты

По проходам `figma-spec` 01–06, в этом порядке: действия и формы → каркас и навигация → таблицы и сетки → значения и статусы → доменные карточки и панели → состояния.

Каждый компонент собирается **из инстансов атомов**, не из новых слоёв.

*Проверка после каждого прохода:*
- ни одной отсоединённой копии — только инстансы;
- правка атома доходит до всех компонентов, которые его используют (проверять руками: измени радиус атома, посмотри на компоненты);
- имена по схеме `<владение>/<Компонент>`;
- свойства, вынесенные в property, вынесены везде одинаково.

### Шаг 7. Блоки

По проходу 07 спеки. У каждого блока варианты ширины 1920 / 1440 / 1280.

*Проверка:* адаптив получается **переключением варианта блока**, а не растягиванием фрейма. Если для 1440 пришлось что-то двигать руками — вариант собран неверно.

### Шаг 8. Публикация

Опубликовать библиотеку. Экраны собираются в отдельном файле, подключённом к ней.

*Проверка:* в файле экранов ни одного локального компонента — все приходят из библиотеки.

## 3. Сквозной чек-лист

Прогонять после каждого прохода, не в конце.

- [ ] Ноль литералов: цвет, размер, отступ, радиус, граница — везде переменные
- [ ] Ноль текстовых слоёв без текстового стиля
- [ ] Ноль отсоединённых инстансов
- [ ] Переключение режима `semantic` даёт корректную светлую тему без ручных правок
- [ ] Смена значения гарнитуры в переменной меняет весь файл
- [ ] Имена совпадают с `tokens-v2.json` и `figma-spec.md`
- [ ] Матрицы вариантов полные, без пустых сочетаний
- [ ] Ни один компонент не превышает 24 варианта — остальное в property

## 4. Промпт для Claude Code

Запускать в пустой папке проекта, где лежат четыре входных файла.

```
Собираем библиотеку дизайн-системы в Figma через Figma MCP.
В папке проекта: tokens-v2.json, brandbook-v2.md, figma-spec.md,
COMPONENT_REGISTRY.md. Это единственные источники — ничего
не придумывай и не бери из общих практик.

ПЕРЕД РАБОТОЙ
1. Проверь, что MCP-соединение с Figma поднято и у тебя есть
   доступ к целевому файлу.
2. Заведи ОДНУ тестовую переменную и покажи результат. Если
   создание переменных недоступно — остановись и скажи, что
   именно не работает. Не обходи ограничение и не переходи
   к следующему шагу.

ПОРЯДОК — СТРОГО ЭТОТ
Переменные → текстовые стили → эффекты и сетка → атомы →
компоненты → блоки. Ни один шаг не начинается, пока предыдущий
не проверен. Порядок не оптимизируется: слой, нарисованный
на литералах, потом дороже связать с переменной, чем перерисовать.

ГЛАВНОЕ ПРАВИЛО
Ни одного литерала. Цвет, размер, отступ, радиус, толщина
границы — только связанные переменные. Текст — только
текстовым стилем. Если для чего-то нет переменной, остановись
и скажи, а не подставляй число.

ПЕРЕМЕННЫЕ
Четыре коллекции из tokens-v2.json: primitives (один режим),
semantic (два режима — dark и light), size, component.
Семантические переменные ССЫЛАЮТСЯ на примитивы, а не содержат
значения. Имена — посимвольно как в JSON, включая слэши.

КОМПОНЕНТЫ
Состав и анатомия — только из figma-spec.md. Список компонентов —
только из COMPONENT_REGISTRY.md. Новых не заводить, существующие
не сливать.
Собираются снизу вверх: сначала атомы со всеми состояниями,
потом компоненты ИЗ ИНСТАНСОВ атомов. Копий не делать — только
инстансы: правка атома обязана доходить до всех потребителей.
Оси вариантов: type → size → state. Потолок 24 варианта
на компонент, остальное в property.
Разные компоненты, а не варианты, если различается набор частей,
источник данных или контракт фокуса.

РАБОТАЙ ПАРТИЯМИ
Одна партия — один проход figma-spec. После каждой партии
остановись, покажи что сделано и что проверил по списку:
литералы, отсоединённые инстансы, полнота матрицы состояний,
совпадение имён. Жди подтверждения.

НЕ ДЕЛАЙ
- Не собирай экраны — это отдельный этап после библиотеки.
- Не улучшай систему: расхождение спеки с твоим представлением
  о хорошем — повод сказать, а не повод исправить.
- Не подставляй значения по умолчанию Figma вместо наших.
```

## 5. GPT-5.6 Sol — где запускать

**Не в браузере.** Работа требует локальных файлов и живого MCP-соединения; вкладка ни того, ни другого не держит.

Годится агентная среда с поддержкой MCP — Codex или десктопное приложение с подключением инструментов. **Первым делом проверь, что клиент вообще получает доступ к MCP-серверу Figma:** список допущенных клиентов ограничен, и произвольное приложение к нему не подключится. Если соединение не поднимается, вопрос выбора модели снимается сам.

Промпт из §4 переносится дословно — он не завязан на конкретного агента. Добавь в начало один абзац под среду:

```
Работай в проекте с четырьмя файлами в рабочей папке. Инструменты
Figma подключены через MCP. Перед первым действием выведи список
доступных инструментов Figma и подтверди, что среди них есть
создание переменных и компонентов. Если чего-то нет — скажи это
и остановись.
```

Разделение труда, если доступны оба агента: один ведёт всю сборку от начала до конца, второй не подключается к тому же файлу параллельно. Два агента в одном файле Figma расходятся молча — конфликт обнаружится через десять компонентов.

## 6. Типовые ошибки, которых стоит ждать

| Ошибка | Как поймать | Почему дорого |
|---|---|---|
| Литерал вместо переменной | выделить слой, посмотреть, показано ли имя переменной | смена оттенка перестаёт быть правкой одного места |
| Копия вместо инстанса | панель слоёв: у инстанса ромб | правка атома не доходит, расхождение всплывает через месяц |
| Семантическая переменная с прямым значением | открыть переменную, посмотреть, ссылка это или значение | светлая тема начинает жить своей жизнью |
| Текст без стиля | выделить всё, проверить панель типографики | смена гарнитуры не проходит по файлу |
| Вариант вместо отдельного компонента | сверить с правилом §1 файла 00 спеки | инстанс с двумя контрактами не проверяется взглядом |
| Адаптив растягиванием | открыть блок на 1440 и посмотреть, вариант это или ручная правка | три ширины расходятся, дальше их не свести |
