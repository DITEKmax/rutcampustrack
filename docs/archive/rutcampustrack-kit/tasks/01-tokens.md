# Этап 1 — переменные, темы, типографика

Первый этап. До него ни одного компонента.

## Что сделать

1. **Перенести токены из `design/tokens-v2.json` в CSS-переменные.**
   Три слоя: примитивы → семантические → компонентные. Семантические
   **ссылаются** на примитивы, а не содержат hex.
   Имена — посимвольно как в JSON.

2. **Завести обе темы.** Переключение атрибутом на корне.
   Композиция при смене темы не меняется, меняются только значения.
   Светлая тема — второй набор значений тех же семантических переменных.

3. **Типографика.** Гарнитура Onest переменной. Шкала из `brandbook-v2.md`
   в rem: размер, вес, межстрочный, межбуквенный.
   **Табличные цифры включить глобально в базовом слое** — у Onest они
   не по умолчанию.

4. **Остальные шкалы:** отступы, радиусы, толщины границ, кольцо фокуса,
   две ступени тени, длительности и кривые движения, высота строки таблицы.

5. **Собрать страницу-образец** — не экран продукта: все ступени всех шкал
   плашками с именем токена и hex, типографическая шкала живым русским
   текстом, таблица чисел на шесть строк для проверки разряда.
   Она нужна, чтобы увидеть систему глазами до первого компонента.

## Чем закончить

Отчёт по чек-листу скилла плюс отдельно:
- каких токенов не хватило и для чего;
- где `tokens-v2.json` и `brandbook-v2.md` разошлись, если разошлись.

## Проверка перед следующим этапом

- [ ] Переключение темы даёт корректную светлую без ручных правок
- [ ] Ни одна семантическая переменная не содержит hex напрямую
- [ ] Смена значения гарнитуры меняет весь файл
- [ ] Числа в таблице-образце выстроены по разряду
- [ ] Контраст посчитан числом для каждой пары «текст на поверхности»
