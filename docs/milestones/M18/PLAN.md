# M18 — Экспорт недельного отчета старосты в DOCX/PDF/PNG

**Статус:** закрыто
**Старт / финиш:** 2026-05-02 / 2026-05-03
**Estimate:** 8-12 человеко-дней

---

## Scope

M18 превращает проверенный шаблон `headman-weekly.docx` в пользовательскую функцию скачивания отчета старосты.

В scope входит:

- скачивание отчета только старостой своей группы;
- экспорт одной текущей недели со страницы `headman/weekly-journal`;
- экспорт нескольких выбранных недель, в том числе не подряд;
- форматы `docx`, `pdf`, `png`;
- одинаковый пользовательский сценарий в web-panel и PWA;
- backend-сбор данных из `schedule-service`, `attendance-service`, `academic-service`;
- backend-генерация DOCX и backend-конвертация в PDF/PNG;
- тесты на шаблон, маппинг данных, RBAC, форматы ответа и UI.

Не входит:

- ручной предпросмотр отчета перед скачиванием;
- редактирование нижней части шаблона: поля "староста" и "подпись" остаются пустыми для ручного заполнения;
- поддержка групп больше 35 студентов или дней больше 5 пар в текущем шаблоне;
- доступ преподавателю, администратору или обычному студенту.

## Пользовательские сценарии

### Web-panel

Страница: `https://ruttrack.site/headman/weekly-journal`.

На странице появляются две кнопки:

- `Скачать отчет за текущую неделю` — открывает компактный выбор формата `docx/pdf/png` и сразу скачивает отчет за неделю, открытую в журнале.
- `Скачать несколько недель` — открывает модалку со списком всех недель активного семестра.

В модалке выбора нескольких недель:

- каждая строка содержит номер учебной недели и диапазон дат `понедельник-воскресенье`;
- недели выбираются чекбоксами;
- можно выбрать недели не подряд;
- формат выбирается один на весь экспорт: `docx`, `pdf` или `png`;
- после подтверждения файл скачивается сразу, без страницы предпросмотра.

### PWA

На странице `Группа` добавляется отдельный блок отчетов старосты.

Функционально блок повторяет web-panel:

- выбор недели или нескольких недель;
- выбор формата `docx/pdf/png`;
- скачивание файла сразу после подтверждения.

Блок виден только старосте.

## Форматы результата

### Одна неделя

- `docx` — один `.docx` файл, одна печатная страница.
- `pdf` — один `.pdf` файл, одна печатная страница.
- `png` — один `.png` файл, вся альбомная печатная страница целиком.

### Несколько недель

- `docx` — один многостраничный `.docx`, каждая выбранная неделя на отдельной странице.
- `pdf` — один многостраничный `.pdf`, каждая выбранная неделя на отдельной странице.
- `png` — `.zip` архив, внутри отдельный `.png` на каждую выбранную неделю.

Если выбраны недели не подряд, имя файла содержит пометку `_С_ПРОПУСКАМИ`.

## Источники данных

- `schedule-service` — расписание выбранных недель, номера/типы пар, предметы, отмененные пары.
- `attendance-service` — отметки посещаемости.
- `academic-service` — состав группы, активный семестр, метаданные группы.

Отмененные пары не включаются в отчет. Если все пары дня отменены или занятий нет, день остается пустым.

## Правила заполнения

- Статусы:
  - `present` -> `+`
  - `absent` -> `н`
  - `excused` / `free_attendance` -> `у`
- Шаблон содержит максимум 5 пар в день.
- Шаблон содержит максимум 35 студентов.
- Нижние поля для старосты и подписи не заполняются автоматически.
- Даты недели всегда считаются как `понедельник-воскресенье`, включая воскресенье даже без занятий.

## Ошибки и ограничения

- Если в выбранной неделе больше 5 пар в один день, backend возвращает `422` с понятным сообщением.
- Если в группе больше 35 студентов, backend возвращает `422` с понятным сообщением.
- Если неделя вне активного семестра, backend возвращает `422`.
- Если формат неизвестен, backend возвращает `400`.
- Если пользователь не староста, backend возвращает `403`.

## Имя файла

Формат имени:

```text
{groupCode}_{dateFrom}_{dateTo}.{ext}
```

Пример одной недели:

```text
УВПВ511_27.04.2026_03.05.2026.docx
```

Пример нескольких недель с пропусками:

```text
УВПВ511_27.04.2026_31.05.2026_С_ПРОПУСКАМИ.pdf
```

Для PNG-архива:

```text
УВПВ511_27.04.2026_31.05.2026_С_ПРОПУСКАМИ_png.zip
```

## Модули / изменения

### Backend: attendance-service

- `report-templates/headman-weekly.docx` — использовать текущий проверенный шаблон из M17.
- `HeadmanWeeklyReportService` — собирает данные по выбранным неделям и строит модель шаблона.
- `DocxRenderer` — заполняет DOCX-шаблон.
- `ReportExportController` или расширение `ReportController` — endpoints скачивания.
- API не принимает `groupId` от клиента: группа берется из `RequestContext`, чтобы не открыть IDOR.

Предлагаемый API:

- `GET /api/attendance/reports/headman-weekly/current?weekStart=YYYY-MM-DD&format=docx|pdf|png`
- `POST /api/attendance/reports/headman-weekly/export`

Тело `POST`:

```json
{
  "weekStarts": ["2026-04-27", "2026-05-11"],
  "format": "pdf"
}
```

### Backend: document-renderer-service

PDF и PNG лучше вынести в отдельный внутренний renderer-сервис/контейнер.

Причина: LibreOffice/headless и системные зависимости тяжелые для `attendance-service`, сложнее тестируются и могут влиять на стабильность основного сервиса. `attendance-service` должен генерировать DOCX и вызывать renderer только для `pdf/png`.

С учетом правил `CLAUDE.md` renderer не должен быть "маленьким REST-сервисом без контракта".

Целевой вариант:

- `services/document-renderer-service/document-renderer-app/` — Spring Boot app без публичного REST API;
- `proto/document_renderer.proto` — gRPC-контракт конвертации;
- межсервисный вызов из `attendance-service` в renderer — только gRPC;
- actuator/health endpoint допускается для Docker healthcheck, но не является пользовательским REST API;
- Gateway не проксирует renderer наружу.

Минимальный gRPC-контракт renderer-сервиса:

- вход: DOCX bytes + target format `pdf` или `png`;
- выход: PDF bytes или PNG bytes;
- доступ только из внутренней Docker-сети;
- timeout и понятная ошибка при сбое конвертации.

Если позже renderer понадобится как публичный REST API, по правилу contract-first придется добавить `document-renderer-api-contract` и интерфейсы контроллеров. В M18 это не нужно.
