## 1. Общее для матриц

`AttendanceJournalGrid` — двухосная сетка, а не поток. Auto Layout
на ней не применяется: строки и колонки задаются сеткой, иначе
600–1000 ячеек начинают пересчитываться при каждой правке.

**Ограничение реестра:** ~600–1000 ячеек в одном ответе, примитив не должен
добавлять пообъектной обвязки на ячейку.

**Следствие для Figma, важное практически.** Матрица 25×24 — это 600 инстансов
в одном фрейме. Файл с несколькими такими макетами становится неработоспособным.
Поэтому:

- в библиотеке хранится **фрагмент сетки 8 колонок × 6 строк** со всеми
  состояниями ячейки, а не полная матрица;
- полноразмерная сетка собирается один раз, в макете экрана, и переиспользуется
  инстансом целиком;
- ячейка не имеет вложенных компонентов глубже одного уровня.

## 2. `attendance/AttendanceJournalGrid`

Реестр: матрица **строки — студенты, колонки — пары**. Над парами одного дня
объединённая ячейка с датой. Первый столбец ФИО фиксирован, горизонтальный
скролл, порядок строк **всегда алфавитный**, сортировки и фильтров по колонкам
нет ни в одном применении.

### 2.1. Анатомия

```
DateHeaderRow     объединённые ячейки дат (или предметов)
ColumnHeaderRow   пара: тип занятия + время либо предмет + тип
├ NameColumn      фиксирован, ФИО
├ CellGrid        матрица ячеек
└ MetricColumns   хвостовые колонки метрик, только у teacher
```

| Часть | Обязательность |
|---|---|
| `DateHeaderRow` | обязательна — верхний уровень шапки |
| `ColumnHeaderRow` | обязательна — нижний уровень |
| `NameCell` | обязательна, залипшая |
| `JournalCell` | обязательна |
| `MetricCell` | видима при `has-row-metrics` |
| `rhythm-divider` | каждые 5 строк |

**`rhythm-divider` — оформление, не структура.** Реестр требует прямо: деление
каждые 5 студентов не превращается в группы строк. В Figma это линия
`color/border/default` поверх обычного разделителя `color/border/subtle`,
а не отдельный контейнер.

### 2.2. Оси

```
lesson-scope  = subject | week
cell-mode     = edit | read
column-label  = date-type | subject-type
```
плюс boolean `has-row-metrics`, `sticky-first-column`, `cross-highlight`.

Состояний у сетки нет — они принадлежат ячейке и строке. Слоты состояний
(`loading` / `empty` / `error`) наследуются от `DataTable`.

**`lesson-scope`** различает два разреза 112: по предмету и по неделе. Ось
колонок та же, шапка та же двухуровневая; различие — правило отбора колонок
и подписи. Поэтому это вариант, а не второй компонент.

### 2.3. Размеры

| | значение |
|---|---|
| высота строки | `row-height/compact` |
| ширина колонки пары | `size/journal-column` |
| ширина колонки ФИО | `size/name-column` |
| ширина колонки метрики | `size/journal-column` × 2 |
| кегль ячейки | `micro` |
| кегль ФИО | `dense` |
| кегль шапки | `micro` |
| padding ячейки | `space/1` |

**Плотность у журнала не настраивается.** `density` есть у `DataTable`,
но журнал всегда `compact`: он и существует ради того, чтобы группа
из 25 человек и неделя пар помещались на экран целиком.

**Ширина колонки пары фиксирована и одинакова для всех колонок.** Иначе
объединённая ячейка даты над разными по ширине колонками перестаёт совпадать
с ними по границам.

### 2.4. `JournalCell`

**Анатомия**

| Часть | Обязательность |
|---|---|
| `status` | обязательна — instance swap |
| `highlight` | слой подсветки, под содержимым |

`status` принимает `AttendanceStatusPicker` `cell` (112, `cell-mode=edit`)
либо `AttendanceStatusBadge` (122, `cell-mode=read`). Оба — проход 04.

**Оси**

```
state = default | hover | focused | disabled
```
плюс boolean `cancelled`, `no-lesson`.

| Состояние | Заливка |
|---|---|
| default | прозрачная |
| hover / focused | `component/journal-cell/highlight` |
| disabled | `color/disabled/surface` |

`cancelled=true` — зачёркивание содержимого: линия `border/hairline`
`color/text/muted`, символ переходит на `color/text/secondary`. Носитель смысла
из §9 брендбука, значение — «этого больше нет».

`no-lesson=true` — **колонка остаётся в сетке**, ячейки неактивны, в шапке
пометка текстом. Признак приходит признаком колонки; сетка его только рисует.

**Ячейка не меняет размер ни в одном состоянии.** Любое изменение габарита
двигает всю матрицу.

### 2.5. Крест-подсветка

При наведении и **при фокусе с клавиатуры** подсвечиваются строка и столбец
целиком. Носитель — `component/journal-cell/highlight`, поверхность на ступень
выше базовой. Цвет текста и геометрия не меняются.

Это единственное исключение из правила «в плотных сетках отклика на наведение
нет» (§8.1 брендбука, правка §13).

В Figma подсветка собирается двумя слоями-полосами под матрицей, а не заливкой
каждой ячейки ряда: 25 + 24 подсвеченных инстанса против двух прямоугольников.

### 2.6. Шапка

Два уровня. Верхний — объединённая ячейка: дата (`column-label=date-type`)
либо предмет (`subject-type`). Нижний — тип занятия и время.

Подпись колонки набрана `micro` горизонтально. **Повёрнутого текста нет**:
он нечитаем и ломает выключку. Длинное название предмета обрезается, полное —
в `Tooltip` и в доступном имени.

Символы и аббревиатуры (`ЛК`, `ПЗ`, `ЛЗ`) разворачиваются словами в доступном
имени — правило реестра §6.2.

### 2.7. Хвостовые метрики

При `has-row-metrics` справа добавляются колонки метрик в каноническом порядке
`%+ · %(+ и у) · %у · %н`. Только у teacher.

Колонки метрик **не залипают** и уезжают вместе с матрицей: они относятся
к строке, а не к её идентификации.

### 2.8. Переполнение

| Случай | Поведение |
|---|---|
| длинное ФИО | обрезка многоточием в залипшей колонке, полное — в `Tooltip` |
| колонок больше экрана | горизонтальный скролл, колонки не скрываются |
| много строк | вертикальный скролл страницы, не внутренний |
| нет пар в колонке | колонка остаётся, помечена |
| пусто в ячейке | символ «нет данных», не пустое место |

## 3. `attendance/LessonAttendanceRoster`

Реестр: строки — студенты, разрез — **одна пара**, порядок алфавитный.
У старосты рабочий инструмент, у преподавателя справка — компонент один,
режим разный.

### 3.1. Анатомия

Строится на `DataTable` `density=compact`.

| Колонка | Обязательность |
|---|---|
| ФИО | обязательна |
| статус | обязательна — `AttendanceStatusPicker` `row` либо `AttendanceStatusBadge` |
| источник отметки | опционально — у teacher нет |
| время | опционально — у teacher нет |

**Состав колонок приходит снаружи.** В Figma — boolean `has-source`,
`has-time`, а не два компонента.

### 3.2. Оси

```
cell-mode = edit | read
scroll    = inner | page
```

`scroll=inner` — на 111 блок скроллится внутри себя: максимальная высота
задаётся блоком, внутри вертикальная прокрутка. `scroll=page` — ростер тянется
по высоте, скроллится страница.

### 3.3. Состояния строки

Наследуются от `Row` прохода 03a. Собственное — `auto-absent`: `н` проставлен
автоматически при закрытии пары, а не старостой. Носитель — обводка вместо
заливки у статуса (§2.6 брендбука), плюс подпись в колонке источника.

**Без различения экран врёт** — прямая формулировка реестра.

## 4. Таблицы отметок студента

Три компонента, все — свой разрез собственных отметок. Строятся на `DataTable`.

### 4.1. `attendance/AttendanceDayTable`

День как мини-таблица: `th scope="col"` = пара (предмет + тип) в порядке
расписания, **единственная строка данных** = мои отметки.

| Часть | Обязательность |
|---|---|
| `day-caption` | обязательна, `dense-strong` — день и дата |
| шапка | обязательна |
| строка отметок | обязательна, ровно одна |

Пробелов между парами нет, отменённая занимает свою колонку с зачёркиванием.

Размерных вариантов нет: компонент существует только внутри
`AttendanceWeekTable`.

### 4.2. `attendance/AttendanceWeekTable`

Контейнер недели: шесть `AttendanceDayTable` подряд, вертикальный Auto Layout,
gap `space/4`.

Оси нет. Единственное состояние — `empty` для дня без пар: день остаётся
в списке с пометкой «пар нет», а не исчезает. Иначе неделя выглядит короче,
чем есть.

### 4.3. `attendance/AttendanceSubjectTable`

Пары одного предмета: колонки-даты (дата + день + тип), одна строка отметок.
**Отметки по парам, не агрегаты.**

Отличается от `AttendanceDayTable` осью колонок: там пары дня, здесь даты
предмета. Свести вариантом нельзя — разное происхождение колонок, как
у `DatePager` и `LessonPager`; но в отличие от них здесь различается и подпись,
и шапка, поэтому компоненты остаются разными и в Figma.

## 5. Статистические таблицы

### 5.1. `attendance/StatsByStudentTable`

Реестр: **строка = студент.** Колонки приходят описанием снаружи. Порядок
серверный и на 113, и на 123. `defaultSort` — `%+`, `multiSort: false`.

**Анатомия**

| Часть | Обязательность |
|---|---|
| колонка ФИО | обязательна, залипшая |
| колонки метрик | обязательны, состав снаружи |
| `ExpandTrigger` | видим при `expandable` |
| `ExpansionRow` | видима при раскрытии — `StatsDetailPanel` |

**Оси**

```
scope = all | subject
```
плюс boolean `expandable`, `has-tickets-columns`, `has-method-column`.

`scope` — **срез данных, ось не меняет.** У старосты колонки шире (тикеты
на «н» и на «у», способ получения «+»), у преподавателя — четыре метрики
с абсолютными числами. Это состав колонок, а не два компонента.

**Строка активируется кнопкой в ячейке**, `<tr>` кнопкой не делается.
Клик по строке — дополнительный путь, не единственный.

**У teacher раскрытия нет** — `expandable=false`: детализация вывела бы
за границы назначения экрана.

### 5.2. `attendance/StatsByGroupTable`

Реестр: **строка = группа.** Четыре метрики в каноническом порядке +
**обязательная колонка «пар учтено»**. Сортировка серверная по всем столбцам,
дефолт `%+` по возрастанию. Строка кликабельна — переключает разрез.

**Колонка «пар учтено» обязательна и не отключается.** Без неё сравниваются
несравнимые знаменатели: 50% при двух парах и при тридцати — разные утверждения.

**Собственные состояния**

| Состояние | Что показывает |
|---|---|
| `single-group` | у преподавателя одна группа — **сравнивать не с чем**: пояснение и переход в разрез по студентам, а не таблица из одной строки |
| `subject-filter-unavailable` | `SubjectFilter` `disabled` с текстовой причиной до появления кросс-групповой идентичности предмета |

`GroupFilter` в этом разрезе не рендерится вовсе.

### 5.3. `attendance/StatsBySubjectTable`

Реестр: **строка = предмет**, дочерние строки — типы занятий, которые
у предмета реально есть. **Единственная иерархическая таблица продукта
и единственная с мультиколоночной сортировкой:** приоритеты накапливаются
в порядке кликов. Дефолт — алфавит по названию.

**Анатомия**

| Часть | Обязательность |
|---|---|
| `parent-row` | обязательна — предмет, с `ExpandTrigger` |
| `child-row` | видима при раскрытии — тип занятия |
| `indent` | у дочерней строки, `space/6` |

Дочерняя строка отличается отступом первой ячейки и приглушённым весом подписи,
**а не заливкой**: заливка занята состояниями строки.

**Оси**

```
state = collapsed | expanded
```
плюс `multi-sort` (всегда `true` — единственная такая таблица).

`SortPriorityBadge` из прохода 03a здесь обязателен во всех активных колонках.

### 5.4. Общее для трёх

**Процент без абсолютных чисел не показывается.** Рядом с метрикой обязательны
числитель и знаменатель — правило реестра §6.2. В библиотеке это значит:
ячейка метрики всегда несёт `MetricValue` с дробью, а не голое число.

**Две метрики показываются всегда и рядом:** `%+` и `%(+ и у)`. Сквозное
правило продукта. Колонки `%у + н` не существует.

Числовые колонки — `align=end`. Колонка ФИО или названия — `align=start`
и залипшая.

## 6. Переполнение — общее по проходу

| Случай | Поведение |
|---|---|
| ФИО длиннее колонки | обрезка, полное в `Tooltip` |
| название предмета в шапке | обрезка, поворота текста нет |
| метрика 100,0% | колонка рассчитана на четыре знака и знак процента |
| «пар учтено» в четыре знака | колонка растёт |
| дочерних строк много | раскрытие тянет высоту таблицы, внутреннего скролла нет |
| нет значения | прочерк, не ноль |

**Ноль и «нет данных» — разные утверждения.** Период не наступил — «нет данных»,
не «0%». Это состояние `future` реестра, и в макете оно рисуется прочерком
с подписью, а не нулём.

## 7. Нужен токен

| Токен | Значение | Почему |
|---|---|---|
| `size/journal-column` | 2.5rem | ширина колонки пары в журнале. Фиксирована и одинакова для всех колонок, иначе объединённая шапка даты не совпадает с границами колонок. Из шкалы отступов не выводится |
| `size/name-column` | 14rem | ширина залипшей колонки ФИО. Подобрана под «Константинопольский К. К.» в `dense`; открытый вопрос прохода 03a закрыт этим значением |

Накопительно: `icon/size/sm|md|lg`, `size/dialog-width`,
`size/popover-max-width`, `shadow/sticky-x`, `size/column-max-text`.

## 8. Что осталось открытым

1. **Фрагмент вместо полной матрицы.** Решение спеки: в библиотеке хранится
   сетка 8×6, полноразмерная собирается в макете экрана. Причина —
   производительность файла, а не дизайн. Если Figma справится с 600
   инстансами, ограничение снимается без последствий.
2. **`size/name-column` = 14rem** подобрана под длинную русскую фамилию
   с двумя инициалами. Проверить на реальном списке группы до сборки макетов.
3. **Плотность журнала не настраивается.** У `DataTable` `density` есть,
   журнал всегда `compact`. Решение спеки; если преподаватели попросят
   разрежённый журнал, ось добавляется.
4. **`AttendanceSubjectTable` и `AttendanceDayTable` не сводятся.** Разное
   происхождение колонок и разная шапка. Отличается от случая
   `DatePager` / `LessonPager`, где анатомия совпадала полностью.
