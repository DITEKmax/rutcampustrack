## Behavior and boundaries

`PasswordChangedOutbox.append` reads the Telegram recipient while the authoritative user row is locked, serializes only the existing metadata envelope and inserts `auth_outbox` in the credential transaction. Both password paths append after their security audit write. The previous post-commit best-effort reset publication is removed.

Producer `auth-service`; schema `password.changed` version 1; durable fanout exchange `rut-uit.events`; empty routing key; existing notification-bot event consumer handles the type and claims `event_id`. No queue, DLQ, ordering or consumer contract changed. The shared publisher retries pending rows in bounded batches; Auth uses `auth-outbox-publisher`/`auth-outbox-cleanup` locks because Academic shares its DB. Rabbit sends persistent raw JSON and waits for publisher confirmation before `sent`. Delivery remains at-least-once; a crash after broker acceptance can cause another physical delivery of the same event.

`POST /internal/auth/confirm-map-deletion`, header `X-Internal-Issuer-Secret`, body `{internalToken,password,targetType:FLOOR|BUILDING,targetId>0,operationId:UUID,previewDigest:64 hex SHA256}`. Success 204; malformed/invalid body 400; invalid session/service secret 401; wrong password/role 403; attempts limited 429; authority unavailable 503. Every result uses `Cache-Control: no-store`. Academic retains target/operation/preview binding and performs deletion; Auth confirms only the current password proof.
