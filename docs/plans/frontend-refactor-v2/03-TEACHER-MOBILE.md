## Контракт TCH-001

Текущий Teacher GET читает вложения заявок по `requestId`. Ручная отметка `EXCUSED` с `NO_TICKET` хранит точную ссылку на другой private blob, привязанный к паре и студенту. В текущих `proto` и сервисах отдельного ручного GET и срока в Teacher roster нет.

Добавляется `GET /api/v1/teacher/lessons/{lessonId}/students/{studentId}/excuse/attachments/{attachmentId}`, отдельный `DownloadTeacherManualExcuseAttachment` в `proto/teacher_reads.proto`, `attachment_expires_at = 17` в lesson roster и nullable ISO `attachmentExpiresAt` в BFF. Сервер проверяет подписанную роль, актуальную группу и предмет, текущую отметку, точный ID файла, ключ пары, владельца, группу, семестр при наличии, активное состояние, срок, MIME, размер и байты. Повторное чтение выявляет замену или утрату доступа до ответа. Ошибки несоответствия и истечения для нового GET скрывают недоступный файл через 404. Ответ содержит private bytes и `Cache-Control: no-store`. Обычный документ заявки продолжает использовать действующий API.

Проверки включают реальный MongoDB для разрешения, отказа и замены/истечения, адресный BFF контракт, права текущего преподавателя и независимое ревью. Браузерные сценарии используют отдельные синтетические данные.

## Первая сверка в браузере

- В «После» у перенесённой пары виден основной статус «Перенесена», а у действий и состояний появились текстовые подписи. На TMA в светлой теме на 320 px с крупным текстом эталон сохраняет один Back в цепочке «Пара → причина → документ».
- В эталонном журнале порог 100% меняет цвет ячейки, 101% вызывает валидацию, строка и дата выделяются одновременно. Ползунок доходит до правой границы таблицы. Колонка «ЛК» открывает конкретную пару. Возврат восстанавливает поиск, тип, сортировку и фильтры «Итогов».
- Поиск «Белов» даёт однофамильцев из двух групп. Результат показывает группу. Для выделения используются точные ID студента и группы, статистика загружается по всей выбранной группе. Отдельно пройдены подтверждение и отмена фильтров и сортировки, пустая выдача, загрузка, сбой и офлайн.
- Текущая сборка теряла выбранный тип при переходе из «Итогов» в журнал, поиск был внутри общей панели, а текущая TMA показывала два Back на экране причины. Эти расхождения входят в перенос.
- PDF в HTML содержит одну страницу. Для проверки перелистывания на локальном стенде подготовлен отдельный синтетический двухстраничный файл. Файлы из реальных заявок в стенд не входят.

- PWA 390 px в тёмной теме. Ручной PNG загрузился сразу после входа в причину, полноэкранный просмотр не вызвал новый GET. Заявочный PDF из точной исторической пары отрисовал первую и вторую страницы. На последней странице действие «Далее» отключено.
- PWA. 100% даёт разные цвета для 100% и 0%. Введённые 101% отмечены как ошибка. Ползунок доходит до 4 828,8 px, клавиша Home возвращает к первой дате. Белов и колонка 01.09 выделяются одновременно. График открывается для той же выборки. После возврата из журнала сохранились «Лекция», поиск, предел 90% и сортировка «Имя: Я–А». Запрос статистики без `studentId`, три GET соответствуют выбору типа и двум подтверждениям.
- TMA 320 px. Первый GET ручного документа получил тестовый 503, «Повторить» получил документ. Системный Back сначала закрыл полноэкранный просмотр, второе нажатие вернуло к паре.
- Независимая сверка UI выявила, что обновление вложения старостой не приходит на текущую подписку преподавателя. Добавлена проверка метаданных открытого ручного файла. Поведение проверено при обычной работе таймеров в активной вкладке. На скрытой вкладке проверки останавливаются.

- Vue. 99 адресных сценариев в 12 файлах на v3, затем 23 адресных проверки после корректировки таймера v4. Строгая типизация PWA, TMA и тестов, scoped ESLint и проверка Git-патча прошли. Независимые повторные ревью TCH-001 и UI v4 завершены с PASS.

В режиме замены внешняя кнопка меняет документ внутри fixture. Для одинаковых карточек с HTML используй `sample=reference`, дату 5 ноября и при необходимости `text=125`.
