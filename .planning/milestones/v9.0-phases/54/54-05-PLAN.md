    SUBMIT METHOD:
    ```typescript
    onSubmit() {
      if (this.form.invalid) { this.form.markAllAsTouched(); return; }
      this.submitting = true;
      this.apiError = null;
      const body = {
        name: this.form.value.name!,
        teacherId: this.form.value.teacherId ?? null
      };
      const call = this.isEdit
        ? this.headmanApi.updateSubject(this.data.subject.id, body)
        : this.headmanApi.createSubject(body);

      call.subscribe({
        next: () => {
          this.submitting = false;
          const msg = this.isEdit ? 'Предмет обновлён.' : 'Предмет создан.';
          this.snackBar.open(msg, undefined, { duration: 4000 });
          this.dialogRef.close(true);
        },
        error: () => {
          this.submitting = false;
          this.apiError = 'Не удалось сохранить предмет. Попробуйте ещё раз.';
        }
      });
    }
    ```

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Subject CRUD | Any authenticated headman can create/edit/delete ANY subject — no group-scoped ownership check in backend SubjectService (known limitation per research Pitfall 6) |
| Teacher select | listTeachers returns all active teachers to any authenticated student |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-54-12 | Elevation of Privilege | Subject delete — no group ownership check | accept | Backend `SubjectService.requireHeadman()` only checks `isHeadman`, not group ownership. This is existing backend behavior, out of scope for Phase 54 to fix. Documented as known limitation in RESEARCH.md Pitfall 6. Phase 55+ can add group-scoped subject FK. |
| T-54-13 | Information Disclosure | `listTeachers` — teacher names visible to students | accept | Teacher names are not sensitive; they are displayed on lesson schedules visible to all students anyway. The endpoint returns only `id`, `fullName`, `login`, `role` — no credentials. |
| T-54-14 | Tampering | Subject name maxlength bypass | mitigate | `maxlength="120"` on input. Backend should validate on its side (existing SubjectRequest validation). Client-side is UX only. |
</threat_model>
