# План аудита перед v0.0.0

**Дата старта:** 2026-04-17
**Язык отчётов:** русский (все файлы, все вопросы).
**Цель:** полный аудит RutCampusTrack перед релизом v0.0.0 — выявить все баги, костыли, мёртвый код, нарушения контрактов, проблемы масштабирования, безопасности, качества тестов и UI/UX. Итог должен быть настолько подробным, чтобы по нему можно было последовательно закрыть все недочёты.

## Принципы

1. **Глубина:** максимальная. Фиксируем даже мелочи (nit-уровень) — помечаем приоритет.
2. **Язык:** только русский. Технические термины (JWT, Flyway, HATEOAS, N+1, P0/P1/P2/P3) и код/пути — в оригинале.
3. **Последовательность:** по одному сервису/папке за раз, чтобы не упираться в лимит контекста.
4. **Коммит:** один итоговый коммит в конце, когда весь аудит готов.
5. **Тесты:** читаем код тестов и документируем проблемы. НЕ запускаем сейчас — запуск будет после правок по аудиту.
6. **Фронты:** полный ревью (архитектура + компоненты + UI/UX + dead code + баги).
7. **Прерываемость:** после каждого файла обновляем `PROGRESS.md`. Можно продолжить с любой точки.

## Чеклист на каждый сервис/модуль

1. **Логика и корректность** — баги, race conditions, инварианты, граничные случаи
2. **Костыли** — TODO/FIXME/HACK, хардкоды, временные решения, обходы
3. **Мёртвый/неиспользуемый код** — классы, методы, поля, endpoints, импорты
4. **Изменённое поведение** — методы, которые делают не то, что следует из имени/сигнатуры
5. **Контракты и правила CLAUDE.md:**
   - contract-first (controller implements interface)
   - enum lowercase в БД / UPPER_CASE в Java / LowercaseEnumConverter
   - Request=record, Response=class
   - Lombok запрещён в `*-api-contract`
   - HATEOAS Level 3, RFC 7807 Problem Details
   - @ControllerAdvice, не catch в контроллере
   - package isolation (Attendance: checkin/ vs report/)
6. **Масштабирование и производительность** — N+1, индексы, кеш, синхронные вызовы, pagination, таймауты
7. **Безопасность** — injection, IDOR, утечки токенов/PII, валидация ввода, authorization checks, CORS, secrets
8. **Качество тестов** — покрытие, корректность, актуальность, mock vs real DB, флейки
9. **Миграции Flyway** — редактирование применённых, обратная совместимость
10. **Конфиги** — application.yml, env, hardcoded значения, дубли

## Формат каждого файла (шаблон на русском)

```markdown
# NN. {Название}

## Сводка
- Общее впечатление (1-2 абзаца)
- Счётчики: P0=X, P1=Y, P2=Z, P3=W

## Структура модуля
(краткое дерево — основные пакеты/классы; явные расхождения с CLAUDE.md отметить)

## Критичные проблемы (P0)
### P0-1: {заголовок}
- **Где:** `путь/до/Файла.java:строки`
- **Что:** описание
- **Риск:** что ломается
- **Как чинить:** конкретные шаги
- **Зависимости:** какие модули/фазы затронуты

## Серьёзные проблемы (P1)
(аналогично)

## Средние (P2)
(аналогично)

## Мелкие и nit (P3)
(аналогично)

## Мёртвый код
- `путь:строка` — что и почему считается мёртвым

## Костыли и TODO/FIXME
- `путь:строка` — текст маркера + комментарий

## Тесты
### Что покрыто хорошо
### Что покрыто плохо / не покрыто
### Некорректные/подозрительные тесты
### Кандидаты на удаление/рефакторинг

## Соответствие CLAUDE.md
(чеклист: ✅/⚠/❌ по каждому правилу с комментарием)

## Зависимости между проблемами
(что блокирует/разблокирует другие правки)

## Вопросы к владельцу проекта
(что неоднозначно — списком)
```

## Приоритеты

- **P0** — блокирует релиз (безопасность, потеря данных, поломка прод-флоу)
- **P1** — серьёзный баг / архитектурное нарушение, исправить до релиза
- **P2** — рефакторинг, некритичные недочёты, можно в следующий спринт
- **P3** — nit, стиль, микрооптимизации

## Ограничения

- Не запускаем тесты в ходе аудита (только после правок)
- Не правим код в ходе аудита (только документируем)
- Коммит один — в конце
- Все отчёты и вопросы — на русском
