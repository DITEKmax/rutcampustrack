# Памятка: как работать с Claude Code + GSD

## Основы

Claude Code — это AI-помощник в терминале. Ты пишешь ему текстом, он читает/создаёт/редактирует файлы, запускает команды, делает коммиты.

GSD — надстройка над Claude Code, которая структурирует работу: разбивает большие задачи на маленькие, следит за прогрессом, сохраняет контекст между сессиями.

---

## Запуск сессии

```powershell
cd C:\Users\maksd\IntelliJIDEA\rutcampustrack
claude
```

Claude Code автоматически прочитает `CLAUDE.md` и будет знать контекст проекта.

---

## Когда какую команду вводить

### Первый раз в проекте (один раз)

```
/gsd:map-codebase
```

**Зачем**: GSD анализирует структуру проекта — файлы, зависимости, архитектуру. Создаёт внутреннюю карту. Делается ОДИН раз. После этого GSD знает проект.

### Начало новой фазы (перед каждой фазой)

```
/gsd:new-milestone
```

**Зачем**: Начинает новый этап разработки. GSD спросит что делать — отвечай:
> "Фаза 1 — Auth Service + API Gateway. Детали в docs/phases-plan.md раздел Фаза 1"

GSD создаст файл с роадмапом в `.planning/`.

### Планирование фазы

```
/gsd:plan-phase 1
```

**Зачем**: GSD разбивает фазу на маленькие задачи (атомарные планы). Каждая задача достаточно маленькая, чтобы Claude выполнил её качественно. Результат — список конкретных задач с файлами и критериями готовности.

### Выполнение плана

```
/gsd:execute-plan
```

**Зачем**: GSD начинает выполнять задачи одну за другой — пишет код, создаёт файлы, делает коммиты. Ты можешь наблюдать или заниматься другим.

### Быстрая задача (баг, мелкая правка)

```
/gsd:quick
```

**Зачем**: Для задач, которые не требуют полного планирования. GSD спросит что сделать, ты описываешь — он делает.

---

## Порядок работы по фазам

### Фаза N — полный цикл

```
Шаг 1: /gsd:new-milestone
        → описываешь что делать

Шаг 2: /gsd:plan-phase N
        → GSD создаёт план задач

Шаг 3: /gsd:execute-plan
        → GSD выполняет задачи

Шаг 4: Проверяешь результат в IntelliJ
        → .\gradlew.bat build
        → тестируешь вручную

Шаг 5: Если есть баги → /gsd:quick → описываешь баг
        Если всё ок → коммит и пуш
```

## Как задавать вопросы и просить что-то сделать

### Просто пиши текстом на русском

Claude Code понимает обычный текст. Не нужны специальные команды для каждого действия.

**Примеры запросов:**

Попросить написать код:
```
Создай JwtService в auth-service с генерацией RSA ключей и выдачей JWT токенов. Следуй правилам из CLAUDE.md.
```

Попросить исправить баг:
```
Запусти gradlew build и исправь все ошибки компиляции
```

Попросить объяснить:
```
Объясни как работает gRPC вызов между Attendance и Schedule сервисами
```

Попросить сделать коммит:
```
Закоммить текущие изменения с сообщением "Phase 1: implement JWT generation"
```

Попросить создать PR:
```
Создай ветку feature/phase-1-auth, закоммить всё туда и создай PR в main
```

Попросить запустить и протестировать:
```
Запусти auth-service и отправь POST /auth/login с тестовыми данными
```

### Как формулировать задачи хорошо

**Плохо** (слишком общо):
```
Сделай авторизацию
```

**Хорошо** (конкретно):
```
Создай endpoint POST /auth/login в AuthController. Он принимает LoginRequest(login, password), проверяет пароль через BCrypt, и возвращает TokenResponse(accessToken, refreshToken, expiresIn). Следуй contract-first подходу из CLAUDE.md.
```

**Ещё лучше** (со ссылкой на документацию):
```
Реализуй Auth Service согласно docs/phases-plan.md раздел "Фаза 1 → Auth Service". Начни с JwtService.
```

## Когда начинать новую сессию

Смотри на индикатор контекста справа внизу:

```
█░░░░░░░░░ 16%   — всё отлично, работай
█████░░░░░ 50%   — нормально
███████░░░ 70%   — скоро закончится, планируй завершение
████████░░ 80%   — начинай новую сессию
██████████ 100%  — контекст потерян, обязательно новая сессия
```

Как начать новую сессию:
```
/exit
claude
```

Claude Code перечитает `CLAUDE.md` и продолжит с полным контекстом.
GSD сохраняет прогресс в `.planning/` — он не потеряется между сессиями.

## Полезные команды в сессии

| Команда | Что делает |
|---------|-----------|
| `/gsd:help` | Список всех GSD команд |
| `/gsd:health` | Проверка состояния GSD |
| `/gsd:quick` | Быстрая задача |
| `/model` | Сменить модель (Opus/Sonnet) |
| `/exit` | Выйти из сессии |
| `?` | Горячие клавиши |

## Типичный рабочий день

```
1. Открыл IntelliJ
2. Терминал → claude
3. "Что было сделано в прошлой сессии? Прочитай .planning/"
4. Продолжаешь работу или начинаешь новую задачу
5. Проверяешь в IntelliJ → gradlew build
6. Коммит и пуш
7. /exit когда закончил
```

---

## Если что-то пошло не так

**Claude Code завис**: Ctrl+C, потом `claude` заново

**Сломал код**: `git stash` (откатить изменения) или `git checkout -- файл`

**GSD потерял контекст**: `/gsd:health --repair`

**Нужна архитектурная помощь**: Иди в веб-чат claude.ai, загрузи `docs/phase-0-report.md` и опиши проблему

**Ошибка сборки непонятная**: Скопируй ошибку и скажи Claude Code "исправь это"
