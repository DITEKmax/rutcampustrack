# План сборки в Figma

Маршрут: макеты собираются в Figma по всем трём ширинам, перенос в код — после. Агент — Codex с удалённым Figma MCP.

Порядок внутри Figma тот же, что был бы в коде, и по той же причине: компонент, собранный на литералах, перерисовывать так же дорого в макете, как в CSS.

---

## Шаг 0. Подключение — один раз, до всего

**Место.** Full seat: запись вне черновиков только на нём, Dev seat снаружи черновиков читает. Сервер — удалённый (`https://mcp.figma.com/mcp`), не десктопный: запись в канву есть только у удалённого.

**Конфиг Codex.** В `.codex/config.toml` остаётся один сервер:

```toml
[mcp_servers.figma]
url = "https://mcp.figma.com/mcp"
```

Сервер shadcn убирается — кода пока нет, ставить компоненты некуда. Refero добавляется на шаге 4, не раньше.

**Скиллы.** Нужны оба: `/figma-use` — базовый, учит агента пользоваться инструментом записи, и официальный скилл Codex `figma-implement-design`. Свой `rutcampustrack-design` остаётся главным по системе: при расхождении выигрывает он, потому что чужие скиллы не знают ни «Табло», ни правила про один выделенный объект.

**Шрифт.** Onest загрузить в аккаунт Figma — MCP-сервер и агент видят загруженные шрифты. Без этого текстовые стили встанут на подстановку, и вся типографика уедет.

**Проверка.** Попросить агента: «Скажи, какую версию сервера Figma ты используешь, какие инструменты записи доступны и какие скиллы подхватились. Ничего не создавай». Если не назовёт `use_figma` — дальше не идти.

## Шаг 1. Структура файла

Два файла, не один:

- **Библиотека** — переменные, стили, компоненты, блоки. Публикуется.
- **Экраны** — макеты, собранные из библиотеки. Потребитель.

Разделение нужно, чтобы правка компонента доезжала до всех экранов сама. Если всё в одном файле, через месяц будет 81 макет с локальными отвязанными копиями.

Страницы библиотеки — по частям `figma-spec`: основания, действия и формы, каркас и навигация, таблицы, журналы, реестры, значения и статусы, карточки и панели, формы, состояния, блоки по ролям.

## Шаг 2. Переменные и стили — задание `f1-variables.md`

Источник — `tokens-v2.json`, ничего не придумывается. Три коллекции, две темы у семантического слоя, тени и текст — стилями. Подробности в задании.

**Контрольная точка:** ни одна семантическая переменная не содержит hex напрямую; смена темы на пустом фрейме переключает поверхность и текст.

## Шаг 3. Компоненты — части 1–10 `figma-spec`

Партиями, по одной части за заход. Порядок частей — как в файле: основания → действия и формы → каркас и навигация → таблицы → журналы → реестры → значения и статусы → карточки и панели → формы → состояния.

По каждому компоненту: все состояния из матрицы, вариантами; пустых клеток не бывает; где `hover` запрещён — так и записать в описание компонента.

**Контрольная точка после каждой партии:** правка переменной доходит до всех вариантов; ни одного локального цвета; имена совпадают с реестром посимвольно.

Здесь же подключается Refero, если по конкретному паттерну непонятно, как решают другие. Точечно — не по два десятка экранов за раз.

## Шаг 4. Блоки — части 11–14

Роли строго по порядку: student → headman → teacher → admin. Части 12–14 написаны как дельта к 11 и ссылаются на неё.

`block/AppHeader` собирается один раз в student, в остальных ролях — варианты.

**Контрольная точка:** у каждого блока есть загрузка, пустота и ошибка; блок собран из компонентов шага 3, а не нарисован заново.

## Шаг 5. Экраны 1920 — часть 15

Первый — 101, главная студента: на нём одновременно график, плотный список, карточки метрик, полоса заполнения и единственный выделенный объект. Если система выдерживает его, выдержит остальные.

Дальше 112 (самый плотный журнал), 121 и 131 (каркасы teacher и admin), потом остальные.

**Контрольная точка:** выделен ровно один объект; обе темы; экран собран из блоков.

## Шаг 6. Адаптивы 1440 и 1280

Только после того, как 1920 принят целиком. Адаптив — **переключение вариантов блоков**, а не отдельная вёрстка. Если для 1440 пришлось двигать руками, вариант блока собран неверно, и чинить надо блок, а не макет.

27 экранов на трёх ширинах — 81 макет. При правильно собранных блоках третья ширина стоит дёшево. При неправильно собранных — это 81 отдельная работа.

## Шаг 7. Перенос в код

Отдельная тема, открывается когда макеты готовы. Здесь же решается развилка Reka UI против полностью своих компонентов, отложенная сейчас.

Одно замечание вперёд: SVG годится для иконок и иллюстраций. Экран, выгруженный в SVG, — мёртвая картинка без состояний, поведения фокуса и переполнения. В код переносить из `figma-spec` и спек, а макет использовать для сверки геометрии.

## Что и когда добавлять

| Когда | Что | Зачем |
|---|---|---|
| Шаг 0 | Figma remote MCP | запись в канву |
| Шаг 0 | скилл `/figma-use` | без него инструмент записи не используется правильно |
| Шаг 0 | скилл Codex `figma-implement-design` | официальная обвязка под Codex |
| Шаг 0 | Onest в аккаунт Figma | иначе текстовые стили встанут на подстановку |
| Шаг 3 | Refero MCP | референсы по конкретным паттернам, точечно |
| Шаг 7 | всё, что касается кода | не раньше |

Не добавлять: shadcn MCP (нечего ставить), Mobbin (второй сервер референсов вытесняет спеки из контекста), скилл Refero целиком (объявляет себя главным авторитетом по дизайну и конфликтует с брендбуком).
