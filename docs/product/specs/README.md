# specs/ — спеки экранов

Копии из папки проектирования. **Здесь ничего не правится**, как и в `design/`.

Спека описывает **что на экране и как оно себя ведёт**: состав, данные, состояния, порядок сжатия, потребности в API. Она не описывает, как это выглядит, — визуал в `design/`.

## Раскладка

```
specs/wireframes/
  00-overview.md        сводка по всем экранам
  nav-integrity.md      переходы между экранами, целостность навигации
  table-filters.md      общее правило фильтров и сортировок для всех таблиц
  shared/               001 — вход
  student/              101, 102, 103, 104, 105, 107, 108
  headman/              111–119, 116.1
  teacher/              121, 122, 123
  admin/                131–135
```

Имя файла — `<код>-<роль>-<название>.md`, например `113-headman-stats.md`. Роль в имени продублирована намеренно: ссылки во всех остальных файлах используют полное имя.

Каждая спека — семь разделов, структура одинаковая у всех.

## Когда читать

- **Этап 3 (блоки)** — когда `figma-spec.md`, части 11–14, отсылает к экрану за поведением или порядком сжатия.
- **Этап 4 (сборка экрана)** — спека собираемого экрана целиком, состав берётся только оттуда.
- `table-filters.md` — перед любой работой с таблицей: правило распределения между фильтрами колонок и панелью общее для всего продукта.
- `nav-integrity.md` — когда добавляется переход между экранами.

Читать по одной. Каждая спека 15–56 КБ, и десяток сразу вытеснит из контекста то, ради чего они открыты.

## Чего в спеках нет

Отбор, порядок и пагинация — только серверные. Поиск и фильтры колонок складываются через И. Эти два правила отменяют часть более ранних формулировок внутри спек; действующая версия записана в блоках «Решения задачи 4» в конце файлов. Если основной текст спеки противоречит такому блоку — прав блок, а расхождение назвать отдельно.
