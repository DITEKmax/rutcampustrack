## 1. `shared/MetricValue`

Реестр: примитив показателя. Владеет **форматированием и доступным именем**.
Дельтой не владеет — отдаёт под неё слот. Семантический элемент не рендерит:
его выбирает обёртка.

### 1.1. Анатомия

| Часть | Обязательность |
|---|---|
| `value` | обязательна |
| `total` | обязательна при `format=ratio` и `percent` |
| `basis` | ✏️ **обязательна при `format=percent`** — дробь-основание второй строкой, см. §1.3 |
| `unit` | опционально — **мельче и приглушённее числа, вплотную** |
| `label` | опционально |
| `hint` | опционально |
| `delta-slot` | опционально, instance swap |

### 1.2. Оси

```
format = number | percent | ratio
size   = inline | display
```

**`size` — два размера, и оба нужны.** `inline` живёт в ячейке таблицы и в
списке определений, `display` — в карточке метрики, где число и есть содержание
блока. Третьего размера нет: промежуточный кегль в системе не используется.

| | `inline` | `display` |
|---|---|---|
| кегль значения | `dense-strong` | `display` |
| кегль единицы | `micro` | `caption` |
| кегль подписи | `micro` | `caption` |
| выключка | `end` | `start` |

### 1.3. Правила форматирования

- **`percent` не показывается без числителя и знаменателя** — правило реестра
  §6.2. Процент разворачивается словом в доступном имени.
- `ratio` читается как «N из M», отображается дробью `18/24`.

✏️ **Правка 11.08.2026 — как именно `percent` показывает числа.** Раньше правило
требовало числитель и знаменатель, но не говорило, куда их деть. Решение владельца:
**дробь идёт второй строкой под процентом**, не в скобках рядом.

```
75 %
18/24
```

| Строка | Кегль `inline` | Кегль `display` | Цвет |
|---|---|---|---|
| процент | `dense-strong` | `display` | `color/text/primary` |
| дробь-основание (`basis`) | `micro` | `caption` | `color/text/muted` |

Дробь пишется так же, как у `ratio`, — через слэш, `tnum`, разряд под разрядом.
Доступное имя разворачивает обе величины словами: «75 процентов, 18 из 24».

**Почему стопкой, а не «75 % (18/24)» в строку.** Хвостовые колонки метрик журнала
имеют ширину `journal/metric-column-width` = 80, и на 122 их четыре подряд
(`%+ · %(+ и у) · %у · %н`). Строка с процентом и дробью в скобках туда не влезает,
а обрезать число нельзя — §1.4. Стопка помещается в ту же ширину.

**Процент — вычисляемая величина, свойств у него нет.** Источник истины —
`value` и `total`; процент считает код. В Figma его число вводится текстовым
переопределением, потому что Plugin API арифметику не выражает — занесено
в `figma-code-gaps.md` §6b.
- Разделитель разрядов — пробел.
- Отсутствие значения — прочерк `—`.
- Все числа `tnum`, выключка вправо, разряд под разрядом.

### 1.4. Переполнение

Число не обрезается никогда: обрезанное число — ложь. Компонент растёт
по ширине. Подпись обрезается многоточием.

## 2. `shared/MetricDelta`

Реестр: суточный прирост. Направление **словом** — «прирост» / «снижение» /
«без изменений». База сравнения текстом. **Стрелка и цвет носителями смысла
не являются.**

### 2.1. Анатомия

| Часть | Обязательность |
|---|---|
| `arrow` | опционально — дублирует, не заменяет |
| `value` | обязательна, со знаком |
| `direction-word` | обязательна |
| `base-label` | обязательна — с чем сравнивается |

### 2.2. Оси

```
direction = up | down | flat
state     = default | unknown | not-applicable
```

| Состояние | Что показывает |
|---|---|
| `unknown` | «нет данных за вчера» — **не «+0»** |
| `not-applicable` | **не рендерится вовсе**: не прочерк, не ноль, не «нет данных» |

Различие обязательное: «не изменилось» и «не с чем сравнить» — разные
утверждения, а суточной дельты у величины «за всё время» не существует.

Цвет: `color/state/success/text` при `up`, `color/state/danger/text` при `down`,
`color/text/muted` при `flat`. **Слово присутствует во всех трёх.**

## 3. `shared/StatCard`

Реестр: числовой показатель с подписью и пояснением. Значение отрисовывает
`MetricValue`; карточка владеет рамкой и пропом `delta`.

### 3.1. Анатомия

| Часть | Обязательность |
|---|---|
| контейнер | обязательна |
| `MetricValue` `display` | обязательна |
| `label` | обязательна |
| `hint` | опционально |
| `MetricDelta` | опционально (`has-delta`) |

Поверхность `color/surface/raised`, граница `border/hairline`
`color/border/default`, радиус `radius/lg`, padding `space/4`,
gap `space/2`, ширина `fill`, высота `hug`, тень `shadow/raised`.

**У карточки нет `hover`** — §8.1 брендбука. Карточка не нажимается
и не подсвечивается.

### 3.2. Оси

Размерных вариантов нет. Карточка тянется по ширине своей колонки в сетке
блока; высота — от содержимого. Разные ширины на 101 (1 шт.), 103 (8 шт.)
и 131 (3 шт.) — это раскладка блока, а не варианты карточки.

```
state = default | loading | empty | error
```

Состояния обязательны: карточка — блок в смысле §9.2 оснований, она грузится
и падает независимо.

### 3.3. Переполнение

Подпись переносится на две строки, дальше обрезается. Значение не обрезается.
Пояснение обрезается по двум строкам.

## 4. `shared/DefinitionList`

Реестр: список пар «термин → значение». Семантически `<dl>`, **не таблица**:
у значений нет второй оси. Порядок элементов — данные, компонент не сортирует.

### 4.1. Анатомия

| Часть | Обязательность |
|---|---|
| `term` | обязательна, `caption`, `color/text/muted` |
| `value` | обязательна — текст либо `MetricValue` |
| `hint` | опционально |
| `delta-slot` | опционально |

### 4.2. Оси

```
variant = inline | stack
```

| | `inline` | `stack` |
|---|---|---|
| направление | горизонтальное, пары в ряд | вертикальное |
| gap между парами | `space/6` | `space/3` |
| внутри пары | термин над значением | термин слева, значение справа |
| где | шапка отчёта, шапка недели, шапка выбранной пары | профиль, блок метрик, разбивка |

`stack` собран по приёму мудборда «две колонки: подпись слева, значение справа,
без рамок полей».

### 4.3. Переполнение

`inline` при нехватке ширины **переносится на вторую строку**, а не скроллится:
шапка обязана быть видна целиком. `stack` — значение переносится, термин
не переносится.

## 5. `shared/ProgressScale` — шкала заполнения

Брендбук §9.2: **один компонент, три применения.** Различаются формой,
не цветом.

Отдельной строкой в реестре не значится — заведён здесь как атом под полосу
текущей пары (`LessonCard featured`), долю (`SubjectProgressCell`, статистика,
дз) и процесс (`FileUploadField`, `ExportButton`). Помечен в §17.

### 5.1. Анатомия

| Часть | Обязательность |
|---|---|
| `track` | обязательна, `color/border/subtle` |
| `fill` | обязательна |
| `segments` | видимы при `type=lesson` и `ratio` |
| `value-label` | опционально — число или дробь рядом |
| `poles` | опционально — названные полюса шкалы |

Высота `progress/bar-height`, радиус `radius/full`, ширина `fill`. ✏️ 11.08: высота была литералом 4px, заведена переменной — §16.

### 5.2. Оси

```
type  = lesson | ratio | process
state = default | error | complete        (ось действует только при type=process)
```

✏️ **Правка 10.08.2026.** ~~`indeterminate`~~ снят: он противоречил правилу
брендбука §6.3 и абзацу ниже — ожидание без известного срока показывается
полосой `busy`, а не этой шкалой.

✏️ **Правка 11.08.2026 — матрица неполная, ~~3 × 3 = 9 вариантов~~ = 5.**
Ось состояний принадлежит **только `type=process`**; у `lesson` и `ratio`
единственное состояние — `default`.

| `type` | Состояния | Почему |
|---|---|---|
| `lesson` | `default` | полоса видима только при `is-current` (часть 08, анатомия `LessonCard`): пара кончилась — карточка перестала быть текущей, полосы нет. «Пара завершилась ошибкой» смысла не имеет |
| `ratio` | `default` | доля не ошибается: не пришедшие данные — `ErrorState` блока (часть 10), а не состояние шкалы. 100% — это **значение**, а не состояние: шкала на 100% и на 40% — один вариант с разным `value` |
| `process` | `default` · `error` · `complete` | состояния приходят от владельцев: `FileUploadField` (`uploading` · `processing` · `error`), `ExportButton` по Р-3 (`queued` · `preparing` · `ready` · `error`), плашка каскада 117 |

Неполная матрица в этой части **не новость**: `MetricDelta` §2.2 собран так же —
5 вариантов вместо 3 × 3, по той же причине. Собираются ровно пять комбинаций:
`lesson/default`, `ratio/default`, `process/default`, `process/error`,
`process/complete`. Остальные шесть **не заводятся**.

**Отрисовка состояний `process`.** Форма от состояния не зависит — она носитель
типа: сплошная полоса остаётся сплошной во всех трёх.

| Состояние | Заполнение | `fill` | `value-label` |
|---|---|---|---|
| `default` | текущее значение | `color/text/secondary` | опционально |
| `error` | **замирает на достигнутом** — не обнуляется и не дотягивается до конца | `color/state/danger/fill` | не обязателен: причина отказа — текстом у владельца (`FileUploadField error`, `ExportButton error`), а не в подписи шкалы |
| `complete` | 100% | `color/state/success/fill` | не обязателен: «готово» пишет владелец |

`track` во всех состояниях прежний — `color/border/subtle`. Цвет здесь
**не единственный носитель**: рядом всегда текст владельца, правило §2.6
не нарушается.

⚠️ **`complete` может оказаться неиспользованным.** У `FileUploadField`
состояние `done` показывает список файлов — полосы там уже нет; у `ExportButton`
`ready` отдаёт ссылку — полоса тоже не нужна. Единственный кандидат — плашка
каскада 117, а она пока заглушка (части 08–09). Вариант **собирается**
сознательно: если не понадобится, он просто не будет использован, а заводить
его задним числом дороже. Решение владельца 11.08.

| `type` | Форма | Цвет заливки | Движение |
|---|---|---|---|
| `lesson` | сегменты, шаг 5 минут, зазор `component/progress-lesson/segment-gap` | `color/accent/now` | идёт, пока пара идёт |
| `ratio` | те же сегменты, значение из данных | `color/text/secondary` | нет |
| `process` | сплошная полоса | `color/text/secondary` | заполнение обновляется по мере готовности |

**`lesson` — единственное применение, где шкала окрашена акцентом**, и это
согласуется с правилом одного выделенного объекта: текущая пара и есть «сейчас».

**Движение у `process` — это рост заполнения, а не бегущая полоса.** ✏️ Уточнено
07.08: прежняя формулировка «есть, пока идёт операция» допускала оба прочтения.
`ProgressScale` применяется только там, где этапы или доля известны; ожидание
без известного срока показывается полосой `busy` по брендбуку §6.3 и этой шкалой
не изображается.

**При `prefers-reduced-motion` полоса остаётся, но не анимируется** — заполнение
обновляется дискретно. Смысл «пара идёт, прошло примерно столько» сохраняется.

### 5.3. Ограничения полосы текущей пары

Из §4.1 направления, действуют целиком:

- полоса длительности — везде, где показана текущая пара;
- **остаток времени — только на главной** (101, 111), рядом с полосой;
- округление шагом не меньше пяти минут, секунд нет;
- последние пять минут — словом «заканчивается», а не числом;
- посекундного обратного отсчёта в продукте не существует.

`value-label` при `type=lesson` содержит остаток **только на 101 и 111**.
В остальных местах его нет.

## 6. `attendance/AttendanceStatusBadge`

Реестр: статус отметки — **ровно три значения**: `+` · `у` · `н`. Плюс состояния
пары и заявки: «отменена» · «нет данных» · «на подтверждении».
**Символ + текст, цветом не кодируем.**

### 6.1. Анатомия

| Часть | Обязательность |
|---|---|
| `shape` | обязательна — круг либо пилюля `radius/full` |
| `symbol` | обязательна — `+` · `у` · `н` · `—` |
| `label` | опционально — слово рядом, вне сетки |

**Форма обязательна**: она говорит «это статус» раньше, чем цвет
(§2.6 брендбука). Символ разворачивается словом в доступном имени всегда.

### 6.2. Оси

```
status = present | excused | absent | none | cancelled | pending
fill   = solid | ring
size   = cell | row
```

| `fill` | Значение |
|---|---|
| `solid` | отметка стоит |
| `ring` | **только автоматическое `н`** от системы (`source=auto_scheduler`) |

✏️ **Правка 10.08.2026.** ~~«`ring` — не окончательна: подана заявка либо `н`
проставлен автоматически»~~ отменено решением владельца 09.08: кольцо без
заливки закреплено за автоматическим `н` и больше ничего не означает.
Источники — реестр, 111 §4.3, 112 §5. Следствие: `ring` допустим только при
`status=absent`; у остальных значений заливка сплошная.

| `size` | Диаметр | Кегль |
|---|---|---|
| `cell` | `space/5` | `micro` |
| `row` | `space/6` | `dense-strong` |

`cancelled` — ✏️ **правка 11.08.2026:** нейтральный серый круг **без
зачёркивания**, символ `color/text/muted`. ~~«зачёркивание символа»~~ отменено:
зачёркнутый символ внутри круга 20px нечитаем; зачёркивание принадлежит владельцу —
заголовку колонки журнала и названию пары, где рядом обязателен текст «отменена».
`none` — прочерк на `color/status/none/fill`; «нет данных» ≠ «отсутствовал».

✏️ **`pending` — правка 10.08.2026.** Кольцо у него отобрано предыдущей правкой,
поэтому нужен другой носитель. **Решение владельца: строку реестра не трогаем**,
`pending` остаётся значением `AttendanceStatusBadge` и рисуется **пилюлей
`radius/full` со словом «на подтверждении»**, без символа: заливка
`color/state/info/bg`, текст `color/state/info/text`. ✏️ **Семейство названо
11.08: `info`, не `warning`.** Янтарный занят статусом «уважительная» — жёлтая
пилюля рядом с жёлтым кругом «у» в одной таблице (101, 122) читается как связь,
которой нет. Синий по §2.5 брендбука несёт «нейтральное выделение, а не оценка»,
и ожидание решения — ровно это. Ось `shape` начинает работать —
круг у статусов отметки, пилюля у `pending`.

Это **временное решение сборки**: визуально `pending` совпадает с
`TicketStatusBadge` `pending`, то есть два компонента дают одинаковую пилюлю
с одинаковым словом. Владелец решил вернуться к этому при переносе в код.
Записано в `figma-code-gaps.md`.

### 6.3. Что запрещено

Цветных статус-пилюль заливкой на каждой строке таблицы быть не должно —
отклонено мудбордом. В журнале цвет несёт только отмеченная ячейка;
неотмеченное и будущее не окрашивается никак.

## 7. `attendance/AttendanceStatusPicker`

Реестр: контрол отметки, **единый для всех мест ручной простановки**.
Отмеченное значение и статус будущей пары рисует **через
`AttendanceStatusBadge`** — своей разметки статуса не заводит.

### 7.1. Механика — из решения владельца, не изобретается здесь

✏️ **Правка 10.08.2026 — механика переписана под решения владельца 09–10.08.**
Источники: строка `AttendanceStatusPicker` в `COMPONENT_REGISTRY.md`, спека 111
§4.3, спека 112 §5. ~~Отменено: «пара заблокирована → ручная простановка
недоступна, остаётся тикет на „у“»~~ — блокировка запрещает взаимодействие
**студенту**, старосте простановка остаётся. ~~Отменён отдельный значок
редактирования (карандаш)~~ — в режиме правки ячейка и есть контрол.

| Ситуация | Что видно |
|---|---|
| пара в будущем | кругов нет, текстовый статус |
| отметки нет | **три нейтральных круга `+` · `у` · `н` видны сразу**, все нажимаемые |
| клик по `+` или `н` | **отметка в один клик**: остаётся один круг со статусной заливкой |
| клик по `у` | статус **не ставится** — открывается ввод причины, §7.4 |
| отметка есть | один круг со статусной заливкой, кругов не видно, карандаша нет |
| клик по отмеченному кругу | раскрывает три круга, текущий выделен — это и есть вход в правку |
| повторный клик по выделенному кругу | **снимает** статус, возвращаются три круга |
| пара заблокирована | простановка **доступна**: ограничение касается студента, не старосты |

**Цикла переключения нет.** Требование «один клик» — ограничение конструкции:
путь «пусто → отмечено» не проходит через раскрытие.

**Кольцо без заливки означает только автоматическое `н` от системы.** Прежнее
«заливка — окончательная, кольцо — не окончательная» отменено 09.08. Размер
круга одинаков во всех состояниях.

### 7.4. Ввод причины при «у»

✏️ **Решение владельца 10.08.2026.** «У» ставится старостой руками и **требует
причины текстом**; файл прикладывать не обязательно. Причина вводится **до**
применения статуса.

| `variant` | Где вводится |
|---|---|
| `cell` | поповер поверх ячейки: ширина `popover/max-width`, поверхность `color/surface/float`, тень `shadow/raised` |
| `row` | раскрытие внутри строки ростера сдвигом — носитель «редактируется», §4.3 направления |

Состав: `FormField` с `TextInput` (причина, обязательна), `AppButton` `primary`
`compact` «Поставить», `AppButton` `ghost` `compact` «Отмена». Кнопка
подтверждения `disabled`, пока поле пусто, с `disabled-reason` «укажите причину».

**Статус не применяется, пока причина не сохранена.** Esc и клик мимо закрывают
ввод и отметку не меняют. Отдельного состояния «выбрано „у“, причина пуста»
у ячейки **не существует**: незавершённый ввод живёт внутри формы, а не в журнале.

**Ширина колонки журнала — `journal/column-width` = 68.** Поле причины в неё
не помещается, поэтому поповер — следствие геометрии, а не вкуса.

**Исключение из правила «один клик» касается только «у».** Для `+` и `н` путь
«пусто → отмечено» остаётся одним кликом; это записано в 112 §5 и 111 §4.3.

### 13.2. Различение серий

**Серии различаются подписями, не только цветом** — требование реестра.
Второй носитель — рисунок линии: сплошная и пунктирная. Пунктир различает

✏️ **Правка 10.08.2026 — решение владельца.** ~~«Прошлое сплошной линией,
будущее пунктиром, „сейчас“ точкой»~~ отменено: пунктир закреплён за значением
«свободно, принимает», второго значения носителю не даётся.

**Будущее не рисуется линией вовсе.** Серия обрывается на последней известной
точке; будущий отрезок оси размечен подписями, но без линии и точек, рядом —
пояснение «дальше данных нет». Носитель — отсутствие данных, и это правда:
§13.3 уже требует от `future` показывать «нет данных», а не «0%».
Приём мудборда «будущее пунктиром» отменён вместе с формулировкой.

Цвета серий в брендбуке не назначены — см. §17.
✏️ **Цвета серий назначены 11.08.2026** — открытый вопрос §17 п. 1 закрыт,
брендбук §11.2 тоже:

| Серия | Линия | Токен |
|---|---|---|
| `%+` — был | сплошная | `color/status/present/text` |
| `%(+ и у)` — был плюс уважительная | пунктирная | `color/status/excused/text` |

Серий всегда ровно две — сквозное решение 113. Третьей в продукте нет, и если
появится, назначение делается заново, а не добавлением «ещё одного цвета».
Те же цвета берёт `ChartDataTable`: он показывает те же точки текстом, и метка
серии в нём окрашивается так же.
