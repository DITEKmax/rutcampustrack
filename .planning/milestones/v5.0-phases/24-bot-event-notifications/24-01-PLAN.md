<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| RabbitMQ -> EventDispatcher | Event payloads from RabbitMQ are consumed and dispatched to handlers |
| EventDispatcher -> Telegram API | Bot sends messages to users via Telegram API |
| EventDispatcher -> Academic gRPC | Resolves group members and subject names |
| Mini App URL in inline button | URL embedded in Telegram message opens external web app |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-24-01 | S (Spoofing) | RabbitMQ events | accept | RabbitMQ is internal infrastructure with auth; events come from trusted services behind VPS network. No external access. |
| T-24-02 | T (Tampering) | event payload fields | mitigate | Validate required payload fields exist before processing (KeyError handling in each handler). Missing fields log warning and skip. |
| T-24-03 | I (Info Disclosure) | telegram_id fan-out | mitigate | Each student only receives their own message. No group member list exposed. Filter `telegram_id > 0` to avoid sending to unlinked accounts. |
| T-24-04 | D (Denial of Service) | group fan-out flooding | mitigate | All sends go through TelegramSendQueue with 30 msg/sec token bucket rate limit. Large groups processed sequentially via queue. |
| T-24-05 | E (Elevation) | mini_app_url injection | accept | URL is configured server-side via Settings (env var or .env). Not user-controlled. Telegram validates WebAppInfo URLs against bot's configured domain. |
</threat_model>
