**SHARED HELPER — Create a utility method or abstract base for headman permission check (D-03).**
Create a package-private helper or put it in each service. The pattern for headman-or-assistant check:

```java
private void requireHeadmanOrAssistant(AssistantPermission requiredPermission) {
    RequestContext ctx = requestContext; // injected
    if (ctx.getRole() != UserRole.STUDENT) {
        throw new AccessDeniedException("Only students (headman/assistant) can perform this operation");
    }
    if (ctx.isHeadman()) {
        return; // headman always allowed
    }
    // Check assistant delegation
    HeadmanAssistant assistant = headmanAssistantRepository
        .findByGroupIdAndStudentId(ctx.getGroupId(), ctx.getUserId())
        .filter(HeadmanAssistant::isActive)
        .orElseThrow(() -> new AccessDeniedException("Not a headman or active assistant"));
    // Compare lowercase — Pitfall 4
    boolean hasPermission = Arrays.asList(assistant.getPermissions())
        .contains(requiredPermission.name().toLowerCase());
    if (!hasPermission) {
        throw new AccessDeniedException("Missing permission: " + requiredPermission);
    }
}
```

Each domain service that needs headman access injects `HeadmanAssistantRepository` and `RequestContext` and implements this check with the appropriate `AssistantPermission`. The relevant permission mappings:
- Subject CRUD: no specific assistant permission needed (only true headman). OR if you want delegation, use a general check. Per D-03, assistant checks use specific permissions. Subjects don't map to a specific AssistantPermission — restrict to headman only (isHeadman=true) for subject CRUD.
- Assignment (teacher assign/remove): same — headman only.
- Assistant management: headman only (assistants cannot manage other assistants).
- Homework CRUD: `MANAGE_HOMEWORK` permission.
- Threshold set (group/subject level): headman only.
