# `journal/` — рабочий журнал агента

Заведён 20.08.2026. Это единственное место, куда агент кладёт **своё**:
решения, принятые по ходу, отчёты партий, состояния файла и формулировки,
которые он не имеет права вписать сам.

Зачем отдельная папка: `design/` — источники истины, они правятся дописыванием
и живут долго. Журнал — рабочий слой, он растёт быстро и его не жалко читать
подряд. Раньше всё это жило только в переписке и терялось между сессиями:
числа спорились по шесть раз, формулировки для документов владельца исчезали
вместе с чатом.

---

## Состав

```
journal/
  README.md        этот файл — правила ведения
  DECISIONS.md     решения владельца по ходу работы, датированные
  to-owner.md      формулировки для файлов, которых нет в kit
  reports/         отчёты партий, по файлу на партию
  state/           снимки состояния Figma в JSON
```

Создавай недостающее сам. Ничего из журнала не удаляй — только дописывай.

---

## `DECISIONS.md` — решения владельца

**Что сюда попадает.** Всё, что владелец решил в переписке и что переживёт
эту сессию: правка конкретного кадра, изменение компонента, отмена закрытого,
новое правило, выбор из вариантов. Особенно — правки «сделай как я вижу»,
которые расходятся с документами: именно они теряются первыми.

**Что не попадает.** Твои предложения, пока владелец их не принял. Вопросы.
Пересказ отчётов.

**Формат — одна запись, одно решение:**

```
## 2026-08-20

### Экран 101 / 1920 — CurrentLesson
Решение: убрать подпись «осталось» над полосой, время оставить справа.
Где лежит: мастер block/CurrentLesson, ось width — задевает 1440 и 1280.
Потребители: 3 (101 × три ширины).
Отменяет: figma-spec часть 11 §4.2 — там подпись названа обязательной.
Сделано: да, запись в figma-spec стр. NNNN.
```

Обязательные поля: **дата, адрес (экран / ширина / компонент), решение,
где лежит, кого задевает**. Если решение отменяет закрытое — назвать что
именно. Если решение принято, но не выполнено — так и написать, и оно остаётся
в журнале открытым.

Заголовок дня — один на сессию, решения внутри списком.

## `to-owner.md` — то, что тебе писать нельзя

Двух файлов в `kit` нет намеренно: **`backend-conflicts.md`** и
**`figma-code-gaps.md`**. Они живут в папке проектирования у владельца,
он вносит записи сам.

Раньше формулировки для них ты отдавал текстом в чат, и часть терялась.
Теперь **накапливай их здесь**, готовыми абзацами, которые можно вставить
как есть.

**Формат:**

```
## Для figma-code-gaps.md

### 2026-08-17 — AuthLayout glass
<готовый абзац целиком>
Статус: не внесено владельцем.

## Для backend-conflicts.md

### 2026-08-16 — агрегат средней по группе
<готовая формулировка пробела одной фразой>
Статус: не внесено владельцем.
```

Статус меняет владелец. Ничего отсюда не удаляй — внесённое просто помечается
внесённым.

Сюда же — расхождения в спеках экранов, которые ты нашёл, но править не имеешь
права: спека 107 сама себе противоречит по чекбоксам в строке, и таких мест
будет ещё.

## `reports/` — отчёты партий

По файлу на партию, имя — `YYYY-MM-DD-<партия>.md`, например
`2026-08-19-part-15-batch-3-step-1920.md`.

Отчёт в файл кладётся **тем же текстом**, что уходит в чат. Требования
к составу — в `AGENTS.md`, раздел «Требования к отчёту».

Зачем дублировать в файл: числа партии (высоты кадров, прирост в узлах A,
потребители мастеров) нужны следующей партии, а чат до неё не доживает.

## `state/` — снимки Figma

JSON-снимки, которые ты и так делал (`figma-state-part-15-batch-2.json`
и подобные). Имя — `<партия>.json`. Кладутся сюда, а не в корень `_work/`.

---

## Правило, ради которого журнал заведён

**Ничего важного не остаётся только в переписке.** Если решение прозвучало
в чате и влияет на файл или макет — оно в тот же заход попадает в журнал.
Не в конце партии, а сразу: партия может оборваться.
