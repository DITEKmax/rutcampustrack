## 2. Единый warning/error с нормальными отступами

Много раз повторялись требования: warning жёлтый, ошибка красная; нельзя
делать жёлтый блок с красной иконкой. Иконка соразмерна первой строке
заголовка, не крошечная; есть отступ до следующей карточки и между блоками.
В том же обсуждении владелец уточнил, что основной поясняющий текст может
быть светлым, цветом достаточно выделить заголовок/иконку/поверхность.
Для light темы использовать соответствующий контрастный токен, а не белый
буквально. Retry — нормальная кнопка в самом сообщении, если есть смысл.
Исправление повторяющегося дефекта внести в web shared component,
не чинить каждую картинку независимо.

## 3. Плотнее, но не мельче ради плотности

## 4. Убирать повторный текст и лишние кнопки, сохранять действия

Не повторять выбранный показатель отдельным заголовком под переключателем,
дублирующий статус отправленного запроса, очевидные «данные доступны»,
служебные «проверка форматов», «версия», «0 из 0» для пустоты.
Если картинка сама открывается, не нужна отдельная кнопка «открыть схему»;
после раскрытия группы её действия видны сразу, не под второй кнопкой
«действия с группой». Copy action можно встроить в поле. Закрытие обычно
иконкой, но с доступным названием. Внешне компактнее не означает удалить
восстановление пароля, скачивание PNG, переход к журналу или реальную ошибку.

## 5. Нормальная прокрутка страницы вместо окна в окне

Для посещаемости владелец выбрал автоподгрузку вместо страниц, для очереди
заявок просил одну страницу. Блок студентов должен расти с содержимым,
без отдельного вертикального скролла внутри. Стандартные грубые scrollbars
не нравились; допустим ненавязчивый индикатор в дизайне. Горизонтальный
индикатор у карточек/графика помогал понять возможность прокрутки.
Для web это принцип, а не требование грузить все записи БД одним запросом:
можно порционно подгружать без кнопок «дальше», сохранять поиск/фильтры,
сквозную нумерацию и доступ к данным. Точный формат таблицы выбирать по
данным и ширине, не прятать важные столбцы ради снимка.

## 6. Иерархия отражает пользовательскую задачу

Журнал уточнялся как группа → предмет → один/несколько типов занятий →
таблица/график, а не случайная общая таблица по отдельной паре. Даты
посещаемости объединяют связанные пары, не повторяются в каждой карточке.
Следующие поля появляются после предыдущего осмысленного выбора.
Взаимоисключающий выбор должен выглядеть единым переключателем, а не
двумя независимыми toggles. При этом реально многозначный выбор остаётся
многозначным. Рекомпоновка ради ясности разрешена; изменение domain/authz — нет.

## 8. Понятные уведомления и подтверждения

«Одно уведомление — один смысл»: короткий заголовок, подробности по
раскрытию, действие/переход по смыслу. Цвет и прочитанность не смешивать,
роль получает свои уведомления. Не добавлять общие служебные пояснения
вместо работающего результата. Опасное удаление/снятие подтверждённого
основания может требовать подтверждения — сокращение кнопок не отменяет
безопасность и сохранение истории. Ранее владелец отдельно настраивал
каналы PWA/TMA и Telegram; не перепроектировать эти права/политику молча.

## 9. Что понравилось в подаче результата

Владелец прямо похвалил HTML-галерею. Скриншоты нужны из работающего Vue,
с постоянными ID, чтобы адресно исправлять состояния. Для мобильных

## 10. Как избежать прежней повторной работы

Сначала обзор всех экранов для поиска повторов, затем один экран со всеми
его размерами/темами/действиями. Принять композицию и общие controls на
небольшом пакете до массового изготовления состояний. Исправление общего
элемента переносить в компонент один раз; не размножать разные warn/select.
Дальше — независимые сценарии параллельно, один автор общих routing/session/
API/tokens/lockfiles. Собирать минимально достаточные проверки, без нового
общего аудита и дублирующих тяжёлых запусков на каждую косметическую правку.

Ретроспектива старого чата описывает реальный провал процесса: ранняя большая
галерея преподавателя потребовала изменения 69→90 состояний после позднего
уточнения пользовательских действий. Это урок о порядке работы, не новое
требование изготовить 90 кадров или все прежние восемь ширин для каждого UI.

## Разрешённая самостоятельность будущих исполнителей

Разумные изменения рамок/отступов/высоты/группировки/warnings/таблиц,
недостающие UI состояния на принятой основе — разрешены текущим дополнением
владельца. Показывать результат/отклонение в галерее, не спрашивать про каждый
отступ. Новые действия, утрата старых данных/полномочий, сомнительная трактовка
бизнес-правила, смена поведения PWA/TMA — durable Q-ID и решение владельца.
При молчании не считать изменение согласованным; продолжать независимый scope.

Старое решение «реализацию светлой темы отложить» не запрещает нынешнюю новую
итерацию: владелец снова включил её в обсуждаемый объём. Раскладка/поведение
тем одинаковы, меняются семантические значения с проверкой контраста.
