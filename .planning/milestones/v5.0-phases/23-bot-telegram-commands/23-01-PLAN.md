**Step 3: Implement getUserByTelegramId in AcademicGrpcServiceImpl.java**

Add override method following the pattern of existing `getUserById`:

```java
@Override
public void getUserByTelegramId(UserByTelegramIdRequest request,
        StreamObserver<UserByTelegramIdResponse> responseObserver) {
    Optional<User> userOpt = academicReadService.fetchUserByTelegramId(request.getTelegramId());

    if (userOpt.isEmpty()) {
        UserByTelegramIdResponse response = UserByTelegramIdResponse.newBuilder()
                .setFound(false)
                .build();
        responseObserver.onNext(response);
        responseObserver.onCompleted();
        return;
    }

    User user = userOpt.get();
    // Look up group name
    String groupName = "";
    if (user.getGroupId() != null) {
        groupName = groupRepository.findById(user.getGroupId())
                .map(Group::getName)
                .orElse("");
    }

    UserByTelegramIdResponse response = UserByTelegramIdResponse.newBuilder()
            .setFound(true)
            .setUserId(user.getId())
            .setLogin(user.getLogin())
            .setDisplayName(user.getDisplayName())
            .setRole(user.getRole().name().toLowerCase())
            .setGroupId(user.getGroupId() != null ? user.getGroupId() : 0L)
            .setGroupName(groupName)
            .setIsHeadman(user.isHeadman())
            .setTelegramId(user.getTelegramId() != null ? user.getTelegramId() : 0L)
            .setInitialPassword(user.getInitialPassword() != null ? user.getInitialPassword() : "")
            .setPasswordChanged(user.isPasswordChanged())
            .build();

    responseObserver.onNext(response);
    responseObserver.onCompleted();
}
```

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Bot -> Academic gRPC | Internal service-to-service, no auth on gRPC (trusted network) |
| Bot -> Auth Service HTTP | Internal service-to-service, OTP endpoints are public |
| OTP code in response body | Code returned to caller — caller is bot, not end user |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-23-01 | Information Disclosure | OTP code in HTTP response | accept | OTP code is returned only to internal bot service (not exposed via API Gateway routes to external clients). Auth Service is on internal docker network. Rate limiting already exists via OtpRateLimitException. |
| T-23-02 | Spoofing | GetUserByTelegramId | accept | gRPC is internal service-to-service on docker network. No authentication on gRPC channel (consistent with all other gRPC calls in the system). Telegram ID is not a secret. |
| T-23-03 | Information Disclosure | initial_password in gRPC response | mitigate | initial_password is only returned via internal gRPC (not exposed via REST). Bot shows it once on /start to the user who owns the telegram_id. After password change, field is null/empty. |
</threat_model>
