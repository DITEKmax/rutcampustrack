# Phase 56 — UI Design Contract

> Visual and interaction contract for Phase 56: PWA Headman Mode.
> Generated by gsd-ui-researcher. Verified by gsd-ui-checker.

## Design System

| Property | Value | Source |
|----------|-------|--------|
| Tool | React + Vite (no UI library) | `frontends/pwa/` — custom Tailwind-first approach |
| Preset | not applicable | — |
| Component library | None (custom primitives + Tailwind + Transit Grid tokens) | Existing PWA components (`BottomNav`, `LoadingSpinner`, card layouts, button patterns) |
| Icon library | `@phosphor-icons/react` — weight `fill` (active), `regular` (inactive) on mobile-first interfaces | `design-decisions.md §1` + Phase 51 extension for headman `Users` icon |
| Font — display | Clash Display (fallback: General Sans → system) | Reuse from Phase 51 web-panel tokens |
| Font — heading | General Sans (fallback: Geist Variable → system) | Reuse from Phase 51 |
| Font — body/label | DM Sans (fallback: Geist Variable → system) | Reuse from Phase 51 |
| Font — mono | JetBrains Mono (for time display in journal) | Reuse from Phase 51 |
| Dark mode | System-default dark (`prefers-color-scheme: dark`); respects device settings | PWA already supports system dark mode via CSS vars |

This phase extends the **existing React PWA** codebase. All Tailwind + Transit Grid tokens, Motion animation primitives, Phosphor Icon patterns, BottomNav structure, and API request patterns are already in place. Do not redefine them — extend only.

## Typography

Base font-size on `<html>` is 14px (inherited from Phase 51 web-panel standard). All sizes use Tailwind scale (`text-sm`, `text-base`, `text-lg`) with Transit Grid CSS vars as fallback.

**Declared weights: 2 only — 400 (regular) and 600 (semibold).**

**Declared font sizes: 4 only**

| Role | Size | Tailwind class | Weight | Font family | Line height | Usage |
|------|------|---------|--------|-------------|-------------|-------|
| Body | 14px | `text-sm` | 400 | `--font-sans` (DM Sans) | 1.5 | Student names in journal rows, input values, icon labels on hub cards, paragraph text |
| Label | 14px | `text-sm` | 600 | `--font-sans` | 1.4 | Form labels (subject, date), status badge text (б/н/у/сп), card meta labels ("Обновлено"), eyebrow labels — use weight 600 + uppercase styling for emphasis |
| Heading | 16px | `text-base` | 600 | `--font-heading` (General Sans) | 1.2 | Hub card titles, page section headers (`Студенты`, `Предметы`), subject row labels in stats, modal headings |
| Display | 20px | `text-lg` | 600 | `--font-display` (Clash Display) | 1.1 | Hub page main heading "Группа", journal page subject name, member count numbers, large attendance percentage numbers in overview/stats pages, group attendance % in stats |

Mono supplement:
- Time values (HH:MM, date displays): `text-sm` / `--font-mono` / weight 600 / `font-variant-numeric: tabular-nums`
- API status codes (error debugging): `text-sm` / `--font-mono` / weight 400

## Focal Points

Explicit primary focal point per route:

### `/group` — Hub screen
Primary focal point: the first 3 cards in the grid (Обзор, Студенты, Предметы) — arranged in a **3-column grid on mobile landscape, 2-column on portrait, 1-column on narrow portrait** (< 480px). Cards have clear affordance (underline on hover, slight shadow elevation). The hub itself is a neutral navigation surface; no single card is visually dominant.

### `/group/journal` — Attendance marking
Primary focal point: the **segmented control buttons** (the 5 status buttons [б][н][у][сп][—] on each student row) — when a segment is selected, it highlights with `--accent-primary` background. The visual hierarchy supports rapid multi-selection: student name (left, light), status buttons (right, interactive, high contrast).

### `/group/stats` — Subject statistics
Primary focal point: the **subject card with highest red-zone breach** (lowest attendance %) — positioned first in the list, visually emphasized with `--accent-warning` background tint on the card. The large attendance % number is the primary data point; per-student rows are secondary detail.

### `/group/overview` — Group overview
Primary focal point: the **pending tickets count badges** (excuse count + late-checkin count) — displayed prominently at top as actionable alert cards. The group member count is secondary context.

### 2. `/group` — GroupHubPage

Layout: **Hub screen** with 7 navigation cards. Mobile-first responsive grid.

**Grid layout:**
- Desktop (≥768px): 3-column grid (responsive to viewport width)
- Tablet (480–768px): 2-column grid
- Mobile (<480px): 1-column grid
- Gap: `--space-5` (24px) between cards
- Page padding: `--space-6` (32px) on sides, `--space-7` (48px) top/bottom

**Hub Cards (7 total):**

Each card is a semantic `<a>` link (`role="article"`) with:
- **Background:** `--bg-secondary` (white/dark card)
- **Border:** `1px solid var(--border-subtle)` (light gray divider)
- **Border-radius:** `--radius-lg` (8px)
- **Padding:** `--space-4` (16px) internal spacing
- **Min-height:** 120px (touch target minimum + visual consistency)
- **Hover state:** 
  - Box-shadow elevation (`0 4px 12px rgba(0,0,0,0.1)` dark, `0 2px 8px rgba(0,0,0,0.08)` light)
  - Underline on heading (color: `--accent-secondary`)
- **Animation on enter:** Motion `<AnimatePresence>` fade-in + slight scale (1.0 → 1.02 on hover) with `transition={{ duration: 0.15 }}`

**Hub Card Contents (standard structure for all 7):**

```
┌─ Card header (icon + title row)
│  ├─ Icon: 24px Phosphor, weight `fill`, color `--accent-primary`
│  └─ Heading: `text-base` (16px), weight 600, `--font-heading`
├─ Card body (optional meta)
│  └─ Body text or small stat (if applicable)
└─ Card footer (arrow indicator)
   └─ Phosphor `CaretRight` 16px, color `--text-muted`, floats right
```

**The 7 Cards:**

| Route | Title | Icon | Body content | Notes |

### 6. `/group/journal` — JournalPage (Mobile-first 2-step flow)

Layout: Full-width page with state-machine-based UI.

**Step 1: Selector Screen**

Header:
- Back button
- Page heading: "Журнал" (`text-base`, weight 600)

Content:
- **Subject selector:** `<select>` or custom dropdown (style: `--bg-secondary` background, `--text-base` text, padding `--space-3`)
  - Label: "Предмет" (`text-sm`, weight 600)
  - Placeholder: "Выберите предмет"
  - On change: populate `selectedSubjectId`

- **Date picker:** native `<input type="date">` (styled to match design) or custom date input
  - Label: "Дата" (`text-sm`, weight 600)
  - Default: today
  - Constraint: only allow lessons within current semester (or last 90 days as fallback per CONTEXT.md D-12)

- **Submit button:** "Загрузить журнал" (Phosphor `ArrowRight` 16px right-aligned, `--accent-primary` button, min-height 44px)
  - On tap: fetch journal data via `getJournal(groupId, subjectId, dateFrom, dateTo)` where both dates are the same day
  - If loading: button shows spinner + "Загружаем…" copy
  - If error (API returns 404 or network error): inline error message — "Ошибка загрузки. Проверьте подключение и попробуйте снова." (red text, resets form, button re-enables)
  - On success: proceed to **Step 2**

**Step 2: Journal Student List (only rendered after Step 1 success)**

Header:
- Back arrow button → returns to Step 1 (clear state)
- Compact breadcrumb: "{Subject} · {Date}" (small text, `--text-muted`)

Content:

For each student in the group (matching the lesson's enrolled students), render a **Student Row** with segmented control:

```
┌─ Student Row (56px min-height, padding --space-3, --bg-secondary card, margin-bottom --space-2)
│  ├─ Left: Student name (weight 600, `text-sm`)
│  └─ Right: Segmented Control (5 buttons, each 40×40px)
│     ├─ [б] — present
│     ├─ [н] — absent
│     ├─ [у] — excused
│     ├─ [сп] — free_attendance
│     └─ [—] — cancelled
└─ Visual state:
   ├─ Selected button: `--bg-accent-primary`, bold white text, shadow (selected state)
   ├─ Unselected buttons: `--bg-surface` light background, `--text-primary` text
   └─ Hover: all buttons respond to touch (min 40×40px tap area per WCAG)
```

**Segment button behavior:**
- Single tap = select immediately (optimistic UI)
- Selected button shows with `--accent-primary` background + bold weight 600 text
- One button per row is always selected (default: `cancelled` / [—] if no prior marking)
- On tap: send `PUT /api/attendance/lessons/{lessonId}/students/{userId}` with `{ status: "present"|"absent"|"excused"|"free_attendance"|"cancelled" }`
- If success: local state updates remain (optimistic)
- If error (network, 400, 403): revert button to prior state + show inline Motion error badge (small red card, "Ошибка. Попробуйте ещё раз.") using `AnimatePresence` + fade-in/out (150ms)

**Empty state (no students or no lessons for date):**
- Centered: "На эту дату занятий нет" (`--text-muted`, `text-sm`)

**Loading state (Step 2 fetching):**
- 3-4 skeleton student rows (each 56px height) with shimmer animation

**Save section (bottom sticky):**
- No explicit "Save" button — each tap auto-saves (optimistic UI)
- Optional: bottom info bar "Изменения сохраняются автоматически" (small, `--text-muted`)

## Interaction & Animation Contract

| Interaction | Mechanism | Duration | Easing | Notes |
|---|---|---|---|---|
| Route enter (all headman routes) | Motion `<AnimatePresence>` fade-in + translateY 8px→0 | 150ms | `easeOut` | Consistent with existing student routes |
| Hub card entrance | Motion stagger container, each card `opacity 0→1, scale 0.95→1` | 200ms | `easeOut` | All 7 cards animate in sequence (40ms stagger) |
| Hub card hover | Box-shadow elevation + border underline on heading | 120ms transition | `ease-in-out` | CSS transition on hover pseudo-class |
| Journal segment button tap | Color change instant (optimistic), ripple animation overlay | 80ms | linear | Tap triggers background color change immediately; optional ripple overlay |
| Journal error toast | `AnimatePresence` fade-in from bottom (translateY 16px→0), auto-dismiss after 3s | 200ms in / 100ms out | `easeOut` | Uses Motion `AnimatePresence` wrapper, not toast library |
| Threshold editor save | Checkmark icon fade-in + scale 0→1 (success confirmation) | 300ms | `easeInOut` | Brief visual celebration before input resets to display mode |
| Stats card red-zone highlight | Card background subtle tint (not animated on load, static) | — | — | Red-zone cards maintain constant visual emphasis |
| Loading skeleton shimmer | CSS `@keyframes gradient-shift` (background-position loop) | 1.5s | linear infinite | Reuse from existing PWA skeletons |
| BottomNav 5th tab entrance | Motion `layoutId` shared-layout animation (pill slides to new position) | 200ms | `easeInOut` | Existing Animation framework preserved; new tab inherits the same animation |

All animations respect `@media (prefers-reduced-motion: reduce)` — disable all transform/opacity transitions, keep functional state changes.

## Service Worker Runtime Caching

### Cache Strategy

**Strategy:** Stale-While-Revalidate (SWR) via Workbox
- Fast response from cache on first load
- Background refresh in parallel
- Updated data served on next visit
- Ideal for read-heavy mobile scenarios

### Cached Endpoints

Register a single named cache `headman-api-cache-v1` for all headman GET endpoints:

| Endpoint Pattern | HTTP method | Status | TTL | Max entries |
|---|---|---|---|---|
| `/api/academic/groups/:id/members` | GET | 200 | 24h | 50 |
| `/api/academic/groups/:id/subjects` | GET | 200 | 24h | 50 |
| `/api/academic/subjects/*` (details + teacher list) | GET | 200 | 24h | 100 |
| `/api/attendance/reports/journal?groupId=*` | GET | 200 | 24h | 100 |
| `/api/academic/thresholds/resolve?groupId=*` | GET | 200 | 24h | 50 |
| `/api/attendance/excuses/pending?groupId=*` | GET | 200 | 24h | 30 |
| `/api/attendance/late-checkins/pending?groupId=*` | GET | 200 | 24h | 30 |

**Cache rules:**
- **TTL:** `maxAgeSeconds: 86400` (24 hours) — entries rotate automatically
- **Max entries:** Per pattern (see table) — prevents unbounded growth
- **Statuses:** `CacheableResponsePlugin({ statuses: [200] })` — only cache successful responses
- **Methods:** GET only — PUT/POST/PATCH/DELETE always go to network
- **Error handling:** Do NOT cache 4xx/5xx responses; always return network error to component

### Implementation Location

File: `frontends/pwa/src/sw.ts` (existing Service Worker file)

Add after the existing `precacheAndRoute()` call:

```typescript
import { registerRoute } from 'workbox-routing'
import { StaleWhileRevalidate } from 'workbox-strategies'
import { ExpirationPlugin } from 'workbox-expiration'
import { CacheableResponsePlugin } from 'workbox-cacheable-response'

// Register headman API runtime cache
const headmanApiMatcher = (request: Request) => {
  const url = new URL(request.url)
  return (
    url.pathname.includes('/api/academic/groups/') ||
    url.pathname.includes('/api/academic/subjects') ||
    url.pathname.includes('/api/attendance/reports/journal') ||
    url.pathname.includes('/api/academic/thresholds/resolve') ||
    url.pathname.includes('/api/attendance/excuses/pending') ||
    url.pathname.includes('/api/attendance/late-checkins/pending')
  )
}

registerRoute(
  headmanApiMatcher,
  new StaleWhileRevalidate({
    cacheName: 'headman-api-cache-v1',
    plugins: [
      new ExpirationPlugin({
        maxAgeSeconds: 86400,
        maxEntries: 100,
      }),
      new CacheableResponsePlugin({
        statuses: [200],
      }),
    ],
  })
)
```
