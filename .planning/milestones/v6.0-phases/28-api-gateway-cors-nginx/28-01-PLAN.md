    }

    This ensures OPTIONS preflight requests pass through without JWT validation. The CORS filter (configured via globalcors YAML) handles the actual CORS response headers.

    **Part B: application.yml globalcors configuration**

    Add two new sections to `spring.cloud.gateway` in application.yml — `globalcors` (BEFORE routes) and `default-filters` (BEFORE routes):

    ```yaml
    spring:
      application:
        name: api-gateway

      cloud:
        gateway:
          globalcors:
            add-to-simple-url-handler-mapping: true
            cors-configurations:
              '[/**]':
                allowed-origins:
                  - "http://localhost:5173"
                  - "http://localhost:80"
                allowed-methods:
                  - GET
                  - POST
                  - PUT
                  - PATCH
                  - DELETE
                  - OPTIONS
                allowed-headers: "*"
                allow-credentials: true
                max-age: 3600
          default-filters:
            - DedupeResponseHeader=Access-Control-Allow-Origin Access-Control-Allow-Credentials, RETAIN_UNIQUE
          routes:
            # ... all existing routes unchanged ...
    ```

    Keep ALL existing route definitions exactly as they are. Only add the `globalcors` and `default-filters` blocks above `routes`.

    Key details:
    - `add-to-simple-url-handler-mapping: true` — required so OPTIONS preflight handled before route matching
    - `allowed-origins` — explicit list (NOT wildcard `*`) because `allow-credentials: true` is incompatible with wildcard
    - `DedupeResponseHeader` — prevents duplicate CORS headers when backend services (notification-web WebSocketConfig) also set CORS headers
    - `max-age: 3600` — browser caches preflight for 1 hour
