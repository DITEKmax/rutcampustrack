## 1. Что за проект

**RutCampusTrack** — система учёта посещаемости и расписания для РУТ (МИИТ). Личный проект, с вузом не связан, согласований нет, язык интерфейса только русский, обращение на «ты». Репозиторий продукта: `github.com/DITEKmax/rutcampustrack`.

Бэкенд написан и работает: Java 21, Spring Boot 3.4, шесть микросервисов, contract-first, gRPC, RabbitMQ, PostgreSQL + MongoDB + Redis, Flyway. Фронтенд переписывается на Vue с нуля. Роли: `student`, `headman` (староста), `teacher`, `admin`.

**Текущий маршрут:** сначала макеты в Figma по всем адаптивам, потом перенос в код. Порядок внутри Figma: переменные → компоненты → блоки → экраны 1920 → адаптивы 1440/1280.

**Скилл Refero не ставили:** он объявляет себя главным авторитетом по дизайну и требует исследовать референсы перед каждым решением, что конфликтует с закрытым брендбуком.

**Анимации в Figma не закладываются** — ни прототипом, ни Smart Animate. Собираются статичные кадры, движение пишется во Vue.

## 5. Как ведётся работа с агентом

Отработанный цикл, повторять его:

1. **Промпт на часть** — ссылка на файл Figma, что перечитать, требование разведки, особое внимание по этой части, правила.
2. **Разведка** — агент проходит часть, ничего не создавая, и выдаёт: состав с числом вариантов, нехватку токенов одним списком, расхождения спеки с реестром и со спеками экранов, ссылки на поздние части.
3. **Ответ на разведку** — решения по всем вопросам разом, чтобы сборка шла без остановок. Здесь же правки в файлы.
4. **Сборка партиями** — после каждой отчёт и остановка.
5. **Контрольные точки** — на самых рискованных местах остановка со скриншотами в обеих темах.
6. **Правки в документы** — после сборки, чтобы формулировки легли на то, что реально собралось.

### Что требовать в каждом отчёте

Непривязанные paints, недействительные `VariableID`, геометрия вне шкалы, отсоединённые экземпляры, пересечения секций, обе темы, длинная русская строка. Числами, а не словами.

### Приёмы, которые окупились

- **Разведка перед сборкой.** В части 2 сэкономила девять остановок.
- **Полный список нехватки разом.** Иначе агент встаёт на каждом токене.
- **Контрольная точка на одном компоненте** до размножения на тридцать.
- **Проверка фактом, а не отчётом.** «Покажи скриншот», «покажи выборку 15 слоёв», «покажи расчёт».
- **Отделять вопрос от поручения.** Агент дважды превращал вопрос в решение и переделывал компоненты; после явного правила перестал.

### Чего требовать нельзя

Не поручать агенту вести документы. Не давать HTML-прототипы как вход (он перенесёт литералы). Не смешивать в одной задаче правку геометрии и добавление осей.

| Решение | Где записано |

| **Форма — носитель смысла:** нажимают → капсула `radius/full`, заполняют → `radius/md`, содержит → `radius/lg`, модалка → `radius/xl` | брендбук §4.2 |

| **Три круга отметки:** не отмечено — три нейтральных нажимаемых, отмечено — один со статусной заливкой; кольцо без заливки = автоматическое «н» | реестр, спеки 111/112 |
| Староста ставит «у» руками с обязательной причиной текстом; тикет — сценарий студента | там же |
| При отмене пары отметки **стираются**; колонка остаётся, ячейки пусты, заголовок зачёркнут + текст «отменена» | спека 112 |
| **`occupied` ≠ `disabled`:** занятый чужой парой слот показывает группу, аудиторию, преподавателя | figma-spec §17 части 6 |

| Пароль показывается до смены, состояния `hidden` нет | спеки 116, 132 |
| Полные подписи метрик — в доступном имени, видимые сокращённые | спека 122 |
| Сегментированный переключатель роли; при одной роли — подпись, не контрол | BRAND_DIRECTION §2.3 |
| Шапка двухъярусная: лого, роли, уведомления сверху; навигация снизу | figma-spec §2 части 3 |

### Носители смысла — все заняты

Заливка акцентом — «сейчас», один объект на экран. Контур 2px — кольцо фокуса. Штриховка — «занято». Пунктир — «свободно, принимает». Зачёркивание — «этого больше нет», рядом обязателен текст. Инверсия — текущий выбор. Раскрытие сдвигом — «редактируется». **Новых не изобретать.**

## 9. Реестр расхождений Figma и кода

`04-figma/figma-code-gaps.md`, восемь пунктов. Главные:

- **Leading и tracking** заданы процентами без привязки к переменным: Figma трактует число в переменной как пиксели.
- **Тень** в CSS одной строкой, в Figma — эффект-стиль плюс семантические цвета: у Effect Style нет режимов.
- **OpenType-функции** (табличные цифры) включаются только руками, Plugin API их не пишет.
- **`dashPattern`** не связывается с переменной — пунктир 4/4 литералом.
- **Арифметика в связях** не выражается: `112 + n × token` остаётся литералом.
- **`radius/full` = 999** — сентинел, в rem не переводится.
- **`radius/none`** нужен только Figma, в CSS не эмитится.

Это главный документ при переносе в код.

## 11. Как работать со мной

Итеративно. Помогай планировать, готовь промпты для агента с учётом реального API, ревьюй структуру и решения, честно говори, если что-то в плане неверно или устарело.

**Файлы отдавай целиком, а не дельтой** — владелец заменяет ими свои. Указывай, куда класть каждый: папка проектирования и `kit`, и надо ли перезаливать в базу знаний.

**Не пересказывай содержимое приложенных файлов** — сразу к делу.

**Не соглашайся из вежливости.** За сессию агент трижды находил ошибки в моих формулировках, и трижды я был неправ: `.agents/skills` вместо `.codex/skills`, кромка полосы занятости, пятый компонентный токен, которого не было. Владелец просил честности прямо.

**Когда решение отменяет закрытое — говори об этом вслух**, а не протаскивай правкой. Отменять можно, молча — нет.

**Правки в документы всегда с датой и объяснением,** старый текст зачёркивается или помечается отменённым, а не удаляется. История важнее аккуратности: через месяц надо понимать, почему решение поменялось.
