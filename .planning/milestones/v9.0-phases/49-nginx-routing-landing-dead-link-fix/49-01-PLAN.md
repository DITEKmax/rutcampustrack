## Why `location = /` (exact match) instead of `location /`
The root catch-all `location /` used to match EVERYTHING that no other block matched. We must not break `/favicon.ico`, `/robots.txt`, or other unknown paths. Using `location = /` (exact-match modifier `=`) makes the redirect apply ONLY to the literal `/` URL. Any other unmatched path will 404 naturally (no fallback to PWA), which is the correct behaviour — the PWA is now at `/app/`.

## Phase 50 dependency (informational only — do NOT implement here)
Phase 50 will later add `location /login`, `location /student/`, `location /headman/`, and change `/admin/` to proxy through the same web-panel-nginx. This plan only redirects the root; Phase 50 completes the `/login` resolution. A temporary 404 on `/login` between Phase 49 ship and Phase 50 ship is acceptable per the phase boundary — Phase 49 success criterion 1 only requires the REDIRECT to fire.
