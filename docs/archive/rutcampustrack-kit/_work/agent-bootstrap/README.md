# Подготовленный комплект для RutCampusTrack

✏️ 05.09.2026. Пакет подготовлен в kit. Основной репозиторий
`C:\Users\maksd\IntelliJIDEA\rutcampustrack` пока не изменён.
Содержимое `project/` предназначено для его корня, а не для отдельного вложенного
приложения. Оно не содержит Vue-код, продуктовые документы или секреты.

## Что установится

- Корневой `AGENTS.md` и инструкции для frontends, services, tests.
- `.codex/config.toml`: root Astra low, fallback Terra medium, до трёх детей.
- Три дочерние роли с динамическим выбором модели при spawn.
- Три коротких skills: design, source resolution, verification.
- `docs/agent-workflow.md`: таблица моделей, S0–S3, эскалация и границы прав.

Комплект не устанавливает OpenCode/внешние модели, не меняет глобальные плагины,
авторизацию и разрешения Codex. Figma/openai-docs/browser из установленного
окружения используются по необходимости; их копии в репозиторий не добавляются.

## Как открыть новый проект

1. В Codex добавь существующую папку
   `C:\Users\maksd\IntelliJIDEA\rutcampustrack` как локальный проект.
   Не создавай новый пустой Git-репозиторий поверх имеющегося и не удаляй старый код.
2. Установи пакет по инструкции ниже. Это можно сделать до переноса документов.
3. Подтверди доверие именно этой папке в клиенте Codex, сохрани действующий
   ограниченный доступ к workspace и запрос разрешения на опасные действия.
   Не добавляй `trust_level = "trusted"` в корень проектного TOML: проект
   не может сам себе выдать доверие.
4. Создай новую задачу в этом проекте, выбери **GPT-6 Astra / low**. Старую задачу
   продолжать для проверки новых настроек не надо. Для дальнейших больших
   реализаций используй worktree; первая задача — сверка обвязки и перенос.
5. Проверь обнаружение AGENTS, трёх skills и ролей, фактический model/effort
   по metadata клиента. Начни с одной read-only делегации Luna medium, затем
   проверь доступность остальных назначений. До этой проверки routing считается
   подготовленным, но не подтверждённым живым запуском нового проекта.

## Установка после просмотра файлов

`install.ps1` по умолчанию только показывает план. Запуск без `-Apply` ничего
не пишет в основной репозиторий. `-Apply` сохраняет заменяемые инструкции в
`docs/archive/agent-bootstrap/<timestamp>/` с неактивными расширениями, убирает
старые проектные skills из обнаружения и копирует готовые файлы.
Старые код, CLAUDE.md, .planning, пользовательский config, MCP и секреты не меняются.
Если найдётся уже существующий `.codex/config.toml` или custom agents, установщик
остановится: их надо объединить адресно, сохранив MCP/permissions.

Из **PowerShell 7** в папке `_work/agent-bootstrap`:

```powershell
.\install.ps1
.\install.ps1 -Apply
```

Перед применением проверь план. Если основной репозиторий изменится между
подготовкой и установкой, новый незнакомый skill блокирует архивирование.
Известные старые skills и причины исключения перечислены в `skill-audit.md`.

## Первый запрос в новом проекте

```text
Проверь готовый агентный комплект и его обнаружение в этом проекте.
Ты root Astra low. Для одной ограниченной read-only проверки используй
explorer Luna medium и проверь фактические model/effort по runtime metadata.
Не подменяй отсутствие настройки текстовой ролью.
Затем выполни только перенос источников design/kit/research по согласованной
карте: происхождение, действующие решения, неактивный архив старых инструкций.
Используй rct-source-resolution; я укажу доступные папки источников.
Сохраняй историю и чужие изменения. Figma, код, базы и production не меняй.
Сначала подготовь канон и список оставшихся продуктовых конфликтов.
К реализации Vue/BFF без следующего задания не переходи.
```

До переноса в `docs/design`, `docs/wireframes`, `docs/product` и
`docs/architecture` ссылки skills на эти источники являются целевой картой.
Их отсутствие блокирует UI/доменную реализацию, но не установку и сверку пакета.
