### Разграничение с 101 и 102

| Что на 103 | Где ещё встречается | Вердикт |
|---|---|---|
| 8 плиток: % и количество по `+`, `н`, `у`, `+ и у` | 102 — те же показатели, но для **выбранного среза** | Не дубль по данным: на 103 срез всегда **семестр целиком** (прим. 4 скана). Дубль по компоненту — и это правильно, `StatCard` один |
| График % `+` по неделям семестра + средняя по группе | 101 — тренд по дням текущей недели | Пересекается только в режиме «Неделя». Новое — семестровая ось и вторая серия |
| Таблица предметы × метрики с раскрытием по типам занятий | 102 — режим «по предметам», но там **отметки по парам** | Разная гранулярность, дубля нет |
| Рейтинг в группе по % `+` | нигде | Полностью новое |

Зоны ответственности зафиксированы в `COMPONENT_REGISTRY.md` §8.1:
101 — оперативный срез (сегодня, текущая неделя) · 102 — фактические отметки по парам · 103 — семестровые агрегаты и сравнение с группой.

**Открыто (предложение фронта, владельцем не подтверждено):** режим «Неделя» на 103 избыточен — недельный срез закрыт 101 (график) и 102 (метрики). Предложение: дефолт «Весь семестр», «Неделя» — только деталь графика.

## 4. Потребности в данных

Сначала ЧТО нужно, потом ГДЕ лежит сейчас.

### 4.1 Итоги семестра (8 плиток)
**Нужно:** по активному семестру для текущего студента — количества `present` / `absent` / `excused`, объединённое `+ и у`, число прошедших пар, и те же четыре доли в процентах.
Правила знаменателя: отменённые пары исключены; будущие не входят; разовые и перенесённые входят наравне с регулярными.
**Сейчас:** `GET /attendance/reports/student/stats`, `GET /attendance/reports/student/dashboard`.
**Пробел:** `[уточнение по контракту]` — какой из двух отдаёт разбивку по трём статусам и в количествах, и в процентах, и как считает отменённые. `[предложение по бэкенду]` — проценты считает сервер и отдаёт вместе с количествами.

### 4.2 Рейтинг в группе
**Нужно:** упорядоченный по % `+` список членов своей группы за семестр: позиция, отображаемое имя, процент, признак «это я». Курсорная подгрузка с якорем на моей позиции, чтобы сразу показать соседей сверху и снизу.
**Сейчас:** `[нет API]`. Есть `GET /academic/groups/my/members` (состав) и `GET /attendance/reports/journal` (сетка группы) — сборка на клиенте означала бы вытягивание всего журнала ради одного числа.
**Пробел:** `[предложение по бэкенду]` — агрегат «рейтинг группы по посещаемости» с пагинацией и якорем; ФИО приходят в самом ответе, иначе N+1 через `GET /academic/users/by-ids` на каждую страницу.

### 4.3 График
**Нужно:** серия точек `{ номер недели, границы недели, чётность, % «+» }` за семестр — моя; вторая серия с тем же ключом — средняя по группе. В режиме «Неделя» — точки по дням выбранной недели.
**Сейчас:** недельный таймсерис есть в `dashboard` (мобильный, только мой).
**Пробел:** `[нет API]` — средней по группе нет. `[предложение по бэкенду]` — обе серии в одном ответе с одинаковой сеткой ключей; номер недели и чётность приходят полями (клиент их не вычисляет).

### 4.4 Таблица по предметам
**Нужно:** список предметов группы за активный семестр, у каждого — агрегаты по трём статусам (количества + проценты) и `+ и у`; вложенный уровень — те же агрегаты по каждому типу занятий, который у предмета реально есть. Сортировка по любой колонке, мультиколоночная с приоритетом, дефолт — алфавит.
**Сейчас:** `[нет API]` для агрегатов. `dashboard` отдаёт только топ пропущенных предметов. `GET /academic/subjects` даёт названия, но не статистику.
**Пробел:** `[предложение по бэкенду]` — агрегат «моя посещаемость по предметам и типам занятий за семестр», сортировка на сервере.

### 4.5 Контекст
Активный семестр (название, границы для `DatePager`), профиль и роли приходят при входе (JS-SYSTEM-14) — повторно экраном не запрашиваются.

## 5. Состояния

На бумаге состояний нет. Красный на скане = «нет взаимодействия», но не «нет состояний». Всё ниже добавлено при разборе.

| Блок | Состояния |
|---|---|
| Плитки | `loading` (скелетон, `aria-busy`) · `future` — прошедших пар нет → «нет данных», **не 0%** · `error` (RFC 9457 + повтор) |
| Рейтинг | `loading` · `empty` — сравнивать не с кем / нет прошедших пар · `partial` — подгружена часть списка · `error` |
| График | `loading` · `empty` — в выбранной неделе нет прошедших пар · `out-of-range` — граница семестра, стрелка недоступна с пояснением · `error` **отдельно для серии группы**: моя линия рисуется, вторая заменяется пояснением |
| Таблица | `loading` · `empty` — предметов нет · `no-data` в ячейке — по этому типу занятий прошедших пар нет · `error` |
| Экран | `no-active-semester` — экран вырождается в пояснение · `forbidden` — без утечки цифр · `offline` — предупреждение, что данные могут быть устаревшими |

Блоки грузятся и падают независимо (реестр §6.2): упавший рейтинг не роняет таблицу.

**Ролевых различий нет** — `headman` видит тот же экран, в рейтинге отображается как обычный студент.

**A11y на уровне структуры:**
- моя позиция в рейтинге помечается текстом, а не только цветом;
- график сопровождается `ChartDataTable`, серии различаются подписями;
- `StatsBySubjectTable` — настоящая `<table>` с `th scope="col"` / `scope="row"`, сортировка через `aria-sort`, раскрытие строки — `<button aria-expanded>`;
- смена периода объявляется через `role="status"`.

## 6. Навигация и действия

| Элемент | Действие |
|---|---|
| `MainNav` | переход на 101 / 102 / 104 / карту / заявки; активный пункт `aria-current="page"` |
| `RoleSwitcher` | переключение активной роли; рендерится только при `roles.length > 1` |
| `ProfileMenu` | «Настройки» → профиль, «Выход» → выход с подтверждением |
| Вкладки разреза (`Tabs`) | «Весь семестр / Неделя» — меняют **только график**, плитки и таблицу не трогают |
| `DatePager` ◀ ▶ | листание недель; на границе семестра стрелка недоступна с пояснением |
| Заголовок колонки `StatsBySubjectTable` | сортировка; приоритеты накапливаются в порядке кликов |
| Строка предмета в `StatsBySubjectTable` | раскрытие / сворачивание типов занятий |
| «Фильтр» | предполагается триггер `Popover` с параметрами сортировки. **Требует уточнения:** в прим. 2 скана описана исключительно сортировка, которую уже дают заголовки колонок |
| «Сбросить» | сброс сортировок и фильтров к дефолту (алфавит). Сброс происходит и при уходе с экрана — состояние не персистится |
| Строка рейтинга | **не кликабельна** — переход к чужой статистике не проектируется |

Деструктивных действий нет → подтверждений нет. Экран целиком на чтение.

## 7. Заметки на будущее

**Адаптив (без брейкпоинтов):**
- 1920: плитки 4×2 слева, рейтинг колонкой справа на всю высоту блока; график и таблица во всю ширину.
- Уже: плитки перетекают в две колонки, рейтинг уходит под них.
- Таблица: горизонтальная прокрутка с закреплённой колонкой предмета; при сильном сужении вложенный уровень показывать раскрытием, а не колонками.
- График: при сужении сокращаются подписи оси, вторая серия не удаляется.

**Открытые вопросы по экрану:**
- нужен ли режим «Неделя» (предложение фронта — оставить только как деталь графика);
- избыточна ли кнопка «Фильтр»;
- `ExportButton` — на скане отсутствует, API для персональной выгрузки нет.

**Для следующих этапов:**
- Мобильный `dashboard`-эндпоинт спроектирован под PWA/Mini-App (donut, топ пропущенных). На 1920 его состав не используется — экран не ужимался под этот ответ.
- Круговая диаграмма на десктопе не применяется: те же доли уже показаны отдельными плитками.
- Число запросов на экран: **4–6, из них три не существуют** — фактура к решению REST/GraphQL, см. `backend-requests.md`.
