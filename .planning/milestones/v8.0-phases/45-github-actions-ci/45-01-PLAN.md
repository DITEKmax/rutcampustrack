**Step 1: Create `services/notification-bot/pyproject.toml`**

Ruff needs a config to exclude protobuf-generated files (`*_pb2.py`, `*_pb2_grpc.py`). Create:

```toml
[tool.ruff]
target-version = "py312"
line-length = 120

[tool.ruff.lint]
select = ["E", "F", "W", "I"]

[tool.ruff.lint.per-file-ignores]
"bot/grpc_client/*_pb2.py" = ["E501", "F401", "E402", "F811"]
"bot/grpc_client/*_pb2_grpc.py" = ["E501", "F401", "E402", "F811"]
```

Selecting only `E` (pycodestyle errors), `F` (pyflakes), `W` (pycodestyle warnings), `I` (isort) keeps initial linting reasonable. The `per-file-ignores` suppresses generated protobuf files which would otherwise cause dozens of false failures.

**Step 2: Create `.github/workflows/ci.yml`**

Create the directory `.github/workflows/` and the workflow file with this exact content:

```yaml
name: CI

on:
  push:
    branches: ['**']
  pull_request:
    branches: ['**']

jobs:
  java-build-test:
    name: Java Build & Test
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - uses: actions/setup-java@v4
        with:
          java-version: '21'
          distribution: 'temurin'

      - name: Setup Gradle
        uses: gradle/actions/setup-gradle@v6

      - name: Make gradlew executable
        run: chmod +x gradlew

      - name: Build and test all Java services
        run: ./gradlew build

  python-lint-test:
    name: Python Lint & Test
    runs-on: ubuntu-latest
    defaults:
      run:
        working-directory: services/notification-bot
    steps:
      - uses: actions/checkout@v4

      - uses: actions/setup-python@v5
        with:
          python-version: '3.12'
          cache: 'pip'
          cache-dependency-path: |
            services/notification-bot/requirements.txt
            services/notification-bot/requirements-test.txt

      - name: Install dependencies
        run: |
          pip install ruff
          pip install -r requirements.txt
          pip install -r requirements-test.txt

      - name: Lint with ruff
        run: ruff check .

      - name: Check formatting with ruff
        run: ruff format --check .

      - name: Run tests
        run: pytest tests/ -v

  frontend-build-test:
    name: Frontend Build & Test
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - uses: actions/setup-node@v4
        with:
          node-version: '22'
          cache: 'npm'
          cache-dependency-path: |
            frontends/pwa/package-lock.json
            frontends/mini-app/package-lock.json
            frontends/web-panel/package-lock.json

      - name: PWA - install, test, build
        working-directory: frontends/pwa
        run: npm ci && npm test && npm run build

      - name: Mini App - install, test, build
        working-directory: frontends/mini-app
        run: npm ci && npm test && npm run build

      - name: Web Panel - install, test, build
        working-directory: frontends/web-panel
        run: npm ci && npm test && npm run build
```

Key design decisions implemented:
- Three independent parallel jobs (no `needs:` between them) — per CI-01, CI-02, CI-03
- `gradle/actions/setup-gradle@v6` provides automatic Gradle dependency + build cache — per CI-04
- `chmod +x gradlew` before build because gradlew is stored as mode 100644 (Windows dev environment)
- `pull_request` trigger (NOT `pull_request_target`) — secure: no secrets exposed to fork PRs
- No `${{ github.event.* }}` interpolation in `run:` steps — prevents script injection
- `cache: 'pip'` on setup-python caches pip download cache
- `cache: 'npm'` on setup-node caches npm download cache using package-lock.json hashes
- All three jobs must pass for the workflow to be green — a failing test in any job fails the workflow

ruff format --check .

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Pull request submitter -> CI runner | Untrusted code from fork PRs executes on GitHub-hosted runner |
| Workflow YAML -> shell execution | YAML interpolation into `run:` steps can inject shell commands |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-45-01 | Tampering | ci.yml `run:` steps | mitigate | No `${{ github.event.* }}` interpolation in any `run:` block — all commands use hardcoded values or `github.sha` only |
| T-45-02 | Elevation of Privilege | workflow trigger | mitigate | Use `pull_request` trigger (not `pull_request_target`) — fork PRs cannot access repo secrets |
| T-45-03 | Tampering | GitHub Action supply chain | accept | Using `@v4`/`@v6` major version tags from official GitHub and Gradle orgs — acceptable risk for portfolio project (SHA pinning is enterprise-grade) |
| T-45-04 | Information Disclosure | build logs | accept | Phase 45 has no secrets configured — no risk of secret leakage. Phase 46 will handle secrets separately |
</threat_model>
