# Этап 2 — компоненты

Начинается после проверки этапа 1.

## Откуда берутся

- **Базовые контролы** — из shadcn-vue через MCP: кнопка, поле ввода,
  чекбокс, переключатель, поповер, вкладки, таблица, календарь,
  пагинация, диалог. Ставить и перекрашивать нашими токенами.
  С нуля не писать.
- **Доменные** — наши, в библиотеках их нет: журнал посещаемости,
  пикер статуса, полоса текущей пары, карточка пары, карточка заявки,
  конструктор расписания, листалки периода.
- **Список закрыт `COMPONENT_REGISTRY.md`.** Новых не заводить.

## Порядок внутри этапа

Снизу вверх, партиями:

1. атомы: поле ввода, число дня, ячейка, чип, бейдж статуса, шкала заполнения
2. действия и формы
3. каркас и навигация
4. таблицы и сетки — самая тяжёлая партия
5. значения и статусы
6. доменные карточки и панели
7. состояния: загрузка, пусто, пусто после фильтра, ошибка, нет доступа

Компонент собирается **из атомов**, а не из новых слоёв.

## По каждому компоненту

- все состояния из `brandbook-v2.md`; пустых клеток в матрице не бывает
- где `hover` запрещён — написать это, а не оставить пусто
- поведение при переполнении: длинное русское имя, число в четыре знака,
  пустое значение
- анатомия — `design/figma-spec.md`, читать нужный раздел, не файл целиком

## Проверка после каждой партии

- [ ] Ни одного литерала
- [ ] Правка атома доходит до всех потребителей
- [ ] Матрица состояний полная
- [ ] Ни одного компонента вне реестра
- [ ] Обе темы проверены
