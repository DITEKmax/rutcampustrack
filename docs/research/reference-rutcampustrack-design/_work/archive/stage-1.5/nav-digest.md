| Элемент | Действие |
|---|---|
| `RoleSwitcher` → другая роль | смена активной роли, редирект на главную выбранной роли. Подтверждения нет: несохранённых данных на экране не бывает. Смена объявляется `role="status"` |
| `MainNav` «главная» | текущая страница, `aria-current="page"` |
| `MainNav` «пользователи» | → **ПК-132** |
| `MainNav` «группы» | → **ПК-133** |
| `MainNav` «семестры» | → **ПК-134** |
| `MainNav` «карта» | → **ПК-135** (ведение схем, **не** просмотр 105) |
| `ProfileMenu` → «Настройки» | → ПК-108, общий экран настроек |
| `ProfileMenu` → «Выход» | `POST /auth/logout` → ПК-001. **Подтверждения нет** — обычный выход обратим; подтверждается только «выйти на всех устройствах» (108) |
| `PeriodTabs` «сегодня» / «Всё время» | перезапрос блока активности. Значение **живёт в URL** (`?period=today`): F5 не сбрасывает, ссылку можно переслать. Между сессиями не сохраняется — «липкий» период опаснее лишнего клика (правило чата 6). **Оптимистичного UI нет**: показывать предположительные числа нельзя, старые значения гасятся на время загрузки |
| Карточки, строки метрик | **не кликабельны**, переходов на скане нет |

### Нехватка прав

| Ситуация | Поведение |
|---|---|
| Неавторизованный | → ПК-001 с сохранением запрошенного адреса для возврата |
| Авторизован, роли admin нет | `ForbiddenState`, **данные не запрашиваются вовсе**. Формулировка — за аудитом безопасности |
| Роль admin есть, активна другая роль | `role-inactive` + кнопка переключения, не `forbidden` |
| Прямая ссылка на несуществующий маршрут внутри `/admin` | состояние «страница не найдена» с возвратом на 131 |
| Прямая ссылка на несуществующую сущность | на 131 неприменимо: экран не адресует сущностей, единственный параметр — период. Невалидное значение периода → откат к значению по умолчанию «сегодня» |

### A11y (структурно)

- `<h1>` «Главная — администратор» присутствует, хотя на скане не нарисован; секции — `<h2>` («Масштаб системы», «Активность»). Skip-link на `#main` из `AppShell`.
- Три карточки — `<ul>`; блок метрик — `<dl>`. **Ни то, ни другое не таблица**: у чисел нет второй оси.
- `MainNav` — один `<nav>` с `aria-label`, активный пункт `aria-current="page"`. У admin **один** набор, второго `<nav>` нет (в отличие от headman).
- `PeriodTabs` — `tablist` с навигацией стрелками; **смена периода объявляется через `role="status"`** («данные за сегодня»), иначе незрячий пользователь не узнает, что числа под ним изменились.
- `MetricDelta`: направление **словом** («прирост 12 за сутки»), не стрелкой и не цветом. Состояния `unknown` и `not-applicable` тоже текстовые.
- Проценты разворачиваются в доступном имени: «доля самостоятельных геоотметок 63 процента, 1240 из 1970» — символ «%» вслух не читается (§6.2), и процент без абсолютных чисел не показывается.
- **Подпись о правиле подсчёта** («один аккаунт может учитываться в нескольких карточках») — часть доступного имени карточки, а не только `Tooltip`.
- Порядок фокуса: skip-link → `RoleSwitcher` → `MainNav` → `ProfileMenu` → карточки (не фокусируемы, читаются как список) → `PeriodTabs` → метрики.
- Тач-таргеты кнопок периода ≥ 44×44. `prefers-reduced-motion` — если появится анимация набегающих чисел, отключать; число обязано быть читаемым сразу.
- Крупных сеток и длинных списков на экране нет — паттерн roving tabindex не требуется.

### A11y (структурно)

- `<h1>` «Пользователи»; поиск и фильтры — в `<search>`-регионе перед таблицей.
- Настоящая `<table>` с `<th scope="col">`. Колонки «Роль» и «Статус» многозначны: **каждый статус называет свою роль в доступном имени** («преподаватель: активен; студент: отчислен»), иначе выравнивание читается только глазами.
- ⋮ — `RowActionsMenu`: `aria-haspopup="menu"`, стрелки внутри, Esc, возврат фокуса на триггер; недоступные пункты — `disabled` с текстовой причиной, не скрыты.
- Изменение результата поиска и фильтрации объявляется `role="status"`; `Pagination` объявляет загруженную порцию.
- При раскрытии формы фокус переводится внутрь, при сворачивании возвращается на кнопку. **При исчезновении строки (архивирование) фокус переводится на следующую строку**, а не теряется в конце документа (§6.2).
- Логин, пароль и Telegram id — строки, которые скринридер читает слитно: доступное имя ячейки поясняет, что это за значение.
- Статусы и роли — **словами**, цвет вторичен. Тач-таргеты ⋮ ≥ 44×44.

### Нехватка прав

Неавторизованный → ПК-001 с возвратом. Без роли admin → `ForbiddenState`, список не запрашивается. Роль есть, активна другая → `role-inactive` с переключением. ### A11y (структурно)

- Статус — **символ + текст**, цветом не кодируется (реестр, §7). Заметка 3 макета упоминает оттенок ячейки — оттенок допустим как дополнение, но не как единственный носитель.

- **Два `LessonPager` требуют разных `aria-label`** («Пара в ручной отметке», «Пара в журнале»): иначе скринридер получит две неразличимые пары «◀ ▶».
- Панели с внутренним скроллом — `role="region"` + `aria-label` + `tabindex="0"`, иначе прокрутка недоступна с клавиатуры.
- `HomeworkComposerDrawer` — `role="dialog"`, `aria-modal="true"`, ловушка фокуса, закрытие по Esc, возврат фокуса на кнопку «Выдать задание».
- Подтверждение блокировки — тот же диалоговый контракт; исход объявляется текстом.
- Анимация выезда панели уважает `prefers-reduced-motion`.
- Кружки статуса — с достаточным зазором между соседними; 44×44 — требование мобильной поверхности, на десктопе закладывается только «не мельче комфортного клика».
- Порядок табуляции совпадает с визуальным: шапка → счётчики → панель отметки (пейджер → блокировка → ростер) → журнал → дз → заявки.

### A11y (структурно) — на этом экране самая нагруженная часть

- **Двухуровневая шапка.** Дата — `<th colspan>` со `scope="colgroup"`; пара (предмет + тип) — `<th scope="col">`; ФИО — `<th scope="row">`. Это прямое следствие подтверждённой владельцем структуры «колонка = пара, над днём — объединённая ячейка». Без двух уровней скринридер не назовёт ни дату, ни пару.
- **Доступное имя ячейки** содержит все три координаты: «Отметка для ‹ФИО›, ‹предмет, тип›, ‹дата, пара №N›». В матрице визуальный контекст не озвучивается сам.
- **Три кружка — `radiogroup`, а не три отдельные кнопки.** Критично по объёму: ~600 ячеек × 3 контрола = 1800 фокусируемых элементов при наивной разметке. В `radiogroup` в порядок табуляции попадает **один** элемент группы, внутри — стрелки. Это снижает число Tab-остановок в три раза и делает таблицу проходимой.
- **Вертикальный текст предмета** — только визуальный приём; доступное имя остаётся обычным текстом.
- **Крестообразная подсветка строки и столбца** (заметка 1 макета) обязана срабатывать **и по фокусу с клавиатуры**, не только по наведению — ради клавиатурного пользователя она в первую очередь и нужна.
- **Деление каждые 5 студентов** (заметка 2 job) — чисто визуальный ритм. **Не превращать в `<tbody>`-группы:** семантической сущности «пятёрка студентов» не существует, скринридер объявит несуществующую структуру.
- **Фиксированный первый столбец** при горизонтальном скролле (заметка 5 макета) не должен выпадать из порядка табуляции.
- **Таблица без вертикального скролла** (заметка 5 макета) — страница получается длинной; отсюда важность skip-link и `h2` на каждой секции.
- Смена недели объявляется через `role="status"` («Неделя 7, 13–18 октября, чётная»): после нажатия ◀ содержимое иначе меняется молча.
- `ExcuseTicketDialog` и `WeeksExportDialog` — `role="dialog"`, `aria-modal="true"`, ловушка фокуса, Esc, возврат фокуса в исходную точку.
- Статус в ячейке — **символ + текст**; оттенок ячейки (заметка 3 job) допустим как дополнение, не как носитель смысла. Активная пара выделяется текстом или иконкой, не только цветом.

### Про триггер детальной панели — рекомендация

Владелец оставил выбор за UX. Предлагаю **оба способа одновременно**, и это не компромисс, а требование доступности:

- **Кнопка-стрелка в конце строки** — основной механизм: у неё есть доступное имя («Подробнее о ‹ФИО›»), она попадает в порядок табуляции и работает с клавиатуры.
- **Клик по строке целиком** — дополнительный способ для мыши, увеличивает область попадания.

Почему не «только строка»: `<tr>` нельзя сделать кнопкой, не сломав семантику таблицы. Строка-кнопка либо выпадает из клавиатурной навигации, либо требует навешивания роли, которая конфликтует с `row`. Кнопка в ячейке решает это чисто. Обратное («только стрелка») тоже хуже: на широкой таблице попасть в маленькую стрелку сложнее, чем в строку.

### Нехватка прав

Неавторизованный → вход с возвратом. Без `is_headman` → `ForbiddenState` без утечки данных группы. Помощник — предположительно по `view_stats`; конкретика после согласования прав (владелец: разбираемся после фронта).

### A11y (структурно)

- `h1` «Статистика — ‹код группы›»; `h2` на каждую из четырёх секций; уровни без пропусков.
- Таблицы — настоящие `<table>`: `<th scope="col">` в шапке, ФИО — `<th scope="row">`. Шапка и первый столбец фиксируются при скролле (заметка 4 макета), **не выпадая из порядка табуляции**.
- Сортировка — `aria-sort`; перестроение объявляется через `role="status"`, иначе после клика таблица меняется молча.
- `TableColumnFilter` — `Popover` из реестра: ловушка фокуса, Esc, возврат фокуса на заголовок колонки.
- **График не может быть единственным носителем информации** — `ChartDataTable` обязателен (A11Y_REQUIREMENTS, реестр).
- Две линии различаются **подписями**, не только цветом; точки доступны с клавиатуры.
- Плавное перетекание графика (заметка 5) уважает `prefers-reduced-motion`.
- Числа в плитках сопровождаются текстовой подписью периода («за семестр»), иначе «42» без контекста.
- `StatsDetailPanel` — `role="region"` с `aria-label`; появление объявляется через `role="status"`; фокус переводится в панель, но **не запирается** — она не модальная.
- Разбивка причин — список определений («тип → количество»), не таблица из div'ов.

- **Три кнопки режима — не `tablist`.** ARIA требует, чтобы одна вкладка была выбрана всегда, а здесь пустой старт штатен. Это кнопки (или ссылки, если режимы адресуемые); смена режима объявляется через `role="status"`.
- `h1` «Домашнее задание — ‹код группы›», `h2` на активную секцию.
- **Календарь:** сетка с перемещением стрелками, `aria-current="date"` на сегодня, **недоступные дни объяснены текстом**, а не просто погашены. В режиме привязки доступен ровно один день — это надо озвучить, иначе календарь выглядит сломанным.
- **Ползунок — `role="switch"`** с видимой подписью обоих состояний. Переключение **обязательно объявляется**: оно молча меняет содержимое календаря.
- Форма — `FormField` из реестра: `label` / `for` / `id`, подсказки и ошибки через `aria-describedby`, ошибки **текстом, не цветом**. Проверка ссылки — текстовая.
- Список заданий — `<ul>`, каждая карточка `<li>` с `h3` (предмет + тип занятия). **Действия внутри карточки имеют доступные имена с предметом и датой** — иначе экран озвучится как «Удалить, Удалить, Удалить».
- **`LinkifiedText`:** автоматически распознанные ссылки должны получать осмысленное доступное имя и видимый домен; голый URL в качестве текста ссылки допустим, но не должен быть единственным ориентиром.
- Подтверждение удаления и `HomeworkHistoryDialog` — `role="dialog"`, `aria-modal="true"`, ловушка фокуса, Esc, возврат фокуса на вызвавшую кнопку.
- История — `<ol>` в хронологическом порядке: записи разнородны, таблица навяжет ложную сетку.
- Заблокированные действия — `aria-disabled` **с текстовым пояснением рядом**, не скрытые.

- **Помощник** — см. §5; при отсутствии права блок данных не рендерится.

### A11y (структурно)

- Один `h1` «Заявки и тикеты». Skip-link на `#main`. Два `<nav>` с разными `aria-label`.
- Вкладки — `Tabs` с полной ARIA-механикой (стрелки, `aria-selected`, перевод фокуса в панель); **счётчик активных входит в доступное имя вкладки**, отдельного бейджа нет.
- Очередь — `<ul>` / `<li>`; каждая карточка — `<article>` с заголовком, включающим **тип тикета и ФИО**.
- Список пар внутри — вложенный `<ul>`, **не таблица**: три поля на строку не требуют табличной семантики.
- **Тип тикета передаётся текстом** («тикет на "у"»), а не только составом полей.
- Раскрытие состава пар — `aria-expanded` на триггере, появление объявляется через `role="status"`.
- Раскрытие формы отклонения — `aria-expanded`, фокус в поле причины, при отмене возврат на кнопку.
- **Исчезновение карточки из «Активных» объявляется через `role="status"`, а фокус переводится на следующую карточку**, а не теряется в конец документа: разбор очереди с клавиатуры — главный сценарий экрана.
- Ошибки — `role="alert"` внутри своей карточки, не общим баннером.
- Все состояния (`loading`, `empty`, `filtered-empty`, `error`, `forbidden`, `offline`) озвучиваемы.

### Модель экрана

Два **типа тикета** и два **представления списка** — это разные оси:

| Ось | Значения |
|---|---|
| Тип тикета | тикет на «у» (уважительная причина + файлы) · тикет на «н» (оспаривание проставленного «н») |

Тикет на «н» — это **пакетный late-checkin из прошедших пар**. Форма у него подмножество формы «у» (прим. 2: «часть тикета на "у"»).

**Решение владельца:** тикет — **неделимая единица**, одобряется или отклоняется целиком. Статусов по отдельным парам внутри тикета нет.

- **Строка целиком ссылкой не делается** — ломает семантику таблицы (правило `RowDetailTrigger`: `<tr>` кнопкой не делать). Основной клавиатурный путь — ссылка в ячейке предмета с полным доступным именем «Посещаемость: УИТ-211, Предмет 1, лекция»; клик по строке целиком — дополнительный путь для мыши.
- **Аббревиатуры ЛК / ПЗ / ЛЗ разворачиваются словом** в доступном имени: «лекция», «практическое занятие», «лабораторное занятие». Аббревиатура без расшифровки доступна только зрячему знающему.
- Доступное имя строки пары включает время и группу: «Посещаемость: 10:15, УИТ-211, Предмет 1, лекция, ауд. 3417». Пометки «разовая», «перенесена», «отменена» входят в него **текстом**.
- `DatePager` имеет собственный `aria-label` (на экране он один, но правило «несколько экземпляров — разные метки» соблюдаем заранее). **Смена дня объявляется через `role="status"`**: дата + количество пар, иначе для скринридера список молча подменяется.
- Порядок фокуса: skip-link → `RoleSwitcher` → `MainNav` → `ProfileMenu` → «Мои группы» → «Мои предметы» → `DatePager` → список пар.
- Списки маленькие (единицы строк) — roving tabindex не нужен, правило крупных сеток (§6.2) здесь не применяется.
- Ошибка — `role="alert"`, смена состояния блока — `role="status"`.
- Тач-таргеты ≥44×44; стрелки пейджера — самые мелкие цели экрана, за ними следить особо.
- `prefers-reduced-motion`: единственная потенциальная анимация — смена дня; переход делаем мгновенным при включённом флаге.

**A11y (структурно)**

- `<h1>` «Посещаемость»; `<h2>` у фильтров, журнала и панели причины. Панель — не `<aside>` в смысле «в стороне», а именованный регион, связанный с ячейкой-триггером.
- Журнал — настоящая `<table>`: `<th scope="row">` = ФИО, `<th scope="col">` = дата (+ тип занятия); **пары одного дня объединяются датой через `colspan` + `scope="colgroup"`** (решение чата 4). Хвостовые колонки метрик — `<th scope="col">` с полными подписями, не «%+».
- **Интерактивна только часть ячеек** (статус «у»), поэтому массовый `radiogroup` здесь не нужен. Но если «у» в сетке десятки, **применяем правило крупных сеток**: одна остановка Tab на таблицу, перемещение стрелками, Enter открывает панель.
- Ячейка «у» — `<button>` **внутри** `<td>`, не кликабельный `<td>`. Доступное имя: «Уважительная причина, Иванов И. И., 12 марта, лекция — открыть заявку».
- `Tooltip` открывается **и по наведению, и по фокусу**; его содержимое дублируется в доступном имени кнопки — подсказка мышью для клавиатуры недостаточна.
- Первый столбец ФИО фиксирован визуально; **порядок чтения при этом не меняется**.
- Перестроение журнала после смены фильтра объявляется через `role="status"`: предмет, типы, число студентов и пар. Иначе таблица молча подменяется.
- Раскрытие панели — **сдвиг в DOM сразу после таблицы**, а не наложение (§6.2).
- Символы `+` · `у` · `н` разворачиваются словами в доступном имени; цвет носителем смысла не является.
- `ExportButton`: выбор формата — именованные варианты, доступное имя включает предмет и формат («Скачать журнал: Предмет 1, лекция, xlsx»).

## 6. Навигация и действия

| Элемент | Действие |

| `LessonTypeToggleGroup` | мульти-выбор, пересчёт. Тип без пар у предмета — `disabled` с пояснением |

| Строка студента | **не кликабельна** (детализации нет) |
| **Строка группы** | переключает разрез на «по студентам» с этой группой — путь от «какая группа плохая» к «кто именно» |

| `MainNav` | 121 / 122 / 123 / 105 |

Оптимистичного UI нет: экран ничего не меняет на сервере.

**Контекст в URL:** разрез, `groupId`, `subjectId`, `lessonType[]`, сортировка — по идентификаторам (правило чата 5). Приход с 121 задаёт только `groupId` и разрез «по студентам». F5 и пересылка ссылки сохраняют картину; между сессиями не сохраняем.

**A11y (структурно)**

- `<h1>` «Статистика», `<h2>` у фильтров и таблицы. `StatsScopeTabs` — ARIA tablist с переводом фокуса в панель.
- `ContextBar` — **список определений**, не таблица; читается до таблицы, чтобы сводка была самодостаточной вслух.
- Настоящая `<table>`: `<th scope="row">` = ФИО или название группы, `<th scope="col">` = метрика.
- **Подписи колонок словами** — «Процент присутствия», «Процент присутствия и уважительных», а не «% +» и «% + и у»: символ `+` вслух не читается.
- Абсолютные числа — в той же ячейке, одной фразой в доступном имени: «72 %, 18 из 25 пар».
- Сортировка: `aria-sort` на активном заголовке, результат объявляется через `role="status"` («отсортировано по проценту присутствия, по возрастанию»), **фокус остаётся на заголовке**.
- Пересчёт после смены фильтра или разреза объявляется `role="status"`: разрез, предмет, типы, число строк и учтённых пар.
- Таблица небольшая (≈25 строк × 4–5 колонок) — правило крупных сеток и roving tabindex не применяются.
- Строка-группа кликабельна: **ссылка/кнопка внутри ячейки названия**, `<tr>` кнопкой не делаем (правило `RowDetailTrigger`).
- `ExportButton`: доступное имя включает разрез и формат («Скачать статистику: УИТ-211, Предмет 1, лекция, xlsx»).
