# A11Y_REQUIREMENTS.md

> Требования доступности для нового фронтенда RutCampusTrack (Vue, микрофронтенды).
> Извлечены из старого `a11y-checklist.md`, очищены от привязки к legacy-приложениям.
> Framework-agnostic: применимо к любому компоненту, независимо от стека.

---

## Цель и критерии приёмки

- **Целевой уровень:** WCAG 2.1 AA. AAA — non-goal.
- **Автоматическая проверка:** axe — **CRITICAL + SERIOUS = 0**. MODERATE/MINOR — фиксировать и закрывать.
- **Lighthouse a11y:** ≥ 95 на каждой поверхности.
- **Контраст:** минимум 4.5:1 для текста, 3:1 для крупного текста и UI-элементов.

---

## Что учитывать уже на этапе wireframe

Это не «полировка перед релизом» — половина требований определяется структурой экрана, а не стилями.

### Структура страницы

- Один `<main>` на страницу, весь основной контент внутри.
- Заголовки строго иерархично: h1 → h2 → h3, без пропусков уровней. На экране один h1.
- Landmark-регионы: `<nav>`, `<header>`, `<footer>`, `<aside>` — с `aria-label`, если их несколько.
- **Skip-link** «Пропустить навигацию» на `#main` — виден только при фокусе.

### Навигация и фокус

- Логичный порядок табуляции, совпадающий с визуальным порядком.
- Видимый фокус (`focus-visible`) на всех интерактивных элементах.
- Модалки/шторки: `role="dialog"`, `aria-modal="true"`, `aria-label`, ловушка фокуса, возврат фокуса при закрытии, закрытие по Esc.
- Никаких кликабельных `<div>` — ссылки это `<a>`, кнопки это `<button>`.

### Данные и таблицы

- Табличные данные — в `<table>` с `<th scope="col">` / `scope="row"`, а не в grid из div'ов.
- Это касается журналов посещаемости, статистики по студентам, расписания в табличном виде.

### Формы

- У каждого поля явный `<label>` со связкой `for`/`id`. `aria-label` — не замена лейблу.
- Подсказки и ошибки — через `aria-describedby`.
- Ошибки валидации: текстом, не только цветом.

### Состояния и обратная связь

- Нейтральные уведомления — `role="status"` (вежливо), критичные — `role="alert"` (немедленно).
- Асинхронные действия — `aria-busy` на время выполнения.
- Состояния `loading` / `empty` / `error` / `forbidden` / `offline` должны быть озвучиваемы, а не только визуальны.

### Motion

- Уважать `prefers-reduced-motion`: отключать/упрощать анимации.
- Не использовать анимацию как единственный носитель информации.

### Тач и мобильные поверхности

- Тач-таргеты не меньше 44×44 CSS-пикселей.
- Достаточные отступы между соседними интерактивными элементами.

### Цвет

- Цвет не единственный способ передать смысл (статус посещаемости, ошибка, роль) — дублировать текстом или иконкой.
- Контраст проверяется в **обеих темах** (dark и light).

## Инструменты (этап реализации, не wireframe)

- `@axe-core/cli` на dev-сборке, интеграция в e2e-тесты.
- ESLint-плагин доступности для Vue (`eslint-plugin-vuejs-accessibility`).
- Lighthouse в CI.
- Ручная проверка скринридером на ключевых флоу (вход, отметка посещаемости).
